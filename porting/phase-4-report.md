## 1. 요약

교과목(버전, 선수·동시수강, 대체과목), 이수 구분별 졸업 요건, 학기 세션, 개설강좌(담당 교원, 강의 시간과 강의실, 수강 대상·제외 대상, 좌석 할당), 시간표, 강의계획서, 이전 학기 복사, 교과목 CSV를 구현했다. Phase 3 이후 합의한 사항(학기 세션과 세션별 업무 기간, 복수전공·부전공 학생 신청, 명령 실행 ID, 관리 화면 가져오기의 담당자 기록 테스트)을 함께 반영했다.

- 테스트 321개(단언 1,112개) 통과. Phase 3 대비 34개 추가. Larastan 레벨 6 오류 0, Pint 위반 0, 명명 검사 위반 0, 번역 누락 0, `composer audit` 통과
- 빈 DB에서 `setup:install --force --profile=korean-university`, `setup:demo --size=small --seed=42` 성공. 데모 두 학기(각 52개 강좌, 강의 시간 94개)가 `schedule:check-conflicts`에서 문제 0건. 다음 학기 편성은 데모 시더가 `CopySections`로 만든다
- CI(GitHub Actions) 통과 (7절)

## 5. 발견해 고친 문제

- **시각 입력의 시간대 변환 (Phase 1부터)**: 관리 화면이 교시 시각(10:30)을 기관 시간대에서 UTC로 바꿔 01:30으로 저장했다. 강의 시간 입력 테스트에서 드러났다. 교시와 강의 시간은 시간대가 없는 벽시계 시각이므로 변환하지 않게 고쳤다. 관리 화면에서 교시를 직접 입력한 설치는 값을 확인해야 한다(매뉴얼 10장 안내).
- **가져오기 실패 행이 남긴 인물 (Phase 2)**: 학생·교원 CSV에서 저장에 실패한 행도 인물은 이미 만들어져 남았다. 인물 생성을 행 세이브포인트 안으로 옮겼다(`PersonImportTest`, 수정 전 코드에서는 실패하는 것을 확인).
- **sync 큐 작업 뒤 사용자 컨텍스트 소실**: 요청 안에서 동기로 실행된 큐 작업이 끝나면 DB 컨텍스트를 비워, 그 요청의 남은 조회가 RLS에 막힐 수 있었다. 작업 전 상태로 되돌리게 고쳤다(`AuditCorrelationTest`).
- **복수전공 승인 담당자의 학적 조회**: 대상 학과 담당자가 신청 학생의 학적을 볼 수 없어 승인할 수 없었다. 처리할 신청의 학적과 이수 중인 복수전공 학생의 학적을 볼 수 있게 했다(애플리케이션과 RLS 양쪽).
- **포기한 복수전공 재이수 불가**: `student_record_programs`의 unique가 종료된 행까지 막았다. 현재 행에만 적용.
