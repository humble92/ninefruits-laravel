# 0012. 강의평가: 익명 응답, 공개 기준, 성적 조회 제한

- 상태: 채택 (2026-10-22, Phase 7)
- 관련: [이식 계획 Phase 7](../porting-plan.md), [0011 성적](0011-grades-and-term-records.md), [관리자 매뉴얼 22장](../../docs/manual/ko/admin/22-course-evaluation.md)

## 레거시 분석 요약

- 응답(`SURITEM`)과 의견(`SURRECORD`)의 기본 키에 학번이 있었고, 교수 계정이 두 테이블을 직접 SELECT할 수 있었다. 익명이 아니었다.
- 문항은 학기마다 SQL로 넣었다. 25문항, 5점 척도, 의견 1개이며, 문항 수가 코드에 박혀 있었다.
- 성적 조회 제한(`GetSurveyIsCompleted`)은 메뉴 링크만 막았고, 평가 기간이 지나도 풀리지 않았다. 판정도 과목 코드만 세서 엉뚱한 과목 평가로 채울 수 있었다.
- 결과 화면:
  - 반올림한 비율로 평균을 냈고, 영역마다 10번째 문항을 빼먹었다.
  - 교수 화면에는 최소 응답 기준이 없었고(교무 화면 링크에만 25%), 교수가 다른 강좌 결과도 볼 수 있었다.
  - 의견을 이스케이프 없이 출력했다.

## 결정

### 완료와 응답을 분리한다

| 테이블 | 내용 | 학생 |
|---|---|---|
| `evaluation_completions` | 수강 하나당 한 행(unique), 완료 시각 | 수강으로 알 수 있음 |
| `evaluation_responses` | 무작위 UUID, 학기, 강좌, 양식 | 없음 |
| `evaluation_answers` | 응답 × 문항의 점수 또는 의견 | 없음 |

- 응답에는 학생뿐 아니라 **순번(일련번호)과 시각도 두지 않는다.** 순번이나 시각이 있으면 완료 기록의 순서·시각과 맞춰 학생을 짐작할 수 있다. 응답 ID는 UUID v4(무작위)이고, 답변은 (응답, 문항) 복합 키다.
- 응답 테이블에는 **데이터 감사 트리거를 걸지 않는다.** 감사 기록은 수행자 ID를 남기므로 학생과 응답을 잇게 된다. 완료 기록도 감사하지 않는다(완료 사실은 행 자체가 기록).
- 응답은 애플리케이션이 학생의 수강, 기간, 중복을 확인한 뒤 **시스템 컨텍스트**에서 한 트랜잭션으로 쓴다. 학생이 없는 행이라 RLS가 학생을 확인할 수 없기 때문이다. 시스템 컨텍스트의 세션 변수에는 사용자 ID가 남지만, 이 테이블들에는 그것을 기록하는 트리거가 없다.
- 남는 한계:
  - DB 물리적 저장 순서는 입력 순서를 따를 수 있다. DB 관리자 수준의 접근이 필요하며, 애플리케이션과 RLS로는 드러나지 않는다.
  - 강좌의 응답이 아주 적으면 내용으로 짐작할 수 있다. 그래서 최소 응답 기준을 둔다.

### 결과는 공개 후, 기준 이상인 강좌만

- `term_evaluations`: 학기의 양식, 최소 응답 수, 최소 응답률, 결과 공개 시각.
- **세부 결과(문항별 평균, 분포, 의견)는 누구에게나 학기 결과 공개 뒤에만** 보인다. 직원도 그렇다. 기간 중 결과 변화를 완료 시각과 맞춰 보면 학생을 짐작할 수 있기 때문이다. 공개 전에는 응답 수와 응답률만 보인다.
- 공개 뒤에도 응답 수 ≥ 최소 응답 수, 응답률 ≥ 최소 응답률인 강좌만 보여 준다. 기본 5명, 25%(레거시 교무 화면 기준, 2026-10-23 결정). 응답 수는 익명성, 응답률은 대표성을 위한 기준이다.
- 교원은 자기 강좌만 본다(애플리케이션과 RLS. 교원의 응답 조회 정책은 공개된 학기의 자기 강좌로 제한).
- 학생은 어떤 응답도 조회할 수 없다(RLS).
- 평균은 원래 점수로 계산한다. 역문항은 (최고점 + 1 − 점수)로 뒤집는다. 의견은 무작위 순서로 보여 주고, 화면에서 이스케이프한다.

### 성적 조회 제한은 기간 동안만

- 설정 `grades_require_evaluation`(기본 켬)이 켜져 있으면, 그 학기 평가 대상 중 미완료 과목이 있고 평가 기간이 열려 있는 동안 **그 학기** 성적을 가린다.
- 학생 성적 화면과 성적표 모두 서버에서 가린다.
- 기간이 끝나면 풀린다(레거시의 영구 잠김을 피함). 다른 학기 성적은 가리지 않는다.

### 평가 대상과 기간

- 대상: 학기 강의평가가 있는 학기의 수강 중·이수 과목. 철회·취소 과목과 교과목 버전의 `requires_evaluation`이 꺼진 과목(실습, 인턴십. 레거시 H 구분)은 뺀다.
- 기간: 세션별 업무 기간 `course_evaluation`(Phase 1, 0009). 대상 조건으로 학년별 기간도 가능하다.

### 양식

- `evaluation_forms`, `evaluation_questions`: 번역 가능한 문항, 영역, 유형(척도, 주관식), 필수, 역문항.
- 응답이 있는 양식은 문항과 척도를 바꿀 수 없고, 복사해서 새 양식을 만든다.
- 학기에 응답이 생긴 뒤에는 그 학기의 양식도 바꿀 수 없다.

## 하지 않은 것

- 응답 수정과 임시 저장(레거시도 없었음). 한 번 제출하면 끝이다.
- 과목 유형별 양식(실험, 실습 등). 학기당 한 양식이다. 필요하면 교과목 또는 강좌에 양식을 지정하는 칸을 더한다.
- 교원·학과별 통계 보고서(레거시 `pingjia`): Phase 11 보고서.
- 레거시 응답 이관: 학번이 붙은 원본이라, 이관한다면 완료 기록과 익명 응답으로 나눠 넣는다.
