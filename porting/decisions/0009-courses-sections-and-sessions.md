# 0009. 교과목, 학기 세션, 개설강좌

- 상태: 채택 (2026-10-22, Phase 4)
- 관련: [이식 계획 10.2절, 10.4절, 10.6절](../porting-plan.md), [0006 기준정보와 업무 기간](0006-reference-data-model.md)

## 학기 세션 (`term_sessions`)

Phase 1에서는 "필요해지면 추가"로 미뤘다. 전반기·후반기, 집중 과목처럼 같은 학기 안에서 수업 기간과 수강 정정·철회·성적 마감이 다른 과목을 다루려고 Phase 4에서 도입했다.

- 모든 학기에 **전체 학기 세션**(`FULL`)이 있다. 학기를 만들 때 생기고 학기 날짜를 따라간다(`Term` 모델 이벤트, 기존 학기는 마이그레이션이 채움). 세션은 학기 안에 있어야 한다(트리거).
- 모든 개설강좌는 세션 하나에 속한다. 세션을 쓰지 않는 대학도 같은 흐름이다.

### 업무 기간을 세션에 붙인다 (세션에 날짜 칸을 두지 않는다)

검토한 두 방식

| | 세션에 마감일 칸 (정정 마감, 철회 마감, 성적 마감) | 업무 기간에 세션을 붙임 (채택) |
|---|---|---|
| 대상별 기간 | 불가(세션당 날짜 하나) | 가능. 예: 졸업예정자 철회 마감을 앞당김 |
| 같은 업무 여러 번 | 불가 | 가능. 1차·2차 정정, 일부 학생 연장 |
| 시작과 끝, 시각 | 칸을 늘려야 함 | 이미 있음 |
| 관리와 점검 | 일정이 두 곳에 나뉨 | 한 화면, `term:inspect` 하나 |
| 기존 코드 | 업무 기간 종류 3개를 옮기고 `TermResolver` 재작성 | 확장 |
| 설정할 줄 수 | 적음 | 세션마다 창을 넣어야 함 → **업무 기간 복사**로 줄임 |

- **과목에 딸린 업무**(수강 정정, 수강 철회, 성적 입력, 성적 이의, 강의평가)는 반드시 세션에 붙고, **학생·학기 업무**(장바구니, 수강신청, 졸업 신청, 복수전공·부전공 신청)는 세션에 붙지 않는다. DB CHECK 제약 `term_windows_session_check`와 복합 외래 키(세션은 같은 학기)로 보장한다. 세션을 지정하지 않은 과목 업무는 전체 학기 세션에 붙는다.
- 질문: `TermResolver::isOpenInSession($type, $section->session, $student)` — "이 학생이 이 과목을 지금 취소할 수 있나".
- `CopySessionWindows`: 원본 세션 전반부에 열리는 창은 세션 시작일 기준, 후반부 창은 종료일 기준으로 옮긴다.

## 교과목

- `courses`(불변 코드, 관리 조직) + `course_versions`(기간, 교과목명, 학점, 시간, 교과 구분, 성적 평가, 학점 상한 포함, 반복 이수). 같은 교과목의 기간 중복은 배제 제약(`course_versions_no_overlap_excl`). 레거시의 "학점은행 과목 코드" 같은 코드 규칙은 버전 속성으로 대신한다.
- 개정(`ReviseCourse`)은 현재 버전을 전날 끝내고 새 버전을 시작한다(선수과목 복사). 개설강좌는 세션 시작일의 버전을 저장하므로 지난 학기는 그대로다.
- 선수·동시수강 과목은 **버전**에 속한다(요건도 시기별로 바뀌므로). 묶음 번호: 묶음 안은 OR, 묶음끼리는 AND.
- 대체과목은 기간을 가진 별도 관계(상호/단방향).

## 졸업 요건

`curriculum_requirement_sets`(프로그램, 이수 구분: 주전공/복수전공/부전공, 교육과정 연도 범위) + `curriculum_requirements`(교과 구분별 학점 / 필수 과목 / 지정 과목 중 선택). 연도 범위는 `int4range` 생성 열과 배제 제약으로 겹침을 막는다. 판정 엔진은 Phase 8.

## 개설강좌와 중복 배정 차단

- `sections`: 학기, 세션(복합 외래 키로 같은 학기), 교과목과 버전(복합 외래 키로 같은 교과목), 분반, 개설 조직(권한 범위), 정원, 상태(작성 중/공개/폐강), 수강 대상과 제외 대상(`TargetCriteria`).
- `section_meetings`: 요일, 시작·종료 시각, 강의실, 날짜(기본 세션 기간). 생성 열 `time_range`(분 단위 `int4range`), `date_range`.
- **강의실**: 배제 제약 `EXCLUDE (room_id =, weekday =, time_range &&, date_range &&) WHERE (room_id IS NOT NULL AND is_active)`. 동시 요청에서도 PostgreSQL이 보장한다.
- **교원**: 교원은 `section_instructors`에 있어 한 테이블 제약으로 표현할 수 없다. 두 테이블의 트리거가 같은 함수로 검사하고, 교원별 advisory lock으로 동시 배정을 직렬화한다. 오류 코드는 배제 제약과 같은 23P01.
- **폐강**: `sections` 트리거가 강의 시간의 `is_active`를 내려 강의실과 교원 시간을 비운다. 다시 열면 같은 검사를 다시 받는다.
- 애플리케이션(`ScheduleConflicts`)은 DB 오류를 겹치는 강좌 이름이 들어간 메시지로 바꿀 뿐 판단하지 않는다. `ScheduleConflictTest`가 순서를 바꾼 배정, 폐강/재개, 애플리케이션을 거치지 않는 쓰기까지 확인한다.

## 복수전공·부전공

- 학생 신청(`additional_program_requests`) → 대상 프로그램 담당자 승인(`additional_programs.approve`, 대상 프로그램 범위) → `student_record_programs` 추가. 신청 기간은 학생 업무 기간(`additional_program_application`), 프로그램별 허용 여부, 동시 이수 한도(설정).
- 학적 조회 범위 확장(애플리케이션과 RLS 같은 규칙)
  - 대상 학과 담당자: 이수 중인 복수전공·부전공 학생의 학적 조회.
  - 승인 담당자: 처리할 신청을 낸 학생의 학적 조회. 정책 재귀를 피하려고 SECURITY DEFINER 함수 `util.additional_program_request_record_ids()`를 쓴다.
- 수강 대상 판단(`TargetSubject`)은 복수전공·부전공 프로그램과 그 조직도 포함한다.
- `student_record_programs`의 unique를 현재 행에만 적용해, 포기한 프로그램을 다시 이수할 수 있다.

## 함께 정리한 것

- **명령 실행 ID**: 감사 기록 명령은 실행마다 `cmd-{uuid}`를 요청 ID 자리에 둔다. 업무 감사, 데이터 변경 기록, 그 명령이 넣은 큐 작업이 같은 ID를 가진다. `--actor`는 인증되지 않은 신고값이라 데이터 변경 기록의 사용자로 넣지 않는다.
- **큐 작업 뒤 DB 컨텍스트 복원**: 작업이 끝나면 컨텍스트를 비우지 않고 작업 전 상태로 되돌린다(`DatabaseSessionContext::enterSystem/leave`). sync 큐로 요청 안에서 실행된 작업 뒤에도 요청의 사용자 컨텍스트가 유지된다. 관리 화면 가져오기의 행 단위 기록에 시작한 담당자가 남는 것을 `AuditCorrelationTest`가 확인한다.
- **벽시계 시각**: 강의 시간과 교시는 시간대가 없는 시각이다. 관리 화면의 시각 입력은 기관 시간대 변환을 하지 않는다(Phase 1 교시 화면의 변환 오류 수정).
- **관리 화면 테마**: 시간표처럼 직접 만든 Blade 화면의 Tailwind 클래스를 쓰려고 Filament 사용자 테마(`resources/css/filament/admin/theme.css`)를 추가했다. 배포 시 `npm run build`에 포함된다.
