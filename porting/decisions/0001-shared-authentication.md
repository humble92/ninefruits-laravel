# 0001. 공용 로그인과 2단계 인증: Fortify 공용 구현 채택

- 상태: 채택 (2026-10-22, Phase 0)
- 관련: [이식 계획 7.3절](../porting-plan.md#73-2단계-인증-정책)

## 배경

포털(Livewire)과 관리 화면(Filament)을 같은 사용자가 함께 쓴다. 2단계 인증을 화면 계층마다 따로 두면 사용자가 두 번 등록하고, 관리자 정책도 두 곳에 적용해야 한다. 계획은 Fortify 공용 구현을 기본안으로 두고 Filament 5 내장 MFA와 비교해 확정하기로 했다.

## 비교

| 관점 | Fortify 공용 (채택) | Filament 5 내장 MFA |
|---|---|---|
| 적용 범위 | 웹 가드 전체 (포털, 관리 화면, 이후 API 세션) | Filament 패널 로그인에만 적용 |
| 포털 사용자(학생, 지원자, 졸업생) | 같은 화면과 같은 등록 정보 사용 | 포털에 별도 구현 필요 |
| 정책 강제(역할별, 유예 기간) | 미들웨어 하나로 포털과 패널에 동일 적용 | 패널 밖은 별도 구현 필요 |
| 기기 기억 | 로그인 파이프라인에 단계 추가로 구현 (`RedirectIfTwoFactorChallengeRequired`) | 패널 기능 범위 안에서만 |
| 화면 | Blade 화면을 직접 작성 (Fortify는 화면 없음) | 패널 화면 제공 |
| 이벤트 | 등록, 확인, 해제, 실패, 복구 코드 사용 이벤트 제공 → 보안 로그 | 패널 이벤트 |

## 결정

- 로그인, 비밀번호 재설정, 비밀번호 확인, 2단계 인증 확인 화면은 Fortify 하나로 운영한다. `/admin`에 미인증으로 들어오면 공용 `/login`으로 이동한다(패널에 `->login()`을 두지 않음).
- 2단계 인증 등록과 복구 코드는 포털 `/portal/security` 한 곳에서만 한다. 관리 화면 사용자 메뉴에서 이 화면으로 연결한다.
- 정책 강제는 `EnforceMfaPolicy` 미들웨어가 매 요청마다 `SecuritySettings`를 읽어 적용한다. 포털 라우트, Filament `authMiddleware`(persistent), Livewire persistent middleware에 모두 등록되어 있다.
- 기기 기억 쿠키는 암호화되고 사용자의 현재 2단계 인증 등록 정보로 서명된다. 관리자가 초기화하거나 사용자가 다시 등록하면 기억된 기기는 모두 무효가 된다.
- 자가 회원가입은 제공하지 않는다. 교직원 계정은 관리자가 만들고(임시 비밀번호 대신 재설정 링크 발송), 지원자 계정은 Phase 3 입학 지원에서 만든다.
- Fortify 1.41의 패스키 기능은 이번 범위에서 끈다. 2단계 인증 정책과의 관계(패스키를 2단계 인증으로 인정할지)를 정한 뒤 다시 검토한다.
- 이메일 일회용 코드(2026-10-22 추가): 인증 앱과 나란한 독립 방식이다(`MfaMethod::EmailCode`). 기관 설정 `mfa_email_code_enabled`(기본 꺼짐)로 허용한다.
  - 로그인 파이프라인은 사용자가 등록한 방식으로 확인한다. 이메일만 등록한 사용자에게는 비밀번호 확인 직후 코드를 보낸다. 확인은 Fortify의 대기 중 로그인(`login.id`)을 그대로 쓰는 별도 경로(`two-factor.email.*`)에서 하므로 기기 기억, 보안 로그, 로그인 응답이 같다.
  - TOTP만 등록한 사용자에게는 이메일 경로를 열지 않는다(우회로 보안 수준이 낮아지는 것을 막음).
  - 코드는 키 기반 해시만 캐시에 저장하고, 10분 유효, 1회용, 5회 오류 시 폐기, 용도(로그인/등록)별로 분리한다. 발송은 사용자별 1분 1회, 1시간 5회로 제한한다.
  - 정책이 필수일 때는 마지막 남은 방식을 해제할 수 없다. 관리자 초기화는 두 방식을 모두 해제한다.

## 결과

- 사용자는 2단계 인증을 한 번만 등록한다. 정책 변경은 다음 요청부터 포털과 관리 화면 모두에 적용된다(테스트: `tests/Feature/Security/MfaPolicyTest.php`).
- Filament 내장 로그인/MFA 화면은 쓰지 않으므로 Filament 업그레이드 시 인증 관련 변경 영향이 작다.
