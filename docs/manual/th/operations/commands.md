# ข้อมูลอ้างอิงคำสั่ง Artisan

- ผู้อ่าน: ผู้ดูแลระบบไอที
- ขอบเขต: คำสั่งของแอปพลิเคชันทุกคำสั่งที่ลงทะเบียนไว้ในรีโพซิทอรีนี้ เมื่อเพิ่มคำสั่งใหม่ต้องเพิ่มไว้ในเอกสารนี้ด้วย มิฉะนั้น CI จะล้มเหลว (`tests/Feature/Tooling/CommandDocumentationTest.php`)

## ข้อตกลงทั่วไป

ทุกคำสั่งรันในรูปแบบ `php artisan {command}` ในสภาพแวดล้อมสำหรับพัฒนาใช้ `./vendor/bin/sail artisan {command}`

| รายการ | กฎ |
|---|---|
| บันทึกการตรวจสอบ | คำสั่งที่เปลี่ยนแปลงข้อมูล ("บันทึกการตรวจสอบ: บันทึก" ด้านล่าง) จะเขียนคำสั่ง อาร์กิวเมนต์ ตัวเลือก ผู้ใช้ระบบปฏิบัติการ รหัสสิ้นสุดการทำงาน และผลลัพธ์ลงในบันทึกการดำเนินงาน (log `command`) ทุกครั้งที่รัน ตรวจสอบได้ที่ **การตรวจสอบ > บันทึกการดำเนินงาน** ในแผงผู้ดูแลระบบ |
| รหัสการรัน | การรันแต่ละครั้งจะได้รับรหัสที่ขึ้นต้นด้วย `cmd-` แทนรหัสคำขอ บันทึกการดำเนินงาน การเปลี่ยนแปลงข้อมูลที่เกิดจากการรันนั้น และงานในคิวที่ส่งออกไปจะมีรหัสเดียวกัน คำถามว่า "คำสั่งใดทำให้เกิดการเปลี่ยนแปลงนี้" จึงตอบได้ด้วยรหัสนี้ `--actor` เป็นค่าที่ผู้ดูแลระบบระบุเอง จึงไม่ถูกใส่ในคอลัมน์ผู้ใช้ของการเปลี่ยนแปลงข้อมูล (ผู้ดำเนินการจริงคือผู้ใช้ระบบปฏิบัติการ) |
| `--actor=<email>` | ใช้ร่วมกันในทุกคำสั่งที่มีบันทึกการตรวจสอบ บันทึกบัญชีผู้ดูแลระบบที่รับผิดชอบ หากระบุอีเมลที่ไม่รู้จัก การรันจะถูกยกเลิก |
| `--dry-run` | แสดงผลลัพธ์โดยไม่เปลี่ยนแปลงสิ่งใด มีในการดำเนินการที่ย้อนกลับได้ยาก |
| `--force` | รันโดยไม่มีการขอยืนยัน (สำหรับงานตามกำหนดเวลาและสคริปต์นำขึ้นใช้งาน) |
| `--reason=` | มีในคำสั่งที่ต้องระบุเหตุผล |
| รหัสสิ้นสุดการทำงาน | 0 สำเร็จ, 1 ล้มเหลวหรือยกเลิก, 2 คำสั่งตรวจสอบพบปัญหา |
| บริบทฐานข้อมูล | ระหว่างที่คำสั่งทำงาน ผู้ดำเนินการของเซสชันฐานข้อมูลจะถูกกำหนดเป็น `system:command:{command}` และปรากฏในการเปลี่ยนแปลงข้อมูล (ทริกเกอร์) |

## การติดตั้งและข้อมูลสาธิต

### `setup:install`

- วัตถุประสงค์: การติดตั้งใหม่และการอัปเดต รันไมเกรชัน ข้อมูลพื้นฐานที่จำเป็น ค่าเริ่มต้นของสถาบัน โปรไฟล์การติดตั้ง และผู้ดูแลระบบเริ่มต้นตามลำดับ รันซ้ำได้อย่างปลอดภัย (ข้อมูลเดิมและค่าที่ผู้ดูแลระบบแก้ไขไว้จะคงอยู่)
- เมื่อใช้: เมื่อติดตั้งครั้งแรกและทุกครั้งที่นำขึ้นใช้งาน
- ตัวเลือก: `--institution-name=`, `--locale=` (ภาษาเริ่มต้น), `--timezone=` (ตัวอย่างเช่น `Asia/Seoul`), `--profile=*` (คีย์ของโปรไฟล์การติดตั้ง), `--grade-scale=` (เกณฑ์ระดับคะแนน `4.5` หรือ `4.3` เปลี่ยนไม่ได้เมื่อกำหนดแล้ว หากว่างจะใช้เกณฑ์ของโปรไฟล์แรก), `--admin-email=`, `--admin-name=`, `--force` (รันโดยไม่ถามคำถาม รหัสผ่านผู้ดูแลระบบจะอ่านจากอินพุตมาตรฐาน)
- บันทึกการตรวจสอบ: บันทึก
- ตัวอย่าง

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="Demo University" --admin-email=admin@example.ac.kr --admin-name="Administrator"
  ```

- การอ่านผลลัพธ์: `DONE`/`FAIL` ในแต่ละขั้นตอน `Administrator exists` หมายความว่ามีการกำหนดบทบาทผู้ดูแลระบบอยู่แล้ว จึงข้ามการสร้าง
- เมื่อล้มเหลว: หากข้อผิดพลาดแจ้งว่าไม่มีคีย์ ให้ใส่ค่าที่สร้างด้วย `key:generate` และ `pii:generate-key` ลงในการตั้งค่าสภาพแวดล้อม ไมเกรชันล้มเหลวมักหมายความว่ายังไม่ได้เตรียมบทบาทของฐานข้อมูล (ดูคู่มือการติดตั้ง)

### `setup:demo`

- วัตถุประสงค์: สร้างข้อมูลของมหาวิทยาลัยสมมติด้วย factory แสดงบัญชีสาธิตแบบคงที่ของแต่ละบทบาท (`registrar@demo.test` เป็นต้น)
- เมื่อใช้: สภาพแวดล้อมสำหรับพัฒนา ฝึกอบรม และสาธิต **จะไม่ทำงานในระบบใช้งานจริง (`APP_ENV=production`) แม้ใช้ `--force`**
- ตัวเลือก: `--size=tiny|small|medium|large` (นักศึกษาประมาณ 20/100/2,000/20,000 คน `tiny` สำหรับการทดสอบและการตรวจสอบอย่างรวดเร็ว), `--seed=` (ค่าเดียวกันให้ข้อมูลเหมือนกัน), `--force`
- `--student-accounts`: สร้างบัญชีให้นักศึกษาที่กำลังศึกษาทุกคน (`student{student number}@demo.test` รหัสผ่านสาธิต) และเขียนลงใน `storage/app/private/load-accounts.csv` สำหรับการทดสอบโหลด ([การทดสอบโหลด](load-testing.md))
- บันทึกการตรวจสอบ: บันทึก
- ตัวอย่าง: `php artisan setup:demo --size=small --seed=42`
- เมื่อล้มเหลว: หากไม่มีข้อมูลพื้นฐานที่จำเป็น บัญชีสาธิตจะไม่มีบทบาทและจะถูกข้าม ให้รัน `setup:install` ก่อน

## ข้อมูลอ้างอิงและภาคการศึกษา

### `reference:import`

- วัตถุประสงค์: นำเข้าข้อมูลอ้างอิงจาก CSV ใช้กฎการนำเข้าเดียวกับ **นำเข้า CSV** ในแผงผู้ดูแลระบบ (แถวเดิมจะจับคู่ตามรหัสและอัปเดต ช่องคำแปลที่ว่างจะคงค่าเดิม เฉพาะแถวที่ล้มเหลวจะถูกบันทึกแยกไว้)
- อาร์กิวเมนต์: `{type}` หนึ่งใน `org_units`, `programs`, `buildings`, `rooms`, `lookup_values`, `students`, `instructors`, `courses`, `registration_holds` / `{file}` ไฟล์ CSV แบบ UTF-8 ที่มีแถวหัวตาราง
- ตัวเลือก: `--actor=` (จำเป็น บันทึกการนำเข้าและการแจ้งเตือนเมื่อเสร็จจะส่งไปยังบัญชีนี้), `--chunk=100` (จำนวนแถวต่องานในคิว), `--dry-run` (ตรวจสอบแถวหัวตารางและนับจำนวนแถวเท่านั้น)
- บันทึกการตรวจสอบ: บันทึก (ประเภท ชื่อไฟล์ จำนวนแถว จำนวนแถวที่ล้มเหลว)
- รูปแบบคอลัมน์: [คู่มือผู้ดูแลระบบ บทที่ 9](../admin/09-csv-import.md)
- รหัสสิ้นสุดการทำงาน: หากคิวทำงานแบบซิงโครนัส ผลลัพธ์จะแสดงทันทีและรหัสสิ้นสุดการทำงานเป็น 2 เมื่อมีแถวที่ล้มเหลว หากทำงานแบบอะซิงโครนัส (Horizon) การนำเข้าจะเพียงถูกรับไว้และรหัสสิ้นสุดการทำงานเป็น 0 ผลลัพธ์จะมาถึงเป็นไฟล์ CSV ของแถวที่ล้มเหลวในการแจ้งเตือนของแผงผู้ดูแลระบบของบัญชี `--actor`
- ตัวอย่าง: `php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- วัตถุประสงค์: แสดงภาคการศึกษาที่อยู่ระหว่างดำเนินการ ณ เวลาที่กำหนด และช่วงเวลาดำเนินการที่เปิดอยู่ (ประเภท ภาคการศึกษา เกณฑ์กลุ่มเป้าหมาย เวลาสิ้นสุด) ใช้เพื่อตรวจสอบการตั้งค่าภาคการศึกษาและช่วงเวลาดำเนินการ หรือตอบคำถามเช่น "ทำไมการลงทะเบียนเรียนยังไม่เปิด"
- ตัวเลือก: `--at=` (ค่าเริ่มต้นคือปัจจุบัน ตัวอย่างเช่น `"2027-02-15 09:00"` หากไม่ระบุเขตเวลาจะตีความตามเขตเวลาของเซิร์ฟเวอร์ (UTC) ระบุเขตเวลาได้ เช่น `"2027-02-15 09:00 Asia/Seoul"`)
- บันทึกการตรวจสอบ: ไม่บันทึก
- การอ่านผลลัพธ์: การตัดสินเรื่องวันที่ใช้เขตเวลาของสถาบัน ช่วงเวลาดำเนินการของภาคการศึกษาที่อยู่ในสถานะวางแผนหรือเก็บถาวรจะไม่เปิดเลย

## ความปลอดภัย

### `security:create-administrator`

- วัตถุประสงค์: สร้างบัญชีที่มีบทบาทผู้ดูแลระบบ โดยปกติ `setup:install` จะเรียกใช้คำสั่งนี้
- ตัวเลือก: `--email=`, `--name=`, `--password-stdin` (รหัสผ่านจากอินพุตมาตรฐาน จำเป็นสำหรับการรันแบบไม่โต้ตอบ)
- บันทึกการตรวจสอบ: บันทึก (ID ของผู้ใช้ที่สร้าง)
- ตัวอย่าง: `php artisan security:create-administrator --email=admin@example.ac.kr --name="Administrator"`
- เมื่อล้มเหลว: `system_administrator role is missing` หมายความว่าต้องรัน `setup:install` หรือ `db:seed` ก่อน รหัสผ่านต้องมีอย่างน้อย 12 ตัวอักษร

### `security:sync-permissions`

- วัตถุประสงค์: ปรับรายการสิทธิ์ในฐานข้อมูลให้ตรงกับแคตตาล็อกสิทธิ์ในโค้ด สิทธิ์ใหม่จะถูกสร้าง สิทธิ์ที่ไม่มีในแคตตาล็อกจะถูกลบ (และถูกนำออกจากทุกบทบาท) บทบาทของระบบได้รับสิทธิ์ทุกรายการเสมอ
- เมื่อใช้: หลังการนำขึ้นใช้งาน (`setup:install` ทำขั้นตอนนี้เป็นส่วนหนึ่งของขั้นตอนข้อมูลพื้นฐานที่จำเป็น)
- ตัวเลือก: `--dry-run` (แสดงเฉพาะรายการที่จะสร้าง/ลบ), `--force` (ข้ามการยืนยันการลบ)
- บันทึกการตรวจสอบ: บันทึก (สิทธิ์ที่สร้าง/ลบ)
- การอ่านผลลัพธ์: บรรทัด `create` และ `delete` จะมีการขอยืนยันเมื่อมีรายการที่จะลบ
- เมื่อล้มเหลว: การตอบ "no" ในการยืนยันจะสิ้นสุดด้วยรหัส 1 และไม่มีการเปลี่ยนแปลงใด ๆ

### `security:reset-mfa`

- วัตถุประสงค์: รีเซ็ตการยืนยันตัวตนแบบสองขั้นตอนของผู้ใช้ (แอปยืนยันตัวตน รหัสทางอีเมล รหัสกู้คืน อุปกรณ์ที่จดจำไว้) ผู้ใช้จะลงทะเบียนใหม่เมื่อเข้าสู่ระบบครั้งถัดไป ใช้เมื่อไม่มีผู้ดูแลระบบคนใดเข้าสู่แผงผู้ดูแลระบบได้ (ตัวอย่างเช่น ผู้ดูแลระบบเพียงคนเดียวทำโทรศัพท์หาย) กรณีอื่นให้ใช้ **ผู้ใช้ > รีเซ็ตการยืนยันตัวตนแบบสองขั้นตอน** ในแผงผู้ดูแลระบบ
- อาร์กิวเมนต์/ตัวเลือก: `{user}` อีเมลของผู้ใช้, `--reason=` (จำเป็น), `--actor=` (จำเป็น ผู้ดูแลระบบที่ตัดสินใจรีเซ็ต)
- บันทึกการตรวจสอบ: บันทึก (ทั้งในบันทึกการดำเนินงานและบันทึกด้านความปลอดภัย พร้อมเหตุผล)
- ตัวอย่าง: `php artisan security:reset-mfa admin@example.ac.kr --reason="Phone lost, identity verified by phone call" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- วัตถุประสงค์: ปลดล็อกบัญชีที่ถูกล็อกเนื่องจากใส่รหัสผ่านผิดซ้ำ ๆ ก่อนครบระยะเวลาล็อก เหมือนกับ **ผู้ใช้ > ปลดล็อกการเข้าสู่ระบบ** ในแผงผู้ดูแลระบบ
- อาร์กิวเมนต์/ตัวเลือก: `{user}` อีเมลของผู้ใช้, `--reason=` (จำเป็น)
- บันทึกการตรวจสอบ: บันทึก (รวมทั้งในบันทึกด้านความปลอดภัย)
- การอ่านผลลัพธ์: `The account is not locked.` หมายความว่าไม่มีการเปลี่ยนแปลงใด ๆ
- หมายเหตุ: เกณฑ์การล็อก (จำนวนครั้งที่ล้มเหลว ระยะเวลาล็อก) กำหนดได้ที่ **การตั้งค่า > วิธีเข้าสู่ระบบ** ในแผงผู้ดูแลระบบ

## บุคคลและระเบียนนักศึกษา

### `people:find-duplicates`

- วัตถุประสงค์: แสดงรายการบุคคลที่น่าจะเป็นคนเดียวกัน เกณฑ์คือเลขประจำตัวประชาชนเหมือนกัน (แฮชสำหรับค้นหา) หรือชื่อแบบอักษรโรมันและวันเกิดเหมือนกัน ไม่รวมบุคคลที่ถูกรวมแล้ว
- ตัวเลือก: `--limit=100` (จำนวนกลุ่มที่จะแสดง)
- บันทึกการตรวจสอบ: ไม่บันทึก (อ่านอย่างเดียว)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อพบรายการที่อาจซ้ำ
- การดำเนินการต่อ: ตรวจสอบแต่ละกลุ่มที่ **บุคคล** ในแผงผู้ดูแลระบบ และหากเป็นคนเดียวกัน ให้ใช้ **รวมข้อมูลซ้ำ** จากหน้าของบุคคลที่จะเก็บไว้ การรวมไม่สามารถย้อนกลับได้ ([คู่มือผู้ดูแลระบบ บทที่ 14](../admin/14-merge-and-invitations.md))

## การรับสมัคร

### `admission:matriculate`

- วัตถุประสงค์: สร้างระเบียนนักศึกษา (รหัสนักศึกษาใหม่) ให้ผู้สมัครที่ยืนยันสิทธิ์แล้วของรอบรับสมัคร เหมือนกับการดำเนินการแบบกลุ่ม **สร้างระเบียนนักศึกษา** ที่ **การรับสมัคร > ใบสมัคร** ในแผงผู้ดูแลระบบ ผู้สมัครแต่ละคนดำเนินการแยกกัน ความล้มเหลวของคนหนึ่งจึงไม่หยุดคนอื่น
- อาร์กิวเมนต์/ตัวเลือก: `{cycle}` รหัสรอบรับสมัคร, `--term=` (จำเป็น รหัสภาคการศึกษาที่เข้าศึกษา ตัวอย่างเช่น `2027-SP` วันที่เข้าศึกษาคือวันแรกของภาคการศึกษา), `--actor=` (จำเป็น บัญชีที่มีสิทธิ์ `สร้างระเบียนนักศึกษาให้ผู้ได้รับคัดเลือก` จะดำเนินการเฉพาะผู้สมัครที่อยู่ในขอบเขตสิทธิ์ของบัญชีนั้น), `--dry-run` (รายชื่อเป้าหมายเท่านั้น)
- บันทึกการตรวจสอบ: บันทึก (รอบรับสมัคร ภาคการศึกษา จำนวนเป้าหมาย จำนวนที่สร้าง เลขที่ใบสมัครที่ล้มเหลว) และมีการเขียนบันทึกการดำเนินงาน (`application.matriculated`) สำหรับผู้สมัครแต่ละคนด้วย
- รหัสสิ้นสุดการทำงาน: 2 เมื่อมีผู้สมัครที่ล้มเหลว
- ตัวอย่าง: `php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- เมื่อล้มเหลว: `not ready` หมายความว่ามีระเบียนนักศึกษาอยู่แล้วหรือผู้สมัครไม่ได้อยู่ในสถานะยืนยันสิทธิ์ `program is not in effect` หมายความว่าหลักสูตรไม่มีผลบังคับใช้ ณ วันที่เข้าศึกษา (ตรวจสอบช่วงเวลาที่มีผลที่ ข้อมูลอ้างอิง > หลักสูตร)

### `admission:expire-drafts`

- วัตถุประสงค์: ทำเครื่องหมายเป็น **หมดอายุ** ให้ใบสมัครฉบับร่างของรอบรับสมัครที่ปิดแล้ว และใบสมัครฉบับร่างที่ไม่มีการแก้ไขตามระยะเวลาที่กำหนด (**การตั้งค่า > การรับสมัคร > ฉบับร่างที่ไม่มีการแก้ไขหมดอายุหลัง (วัน)** ค่าเริ่มต้น 90 วัน) ใบสมัครที่หมดอายุจะไม่ขัดขวางการยื่นใบสมัครใหม่ในรอบเดียวกัน
- เมื่อใช้: ตามกำหนดเวลา (ทุกวันเวลา 03:10, [งานตามกำหนดเวลา](scheduled-jobs.md))
- ตัวเลือก: `--dry-run` (นับจำนวนเท่านั้น)
- บันทึกการตรวจสอบ: บันทึก (จำนวนที่หมดอายุ)

## กลุ่มเรียน

### `section:copy`

- วัตถุประสงค์: เริ่มวางแผนภาคการศึกษาใหม่จากกลุ่มเรียนของภาคการศึกษาก่อนหน้า เหมือนกับ **กลุ่มเรียน > คัดลอกจากภาคการศึกษาอื่น** ในแผงผู้ดูแลระบบ คัดลอกกลุ่มเรียนที่ไม่ได้ยกเลิกเป็นฉบับร่าง พร้อมอาจารย์ผู้สอน (หากยังปฏิบัติงานอยู่) เวลาเรียนและห้อง ที่นั่งสำรอง (เลื่อนเวลาปล่อยตามส่วนต่างของวันเริ่มภาคการศึกษา) และประมวลรายวิชา (เป็นฉบับร่างที่ไม่เปิดเผย) ฉบับรายวิชาจะถูกแทนที่ด้วยฉบับที่มีผล ณ วันเริ่มช่วงการเรียนใหม่
- อาร์กิวเมนต์/ตัวเลือก: `{from-term}`, `{to-term}` รหัสภาคการศึกษา (ตัวอย่างเช่น `2026-FA`), `--org-unit=*` (เฉพาะกลุ่มเรียนของรหัสหน่วยงานนี้), `--dry-run` (แสดงผลลัพธ์เท่านั้น ไม่บันทึกสิ่งใด), `--actor=` (จำเป็น จะคัดลอกเฉพาะกลุ่มเรียนที่อยู่ในขอบเขตสิทธิ์ `วางแผนกลุ่มเรียน` ของบัญชีนั้น)
- บันทึกการตรวจสอบ: บันทึก (จำนวนที่คัดลอก ข้าม และต้องตรวจสอบ)
- การอ่านผลลัพธ์: `skipped` หมายความว่าภาคการศึกษาปลายทางมีรหัสกลุ่มเรียนเดียวกันอยู่แล้ว หรือไม่มีฉบับรายวิชาที่มีผล `note` หมายความว่าคัดลอกกลุ่มเรียนแล้วแต่มีบางส่วนไม่ได้คัดลอก (คัดลอกโดยไม่มีห้องเพราะห้องถูกใช้แล้ว อาจารย์ผู้สอนที่เกษียณแล้ว ฯลฯ) ช่วงการเรียนจับคู่ตามรหัส หากไม่มี กลุ่มเรียนจะอยู่ในช่วงการเรียนเต็มภาคการศึกษา
- ตัวอย่าง: `php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- วัตถุประสงค์: ตรวจสอบกลุ่มเรียนของภาคการศึกษาก่อนเผยแพร่ตารางเรียน การใช้ห้องและอาจารย์ผู้สอนซ้อนกันถูกป้องกันโดยฐานข้อมูลอยู่แล้ว คำสั่งนี้ค้นหาปัญหาที่ฐานข้อมูลยอมให้เกิดขึ้น: ความจุเกินความจุของห้อง ฉบับรายวิชาไม่มีผล ณ วันเริ่มช่วงการเรียน อาจารย์ผู้สอนที่เกษียณแล้ว ที่นั่งสำรองเกินความจุ วันเรียนอยู่นอกช่วงการเรียน และยังตรวจสอบการใช้ห้องซ้อนกันในข้อมูลที่เข้ามาโดยไม่มีข้อจำกัด เช่น การกู้คืนข้อมูลสำรอง
- อาร์กิวเมนต์: `{term}` รหัสภาคการศึกษา
- บันทึกการตรวจสอบ: ไม่บันทึก (อ่านอย่างเดียว)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อพบปัญหา กลุ่มเรียนที่ยังไม่มีอาจารย์ผู้สอนหรือห้องจะแสดงไว้เพื่อเป็นข้อมูลเท่านั้น

## การลงทะเบียนเรียน

### `registration:preflight`

- วัตถุประสงค์: ตรวจสอบภาคการศึกษาก่อนเปิดการลงทะเบียนเรียน แสดงช่วงเวลาลงทะเบียนเรียนและเพิ่ม/ลดรายวิชา ชุดกฎ จำนวนกลุ่มเรียนที่เผยแพร่ กลุ่มเรียนที่มีความจุ 0 ที่นั่งสำรองเกินความจุ ฉบับรายวิชาที่ไม่มีผล ณ วันเริ่มช่วงการเรียน จำนวนนักศึกษาที่กำลังศึกษาซึ่งไม่อยู่ในหน่วยกิตสูงสุดใด และจำนวนนักศึกษาที่มีการระงับการลงทะเบียนเรียน
- อาร์กิวเมนต์: `{term}` รหัสภาคการศึกษา (ตัวอย่างเช่น `2027-SP`)
- บันทึกการตรวจสอบ: ไม่บันทึก (อ่านอย่างเดียว)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อพบปัญหา การไม่มีชุดกฎจะแสดงเป็นข้อมูล ไม่ถือเป็นปัญหา (ใช้ค่าเริ่มต้นของกฎ)
- ตัวอย่าง: `php artisan registration:preflight 2027-SP`

### `registration:simulate`

- วัตถุประสงค์: แสดงทีละกฎว่าจะเกิดอะไรขึ้นหากนักศึกษาลงทะเบียนกลุ่มเรียนนั้นในขณะนี้ (หรือ ณ เวลาที่กำหนด) ไม่มีการบันทึกสิ่งใดและไม่มีการบันทึกความพยายาม ใช้สำหรับคำถาม "ทำไมลงทะเบียนไม่ได้"
- อาร์กิวเมนต์: `{student-number}` รหัสนักศึกษา, `{section}` `รหัสวิชา-รหัสกลุ่มเรียน` (ตัวอย่างเช่น `CSE2010-01`)
- ตัวเลือก: `--term=` (รหัสภาคการศึกษา ค่าเริ่มต้นคือภาคการศึกษาล่าสุดที่มีกลุ่มเรียนนั้น), `--at=` (เวลาที่ประเมิน ตัวอย่างเช่น `"2027-02-10 10:00 Asia/Seoul"`)
- บันทึกการตรวจสอบ: ไม่บันทึก (อ่านอย่างเดียว)
- การอ่านผลลัพธ์: ในแต่ละกฎ แสดงผ่าน/ไม่ผ่าน ปิดกั้น/เตือน และข้อความ กฎที่มีการอนุญาตพิเศษครอบคลุมจะแสดงว่าไม่ผ่านแต่ไม่ปิดกั้น ความจุแสดงแยกไว้ใต้ตารางกฎ
- รหัสสิ้นสุดการทำงาน: 2 เมื่อการลงทะเบียนจะถูกปฏิเสธ

### `waitlist:promote`

- วัตถุประสงค์: ลงทะเบียนนักศึกษาในรายชื่อสำรองตามลำดับให้กลุ่มเรียนที่มีที่นั่งว่าง กฎทุกข้อจะถูกตรวจสอบอีกครั้งเมื่อเลื่อน รายการในรายชื่อสำรองที่ไม่ผ่านกฎจะถูกนำออกจากรายชื่อสำรอง (พร้อมบันทึกเหตุผล) รายชื่อสำรองของกลุ่มเรียนที่ช่วงเวลาลงทะเบียนเรียนและเพิ่ม/ลดรายวิชาปิดแล้วทั้งคู่จะหมดอายุ นักศึกษาจะได้รับผลทางอีเมล
- อาร์กิวเมนต์/ตัวเลือก: `{term?}` รหัสภาคการศึกษา (ค่าเริ่มต้น: ทุกภาคการศึกษาที่มีรายชื่อสำรอง), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนกลุ่มเรียน ที่เลื่อน ที่นำออก ที่หมดอายุ)
- เมื่อใช้: เมื่อมีการลดรายวิชา ถอนรายวิชา หรือการปล่อยที่นั่งสำรอง กลุ่มเรียนที่ได้รับผลกระทบจะถูกดำเนินการทันทีโดยงานในคิว คำสั่งนี้เป็นตาข่ายนิรภัยตามกำหนดเวลาทุกชั่วโมงที่จัดการสิ่งที่อาจตกหล่น
- ตัวอย่าง: `php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- วัตถุประสงค์: ทำเครื่องหมายที่นั่งสำรองที่เลยเวลาปล่อยแล้ว (ตัวอย่างเช่น ที่นั่งที่สำรองไว้สำหรับนักศึกษาในสาขาวิชา) ว่าดำเนินการแล้ว และส่งงานเลื่อนรายชื่อสำรองของกลุ่มเรียนเหล่านั้นเข้าคิว ที่นั่งสำรองจะกลายเป็นที่นั่งทั่วไปในการคำนวณทันทีที่เลยเวลาปล่อย คำสั่งนี้จึงทำหน้าที่เพียงส่งต่อที่นั่งให้รายชื่อสำรอง
- บันทึกการตรวจสอบ: ไม่บันทึก (ทำงานทุก 5 นาที ผลการเลื่อนอยู่ในรายการลงทะเบียน)
- เมื่อใช้: ตามกำหนดเวลา (ทุก 5 นาที)

## ผลการเรียน

### `term:close`

- วัตถุประสงค์: ปิดภาคการศึกษา เกรดทุกรายการในภาคการศึกษาต้องยืนยันแล้ว สำหรับนักศึกษาแต่ละคน คำสั่งจะคำนวณบันทึกผลรายภาคการศึกษา (หน่วยกิต เกรดเฉลี่ยภาคการศึกษาและเกรดเฉลี่ยสะสม) กำหนดสถานภาพทางวิชาการ (สถานภาพปกติ รอพินิจ พิจารณาพ้นสภาพ) และสิทธิ์ได้รับเกียรตินิยม (แบตช์ในคิว) จากนั้นจัดอันดับเกียรตินิยมตามหลักสูตร ปิดบันทึกผลรายภาคการศึกษาเป็นบันทึกทางการ และกำหนดภาคการศึกษาเป็น **ปิดผลการเรียน** เหมือนกับ **ผลการเรียน > บันทึกผลรายภาคการศึกษา > ปิดภาคการศึกษา** ในแผงผู้ดูแลระบบ
- อาร์กิวเมนต์/ตัวเลือก: `{term}` รหัสภาคการศึกษา, `--dry-run` (ตรวจสอบเพียงว่าปิดภาคการศึกษาได้หรือไม่), `--reason=` (เหตุผลที่เก็บไว้ในบันทึก), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนนักศึกษา จำนวนกลุ่มเรียนที่มีเกรดยังไม่ยืนยัน) เมื่อการปิดเสร็จสิ้น บันทึกการตรวจสอบ `term.closed` จะเก็บจำนวนนักศึกษารอพินิจ พิจารณาพ้นสภาพ และเกียรตินิยม
- รหัสสิ้นสุดการทำงาน: 2 เมื่อบางกลุ่มเรียนมีเกรดที่ยังไม่ยืนยัน (แสดงจำนวนที่ยังไม่ยืนยันของแต่ละกลุ่มเรียน) 1 เมื่อภาคการศึกษาไม่ได้อยู่ในสถานะเผยแพร่
- เมื่อใช้: หลังการกรอกเกรดและการยืนยันเกรดเสร็จสมบูรณ์ ติดตามความคืบหน้าของแบตช์ใน Horizon หากไม่มีตัวประมวลผลคิว สถานะภาคการศึกษาจะไม่เปลี่ยน
- ตัวอย่าง: `php artisan term:close 2026-FA --dry-run`, `php artisan term:close 2026-FA --reason="Fall 2026 grades closed" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- วัตถุประสงค์: คำนวณบันทึกผลรายภาคการศึกษา (หน่วยกิต เกรดเฉลี่ยภาคการศึกษาและเกรดเฉลี่ยสะสม) ใหม่จากเกรดที่ยืนยันแล้ว ใช้เพื่อนำนโยบายการให้เกรดที่เปลี่ยนไป (จำนวนตำแหน่งทศนิยมของเกรดเฉลี่ย การจัดการการเรียนซ้ำ) มาใช้กับภาคการศึกษาที่ผ่านมา สถานภาพทางวิชาการและเกียรตินิยมคงค่าที่กำหนดไว้ ณ การปิดภาคการศึกษา การแก้ไขเกรดที่อนุมัติแล้วจะคำนวณใหม่ให้นักศึกษาคนนั้นโดยอัตโนมัติ จึงไม่จำเป็นต้องใช้คำสั่งนี้
- ตัวเลือก: `--term=` (นักศึกษาที่มีเกรดในภาคการศึกษานั้น ตั้งแต่ภาคการศึกษานั้นเป็นต้นไป), `--student-number=` (นักศึกษาหนึ่งคน), `--reason=` (จำเป็น), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนนักศึกษา เหตุผล)
- ตัวอย่าง: `php artisan grades:recalculate --term=2026-SP --reason="GPA changed to three decimal places"`

### `grades:remind-missing`

- วัตถุประสงค์: ส่งอีเมลถึงอาจารย์ผู้สอนของกลุ่มเรียนที่ยังไม่ได้ส่งเกรด (ยังไม่กรอกหรือบันทึกเป็นฉบับร่าง) กลุ่มเรียนจะถูกรวมตามอาจารย์ผู้สอนเป็นข้อความเดียวต่อคน
- อาร์กิวเมนต์/ตัวเลือก: `{term}` รหัสภาคการศึกษา, `--dry-run` (แสดงเป้าหมายโดยไม่ส่ง), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนกลุ่มเรียน อาจารย์ผู้สอน ข้อความที่ส่ง)
- เมื่อใช้: ไม่กี่วันก่อนช่วงเวลากรอกเกรดจะปิด เพิ่มในกำหนดเวลาได้หากจำเป็น

## การประเมินรายวิชา

### `evaluation:remind`

- วัตถุประสงค์: ส่งอีเมลถึงนักศึกษาที่ยังมีรายวิชาที่ยังไม่ได้ประเมินในขณะที่ช่วงเวลาการประเมินรายวิชาเปิดอยู่ รายวิชาที่เหลือจะถูกรวมเป็นข้อความเดียวต่อนักศึกษาหนึ่งคน
- อาร์กิวเมนต์/ตัวเลือก: `{term}` รหัสภาคการศึกษา, `--dry-run` (จำนวนนักศึกษาเป้าหมายเท่านั้น ไม่ส่งสิ่งใด), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (นักศึกษาเป้าหมาย ข้อความที่ส่ง)
- เมื่อใช้: หนึ่งหรือสองครั้งในช่วงเวลาการประเมิน เพิ่มในกำหนดเวลาได้หากจำเป็น

### `evaluation:publish-results`

- วัตถุประสงค์: ประกาศผลการประเมินรายวิชาของภาคการศึกษาให้อาจารย์ผู้สอน เหมือนกับ **การประเมินรายวิชา > การประเมินประจำภาคการศึกษา > ประกาศผล** ในแผงผู้ดูแลระบบ แม้ประกาศผลแล้ว ผลจะมองเห็นได้เฉพาะกลุ่มเรียนที่มีจำนวนผู้ตอบและอัตราการตอบถึงขั้นต่ำ
- อาร์กิวเมนต์/ตัวเลือก: `{term}` รหัสภาคการศึกษา, `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนผู้ตอบ ประกาศผลแล้วหรือไม่)
- เมื่อใช้: หลังช่วงเวลาการประเมินและการดำเนินการเรื่องเกรดเสร็จสิ้น ภาคการศึกษาที่ประกาศผลแล้วจะไม่ถูกเปลี่ยนแปลง

## หนังสือรับรอง

### `certificate:verify`

- วัตถุประสงค์: ตรวจสอบรหัสตรวจสอบของหนังสือรับรองด้วยเกณฑ์เดียวกับหน้าตรวจสอบสาธารณะ แสดงประเภท เลขที่เอกสาร วันที่ออก และผู้ถือ (แบบปิดบังบางส่วน)
- อาร์กิวเมนต์/ตัวเลือก: `{code}` รหัสตรวจสอบ
- บันทึกการตรวจสอบ: ไม่มี (อ่านอย่างเดียว)
- รหัสสิ้นสุดการทำงาน: 0 เมื่อถูกต้อง 2 สำหรับรหัสที่ไม่รู้จัก หนังสือรับรองที่ถูกเพิกถอน หรือหมดอายุแล้ว

### `certificate:render`

- วัตถุประสงค์: สร้าง PDF ของหนังสือรับรองที่ออกแล้วใหม่ด้วยข้อมูลและแม่แบบปัจจุบัน แทนที่ไฟล์ที่เก็บไว้ เหมือนกับ **หนังสือรับรองที่ออกแล้ว > สร้างใหม่** ในแผงผู้ดูแลระบบ เลขที่เอกสารและรหัสตรวจสอบยังคงเดิม แต่ checksum จะเปลี่ยน
- อาร์กิวเมนต์/ตัวเลือก: `{issue}` เลขที่เอกสาร, `--reason=` (จำเป็น), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (เลขที่เอกสาร checksum ใหม่)
- เมื่อใช้: เพื่อสร้างหนังสือรับรองฉบับใดฉบับหนึ่งใหม่หลังแก้ไขแม่แบบหรือการสะกดชื่อ

## การสอบ

### `assessment:import-results`

- วัตถุประสงค์: กรอกผลสอบของรอบสอบจาก CSV ใช้กฎเดียวกับ **รอบสอบ > นำเข้าผลสอบ (CSV)** ในแผงผู้ดูแลระบบ (เฉพาะนักศึกษาที่สมัครสอบ ผ่าน/ไม่ผ่านตัดสินจากคะแนน การกรอกซ้ำก่อนประกาศผลจะแทนที่ผลเดิม)
- อาร์กิวเมนต์/ตัวเลือก: `{type}` รหัสประเภทการสอบ / `{held_date}` วันที่สอบ `YYYY-MM-DD` / `{file}` ไฟล์ CSV แบบ UTF-8 ที่มีแถวหัวตาราง, `--actor=` (จำเป็น), `--dry-run` (ตรวจสอบแถวเท่านั้น ไม่บันทึกสิ่งใด)
- รูปแบบคอลัมน์: [คู่มือผู้ดูแลระบบ บทที่ 24](../admin/24-assessments.md)
- บันทึกการตรวจสอบ: บันทึก (รอบสอบ ชื่อไฟล์ จำนวนแถว จำนวนที่กรอก/ขาดสอบ/ผิดพลาด)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อมีแถวที่ผิดพลาด (แถวอื่นจะถูกบันทึก)
- ตัวอย่าง: `php artisan assessment:import-results ENG_COMP 2026-05-15 storage/app/eng.csv --actor=registrar@example.ac.kr --dry-run`

### `assessment:publish-results`

- วัตถุประสงค์: ประกาศผลสอบของรอบสอบให้นักศึกษา เหมือนกับ **รอบสอบ > ประกาศผลสอบ** ในแผงผู้ดูแลระบบ
- อาร์กิวเมนต์/ตัวเลือก: `{type}` รหัสประเภทการสอบ / `{held_date}` วันที่สอบ, `--actor=` (จำเป็น)
- บันทึกการตรวจสอบ: บันทึก (รอบสอบ จำนวนผลสอบ)
- เมื่อใช้: หลังการกรอกผลสอบเสร็จสมบูรณ์ รอบสอบที่ประกาศผลแล้วจะล้มเหลว

## การเข้าเรียน

### `attendance:generate-sessions`

- วัตถุประสงค์: สร้างครั้งเรียนให้ทุกกลุ่มเรียนของภาคการศึกษาจากเวลาเรียน (วันในสัปดาห์ เวลา คาบ) เหมือนกับ **สร้างครั้งเรียน** ในพอร์ทัลอาจารย์และแผงผู้ดูแลระบบ ครั้งเรียนเดิมและข้อมูลการเข้าเรียนจะยังคงอยู่ (รันซ้ำได้อย่างปลอดภัย)
- อาร์กิวเมนต์/ตัวเลือก: `{term}` รหัสภาคการศึกษา, `--section=` (รหัสวิชา-รหัสกลุ่มเรียน ตัวอย่างเช่น `CSE2010-01` เพียงหนึ่งกลุ่ม), `--dry-run` (จำนวนกลุ่มเรียนเป้าหมายเท่านั้น), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (ภาคการศึกษา กลุ่มเรียน ครั้งเรียนที่สร้าง)
- เมื่อใช้: ก่อนเริ่มภาคการศึกษา หลังยืนยันเวลาเรียนแล้ว รันอีกครั้งเมื่อเวลาเรียนเปลี่ยน

## การสำเร็จการศึกษา

### `degree-audit:run`

- วัตถุประสงค์: บันทึกผลการตรวจสอบเกณฑ์การสำเร็จการศึกษาของนักศึกษาที่กำลังศึกษาทุกคน เหมือนกับ **การตรวจสอบการสำเร็จการศึกษา > ดำเนินการตรวจสอบ** ในแผงผู้ดูแลระบบ ผลการตรวจสอบล่าสุดที่บันทึกไว้เป็นฐานในการดำเนินการสำเร็จการศึกษา
- ตัวเลือก: `--term=` (รหัสภาคการศึกษาที่ผลการตรวจสอบสังกัด), `--student-number=` (นักศึกษาหนึ่งคน), `--min-year-level=` (เฉพาะชั้นปีนี้ขึ้นไป), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนนักศึกษา จำนวนที่ผ่านเกณฑ์)
- เมื่อใช้: ก่อนการพิจารณาการสำเร็จการศึกษา (ปลายภาคการศึกษา) และหลังเปลี่ยนชุดเกณฑ์หรือรายวิชาเทียบเท่า

## การเชื่อมต่อ LMS

### `lms:sync`

- วัตถุประสงค์: ส่งกลุ่มเรียนที่เผยแพร่แล้วไปยังแพลตฟอร์ม (การสร้างและเชื่อมโยงรายวิชา อาจารย์ผู้สอน นักศึกษาที่ลงทะเบียน) ทำสิ่งที่ **การเชื่อมโยงรายวิชา > ซิงค์อีกครั้ง** ในแผงผู้ดูแลระบบทำ แต่สำหรับทั้งภาคการศึกษา กลุ่มเรียนที่เชื่อมโยงแล้วจะเพียงถูกยืนยันซ้ำ (idempotent)
- อาร์กิวเมนต์/ตัวเลือก: `{platform}` รหัสแพลตฟอร์ม, `--term=` (รหัสภาคการศึกษา ค่าเริ่มต้นคือทุกภาคการศึกษาที่ยังไม่สิ้นสุด), `--section=` (รหัสวิชา-รหัสกลุ่มเรียนหนึ่งรายการ), `--dry-run` (บันทึกเพียงสิ่งที่จะส่งเป็น "skipped"), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (แพลตฟอร์ม กลุ่มเรียน สมาชิก ความล้มเหลว)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อมีกลุ่มเรียนที่ล้มเหลว

### `lms:reconcile`

- วัตถุประสงค์: เปรียบเทียบรายชื่อในรายวิชาของแพลตฟอร์มกับรายการลงทะเบียนในระบบสารสนเทศนักศึกษา เพิ่มสมาชิกที่ขาด และนำสมาชิกที่เกินออก ความแตกต่างจะเก็บไว้ในบันทึกการซิงค์ (`reconcile`)
- อาร์กิวเมนต์/ตัวเลือก: `{platform?}` (ทุกแพลตฟอร์มที่ใช้งานอยู่หากไม่ระบุ), `--term=`, `--dry-run` (บันทึกเฉพาะความแตกต่าง), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (กลุ่มเรียนต่อแพลตฟอร์ม จำนวนที่เพิ่ม/นำออก/ล้มเหลว)
- เมื่อใช้: ตามกำหนดเวลาทุกวันเวลา 02:30 รันด้วยตนเองหลังแพลตฟอร์มขัดข้อง

## การตรวจสอบการทำงานและการล้างข้อมูล

### `system:health-check`

- วัตถุประสงค์: ตรวจสอบการตั้งค่าและคีย์ (APP_KEY, คีย์ PII, APP_DEBUG) การเชื่อมต่อและบทบาทของฐานข้อมูล (runtime, migrator, reporting) RLS บนตารางข้อมูลส่วนบุคคล ไมเกรชันที่ค้างอยู่ การซิงค์แคตตาล็อกสิทธิ์ Redis คิว (Horizon) Gotenberg การเขียนที่จัดเก็บสื่อ และสัญญาณชีพของตัวจัดกำหนดเวลา
- ตัวเลือก: `--json` (ผลลัพธ์สำหรับระบบเฝ้าติดตาม)
- บันทึกการตรวจสอบ: ไม่มี (อ่านอย่างเดียว)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อการตรวจสอบใดล้มเหลว
- เมื่อใช้: ทันทีหลังการนำขึ้นใช้งาน เมื่อสงสัยว่าระบบขัดข้อง และเป็นระยะจากระบบเฝ้าติดตาม

### `audit:seal`

- วัตถุประสงค์: เชื่อมแถวใหม่ของตารางบันทึกการตรวจสอบเข้ากับห่วงโซ่แฮช ([ความถูกต้องของบันทึกการตรวจสอบ](audit-and-maintenance.md))
- ตัวเลือก: `--table=` (หนึ่งใน record_changes, activity_log, security_events ระบุซ้ำได้), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (จำนวนแถวที่ผนึกต่อตาราง)
- เมื่อใช้: ตามกำหนดเวลาทุกวันเวลา 03:30

### `audit:verify-chain`

- วัตถุประสงค์: คำนวณแฮชของเนื้อหาและห่วงโซ่ของแถวบันทึกการตรวจสอบใหม่ เพื่อค้นหาการแก้ไขโดยมิชอบ การลบ และการสลับลำดับ
- ตัวเลือก: `--table=`
- บันทึกการตรวจสอบ: ไม่มี (อ่านอย่างเดียว)
- รหัสสิ้นสุดการทำงาน: 2 เมื่อพบความไม่ตรงกัน
- เมื่อใช้: ก่อนการสำรองข้อมูล ระหว่างการทบทวนด้านความปลอดภัย หลังการลบ

### `audit:prune`

- วัตถุประสงค์: ลบแถวบันทึกการตรวจสอบที่ **ผนึกแล้ว** ซึ่งเกินระยะเวลาเก็บรักษา ทำงานผ่านการเชื่อมต่อของเจ้าของสคีมา
- ตัวเลือก: `--before=YYYY-MM-DD` (จำเป็น), `--table=`, `--dry-run` (นับจำนวนเท่านั้น), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (วันที่ตัดรอบ จำนวนแถวที่ลบต่อตาราง)
- เมื่อใช้: ตามนโยบายการเก็บรักษา หลังการสำรองข้อมูล

### `media:prune-orphans`

- วัตถุประสงค์: ลบแถวสื่อที่ไม่มีเจ้าของแล้ว และไดเรกทอรีที่ไม่มีแถวข้อมูล (รูปถ่ายบุคคล เอกสารใบสมัคร ไฟล์ PDF หนังสือรับรอง หลักฐานการสอบ)
- ตัวเลือก: `--dry-run` (แสดงรายการเท่านั้น), `--actor=`
- บันทึกการตรวจสอบ: บันทึก (แถว ไดเรกทอรี)
- เมื่อใช้: ทุกเดือนหรือหลังการลบข้อมูลจำนวนมาก

## คีย์เข้ารหัสข้อมูลส่วนบุคคล

### `pii:generate-key`

- วัตถุประสงค์: แสดงคีย์ใหม่สำหรับ `PII_ENCRYPTION_KEY` และ `PII_HASH_KEY` ไม่บันทึกสิ่งใด
- บันทึกการตรวจสอบ: ไม่บันทึก
- ข้อควรระวัง: การเปลี่ยน `PII_HASH_KEY` ทำให้แฮชสำหรับค้นหาทั้งหมดใช้ไม่ได้ ขั้นตอนการเปลี่ยนคีย์อยู่ใน [security-keys.md](security-keys.md)

### `pii:reencrypt`

- วัตถุประสงค์: หลังการเปลี่ยนคีย์ ให้เข้ารหัสข้อมูลส่วนบุคคลที่เข้ารหัสด้วยคีย์เดิมใหม่ด้วยคีย์ปัจจุบัน ทำงานเป็นแบตช์ในคิว
- อาร์กิวเมนต์: คลาสของโมเดล (ปัจจุบันคือ `App\\Models\\Person\\Person`)
- ตัวเลือก: `--chunk=500`, `--dry-run` (นับเฉพาะรายการที่ใช้คีย์เดิม), `--force`
- บันทึกการตรวจสอบ: บันทึก (ID ของแบตช์ จำนวนงาน / จำนวนจากการดูตัวอย่าง)
- การตรวจสอบ: ติดตามความคืบหน้าของแบตช์ใน Horizon (`/horizon`) เมื่อเสร็จสิ้นและ `--dry-run` รายงาน 0 ให้นำคีย์เดิมออกจาก `PII_PREVIOUS_KEYS`

## การแปลภาษา

### `i18n:missing`

- วัตถุประสงค์: แสดงคีย์ที่ขาดหายเมื่อเทียบกับภาษาหลัก (en) และคีย์ที่ไม่ได้ใช้แล้วในแต่ละภาษา
- อาร์กิวเมนต์/ตัวเลือก: `{locale?}` (เพียงภาษาเดียว), `--strict` (รหัสสิ้นสุดการทำงาน 2 เมื่อมีคีย์ขาดหาย ใช้ใน CI)
- บันทึกการตรวจสอบ: ไม่บันทึก

### `i18n:export`

- วัตถุประสงค์: สร้างไฟล์ JSON เพื่อส่งให้ผู้แปล รูปแบบ: `{"key": {"source": "English text", "translation": "translation"}}`
- อาร์กิวเมนต์/ตัวเลือก: `{locale} {path}`, `--missing` (เฉพาะคีย์ที่ขาดหาย)
- บันทึกการตรวจสอบ: ไม่บันทึก
- ตัวอย่าง: `php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- วัตถุประสงค์: นำ JSON ที่ผู้แปลกรอกแล้วมาใช้กับ `lang/{locale}` นำเข้าเฉพาะคีย์ที่มีอยู่ในภาษาหลัก คำแปลที่ว่างจะถูกข้าม
- อาร์กิวเมนต์/ตัวเลือก: `{locale} {path}`, `--dry-run` (แสดงเฉพาะรายการคีย์ที่จะถูกเขียน)
- บันทึกการตรวจสอบ: บันทึก
- ข้อควรระวัง: ไฟล์คำแปลจัดการอยู่ในรีโพซิทอรี ให้ commit การเปลี่ยนแปลงหลังการนำเข้า

## การตรวจสอบ

### `naming:check`

- วัตถุประสงค์: ตรวจสอบชื่อตารางและคอลัมน์ในไมเกรชันตาม [หลักการตั้งชื่อ](../../../development/naming.md)
- ตัวเลือก: `--path=*` (ไดเรกทอรีที่จะตรวจสอบ ค่าเริ่มต้น `database/migrations`)
- บันทึกการตรวจสอบ: ไม่บันทึก
- รหัสสิ้นสุดการทำงาน: 2 เมื่อพบปัญหา

### `pdf:sample`

- วัตถุประสงค์: สร้าง PDF ของตารางที่ผสมอักษรฮันกึล อักษร CJK อักษรลาว อักษรไทย อักษรเทวนาครี อักษรซีริลลิก และอักษรละติน เพื่อตรวจสอบฟอนต์และการเชื่อมต่อกับบริการ PDF (Gotenberg)
- อาร์กิวเมนต์: `{path=pdf-sample.pdf}` (เทียบกับดิสก์ภายใน `storage/app/private`)
- บันทึกการตรวจสอบ: ไม่บันทึก
- เมื่อล้มเหลว: หากเกิดข้อผิดพลาดในการเชื่อมต่อ ให้ตรวจสอบ `GOTENBERG_URL` และสถานะของคอนเทนเนอร์ Gotenberg
