# การสำรองและกู้คืนข้อมูล

- ผู้อ่าน: ผู้ดูแลระบบไอที

## สิ่งที่ต้องสำรอง

| เป้าหมาย | วิธีการ | ความถี่ (แนะนำ) |
|---|---|---|
| PostgreSQL | `pg_dump -Fc` หรือ PITR (การเก็บ WAL) | สำรองเต็มรายวัน + WAL ต่อเนื่อง |
| ที่จัดเก็บไฟล์ (`storage/app/private` หรือ S3) | สแนปช็อต หรือบักเก็ตที่เปิดการจัดเก็บหลายเวอร์ชัน | เช่นเดียวกับฐานข้อมูล |
| การตั้งค่าสภาพแวดล้อมและคีย์ | ที่จัดเก็บข้อมูลลับ | ทุกครั้งที่มีการเปลี่ยนแปลง |

ฐานข้อมูลและที่จัดเก็บไฟล์ต้องกู้คืนได้ ณ จุดเวลาเดียวกัน (เมทาดาทาของรูปถ่ายและไฟล์ PDF หนังสือรับรองอยู่ในฐานข้อมูล)

## ตัวอย่างการสำรองฐานข้อมูล

```bash
pg_dump -U app_migrator -d sis -Fc -f sis-$(date +%F).dump
```

`app_migrator` เป็นเจ้าของทุกสคีมา (`public`, `audit`, `reporting`, `util`) จึงต้องสำรองด้วยบัญชีนี้ บทบาท (`app_*`) เป็นออบเจ็กต์ระดับคลัสเตอร์และไม่รวมอยู่ใน dump บนเซิร์ฟเวอร์ที่จะกู้คืน ให้สร้างบทบาทก่อนตามที่อธิบายใน [การติดตั้ง](installation.md) หัวข้อที่ 2

## ตัวอย่างการกู้คืน

```bash
createdb -U postgres sis_restore
psql -U postgres -d sis_restore -f database/sql/roles/prepare_database.sql
pg_restore -U app_migrator -d sis_restore --no-owner --role=app_migrator sis-2026-10-22.dump
```

## การซ้อมกู้คืน

ทุกไตรมาส ให้กู้คืนไปยังเซิร์ฟเวอร์แยกต่างหากและตรวจสอบรายการต่อไปนี้: การเข้าสู่ระบบ การถอดรหัสข้อมูลส่วนบุคคล (คีย์ตรงกัน) การดูบันทึกการตรวจสอบ การเปิดไฟล์ (รูปถ่าย, PDF)
