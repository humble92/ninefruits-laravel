# การจัดการคีย์

- ผู้อ่าน: ผู้ดูแลระบบไอที

| คีย์ | วัตถุประสงค์ | หากสูญหาย | การเปลี่ยนคีย์ |
|---|---|---|---|
| `APP_KEY` | เซสชัน คุกกี้ ข้อมูลลับของการยืนยันตัวตนแบบสองขั้นตอน การลงนามคุกกี้ของอุปกรณ์ที่จดจำไว้ | ผู้ใช้ทุกคนจะออกจากระบบ การยืนยันตัวตนแบบสองขั้นตอนที่ลงทะเบียนไว้ (แอปยืนยันตัวตน) จะใช้งานไม่ได้ | ใส่คีย์เดิมใน `APP_PREVIOUS_KEYS` แล้วจึงเปลี่ยนคีย์ |
| `PII_ENCRYPTION_KEY` | การเข้ารหัสข้อมูลส่วนบุคคล เช่น เลขประจำตัวประชาชน | **ไม่สามารถกู้คืนข้อมูลส่วนบุคคลที่เข้ารหัสไว้ได้** | ขั้นตอนด้านล่าง |
| `PII_HASH_KEY` | แฮชสำหรับการค้นหาข้อมูลส่วนบุคคลแบบตรงทุกตัวอักษร | การค้นหาจะใช้งานไม่ได้ (ข้อมูลยังอยู่) | โดยหลักแล้วไม่เปลี่ยน |

หลักการจัดเก็บ

- เก็บคีย์ทั้งสามชุดอย่างน้อยสองสำเนาไว้นอกการตั้งค่าสภาพแวดล้อมของเซิร์ฟเวอร์ ในที่จัดเก็บข้อมูลลับ (Vault, ตัวจัดการข้อมูลลับบนคลาวด์ ฯลฯ) หรือในที่เก็บแบบออฟไลน์ที่ปิดผนึก
- ห้ามเก็บคีย์ไว้ร่วมกับไฟล์สำรองข้อมูล แม้ข้อมูลสำรองของฐานข้อมูลจะรั่วไหล ข้อมูลส่วนบุคคลต้องยังอ่านไม่ได้หากไม่มีคีย์

## ขั้นตอนการเปลี่ยนคีย์ข้อมูลส่วนบุคคล

1. สร้างคีย์ใหม่ด้วย `php artisan pii:generate-key` (ใช้เฉพาะ `PII_ENCRYPTION_KEY` จากผลลัพธ์)
2. ใส่คีย์ปัจจุบันใน `PII_PREVIOUS_KEYS` (คั่นด้วยจุลภาคหากมีหลายคีย์) และใส่คีย์ใหม่ใน `PII_ENCRYPTION_KEY`
3. โหลดการตั้งค่าใหม่: `php artisan config:cache`, `php artisan horizon:terminate`
4. สำหรับแต่ละโมเดลข้อมูลส่วนบุคคล ให้ตรวจสอบจำนวนรายการที่ได้รับผลกระทบด้วย `php artisan pii:reencrypt {model} --dry-run` แล้วรันโดยไม่มี `--force`
5. เมื่อ Horizon แสดงว่าแบตช์เสร็จสิ้นและ `--dry-run` รายงาน 0 ให้นำคีย์เดิมออกจาก `PII_PREVIOUS_KEYS`
6. เก็บคีย์เดิมแบบปิดผนึกไว้ตลอดระยะเวลาเก็บรักษาข้อมูลสำรอง (จำเป็นสำหรับการกู้คืนข้อมูลสำรองที่เก่ากว่า)
