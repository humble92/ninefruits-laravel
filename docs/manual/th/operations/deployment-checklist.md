# รายการตรวจสอบการนำขึ้นใช้งานและการตั้งค่าความปลอดภัยของ PHP

## เวอร์ชัน PHP

- ใช้ **PHP ≥ 8.5.12** (หรือ 8.4.27, 8.3.36) รุ่นแก้ไขด้านความปลอดภัยเมื่อวันที่ 2026-10-21 ได้แก้ไขช่องโหว่การรันโค้ดจากระยะไกลโดยไม่ต้องยืนยันตัวตนสองรายการ (CVE-2026-109618 สถานะเสียหายจากหน่วยความจำไม่พอ (OOM), CVE-2026-109619 สถานะรั่วไหลระหว่างคำขอ) และ php.net ระบุว่า "ไม่มีวิธีบรรเทาที่สมบูรณ์ การอัปเดตเป็นทางเลือกเดียวที่ปลอดภัย" ข้อกำหนด `"php": "^8.5.12"` ใน `composer.json` จะป้องกันการติดตั้งบน PHP เวอร์ชันที่ต่ำกว่านี้
- สภาพแวดล้อมสำหรับพัฒนา: รัน `./vendor/bin/sail build --no-cache && ./vendor/bin/sail up -d` แล้วยืนยันด้วย `./vendor/bin/sail php -v`
- เมื่อสร้างอิมเมจของคอนเทนเนอร์หรือเซิร์ฟเวอร์ อย่าตรึงเวอร์ชันแพ็กเกจ PHP ให้ใช้รุ่นแพตช์ล่าสุด `system:health-check` ก็แสดงเวอร์ชัน PHP ด้วย

## php.ini สำหรับระบบใช้งานจริง (การตั้งค่า php-fpm pool หรือเซิร์ฟเวอร์ ไม่ใช่ `.user.ini` หรือ `ini_set()`)

| การตั้งค่า | ค่า | เหตุผล |
|---|---|---|
| `session.upload_progress.enabled` | `0` | ปิดเส้นทางการโจมตีของ CVE-2026-109619 และ CVE-2026-115560 (ประกาศของ php.net วันที่ 2026-10-21 และ 23) ระบบนี้ไม่ใช้ความคืบหน้าการอัปโหลด |
| `fatal_error_backtraces` | `0` (PHP 8.5) | ปิดเส้นทางผ่าน backtrace ของข้อผิดพลาดร้ายแรงตามประกาศฉบับเดียวกัน |
| `memory_limit` | `256M` ขึ้นไป ตรึงด้วย `php_admin_value` | เพื่อไม่ให้โค้ดของแอปพลิเคชันเปลี่ยนค่าได้ |
| `post_max_size` / `upload_max_filesize` | `32M` / `20M` | ขีดจำกัดสูงสุดสำหรับการอัปโหลดเอกสารการรับสมัคร หลักฐานการสอบ และรูปถ่าย (เผื่อไว้เหนือการตรวจสอบของแอปพลิเคชันที่ 5MB และ 2MB) |
| `expose_php` | `Off` | ไม่เปิดเผยเวอร์ชัน |
| `display_errors` | `Off`, `log_errors=On` | ระบบใช้งานจริง |
| `session.cookie_secure`, `session.cookie_httponly`, `session.cookie_samesite` | `1`, `1`, `Lax` | ใช้ร่วมกับการตั้งค่าเซสชันของ Laravel (`SESSION_SECURE_COOKIE=true`) |
| `opcache.enable`, `opcache.validate_timestamps` | `1`, `0` (รีสตาร์ตเมื่อนำขึ้นใช้งาน) | ประสิทธิภาพ |

## สภาพแวดล้อมของแอปพลิเคชัน (.env)

- `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` กำหนดเป็นที่อยู่จริง
- นำ `APP_KEY`, `PII_ENCRYPTION_KEY` และ `PII_HASH_KEY` เข้ามาจากที่จัดเก็บข้อมูลลับและสำรองไว้ ([การจัดการคีย์](security-keys.md)) หากคีย์สูญหาย จะไม่สามารถถอดรหัสข้อมูลส่วนบุคคลได้
- ฐานข้อมูล: `DB_USERNAME=app_runtime`, `DB_MIGRATOR_USERNAME=app_migrator` (รหัสผ่านที่ใช้สำหรับไมเกรชันเท่านั้น), `app_reporting` สำหรับเครื่องมือ BI เท่านั้น
- `QUEUE_CONNECTION=redis`, `CACHE_STORE=redis`, `SESSION_DRIVER=redis` ลงทะเบียน Horizon (`php artisan horizon`) และตัวจัดกำหนดเวลา (`* * * * * php artisan schedule:run`) เป็นบริการ
- `GOTENBERG_URL`: ที่อยู่ในเครือข่ายภายใน ห้ามเปิด Gotenberg ให้เข้าถึงจากภายนอก
- อีเมล (`MAIL_*`): ใช้สำหรับคำเชิญ อีเมลการยืนยันตัวตนแบบสองขั้นตอน และการแจ้งเตือนเรื่องการลงทะเบียนเรียนและผลการเรียน

## ขั้นตอนการนำขึ้นใช้งาน

1. สำรองข้อมูล ([การสำรองและกู้คืนข้อมูล](backup-restore.md))
2. นำโค้ดขึ้นใช้งาน, `composer install --no-dev --optimize-autoloader`, `npm ci && npm run build`
3. `php artisan migrate --force` (สลับไปใช้การเชื่อมต่อ migrator โดยอัตโนมัติ), `php artisan security:sync-permissions`, `php artisan setup:install --force` (ปรับปรุงข้อมูลพื้นฐานที่จำเป็น โดยคงค่าที่ผู้ดูแลระบบแก้ไขไว้)
4. `php artisan optimize` รีสตาร์ต Horizon (`horizon:terminate`) รีสตาร์ต php-fpm (เพื่อให้ php.ini ใหม่มีผล)
5. ตรวจสอบด้วย `php artisan system:health-check` ตรวจสอบห่วงโซ่บันทึกการตรวจสอบด้วย `audit:verify-chain`

## การตรวจสอบตามรอบ

| ความถี่ | งาน |
|---|---|
| รายวัน (อัตโนมัติ) | `audit:seal`, `lms:reconcile` การปล่อยที่นั่งสำรองของการลงทะเบียนเรียน การเลื่อนรายชื่อสำรอง การหมดอายุของฉบับร่างใบสมัคร |
| รายสัปดาห์ | `system:health-check` ตรวจสอบการอัปเดตความปลอดภัยของ PHP และระบบปฏิบัติการ ตรวจสอบงานที่ล้มเหลวใน Horizon |
| รายเดือน | `media:prune-orphans --dry-run` การซ้อมกู้คืนข้อมูลสำรอง, `audit:verify-chain` |
| ทุกภาคการศึกษา | ทบทวนการกำหนดบทบาท (ผู้ที่ลาออกหรือย้ายหน่วยงาน) ลบบันทึกการตรวจสอบที่เกินระยะเวลาเก็บรักษา (`audit:prune`) |
