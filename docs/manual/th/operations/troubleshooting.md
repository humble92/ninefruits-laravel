# การแก้ไขปัญหา

- ผู้อ่าน: ผู้ดูแลระบบไอที

| อาการ | สิ่งที่ต้องตรวจสอบ |
|---|---|
| ถูกนำไปยังหน้าความปลอดภัยทันทีหลังเข้าสู่ระบบ | นโยบายการยืนยันตัวตนแบบสองขั้นตอนเป็น "บังคับ" และเลยระยะผ่อนผันแล้ว จะหายไปเมื่อผู้ใช้ลงทะเบียนการยืนยันตัวตน นโยบายอยู่ที่ **การตั้งค่า > ความปลอดภัย** |
| 403 ในแผงผู้ดูแลระบบ | ผู้ใช้ไม่มีการกำหนดบทบาทที่มีผลอยู่ซึ่งมีสิทธิ์ `admin_panel.access` ตรวจสอบที่ **ผู้ใช้และสิทธิ์การเข้าถึง > ผู้ใช้ > การกำหนดบทบาท** |
| เมนูบางรายการหายไป | บทบาทไม่มีสิทธิ์สำหรับหน้าจอนั้น (ตัวอย่างเช่น `roles.view`) |
| ไม่ได้รับรหัสทางอีเมล | การตั้งค่าอีเมล (`MAIL_*`) รายการ `ส่งรหัสทางอีเมล` ในเหตุการณ์ด้านความปลอดภัย ขีดจำกัดการส่ง (หนึ่งครั้งต่อนาที ห้าครั้งต่อชั่วโมง) |
| หน้าจอแสดงข้อมูลของผู้อื่น 0 รายการ | อาจเป็นเรื่องปกติ (การรักษาความปลอดภัยระดับแถว) ยืนยันว่ามีการกำหนดผู้ดำเนินการของเซสชันฐานข้อมูลแล้วโดยดูคอลัมน์ผู้ใช้ใน **การเปลี่ยนแปลงข้อมูล** |
| `permission denied for schema public` | แอปพลิเคชันพยายามรัน DDL ด้วย `app_runtime` ให้รันไมเกรชันด้วย `php artisan migrate` เท่านั้น (ซึ่งใช้ `app_migrator` โดยอัตโนมัติ) |
| `Audit records are append-only` | มีความพยายามแก้ไขหรือลบตารางบันทึกการตรวจสอบ การปิดกั้นนี้เป็นไปตามที่ออกแบบไว้ |
| การสร้าง PDF ล้มเหลว | `php artisan pdf:sample` สถานะของ Gotenberg, `GOTENBERG_URL` |
| งานในคิวค้าง | ตรวจสอบงานที่ล้มเหลวใน `/horizon`, `php artisan horizon:status` |

การติดตามรายคำขอ: ด้วยค่าของส่วนหัวการตอบกลับ `X-Request-Id` ท่านสามารถค้นหาล็อก บันทึกการดำเนินงาน การเปลี่ยนแปลงข้อมูล และเหตุการณ์ด้านความปลอดภัยได้พร้อมกัน
