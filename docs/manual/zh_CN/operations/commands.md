# Artisan 命令参考

- 对象：IT 运维人员
- 范围：本仓库注册的全部应用命令。新增命令时必须同时添加到本文档，否则 CI 不通过（`tests/Feature/Tooling/CommandDocumentationTest.php`）。

## 通用说明

所有命令通过 `php artisan {命令}` 执行。开发环境中为 `./vendor/bin/sail artisan {命令}`。

| 项目 | 规则 |
|---|---|
| 审计记录 | 修改数据的命令（下文标注"审计：记录"）每次执行都会在业务审计（日志 `command`）中留下命令、参数、选项、OS 用户、退出码和结果。在管理界面 **审计 > 业务审计记录** 中查看 |
| 执行 ID | 每次执行都会在请求 ID 的位置附加一个以 `cmd-` 开头的 ID。业务审计、该次执行修改的数据变更记录、该次执行放入的队列任务都带有同一个 ID，因此可以用 ID 查找"这条变更来自哪个命令"。`--actor` 是执行者填写的值，不会写入数据变更记录的用户栏（实际执行者是 OS 用户） |
| `--actor=<邮箱>` | 带审计记录的命令都有此选项。记录负责的管理员账户。邮箱不存在时不执行 |
| `--dry-run` | 不做修改，只输出结果。难以撤销的操作都有此选项 |
| `--force` | 不询问确认直接执行（用于定时任务、部署脚本） |
| `--reason=` | 需要事由的命令有此选项 |
| 退出码 | 0 成功，1 失败或取消，2 检查命令发现了问题 |
| 数据库上下文 | 执行期间数据库会话的执行者被设为 `system:command:{命令}`，并记录到数据变更记录（触发器）中 |

## 安装与演示

### `setup:install`

- 用途：新安装和更新。依次处理迁移、必要数据、机构默认设置、安装配置文件、初始管理员。重复执行是安全的（已有数据和管理员修改过的值会保留）。
- 执行时机：首次安装，以及每次部署时。
- 选项：`--institution-name=`、`--locale=`（默认语言）、`--timezone=`（例如 `Asia/Seoul`）、`--profile=*`（安装配置文件键）、`--grade-scale=`（绩点等级制 `4.5` 或 `4.3`。一旦确定不能更改。留空时使用第一个配置文件的等级制）、`--admin-email=`、`--admin-name=`、`--force`（不询问直接执行。管理员密码从标准输入读取）。
- 审计：记录
- 示例

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="데모대학교" --admin-email=admin@example.ac.kr --admin-name="관리자"
  ```

- 输出解读：按步骤显示 `DONE`/`FAIL`。`Administrator exists` 表示系统管理员分配已存在，跳过了创建。
- 失败时：如果报错提示缺少密钥，把 `key:generate`、`pii:generate-key` 生成的值写入环境配置。迁移失败时检查数据库角色准备（安装手册）。

### `setup:demo`

- 用途：用工厂生成虚拟大学数据。输出各角色的固定演示账户（`registrar@demo.test` 等）。
- 执行时机：开发、培训、演示环境。**在生产环境（`APP_ENV=production`）中即使加 `--force` 也不会执行。**
- 选项：`--size=tiny|small|medium|large`（学生约 20/100/2,000/20,000 人。`tiny` 用于测试和快速确认）、`--seed=`（相同的值生成相同的数据）、`--force`。
- `--student-accounts`：为全部在校学生创建账户（`student{学号}@demo.test`，演示密码）并写入 `storage/app/private/load-accounts.csv`。用于负载测试（[负载测试](load-testing.md)）。
- 审计：记录
- 示例：`php artisan setup:demo --size=small --seed=42`
- 失败时：缺少必要数据时演示账户没有角色，会被跳过。先执行 `setup:install`。

## 基础数据与学期

### `reference:import`

- 用途：导入基础数据 CSV。使用与管理界面 **导入 CSV** 相同的导入规则（按代码查找并更新已有行，空的翻译栏保留原值，只单独记录失败的行）。
- 参数：`{type}` `org_units`、`programs`、`buildings`、`rooms`、`lookup_values`、`students`、`instructors`、`courses`、`registration_holds` / `{file}` 带标题行的 UTF-8 CSV。
- 选项：`--actor=`（必填。导入记录和完成通知都归于此账户）、`--chunk=100`（每个队列任务的行数）、`--dry-run`（只检查标题行并统计行数）。
- 审计：记录（类型、文件名、行数、失败行数）
- 列格式：[管理员手册第 9 章](../admin/09-csv-import.md)。
- 退出码：队列为同步执行时直接输出结果，有失败行则为 2。异步（Horizon）时只受理，返回 0。结果以失败行 CSV 的形式在 `--actor` 账户的管理界面通知中获取。
- 示例：`php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- 用途：显示指定时刻正在上课的学期和开放中的业务期间（类型、学期、对象条件、结束时间）。用于检查学期和业务期间设置，或处理"为什么选课没有开放"之类的咨询。
- 选项：`--at=`（默认为当前时间。例如 `"2027-02-15 09:00"`。不带时区时按服务器时区（UTC）解释。可以写成 `"2027-02-15 09:00 Asia/Seoul"` 的形式指定）。
- 审计：不记录
- 输出解读：日期判断以机构时区为准。计划中（planned）或已归档（archived）状态学期的业务期间不会开放。

## 安全

### `security:create-administrator`

- 用途：创建拥有系统管理员角色的账户。通常由 `setup:install` 调用。
- 选项：`--email=`、`--name=`、`--password-stdin`（从标准输入读取密码。非交互执行时必填）。
- 审计：记录（创建的用户 ID）
- 示例：`php artisan security:create-administrator --email=admin@example.ac.kr --name="관리자"`
- 失败时：`system_administrator role is missing` 表示需要先执行 `setup:install` 或 `db:seed`。密码至少 12 个字符。

### `security:sync-permissions`

- 用途：使代码中的权限目录与数据库权限列表一致。创建新权限，删除目录中已不存在的权限（会从所有角色中移除）。系统角色始终获得全部权限。
- 执行时机：部署后（`setup:install` 在必要数据步骤中一并处理）。
- 选项：`--dry-run`（只输出创建/删除列表）、`--force`（跳过删除确认）。
- 审计：记录（创建/删除的权限）
- 输出解读：`create`、`delete` 行。有删除时会出现确认提问。
- 失败时：在确认提问中选择"否"时以退出码 1 结束，不做任何修改。

### `security:reset-mfa`

- 用途：重置用户的双重身份验证（身份验证器应用、邮件验证码、恢复码、已记住的设备）。下次登录时重新注册。用于没有管理员能登录管理界面的情况（例如唯一的管理员丢失了手机）。其他情况使用管理界面 **用户 > 重置双重身份验证**。
- 参数/选项：`{user}` 用户邮箱、`--reason=`（必填）、`--actor=`（必填。决定重置的管理员）。
- 审计：记录（业务审计和安全日志都记录，含事由）
- 示例：`php artisan security:reset-mfa admin@example.ac.kr --reason="휴대폰 분실, 본인 확인 완료(전화)" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- 用途：在锁定时间结束前解锁因连续输错密码而被锁定的账户。与管理界面 **用户 > 解除登录锁定** 相同。
- 参数/选项：`{user}` 用户邮箱、`--reason=`（必填）。
- 审计：记录（安全日志中也会留下记录）
- 输出解读：`The account is not locked.` 表示没有做任何修改。
- 参考：锁定标准（失败次数、锁定时间）在管理界面 **设置 > 登录方式** 中设置。

## 人员与学籍

### `people:find-duplicates`

- 用途：显示疑似同一人的人员列表。判断标准是身份证号（搜索哈希）相同，或罗马字姓名与出生日期都相同。已合并的人员除外。
- 选项：`--limit=100`（输出的分组数）。
- 审计：不记录（仅查询）
- 退出码：存在重复候选时为 2。
- 后续处理：在管理界面 **人员** 中逐组核对，确认是同一人时在要保留的人员页面执行 **合并重复人员**。合并不可撤销（[管理员手册第 14 章](../admin/14-merge-and-invitations.md)）。

## 招生

### `admission:matriculate`

- 用途：为招生批次中已确认注册的申请人创建学籍（新学号）。与管理界面 **招生 > 申请** 的批量 **创建学籍** 相同。逐个申请人处理，一人失败不影响其余。
- 参数/选项：`{cycle}` 招生批次代码、`--term=`（必填。入学学期代码，例如 `2027-SP`。入学日期为学期第一天）、`--actor=`（必填。拥有 `为录取者创建学籍` 权限的账户。只处理该账户权限范围内的申请人）、`--dry-run`（只列出对象）。
- 审计：记录（批次、学期、对象数、创建数、失败的报名号）。每个申请人还会留下业务审计（`application.matriculated`）。
- 退出码：有失败的申请人时为 2。
- 示例：`php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- 失败时：`not ready` 表示已有学籍或不是已确认注册状态，`program is not in effect` 表示入学日期当天专业项目不在生效期内（检查基础数据 > 专业项目的生效期间）。

### `admission:expire-drafts`

- 用途：把已截止批次中填写中的申请，以及在设定期间（**设置 > 招生 > 草稿过期天数**，默认 90 天）内未修改的填写中申请改为**已过期**。已过期的申请不妨碍在同一批次中重新申请。
- 执行时机：定时任务（每天 03:10，[定时任务](scheduled-jobs.md)）。
- 选项：`--dry-run`（只统计对象数）。
- 审计：记录（过期数）

## 开课

### `section:copy`

- 用途：以上一学期的开课为基础开始新学期的编排。与管理界面 **开课 > 从其他学期复制** 相同。把未停开的课程班以草稿状态复制，并一并复制任课教师（在职时）、上课时间与教室、预留名额（转换时刻按学期开始日的差值平移）、教学大纲（非公开草稿）。课程版本会换成新时段开始日生效的版本。
- 参数/选项：`{from-term}`、`{to-term}` 学期代码（例如 `2026-FA`）、`--org-unit=*`（只复制该组织代码的课程班）、`--dry-run`（不保存，只显示结果）、`--actor=`（必填。只复制该账户 `编排开课` 权限范围内的课程班）。
- 审计：记录（复制、跳过、需确认的数量）
- 输出解读：`skipped` 表示目标学期已有相同班号，或没有生效的课程版本；`note` 表示已复制但有遗漏（教室已被占用而不含教室复制、教师已离职等）。时段按代码匹配，没有时放入全学期时段。
- 示例：`php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- 用途：在公布课表之前检查学期开课。教室和教师的重复安排数据库已经阻止，此命令查找数据库允许但有问题的情况：名额大于教室容量、在时段开始日不生效的课程版本、已离职的任课教师、超过名额的预留名额、时段之外的上课日期。也检查像备份恢复那样未经约束进入的数据中的教室冲突。
- 参数：`{term}` 学期代码。
- 审计：不记录（仅查询）
- 退出码：有问题时为 2。尚未安排任课教师或教室的课程班只作为参考显示。

## 选课

### `registration:preflight`

- 用途：在开放选课前检查学期。显示选课和加退选期间、规则集、已公开的课程班数、名额为 0 的课程班、超过名额的预留名额、在时段开始日不生效的课程版本、未应用学分上限的在校学生数、被选课限制的学生数。
- 参数：`{term}` 学期代码（例如 `2027-SP`）。
- 审计：不记录（仅查询）
- 退出码：有问题时为 2。没有规则集不算问题，只作为参考显示（应用规则默认值）。
- 示例：`php artisan registration:preflight 2027-SP`

### `registration:simulate`

- 用途：按规则逐条显示学生现在（或在指定时刻）选某个课程班会得到什么结果。不保存，也不留下尝试记录。用于处理"为什么选不上？"的咨询。
- 参数：`{student-number}` 学号、`{section}` `课程代码-班号`（例如 `CSE2010-01`）。
- 选项：`--term=`（学期代码。默认为该班号所在的最近学期）、`--at=`（判断时刻。例如 `"2027-02-10 10:00 Asia/Seoul"`）。
- 审计：不记录（仅查询）
- 输出解读：每条规则显示通过/失败、阻止/警告、消息。应用了例外（override）的规则显示为失败但不阻止。名额在规则表下方单独显示。
- 退出码：选课会被拒绝时为 2。

### `waitlist:promote`

- 用途：对有空位的课程班按顺序为候补者办理选课。递补时重新检查所有规则，未通过规则的候补者从候补中移除（记录事由）。选课和加退选期间都已关闭的课程班，其候补会被设为过期。向学生发送结果邮件。
- 参数/选项：`{term?}` 学期代码（默认：所有有候补者的学期）、`--actor=`。
- 审计：记录（课程班数、递补、移除、过期数）
- 执行时机：退选、撤销选课和释放预留名额时，相关课程班会通过队列任务立即处理。此命令是每小时定时执行、处理遗漏情况的安全网。
- 示例：`php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- 用途：把已过转换时刻的预留名额（例如本专业学生保留名额）标记为已处理，并把该课程班的候补递补任务放入队列。预留名额在转换时刻之后在计算上立即变为普通名额，因此此命令只负责把空位让给候补者。
- 审计：不记录（每 5 分钟执行。递补结果留在选课记录中）
- 执行时机：定时任务（每 5 分钟）。

## 成绩

### `term:close`

- 用途：结算学期。学期的所有成绩必须已确定。为每个学生计算学期记录（学分、学期和累计绩点），判定学业状态（正常、学业警告、退学审查）和是否成绩优秀（队列批处理），然后按专业项目排出成绩优秀名次，把学期记录封存为正式记录，并把学期改为**成绩已关闭**状态。与管理界面 **成绩 > 学期记录 > 学期结算** 相同。
- 参数/选项：`{term}` 学期代码、`--dry-run`（只确认是否可以结算）、`--reason=`（写入记录的事由）、`--actor=`。
- 审计：记录（学生数、未确定课程班数）。结算完成后，`term.closed` 审计记录中会留下学业警告、退学审查、成绩优秀的人数。
- 退出码：存在成绩未确定的课程班时为 2（输出每个课程班的未确定数量）。学期不是已公开（published）状态时为 1。
- 执行时机：成绩录入和确定全部完成之后。批处理进度在 Horizon 中查看。没有队列工作进程时学期状态不会改变。
- 示例：`php artisan term:close 2026-FA --dry-run`、`php artisan term:close 2026-FA --reason="2026-2 성적 마감" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- 用途：根据已确定的成绩重新计算学期记录（学分、学期和累计绩点）。用于修改成绩处理政策（绩点小数位数、重修计入方式）后应用到过去的学期。学业状态和成绩优秀保持学期结算时确定的值。成绩更正的批准会自动重新计算该学生，不需要此命令。
- 选项：`--term=`（该学期有成绩的学生，从该学期开始）、`--student-number=`（单个学生）、`--reason=`（必填）、`--actor=`。
- 审计：记录（学生数、事由）
- 示例：`php artisan grades:recalculate --term=2026-SP --reason="평점 소수 셋째 자리로 변경"`

### `grades:remind-missing`

- 用途：向尚未提交成绩的课程班（未录入或暂存）的任课教师发送提醒邮件。按教师汇总其课程班，每人发送一封。
- 参数/选项：`{term}` 学期代码、`--dry-run`（不发送，只输出对象）、`--actor=`。
- 审计：记录（课程班数、教师数、发送数）
- 执行时机：成绩录入期间截止前几天。需要时注册为定时任务。

## 课程评价

### `evaluation:remind`

- 用途：向课程评价期间开放中、但仍有课程未评价的学生发送提醒邮件。按学生汇总剩余课程，每人发送一封。
- 参数/选项：`{term}` 学期代码、`--dry-run`（不发送，只统计对象学生数）、`--actor=`。
- 审计：记录（对象学生数、发送数）
- 执行时机：评价期间内执行一两次。需要时注册为定时任务。

### `evaluation:publish-results`

- 用途：向教师公布学期课程评价结果。与管理界面 **课程评价 > 学期课程评价 > 公布结果** 相同。公布后也只有达到最低回答数和回答率的课程班才能看到结果。
- 参数/选项：`{term}` 学期代码、`--actor=`。
- 审计：记录（回答数、是否已公布）
- 执行时机：评价期间和成绩处理结束之后。已公布的学期不会改变。

## 证明

### `certificate:verify`

- 用途：按与公开真伪验证页面相同的标准检查证明验证码。输出类型、编号、开具日期、已遮蔽的持有人。
- 参数/选项：`{code}` 验证码。
- 审计：无（查询）
- 退出码：有效时为 0；验证码不存在、已撤销或已过期时为 2。

### `certificate:render`

- 用途：用当前数据和模板重新生成已开具证明的 PDF，并替换存档文件。与管理界面 **开具台账 > 重新生成** 相同。编号和验证码不变，校验和会改变。
- 参数/选项：`{issue}` 编号、`--reason=`（必填）、`--actor=`。
- 审计：记录（编号、新校验和）
- 执行时机：修正模板或姓名写法后，需要重新生成特定证明时。

## 语言/综合考试

### `assessment:import-results`

- 用途：通过 CSV 录入考试场次的成绩。规则与管理界面 **考试场次 > 导入成绩（CSV）** 相同（只限已报名的学生，按分数判定合格，公布前重新录入会覆盖）。
- 参数/选项：`{type}` 考试种类代码 / `{held_date}` 考试日期 `YYYY-MM-DD` / `{file}` 带标题行的 UTF-8 CSV，`--actor=`（必填）、`--dry-run`（不写入，只检查行）。
- 列格式：[管理员手册第 24 章](../admin/24-assessments.md)。
- 审计：记录（场次、文件名、行数、录入、缺考、错误数）
- 退出码：有错误行时为 2（其余行已写入）。
- 示例：`php artisan assessment:import-results ENG_COMP 2026-05-15 storage/app/eng.csv --actor=registrar@example.ac.kr --dry-run`

### `assessment:publish-results`

- 用途：向学生公布场次的成绩。与管理界面 **考试场次 > 公布成绩** 相同。
- 参数/选项：`{type}` 考试种类代码 / `{held_date}` 考试日期，`--actor=`（必填）。
- 审计：记录（场次、成绩数）
- 执行时机：成绩录入完成之后。已公布的场次会失败。

## 考勤

### `attendance:generate-sessions`

- 用途：按上课时间（星期、时间、期间）为学期的每个开课生成课次。与教师门户和管理界面的 **生成课次** 相同。已有的课次和考勤保持不变（重复执行是安全的）。
- 参数/选项：`{term}` 学期代码、`--section=`（课程代码-班号，例如 `CSE2010-01`，只能一个）、`--dry-run`（只统计对象课程班数）、`--actor=`。
- 审计：记录（学期、课程班数、生成课次数）
- 执行时机：学期开始前、上课时间确定之后。上课时间变更后重新执行。

## 毕业

### `degree-audit:run`

- 用途：为每个在校学生保存毕业资格审核。与管理界面 **毕业资格审核 > 执行审核** 相同。保存的最新审核是毕业处理的依据。
- 选项：`--term=`（审核所属的学期代码）、`--student-number=`（单个学生）、`--min-year-level=`（只限该年级及以上）、`--actor=`。
- 审计：记录（学生数、满足数）
- 执行时机：毕业审定之前（学期末），以及修改要求集或替代课程之后。

## LMS 对接

### `lms:sync`

- 用途：把已公开的开课推送到平台（创建和关联课程、任课教师、选课中的学生）。按学期执行与管理界面 **课程关联 > 重新同步** 相同的处理。已关联的课程只做再次保证（幂等）。
- 参数/选项：`{platform}` 平台代码、`--term=`（学期代码，默认为所有未结束的学期）、`--section=`（单个课程代码-班号）、`--dry-run`（只把要发送的内容记录为"跳过"）、`--actor=`。
- 审计：记录（平台、课程班数、成员数、失败数）
- 退出码：有失败的课程班时为 2。

### `lms:reconcile`

- 用途：比较平台的课程名单与教务系统的选课名单，补充缺少的成员，移除多余的成员。差异记录在同步日志（`reconcile`）中。
- 参数/选项：`{platform?}`（省略时为所有启用的平台）、`--term=`、`--dry-run`（只记录差异）、`--actor=`。
- 审计：记录（各平台的课程班数、添加、移除、失败数）
- 执行时机：每天 02:30 定时执行。平台故障后手动执行。

## 运维检查与清理

### `system:health-check`

- 用途：检查配置与密钥（APP_KEY、PII 密钥、APP_DEBUG）、数据库连接与角色（runtime、migrator、reporting）、个人信息表的 RLS、待执行的迁移、权限目录同步、Redis、队列（Horizon）、Gotenberg、媒体存储写入、调度器心跳。
- 选项：`--json`（监控用输出）。
- 审计：无（查询）
- 退出码：任一项失败时为 2。
- 执行时机：部署后立即执行、怀疑故障时、由监控系统定期执行。

### `audit:seal`

- 用途：把审计表的新行接入哈希链（[审计完整性](audit-and-maintenance.md)）。
- 选项：`--table=`（从 record_changes、activity_log、security_events 中选择，可多次指定）、`--actor=`。
- 审计：记录（各表的封存数）
- 执行时机：每天 03:30 定时执行。

### `audit:verify-chain`

- 用途：重新计算审计行的内容哈希和链，查找篡改、删除、顺序变动。
- 选项：`--table=`。
- 审计：无（查询）
- 退出码：有不一致时为 2。
- 执行时机：备份前、安全检查时、清理后。

### `audit:prune`

- 用途：删除超过保留期限的**已封存**审计行。以模式所有者连接执行。
- 选项：`--before=YYYY-MM-DD`（必填）、`--table=`、`--dry-run`（只统计数量）、`--actor=`。
- 审计：记录（基准日期、各表删除数）
- 执行时机：按保留政策，在备份之后。

### `media:prune-orphans`

- 用途：删除所有者已不存在的媒体行以及没有对应行的目录（人员照片、申请材料、证明 PDF、考试凭证）。
- 选项：`--dry-run`（只列出）、`--actor=`。
- 审计：记录（行数、目录数）
- 执行时机：每月一次，或大批量删除之后。

## 个人信息加密密钥

### `pii:generate-key`

- 用途：输出用于 `PII_ENCRYPTION_KEY`、`PII_HASH_KEY` 的新密钥。不保存任何内容。
- 审计：不记录
- 注意：更换 `PII_HASH_KEY` 会使所有搜索哈希失效。密钥更换步骤见 [security-keys.md](security-keys.md)。

### `pii:reencrypt`

- 用途：更换密钥后，把用旧密钥加密的个人信息用当前密钥重新加密。以队列批处理执行。
- 参数：模型类（目前为 `App\\Models\\Person\\Person`）。
- 选项：`--chunk=500`、`--dry-run`（只统计使用旧密钥的记录数）、`--force`。
- 审计：记录（批次 ID、任务数 / 预览数量）
- 确认：在 Horizon（`/horizon`）中查看批次进度。结束后 `--dry-run` 结果为 0 时，从 `PII_PREVIOUS_KEYS` 中移除旧密钥。

## 多语言

### `i18n:missing`

- 用途：相对于基准语言（en），显示各语言缺失的键和不再使用的键。
- 参数/选项：`{locale?}`（只限一种语言）、`--strict`（有缺失时退出码为 2。用于 CI）。
- 审计：不记录

### `i18n:export`

- 用途：生成交给翻译人员的 JSON 文件。格式：`{"键": {"source": "英文", "translation": "译文"}}`。
- 参数/选项：`{locale} {path}`、`--missing`（只导出缺失的键）。
- 审计：不记录
- 示例：`php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- 用途：把翻译人员填写的 JSON 写入 `lang/{locale}`。只导入基准语言中存在的键，忽略空译文。
- 参数/选项：`{locale} {path}`、`--dry-run`（只输出将写入的键列表）。
- 审计：记录
- 注意：翻译文件由仓库管理。导入后提交变更内容。

## 检查

### `naming:check`

- 用途：按[命名规则](../../../development/naming.md)检查迁移中的表名和列名。
- 选项：`--path=*`（要检查的目录，默认 `database/migrations`）。
- 审计：不记录
- 退出码：有问题时为 2。

### `pdf:sample`

- 用途：把混合韩文、中文、老挝文、英文的表格渲染为 PDF，检查字体和 PDF 服务（Gotenberg）连接。
- 参数：`{path=pdf-sample.pdf}`（相对于本地磁盘 `storage/app/private`）。
- 审计：不记录
- 失败时：如果是连接错误，检查 `GOTENBERG_URL` 和 Gotenberg 容器状态。
