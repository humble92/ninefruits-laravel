# Artisan 명령 레퍼런스

- 대상: IT 운영자
- 기준: 이 저장소에 등록된 애플리케이션 명령 전체. 명령을 추가하면 이 문서에도 추가해야 CI가 통과한다(`tests/Feature/Tooling/CommandDocumentationTest.php`).

## 공통 사항

모든 명령은 `php artisan {명령}`으로 실행한다. 개발 환경에서는 `./vendor/bin/sail artisan {명령}`.

| 항목 | 규칙 |
|---|---|
| 감사 기록 | 데이터를 바꾸는 명령(아래 "감사: 기록")은 실행할 때마다 업무 감사(로그 `command`)에 명령, 인수, 옵션, OS 사용자, 종료 코드, 결과를 남긴다. 관리 화면 **감사 > 업무 감사 기록**에서 확인한다 |
| 실행 ID | 실행마다 `cmd-`로 시작하는 ID가 요청 ID 자리에 붙는다. 업무 감사, 그 실행이 바꾼 데이터 변경 기록, 실행이 넣은 큐 작업이 같은 ID를 가지므로 "이 변경이 어느 명령에서 왔는가"를 ID로 찾는다. `--actor`는 실행자가 적는 값이라 데이터 변경 기록의 사용자 칸에는 넣지 않는다(실제 실행자는 OS 사용자) |
| `--actor=<이메일>` | 감사 기록 명령에 공통으로 있다. 책임자 관리자 계정을 기록한다. 없는 이메일이면 실행하지 않는다 |
| `--dry-run` | 변경 없이 결과만 출력한다. 되돌리기 어려운 작업에 있다 |
| `--force` | 확인 질문 없이 실행한다(스케줄, 배포 스크립트용) |
| `--reason=` | 사유가 필요한 명령에 있다 |
| 종료 코드 | 0 성공, 1 실패 또는 취소, 2 점검 명령이 문제를 발견함 |
| DB 컨텍스트 | 실행 중에는 DB 세션의 수행자가 `system:command:{명령}`으로 설정되어 데이터 변경 기록(트리거)에 남는다 |

## 설치와 데모

### `setup:install`

- 용도: 신규 설치와 업데이트. 마이그레이션, 필수 데이터, 기관 기본 설정, 설치 프로파일, 최초 관리자를 차례로 처리한다. 다시 실행해도 안전하다(이미 있는 데이터와 관리자가 바꾼 값은 유지).
- 실행 시점: 최초 설치, 그리고 배포할 때마다.
- 옵션: `--institution-name=`, `--locale=`(기본 언어), `--timezone=`(예: `Asia/Seoul`), `--profile=*`(설치 프로파일 키), `--grade-scale=`(성적 척도 `4.5` 또는 `4.3`. 한 번 정하면 바꿀 수 없다. 비우면 첫 프로파일의 척도), `--admin-email=`, `--admin-name=`, `--force`(질문 없이 실행. 관리자 비밀번호는 표준 입력으로 받음).
- 감사: 기록
- 예시

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="데모대학교" --admin-email=admin@example.ac.kr --admin-name="관리자"
  ```

- 출력 해석: 단계별 `DONE`/`FAIL`. `Administrator exists`는 시스템 관리자 할당이 이미 있어 생성을 건너뛴 것이다.
- 실패 시: 키가 없다는 오류면 `key:generate`, `pii:generate-key`로 만든 값을 환경 설정에 넣는다. 마이그레이션 실패는 DB 역할 준비(설치 매뉴얼)를 확인한다.

### `setup:demo`

- 용도: 팩토리로 가상 대학 데이터를 만든다. 역할별 고정 데모 계정(`registrar@demo.test` 등)을 출력한다.
- 실행 시점: 개발, 교육, 시연 환경. **운영 환경(`APP_ENV=production`)에서는 `--force`를 줘도 실행되지 않는다.**
- 옵션: `--size=tiny|small|medium|large`(학생 약 20/100/2,000/20,000명. `tiny`는 테스트와 빠른 확인용), `--seed=`(같은 값이면 같은 데이터), `--force`.
- 감사: 기록
- 예시: `php artisan setup:demo --size=small --seed=42`
- 실패 시: 필수 데이터가 없으면 데모 계정의 역할이 없어 건너뛴다. 먼저 `setup:install`을 실행한다.

## 기준정보와 학기

### `reference:import`

- 용도: 기준정보 CSV를 가져온다. 관리 화면의 **CSV 가져오기**와 같은 가져오기 규칙을 쓴다(코드로 기존 행을 찾아 갱신, 빈 번역 칸은 기존 값 유지, 실패한 행만 따로 기록).
- 인수: `{type}` `org_units`, `programs`, `buildings`, `rooms`, `lookup_values`, `students`, `instructors`, `courses`, `registration_holds` / `{file}` 머리글 행이 있는 UTF-8 CSV.
- 옵션: `--actor=`(필수. 가져오기 기록과 완료 알림이 이 계정으로 간다), `--chunk=100`(큐 작업당 행 수), `--dry-run`(머리글 검사와 행 수만).
- 감사: 기록 (유형, 파일 이름, 행 수, 실패 행 수)
- 열 형식: [관리자 매뉴얼 9장](../admin/09-csv-import.md).
- 종료 코드: 큐가 동기 실행이면 결과를 바로 출력하고 실패 행이 있으면 2. 비동기(Horizon)이면 접수만 하고 0. 결과는 `--actor` 계정의 관리 화면 알림에서 실패 행 CSV로 받는다.
- 예시: `php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- 용도: 지정 시각에 수업 중인 학기와 열려 있는 업무 기간(종류, 학기, 대상 조건, 종료 시각)을 보여 준다. 학기와 업무 기간 설정을 점검하거나 "왜 수강신청이 안 열렸는가" 같은 문의에 쓴다.
- 옵션: `--at=`(기본 현재. 예: `"2027-02-15 09:00"`. 시간대를 붙이지 않으면 서버 시간대(UTC)로 해석한다. `"2027-02-15 09:00 Asia/Seoul"`처럼 지정할 수 있다).
- 감사: 기록 안 함
- 출력 해석: 날짜 판단은 기관 시간대 기준이다. 계획(planned)이나 보관(archived) 상태 학기의 업무 기간은 열리지 않는다.

## 보안

### `security:create-administrator`

- 용도: 시스템 관리자 역할을 가진 계정을 만든다. 보통 `setup:install`이 호출한다.
- 옵션: `--email=`, `--name=`, `--password-stdin`(표준 입력으로 비밀번호. 비대화식 실행 시 필수).
- 감사: 기록 (생성한 사용자 ID)
- 예시: `php artisan security:create-administrator --email=admin@example.ac.kr --name="관리자"`
- 실패 시: `system_administrator role is missing`이면 `setup:install` 또는 `db:seed`를 먼저 실행한다. 비밀번호는 12자 이상이어야 한다.

### `security:sync-permissions`

- 용도: 코드의 권한 카탈로그와 DB 권한 목록을 맞춘다. 새 권한은 만들고, 카탈로그에서 빠진 권한은 삭제한다(모든 역할에서 제거됨). 시스템 역할은 항상 모든 권한을 받는다.
- 실행 시점: 배포 후(`setup:install`이 필수 데이터 단계에서 함께 처리한다).
- 옵션: `--dry-run`(생성/삭제 목록만 출력), `--force`(삭제 확인 생략).
- 감사: 기록 (생성/삭제한 권한)
- 출력 해석: `create`, `delete` 줄. 삭제가 있으면 확인 질문이 나온다.
- 실패 시: 확인 질문에 "아니요"를 고르면 종료 코드 1로 아무것도 바꾸지 않는다.

### `security:reset-mfa`

- 용도: 사용자의 2단계 인증(인증 앱, 이메일 코드, 복구 코드, 기억한 기기)을 초기화한다. 다음 로그인 때 다시 등록한다. 관리 화면에 로그인할 수 있는 관리자가 없을 때(예: 유일한 관리자가 휴대폰을 잃어버림) 쓴다. 그 밖에는 관리 화면 **사용자 > 2단계 인증 초기화**를 쓴다.
- 인수/옵션: `{user}` 사용자 이메일, `--reason=`(필수), `--actor=`(필수. 초기화를 결정한 관리자).
- 감사: 기록 (업무 감사와 보안 로그 모두. 사유 포함)
- 예시: `php artisan security:reset-mfa admin@example.ac.kr --reason="휴대폰 분실, 본인 확인 완료(전화)" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- 용도: 비밀번호를 연속으로 틀려 잠긴 계정을 잠금 시간이 끝나기 전에 푼다. 관리 화면 **사용자 > 로그인 잠금 해제**와 같다.
- 인수/옵션: `{user}` 사용자 이메일, `--reason=`(필수).
- 감사: 기록 (보안 로그에도 남음)
- 출력 해석: `The account is not locked.`이면 아무것도 바꾸지 않았다.
- 참고: 잠금 기준(실패 횟수, 잠금 시간)은 관리 화면 **설정 > 로그인 수단**에서 정한다.

## 인물과 학적

### `people:find-duplicates`

- 용도: 같은 사람으로 보이는 인물 목록을 보여 준다. 기준은 주민등록번호(검색 해시)가 같거나, 로마자 성명과 생년월일이 같은 경우다. 병합된 인물은 제외한다.
- 옵션: `--limit=100`(출력할 묶음 수).
- 감사: 기록 안 함 (조회만)
- 종료 코드: 중복 후보가 있으면 2.
- 후속 조치: 각 묶음을 관리 화면 **인물**에서 확인하고, 같은 사람이면 남길 인물 화면에서 **중복 인물 병합**을 실행한다. 병합은 되돌릴 수 없다([관리자 매뉴얼 14장](../admin/14-merge-and-invitations.md)).

## 입학

### `admission:matriculate`

- 용도: 모집 회차의 등록 확정 지원자에게 학적을 만든다(새 학번). 관리 화면 **입학 > 지원서**의 일괄 **학적 생성**과 같다. 지원자마다 따로 처리하므로 한 명이 실패해도 나머지는 계속한다.
- 인수/옵션: `{cycle}` 모집 회차 코드, `--term=`(필수. 입학 학기 코드, 예: `2027-SP`. 입학일은 학기 첫날), `--actor=`(필수. `합격자 학적 생성` 권한이 있는 계정. 그 계정의 권한 범위 안의 지원자만 처리), `--dry-run`(대상 목록만).
- 감사: 기록 (회차, 학기, 대상 수, 생성 수, 실패한 수험 번호). 지원자별로 업무 감사(`application.matriculated`)도 남는다.
- 종료 코드: 실패한 지원자가 있으면 2.
- 예시: `php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- 실패 시: `not ready`는 이미 학적이 있거나 등록 확정 상태가 아닌 경우, `program is not in effect`는 입학일에 프로그램이 유효하지 않은 경우다(기준정보 > 프로그램의 적용 기간 확인).

### `admission:expire-drafts`

- 용도: 마감된 회차의 작성 중 지원서와, 설정한 기간(**설정 > 입학 > 작성 중 지원서 만료**, 기본 90일) 동안 고치지 않은 작성 중 지원서를 **기한 만료**로 바꾼다. 만료된 지원서는 같은 회차의 새 지원을 막지 않는다.
- 실행 시점: 스케줄(매일 03:10, [스케줄 작업](scheduled-jobs.md)).
- 옵션: `--dry-run`(대상 수만).
- 감사: 기록 (만료한 수)

## 개설강좌

### `section:copy`

- 용도: 이전 학기의 개설강좌로 새 학기 편성을 시작한다. 관리 화면 **개설강좌 > 다른 학기에서 복사**와 같다. 폐강되지 않은 강좌를 작성 중 상태로 복사하고, 담당 교원(재직 중인 경우), 강의 시간과 강의실, 좌석 할당(전환 시각은 학기 시작일 차이만큼 이동), 강의계획서(비공개 초안)를 함께 복사한다. 교과목 버전은 새 세션 시작일에 유효한 버전으로 바뀐다.
- 인수/옵션: `{from-term}`, `{to-term}` 학기 코드(예: `2026-FA`), `--org-unit=*`(이 조직 코드의 강좌만), `--dry-run`(저장하지 않고 결과만), `--actor=`(필수. 그 계정의 `개설강좌 편성` 권한 범위 안의 강좌만 복사).
- 감사: 기록 (복사, 건너뜀, 확인 필요 건수)
- 출력 해석: `skipped`는 대상 학기에 같은 분반이 이미 있거나 유효한 교과목 버전이 없는 강좌, `note`는 복사했지만 빠진 것(강의실이 이미 사용 중이라 강의실 없이 복사, 퇴직한 교원 등)이다. 세션은 코드로 맞추고, 없으면 전체 학기 세션에 넣는다.
- 예시: `php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- 용도: 시간표를 공개하기 전에 학기 개설강좌를 점검한다. 강의실·교원 중복 배정은 DB가 이미 막지만, 다음처럼 DB가 허용하는 문제를 찾는다: 강의실 수용 인원보다 큰 정원, 세션 시작일에 유효하지 않은 교과목 버전, 퇴직한 담당 교원, 정원을 넘는 좌석 할당, 세션 밖의 강의 날짜. 백업 복원처럼 제약 없이 들어온 데이터의 강의실 중복도 확인한다.
- 인수: `{term}` 학기 코드.
- 감사: 기록 안 함 (조회만)
- 종료 코드: 문제가 있으면 2. 담당 교원이나 강의실이 아직 없는 강좌는 참고로만 보여 준다.

## 수강신청

### `registration:preflight`

- 용도: 수강신청을 열기 전에 학기를 점검한다. 수강신청·수강 정정 기간, 규칙 세트, 공개 강좌 수, 정원 0인 강좌, 정원을 넘는 좌석 할당, 세션 시작일에 유효하지 않은 교과목 버전, 학점 상한이 적용되지 않는 재학생 수, 수강신청 제한이 걸린 학생 수를 보여 준다.
- 인수: `{term}` 학기 코드(예: `2027-SP`).
- 감사: 기록 안 함 (조회만)
- 종료 코드: 문제가 있으면 2. 규칙 세트가 없으면 문제가 아니라 참고로 보여 준다(규칙 기본값 적용).
- 예시: `php artisan registration:preflight 2027-SP`

### `registration:simulate`

- 용도: 학생이 지금(또는 지정 시각에) 강좌를 신청하면 어떻게 되는지 규칙별 결과를 보여 준다. 저장하지 않고 시도 기록도 남기지 않는다. "왜 신청이 안 되나요?" 문의에 쓴다.
- 인수: `{student-number}` 학번, `{section}` `과목코드-분반`(예: `CSE2010-01`).
- 옵션: `--term=`(학기 코드. 기본은 그 분반이 있는 가장 최근 학기), `--at=`(판단 시각. 예: `"2027-02-10 10:00 Asia/Seoul"`).
- 감사: 기록 안 함 (조회만)
- 출력 해석: 규칙마다 통과/실패, 차단/경고, 메시지. 예외(override)가 적용된 규칙은 실패로 보이지만 차단하지 않는다. 정원은 규칙 표 아래에 따로 나온다.
- 종료 코드: 신청이 거절될 상황이면 2.

### `waitlist:promote`

- 용도: 빈자리가 있는 강좌의 대기자를 순서대로 신청 처리한다. 승격 때 모든 규칙을 다시 확인하고, 규칙을 통과하지 못한 대기자는 대기에서 제외(사유 기록)한다. 수강신청·수강 정정 기간이 모두 닫힌 강좌의 대기는 만료한다. 학생에게 결과 메일을 보낸다.
- 인수/옵션: `{term?}` 학기 코드(기본: 대기자가 있는 모든 학기), `--actor=`.
- 감사: 기록 (강좌 수, 승격, 제외, 만료 수)
- 실행 시점: 취소·철회와 좌석 할당 해제 때 해당 강좌만 큐 작업으로 즉시 처리된다. 이 명령은 매시간 스케줄로 빠진 것을 처리하는 안전망이다.
- 예시: `php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- 용도: 전환 시각이 지난 좌석 할당(예: 전공자 유보석)을 처리 완료로 표시하고 그 강좌의 대기자 승격 작업을 큐에 넣는다. 유보석은 전환 시각이 지나면 계산상 바로 일반석이 되므로, 이 명령은 대기자에게 자리를 넘기는 역할만 한다.
- 감사: 기록 안 함 (5분마다 실행. 승격 결과는 수강신청 기록에 남는다)
- 실행 시점: 스케줄(5분마다).

## 성적

### `term:close`

- 용도: 학기를 마감한다. 학기의 모든 성적이 확정되어 있어야 한다. 학생마다 학기 기록(학점, 학기·누적 평점)을 계산하고 학업 상태(정상, 학사경고, 제적 검토)와 성적우수 해당 여부를 판정한 뒤(큐 배치), 프로그램별 성적우수 순위를 매기고 학기 기록을 공식 기록으로 마감하고 학기를 **성적 마감** 상태로 바꾼다. 관리 화면 **성적 > 학기 기록 > 학기 마감**과 같다.
- 인수/옵션: `{term}` 학기 코드, `--dry-run`(마감할 수 있는지만 확인), `--reason=`(기록에 남길 사유), `--actor=`.
- 감사: 기록 (학생 수, 미확정 강좌 수). 마감이 끝나면 `term.closed` 감사 기록에 학사경고, 제적 검토, 성적우수 인원이 남는다.
- 종료 코드: 확정되지 않은 성적이 있는 강좌가 있으면 2(강좌별 미확정 건수 출력). 공개(published) 상태가 아닌 학기는 1.
- 실행 시점: 성적 입력·확정이 끝난 뒤. 배치 진행은 Horizon에서 본다. 큐 워커가 없으면 학기 상태가 바뀌지 않는다.
- 예시: `php artisan term:close 2026-FA --dry-run`, `php artisan term:close 2026-FA --reason="2026-2 성적 마감" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- 용도: 확정 성적으로 학기 기록(학점, 학기·누적 평점)을 다시 계산한다. 성적 처리 정책(평점 자릿수, 재수강 반영)을 바꾼 뒤 지난 학기에 적용할 때 쓴다. 학업 상태와 성적우수는 학기 마감 때 정한 값을 유지한다. 성적 정정 승인은 그 학생을 자동으로 다시 계산하므로 이 명령이 필요 없다.
- 옵션: `--term=`(그 학기에 성적이 있는 학생을 그 학기부터), `--student-number=`(한 학생), `--reason=`(필수), `--actor=`.
- 감사: 기록 (학생 수, 사유)
- 예시: `php artisan grades:recalculate --term=2026-SP --reason="평점 소수 셋째 자리로 변경"`

### `grades:remind-missing`

- 용도: 아직 성적을 제출하지 않은 강좌(미입력 또는 임시 저장)의 담당 교원에게 안내 메일을 보낸다. 교원별로 강좌를 묶어 한 통씩 보낸다.
- 인수/옵션: `{term}` 학기 코드, `--dry-run`(보내지 않고 대상만 출력), `--actor=`.
- 감사: 기록 (강좌 수, 교원 수, 보낸 수)
- 실행 시점: 성적 입력 기간 마감 며칠 전. 필요하면 스케줄에 등록한다.

## 강의평가

### `evaluation:remind`

- 용도: 강의평가 기간이 열려 있는데 아직 평가하지 않은 과목이 있는 학생에게 안내 메일을 보낸다. 학생마다 남은 과목을 묶어 한 통을 보낸다.
- 인수/옵션: `{term}` 학기 코드, `--dry-run`(보내지 않고 대상 학생 수만), `--actor=`.
- 감사: 기록 (대상 학생 수, 보낸 수)
- 실행 시점: 평가 기간 중 한두 번. 필요하면 스케줄에 등록한다.

### `evaluation:publish-results`

- 용도: 학기 강의평가 결과를 교원에게 공개한다. 관리 화면 **강의평가 > 학기 강의평가 > 결과 공개**와 같다. 공개 후에도 최소 응답 수와 응답률을 채운 강좌만 결과가 보인다.
- 인수/옵션: `{term}` 학기 코드, `--actor=`.
- 감사: 기록 (응답 수, 이미 공개되었는지)
- 실행 시점: 평가 기간과 성적 처리가 끝난 뒤. 이미 공개된 학기는 바꾸지 않는다.

## 증명서

### `certificate:verify`

- 용도: 증명서 확인 코드를 공개 진위 확인 페이지와 같은 기준으로 검사한다. 종류, 발급번호, 발급일, 가려진 명의자를 출력한다.
- 인수/옵션: `{code}` 확인 코드.
- 감사: 없음 (조회)
- 종료 코드: 유효하면 0, 없는 코드·취소·기간 만료면 2.

### `certificate:render`

- 용도: 발급한 증명서의 PDF를 현재 데이터와 서식으로 다시 만들어 보관 파일을 바꾼다. 관리 화면 **발급 대장 > 다시 만들기**와 같다. 발급번호와 확인 코드는 그대로이고 체크섬이 바뀐다.
- 인수/옵션: `{issue}` 발급번호, `--reason=`(필수), `--actor=`.
- 감사: 기록 (발급번호, 새 체크섬)
- 실행 시점: 서식이나 이름 표기를 고친 뒤 특정 증명서를 다시 만들 때.

## 어학/종합시험

### `assessment:import-results`

- 용도: 시험 회차의 결과를 CSV로 입력한다. 관리 화면 **시험 회차 > 결과 가져오기**와 같은 규칙이다(접수한 학생만, 점수로 합격 판정, 공개 전에는 다시 입력하면 교체).
- 인수/옵션: `{type}` 시험 종류 코드 / `{held_date}` 시험일 `YYYY-MM-DD` / `{file}` 머리글 행이 있는 UTF-8 CSV, `--actor=`(필수), `--dry-run`(기록하지 않고 행 검사만).
- 열 형식: [관리자 매뉴얼 24장](../admin/24-assessments.md).
- 감사: 기록 (회차, 파일 이름, 행 수, 입력·결시·오류 수)
- 종료 코드: 오류 행이 있으면 2(나머지 행은 기록됨).
- 예시: `php artisan assessment:import-results ENG_COMP 2026-05-15 storage/app/eng.csv --actor=registrar@example.ac.kr --dry-run`

### `assessment:publish-results`

- 용도: 회차의 결과를 학생에게 공개한다. 관리 화면 **시험 회차 > 결과 공개**와 같다.
- 인수/옵션: `{type}` 시험 종류 코드 / `{held_date}` 시험일, `--actor=`(필수).
- 감사: 기록 (회차, 결과 수)
- 실행 시점: 결과 입력이 끝난 뒤. 이미 공개한 회차는 실패한다.

## 출석

### `attendance:generate-sessions`

- 용도: 학기의 개설강좌마다 강의 시간(요일·시간·기간)으로 수업 회차를 만든다. 교원 포털과 관리 화면의 **회차 생성**과 같다. 이미 있는 회차와 출석은 그대로 둔다(다시 실행해도 안전).
- 인수/옵션: `{term}` 학기 코드, `--section=`(과목코드-분반, 예: `CSE2010-01`, 하나만), `--dry-run`(대상 강좌 수만), `--actor=`.
- 감사: 기록 (학기, 강좌 수, 생성 회차 수)
- 실행 시점: 학기 시작 전 강의 시간 확정 뒤. 강의 시간이 바뀌면 다시 실행한다.

## 졸업

### `degree-audit:run`

- 용도: 재학생마다 졸업 요건 점검을 저장한다. 관리 화면 **졸업 요건 점검 > 점검 실행**과 같다. 저장된 최신 점검이 졸업 처리의 근거가 된다.
- 옵션: `--term=`(점검이 속하는 학기 코드), `--student-number=`(한 명), `--min-year-level=`(이 학년 이상만), `--actor=`.
- 감사: 기록 (학생 수, 충족 수)
- 실행 시점: 졸업 사정 전(학기 말), 요건 세트나 대체과목을 고친 뒤.

## LMS 연동

### `lms:sync`

- 용도: 공개된 개설강좌를 플랫폼으로 밀어넣는다(강좌 생성·연결, 담당 교원, 수강 중인 학생). 관리 화면 **강좌 연결 > 다시 동기화**와 같은 처리를 학기 단위로 한다. 이미 연결된 강좌는 다시 보장만 한다(멱등).
- 인수/옵션: `{platform}` 플랫폼 코드, `--term=`(학기 코드, 기본은 끝나지 않은 학기 전부), `--section=`(과목코드-분반 하나), `--dry-run`(보낼 내용을 "건너뜀"으로 기록만), `--actor=`.
- 감사: 기록 (플랫폼, 강좌 수, 구성원 수, 실패 수)
- 종료 코드: 실패한 강좌가 있으면 2.

### `lms:reconcile`

- 용도: 플랫폼의 강좌 명단과 학사 시스템의 수강 명단을 비교해 빠진 구성원을 추가하고 남은 구성원을 제거한다. 차이는 동기화 기록(`reconcile`)에 남는다.
- 인수/옵션: `{platform?}`(없으면 활성 플랫폼 전부), `--term=`, `--dry-run`(차이만 기록), `--actor=`.
- 감사: 기록 (플랫폼별 강좌 수, 추가·제거·실패 수)
- 실행 시점: 매일 02:30 스케줄. 플랫폼 장애 뒤 수동 실행.

## 개인정보 암호화 키

### `pii:generate-key`

- 용도: `PII_ENCRYPTION_KEY`, `PII_HASH_KEY`에 넣을 새 키를 출력한다. 아무것도 저장하지 않는다.
- 감사: 기록 안 함
- 주의: `PII_HASH_KEY`를 바꾸면 모든 검색 해시가 무효가 된다. 키 교체 절차는 [security-keys.md](security-keys.md).

### `pii:reencrypt`

- 용도: 키 교체 후 이전 키로 암호화된 개인정보를 현재 키로 다시 암호화한다. 큐 배치로 실행한다.
- 인수: 모델 클래스(현재 `App\\Models\\Person\\Person`).
- 옵션: `--chunk=500`, `--dry-run`(이전 키를 쓰는 레코드 수만 셈), `--force`.
- 감사: 기록 (배치 ID, 작업 수 / 미리보기 건수)
- 확인: Horizon(`/horizon`)에서 배치 진행률을 본다. 끝난 뒤 `--dry-run` 결과가 0이면 이전 키를 `PII_PREVIOUS_KEYS`에서 뺀다.

## 다국어

### `i18n:missing`

- 용도: 기준 언어(en) 대비 언어별 누락 키와 더 이상 쓰지 않는 키를 보여 준다.
- 인수/옵션: `{locale?}`(한 언어만), `--strict`(누락이 있으면 종료 코드 2. CI에서 사용).
- 감사: 기록 안 함

### `i18n:export`

- 용도: 번역가에게 줄 JSON 파일을 만든다. 형식: `{"키": {"source": "영문", "translation": "번역"}}`.
- 인수/옵션: `{locale} {path}`, `--missing`(누락 키만).
- 감사: 기록 안 함
- 예시: `php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- 용도: 번역가가 채운 JSON을 `lang/{locale}`에 반영한다. 기준 언어에 있는 키만 가져오고 빈 번역은 무시한다.
- 인수/옵션: `{locale} {path}`, `--dry-run`(쓸 키 목록만 출력).
- 감사: 기록
- 주의: 번역 파일은 저장소에서 관리한다. 가져온 뒤 변경 내용을 커밋한다.

## 점검

### `naming:check`

- 용도: 마이그레이션의 테이블/컬럼 이름을 [명명 규칙](../../conventions/naming.md)으로 검사한다.
- 옵션: `--path=*`(검사할 디렉토리, 기본 `database/migrations`).
- 감사: 기록 안 함
- 종료 코드: 문제가 있으면 2.

### `pdf:sample`

- 용도: 한국어, 중국어, 영어가 섞인 표를 PDF로 렌더링해 글꼴과 PDF 서비스(Gotenberg) 연결을 점검한다.
- 인수: `{path=pdf-sample.pdf}` (로컬 디스크 `storage/app/private` 기준).
- 감사: 기록 안 함
- 실패 시: 연결 오류면 `GOTENBERG_URL`과 Gotenberg 컨테이너 상태를 확인한다.
