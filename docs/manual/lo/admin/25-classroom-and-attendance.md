# 25. ຫ້ອງຮຽນຂອງອາຈານ ແລະ ການເຂົ້າຮຽນ

ເມນູ: ອາຈານໃຊ້ພອດທໍ **ການສອນຂອງຂ້ອຍ > ລາຍຊື່ນັກສຶກສາ ແລະ ການເຂົ້າຮຽນ**, ນັກສຶກສາໃຊ້ພອດທໍ **ການເຂົ້າຮຽນ**. ພະນັກງານໃຊ້ **ຄາບຮຽນ** ຢູ່ລຸ່ມໜ້າ **ຫຼັກສູດ ແລະ ກຸ່ມຮຽນ > ກຸ່ມຮຽນ > ແກ້ໄຂ**.

| ໃຜ | ສິ່ງທີ່ເຮັດໄດ້ |
|---|---|
| ອາຈານຜູ້ສອນ | ລາຍຊື່ນັກສຶກສາ (ລວມຮູບ) ແລະ CSV, PDF ບັນຊີເຂົ້າຮຽນ, ສ້າງ·ເພີ່ມ·ຍົກເລີກຄາບຮຽນ, ປ້ອນການເຂົ້າຮຽນ |
| ພະນັກງານທີ່ມີສິດ `ວາງແຜນກຸ່ມຮຽນ` (ພາຍໃນຂອບເຂດ) | ຄືກັບອາຈານ + ຄາບຮຽນໃນໜ້າບໍລິຫານ |
| ພະນັກງານທີ່ມີສິດ `ເບິ່ງກຸ່ມຮຽນ` (ພາຍໃນຂອບເຂດ) | ເບິ່ງລາຍຊື່ນັກສຶກສາ, ບັນຊີເຂົ້າຮຽນ, ການເຂົ້າຮຽນ |
| ນັກສຶກສາ | ການເຂົ້າຮຽນຂອງຕົນ |

ຟັງຊັນຫ້ອງຮຽນ ເຊັ່ນ ປະກາດ, ວຽກບ້ານ, ເອກະສານ ຍົກໃຫ້ LMS (ແຜນການຍ້າຍລະບົບ ຂໍ້ 12).

## ສິ່ງທີ່ຕ່າງຈາກລະບົບເກົ່າ

- **ລະບົບເກົ່າ (YUSTIC) ບໍ່ໄດ້ບັນທຶກການເຂົ້າຮຽນ.** "ບັນຊີເຂົ້າຮຽນ" ເປັນ PDF ທີ່ພິມລາຍຊື່ນັກສຶກສາພ້ອມຊ່ອງວ່າງ (27~34 ຊ່ອງ ຕ່າງກັນໄປຕາມສຳເນົາ) ບໍ່ມີວັນທີ ແລະ ບໍ່ມີການສະຫຼຸບ. ລະບົບໃໝ່ສ້າງ **ຄາບຮຽນ** ຈາກເວລາຮຽນ ບັນທຶກ ມາຮຽນ·ມາຊ້າ·ຂາດ·ລາ ໃນທຸກຄາບ ແລະ ພິມບັນທຶກ ແລະ ຜົນລວມໃນ PDF ບັນຊີເຂົ້າຮຽນ.
- **ລາຍຊື່ນັກສຶກສາ.** ໜ້າຈໍອາຈານຂອງລະບົບເກົ່າສະແດງພຽງລະຫັດນັກສຶກສາ·ຊື່ (ແຕ່ປັອບອັບເປີດເຜີຍເຖິງເລກປະຈຳຕົວ·ທີ່ຢູ່) ແລະ ບໍ່ມີການດາວໂຫຼດ Excel. ລະບົບໃໝ່ສະແດງສະເພາະລະຫັດນັກສຶກສາ, ຊື່, ຮູບ, ຫຼັກສູດ, ປີຮຽນ, ອີເມວຕິດຕໍ່ ແລະ ດາວໂຫຼດເປັນ CSV. ການດາວໂຫຼດຖືກບັນທຶກໃນບັນທຶກການກວດສອບ.
- **ສິດເບິ່ງນັກສຶກສາຂອງອາຈານ.** ເພີ່ມນະໂຍບາຍ RLS ເພື່ອໃຫ້ອາຈານເບິ່ງບັນທຶກນັກສຶກສາ·ບຸກຄົນຂອງນັກສຶກສາໃນກຸ່ມຮຽນທີ່ຕົນສອນໄດ້ (ກ່ອນໜ້ານີ້ເຫັນສະເພາະນັກສຶກສາທີ່ປຶກສາ ຈຶ່ງມີຂໍ້ບົກພ່ອງທີ່ຊື່ວ່າງໃນໜ້າປ້ອນເກຣດ).

## ຄາບຮຽນ

- **ສ້າງ**: ສ້າງຄາບຮຽນໜຶ່ງຄາບຕໍ່ວັນຂອງເວລາຮຽນ (ວັນ·ເວລາ·ໄລຍະເວລາ). ອາຈານໃຊ້ປຸ່ມ **ສ້າງຈາກເວລາຮຽນ**, ພະນັກງານໃຊ້ **ຄາບຮຽນ > ສ້າງຄາບຮຽນ** ໃນໜ້າບໍລິຫານ ຫຼື ຄຳສັ່ງ `attendance:generate-sessions {ພາກຮຽນ}` (ທັງພາກຮຽນ). ຄາບຮຽນ ແລະ ການເຂົ້າຮຽນທີ່ມີຢູ່ແລ້ວຈະຄົງໄວ້ ຈຶ່ງແລ່ນອີກຄັ້ງຫຼັງແກ້ໄຂເວລາຮຽນໄດ້.
- **ເພີ່ມ**: ຄາບນອກເວລາຮຽນ ເຊັ່ນ ການສອນຊົດເຊີຍ. ສະເພາະວັນທີພາຍໃນໄລຍະເວລາຂອງຊ່ວງຮຽນ (ຊ່ວງຍ່ອຍຂອງພາກຮຽນ).
- **ຍົກເລີກ**: ໃສ່ເຫດຜົນແລ້ວຍົກເລີກຄາບ. ຄາບຍັງຄົງຢູ່ ແຕ່ບໍ່ນັບໃນການສະຫຼຸບ. ກູ້ຄືນດ້ວຍ **ກູ້ຄືນ**.
- ບໍ່ມີປະຕິທິນວັນພັກລັດຖະການ. ຄາບຮຽນທີ່ຕົກວັນພັກ ໃຫ້ຍົກເລີກ (ເບິ່ງຂໍ້ 13.2 ເມື່ອມີປະຕິທິນພາກຮຽນໃນອະນາຄົດ ຈະເປັນອັດຕະໂນມັດ).

## ການປ້ອນການເຂົ້າຮຽນ

ທີ່ **ການເຂົ້າຮຽນ** ຂອງຄາບ ເລືອກ ມາຮຽນ/ມາຊ້າ/ຂາດ/ລາ ຕໍ່ນັກສຶກສາ ແລະ ໃສ່ໝາຍເຫດ (200 ຕົວອັກສອນ). ວິທີທີ່ໄວຄືກົດ **ມາຮຽນທັງໝົດ** ແລ້ວປ່ຽນສະເພາະຂໍ້ຍົກເວັ້ນ.

- ປ້ອນໄດ້ຕັ້ງແຕ່ມື້ຮຽນເປັນຕົ້ນໄປ (ຄາບໃນອະນາຄົດບໍ່ໄດ້).
- ຖ້າບັນທຶກອີກຄັ້ງ ຈະບັນທຶກສະເພາະນັກສຶກສາທີ່ປ່ຽນ ແລະ ບັນທຶກການກວດສອບ (`attendance.recorded`) ຈະມີຄ່າເກົ່າ ແລະ ຄ່າໃໝ່.
- ຖ້າປ່ອຍສະຖານະວ່າງ ຈະກັບໄປເປັນ "ບໍ່ໄດ້ບັນທຶກ".

## ການສະຫຼຸບ

| ລາຍການ | ນິຍາມ |
|---|---|
| ຄາບທີ່ດຳເນີນແລ້ວ | ຄາບທີ່ບໍ່ຖືກຍົກເລີກ ແລະ ຢູ່ກ່ອນມື້ນີ້ (ລວມມື້ນີ້) |
| ອັດຕາການເຂົ້າຮຽນ | (ມາຮຽນ + ມາຊ້າ + ລາ) ÷ ຄາບທີ່ດຳເນີນແລ້ວ × 100 |
| ບໍ່ໄດ້ບັນທຶກ | ຈຳນວນຄາບທີ່ດຳເນີນແລ້ວທີ່ບໍ່ມີບັນທຶກ |

ບໍ່ມີກົດທີ່ແປງການມາຊ້າຈຳນວນໜຶ່ງເປັນການຂາດ ຫຼື ໃຫ້ F ເມື່ອຂາດເກີນ 1/3. ເພາະແຕ່ລະມະຫາວິທະຍາໄລຕ່າງກັນ ອາຈານຈຶ່ງນຳໄປສະທ້ອນໃນເກຣດເອງ (ຂໍ້ພິຈາລະນາ 13.5).

## PDF ບັນຊີເຂົ້າຮຽນ ແລະ CSV ລາຍຊື່ນັກສຶກສາ

ການດາວໂຫຼດທັງສອງຖືກບັນທຶກໃນບັນທຶກການກວດສອບ (`attendance.sheet_exported`, CSV ລາຍຊື່ນັກສຶກສາຄືເດີມ). ຄ່າໃນ CSV ທີ່ຂຶ້ນຕົ້ນດ້ວຍ `=`, `+`, `-`, `@` ຈະຖືກໃສ່ເຄື່ອງໝາຍວົງຢືມດ່ຽວນຳໜ້າເພື່ອບໍ່ໃຫ້ຖືກແລ່ນເປັນສູດ.

- **ບັນຊີເຂົ້າຮຽນ (PDF)**: A4 ແນວນອນ. ນັກສຶກສາຕາມແນວຕັ້ງ ຄາບຮຽນຕາມແນວນອນ (ບໍ່ລວມຄາບທີ່ຍົກເລີກ) ເຄື່ອງໝາຍ O/△/X/E ແລະ ຜົນລວມຕໍ່ນັກສຶກສາ. ຄາບທີ່ຍັງບໍ່ມາເຖິງເປັນຊ່ອງວ່າງ ຈຶ່ງໃຊ້ສຳລັບບັນທຶກດ້ວຍມືໄດ້.
- **ລາຍຊື່ນັກສຶກສາ (CSV)**: ລະຫັດນັກສຶກສາ, ຊື່, ຫຼັກສູດ, ປີຮຽນ, ອີເມວຕິດຕໍ່, ສະຖານະການລົງທະບຽນ. ເປັນ UTF-8 (BOM) ຈຶ່ງເປີດໃນ Excel ໄດ້ທັນທີ. ທຸກການດາວໂຫຼດບັນທຶກການກວດສອບ `attendance.roster_exported`.

## ພອດທໍຂອງນັກສຶກສາ

**ການເຂົ້າຮຽນ**: ຈຳນວນ ມາຮຽນ·ມາຊ້າ·ຂາດ·ລາ ແລະ ອັດຕາການເຂົ້າຮຽນຂອງວິຊາທີ່ລົງທະບຽນຕາມພາກຮຽນ, ບັນທຶກຕໍ່ຄາບ (ສະເພາະທີ່ອາຈານປ້ອນແລ້ວ).

## ຂັ້ນຕອນການດຳເນີນງານ

1. ກ່ອນພາກຮຽນເລີ່ມ ຢືນຢັນເວລາຮຽນຂອງກຸ່ມຮຽນ ([ບົດທີ 18](18-sections-and-timetables.md)).
2. ສ້າງຄາບຮຽນດ້ວຍ `php artisan attendance:generate-sessions {ພາກຮຽນ} --actor=...` (ອາຈານສ້າງເອງໃນໜ້າຈໍກໍໄດ້).
3. ຖ້າເວລາຮຽນປ່ຽນ ໃຫ້ແລ່ນອີກຄັ້ງ. ຄາບຂອງເວລາທີ່ຖືກລຶບບໍ່ຖືກລຶບອັດຕະໂນມັດ ຈຶ່ງຕ້ອງຍົກເລີກເອງ.
