# ເອກະສານອ້າງອີງຄຳສັ່ງ Artisan

- ກຸ່ມເປົ້າໝາຍ: ຜູ້ປະຕິບັດງານ IT
- ຂອບເຂດ: ຄຳສັ່ງຂອງແອັບພລິເຄຊັນທັງໝົດທີ່ລົງທະບຽນໃນ repository ນີ້. ເມື່ອເພີ່ມຄຳສັ່ງ ຕ້ອງເພີ່ມໃສ່ເອກະສານນີ້ດ້ວຍ CI ຈຶ່ງຜ່ານ (`tests/Feature/Tooling/CommandDocumentationTest.php`).

## ຂໍ້ມູນທົ່ວໄປ

ທຸກຄຳສັ່ງແລ່ນດ້ວຍ `php artisan {ຄຳສັ່ງ}`. ໃນສະພາບແວດລ້ອມພັດທະນາໃຊ້ `./vendor/bin/sail artisan {ຄຳສັ່ງ}`.

| ລາຍການ | ກົດລະບຽບ |
|---|---|
| ບັນທຶກການກວດສອບ | ຄຳສັ່ງທີ່ປ່ຽນຂໍ້ມູນ ("ການກວດສອບ: ບັນທຶກ" ຂ້າງລຸ່ມ) ຈະບັນທຶກຄຳສັ່ງ, ອາກິວເມັນ, ຕົວເລືອກ, ຜູ້ໃຊ້ OS, ລະຫັດອອກ ແລະ ຜົນລົງບັນທຶກການກວດສອບທາງທຸລະກິດ (log `command`) ທຸກຄັ້ງທີ່ແລ່ນ. ກວດທີ່ **ການກວດສອບ > ບັນທຶກການກວດສອບທາງທຸລະກິດ** ໃນໜ້າບໍລິຫານ |
| ID ການແລ່ນ | ທຸກຄັ້ງທີ່ແລ່ນ ID ທີ່ຂຶ້ນຕົ້ນດ້ວຍ `cmd-` ຈະຖືກໃສ່ແທນທີ່ ID ຄຳຮ້ອງຂໍ. ບັນທຶກການກວດສອບທາງທຸລະກິດ, ບັນທຶກການປ່ຽນແປງຂໍ້ມູນທີ່ການແລ່ນນັ້ນປ່ຽນ ແລະ ວຽກໃນຄິວທີ່ການແລ່ນນັ້ນໃສ່ເຂົ້າ ມີ ID ດຽວກັນ ດັ່ງນັ້ນຈຶ່ງຄົ້ນຫາ "ການປ່ຽນແປງນີ້ມາຈາກຄຳສັ່ງໃດ" ດ້ວຍ ID ໄດ້. `--actor` ເປັນຄ່າທີ່ຜູ້ແລ່ນຂຽນເອງ ຈຶ່ງບໍ່ໃສ່ໃນຊ່ອງຜູ້ໃຊ້ຂອງບັນທຶກການປ່ຽນແປງຂໍ້ມູນ (ຜູ້ແລ່ນຕົວຈິງຄືຜູ້ໃຊ້ OS) |
| `--actor=<ອີເມວ>` | ມີຢູ່ທົ່ວໄປໃນຄຳສັ່ງທີ່ບັນທຶກການກວດສອບ. ບັນທຶກບັນຊີຜູ້ບໍລິຫານທີ່ຮັບຜິດຊອບ. ຖ້າເປັນອີເມວທີ່ບໍ່ມີຢູ່ ຈະບໍ່ແລ່ນ |
| `--dry-run` | ສະແດງສະເພາະຜົນໂດຍບໍ່ປ່ຽນແປງຫຍັງ. ມີຢູ່ໃນວຽກທີ່ຍ້ອນກັບຍາກ |
| `--force` | ແລ່ນໂດຍບໍ່ຖາມຢືນຢັນ (ສຳລັບວຽກຕາມກຳນົດເວລາ ແລະ ສະຄຣິບນຳໃຊ້ລະບົບ) |
| `--reason=` | ມີຢູ່ໃນຄຳສັ່ງທີ່ຕ້ອງການເຫດຜົນ |
| ລະຫັດອອກ | 0 ສຳເລັດ, 1 ລົ້ມເຫຼວ ຫຼື ຍົກເລີກ, 2 ຄຳສັ່ງກວດກາພົບບັນຫາ |
| ບໍລິບົດ DB | ໃນຂະນະແລ່ນ ຜູ້ປະຕິບັດຂອງເຊສຊັນ DB ຖືກຕັ້ງເປັນ `system:command:{ຄຳສັ່ງ}` ແລະ ຖືກບັນທຶກໃນບັນທຶກການປ່ຽນແປງຂໍ້ມູນ (trigger) |

## ການຕິດຕັ້ງ ແລະ ເດໂມ

### `setup:install`

- ການນຳໃຊ້: ການຕິດຕັ້ງໃໝ່ ແລະ ການອັບເດດ. ດຳເນີນ migration, ຂໍ້ມູນຈຳເປັນ, ການຕັ້ງຄ່າພື້ນຖານຂອງສະຖາບັນ, ໂປຣໄຟລ໌ການຕິດຕັ້ງ ແລະ ຜູ້ບໍລິຫານຄົນທຳອິດຕາມລຳດັບ. ແລ່ນຊ້ຳໄດ້ຢ່າງປອດໄພ (ຂໍ້ມູນທີ່ມີຢູ່ແລ້ວ ແລະ ຄ່າທີ່ຜູ້ບໍລິຫານປ່ຽນແລ້ວຈະຖືກຮັກສາໄວ້).
- ເວລາແລ່ນ: ການຕິດຕັ້ງຄັ້ງທຳອິດ ແລະ ທຸກຄັ້ງທີ່ນຳໃຊ້ລະບົບ.
- ຕົວເລືອກ: `--institution-name=`, `--locale=` (ພາສາເລີ່ມຕົ້ນ), `--timezone=` (ຕົວຢ່າງ: `Asia/Seoul`), `--profile=*` (ກະແຈໂປຣໄຟລ໌ການຕິດຕັ້ງ), `--grade-scale=` (ມາດຕາເກຣດ `4.5` ຫຼື `4.3`. ກຳນົດແລ້ວປ່ຽນບໍ່ໄດ້. ຖ້າປະວ່າງ ຈະໃຊ້ມາດຕາຂອງໂປຣໄຟລ໌ທຳອິດ), `--admin-email=`, `--admin-name=`, `--force` (ແລ່ນໂດຍບໍ່ຖາມ. ລະຫັດຜ່ານຜູ້ບໍລິຫານຮັບຈາກ standard input).
- ການກວດສອບ: ບັນທຶກ
- ຕົວຢ່າງ

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="데모대학교" --admin-email=admin@example.ac.kr --admin-name="관리자"
  ```

- ການອ່ານຜົນອອກ: `DONE`/`FAIL` ຕໍ່ຂັ້ນຕອນ. `Administrator exists` ໝາຍວ່າມີການມອບບົດບາດຜູ້ບໍລິຫານລະບົບຢູ່ແລ້ວ ຈຶ່ງຂ້າມການສ້າງ.
- ເມື່ອລົ້ມເຫຼວ: ຖ້າເປັນຂໍ້ຜິດພາດວ່າບໍ່ມີກະແຈ ໃຫ້ໃສ່ຄ່າທີ່ສ້າງດ້ວຍ `key:generate`, `pii:generate-key` ໃນການຕັ້ງຄ່າສະພາບແວດລ້ອມ. ຖ້າ migration ລົ້ມເຫຼວ ໃຫ້ກວດການກຽມບົດບາດ DB (ຄູ່ມືການຕິດຕັ້ງ).

### `setup:demo`

- ການນຳໃຊ້: ສ້າງຂໍ້ມູນມະຫາວິທະຍາໄລສົມມຸດດ້ວຍ factory. ສະແດງບັນຊີເດໂມຄົງທີ່ຕໍ່ບົດບາດ (`registrar@demo.test` ແລະ ອື່ນໆ).
- ເວລາແລ່ນ: ສະພາບແວດລ້ອມພັດທະນາ, ຝຶກອົບຮົມ ແລະ ສາທິດ. **ໃນສະພາບແວດລ້ອມນຳໃຊ້ຈິງ (`APP_ENV=production`) ຈະບໍ່ແລ່ນ ເຖິງວ່າຈະໃສ່ `--force` ກໍຕາມ.**
- ຕົວເລືອກ: `--size=tiny|small|medium|large` (ນັກສຶກສາປະມານ 20/100/2,000/20,000 ຄົນ. `tiny` ສຳລັບການທົດສອບ ແລະ ການກວດແບບໄວ), `--seed=` (ຄ່າດຽວກັນໃຫ້ຂໍ້ມູນດຽວກັນ), `--force`.
- `--student-accounts`: ສ້າງບັນຊີໃຫ້ນັກສຶກສາປັດຈຸບັນທຸກຄົນ (`student{ລະຫັດນັກສຶກສາ}@demo.test`, ລະຫັດຜ່ານເດໂມ) ແລະ ຂຽນລົງ `storage/app/private/load-accounts.csv`. ສຳລັບການທົດສອບພາລະ ([ການທົດສອບພາລະ](load-testing.md)).
- ການກວດສອບ: ບັນທຶກ
- ຕົວຢ່າງ: `php artisan setup:demo --size=small --seed=42`
- ເມື່ອລົ້ມເຫຼວ: ຖ້າບໍ່ມີຂໍ້ມູນຈຳເປັນ ບັນຊີເດໂມຈະບໍ່ມີບົດບາດ ຈຶ່ງຖືກຂ້າມ. ແລ່ນ `setup:install` ກ່ອນ.

## ຂໍ້ມູນອ້າງອີງ ແລະ ພາກຮຽນ

### `reference:import`

- ການນຳໃຊ້: ນຳເຂົ້າຂໍ້ມູນອ້າງອີງຈາກ CSV. ໃຊ້ກົດລະບຽບການນຳເຂົ້າດຽວກັນກັບ **ການນຳເຂົ້າ CSV** ໃນໜ້າບໍລິຫານ (ຄົ້ນຫາແຖວເດີມດ້ວຍລະຫັດແລ້ວອັບເດດ, ຊ່ອງຄຳແປທີ່ວ່າງຮັກສາຄ່າເດີມ, ບັນທຶກສະເພາະແຖວທີ່ລົ້ມເຫຼວແຍກຕ່າງຫາກ).
- ອາກິວເມັນ: `{type}` `org_units`, `programs`, `buildings`, `rooms`, `lookup_values`, `students`, `instructors`, `courses`, `registration_holds` / `{file}` CSV ແບບ UTF-8 ທີ່ມີແຖວຫົວ.
- ຕົວເລືອກ: `--actor=` (ຈຳເປັນ. ບັນທຶກການນຳເຂົ້າ ແລະ ການແຈ້ງເຕືອນເມື່ອສຳເລັດຈະໄປຫາບັນຊີນີ້), `--chunk=100` (ຈຳນວນແຖວຕໍ່ວຽກໃນຄິວ), `--dry-run` (ກວດແຖວຫົວ ແລະ ນັບແຖວເທົ່ານັ້ນ).
- ການກວດສອບ: ບັນທຶກ (ປະເພດ, ຊື່ໄຟລ໌, ຈຳນວນແຖວ, ຈຳນວນແຖວທີ່ລົ້ມເຫຼວ)
- ຮູບແບບຖັນ: [ຄູ່ມືຜູ້ບໍລິຫານ ບົດທີ 9](../admin/09-csv-import.md).
- ລະຫັດອອກ: ຖ້າຄິວແລ່ນແບບ synchronous ຈະສະແດງຜົນທັນທີ ແລະ ຖ້າມີແຖວທີ່ລົ້ມເຫຼວຈະເປັນ 2. ຖ້າເປັນ asynchronous (Horizon) ຈະຮັບວຽກໄວ້ເທົ່ານັ້ນ ແລະ ເປັນ 0. ຮັບຜົນເປັນ CSV ຂອງແຖວທີ່ລົ້ມເຫຼວຈາກການແຈ້ງເຕືອນໃນໜ້າບໍລິຫານຂອງບັນຊີ `--actor`.
- ຕົວຢ່າງ: `php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- ການນຳໃຊ້: ສະແດງພາກຮຽນທີ່ກຳລັງມີການຮຽນການສອນ ແລະ ໄລຍະທຸລະກິດທີ່ເປີດຢູ່ (ປະເພດ, ພາກຮຽນ, ເງື່ອນໄຂເປົ້າໝາຍ, ເວລາສິ້ນສຸດ) ໃນເວລາທີ່ລະບຸ. ໃຊ້ເພື່ອກວດການຕັ້ງຄ່າພາກຮຽນ ແລະ ໄລຍະທຸລະກິດ ຫຼື ຕອບຄຳຖາມເຊັ່ນ "ເປັນຫຍັງການລົງທະບຽນຮຽນຈຶ່ງບໍ່ເປີດ".
- ຕົວເລືອກ: `--at=` (ຄ່າເລີ່ມຕົ້ນຄືປັດຈຸບັນ. ຕົວຢ່າງ: `"2027-02-15 09:00"`. ຖ້າບໍ່ໃສ່ເຂດເວລາ ຈະຕີຄວາມຕາມເຂດເວລາຂອງເຊີບເວີ (UTC). ສາມາດລະບຸໄດ້ເຊັ່ນ `"2027-02-15 09:00 Asia/Seoul"`).
- ການກວດສອບ: ບໍ່ບັນທຶກ
- ການອ່ານຜົນອອກ: ການຕັດສິນວັນທີອ້າງອີງຕາມເຂດເວລາຂອງສະຖາບັນ. ໄລຍະທຸລະກິດຂອງພາກຮຽນທີ່ຢູ່ໃນສະຖານະວາງແຜນ (planned) ຫຼື ເກັບຖາວອນ (archived) ຈະບໍ່ເປີດ.

## ຄວາມປອດໄພ

### `security:create-administrator`

- ການນຳໃຊ້: ສ້າງບັນຊີທີ່ມີບົດບາດຜູ້ບໍລິຫານລະບົບ. ໂດຍປົກກະຕິ `setup:install` ເປັນຜູ້ເອີ້ນ.
- ຕົວເລືອກ: `--email=`, `--name=`, `--password-stdin` (ລະຫັດຜ່ານຈາກ standard input. ຈຳເປັນເມື່ອແລ່ນແບບບໍ່ໂຕ້ຕອບ).
- ການກວດສອບ: ບັນທຶກ (ID ຜູ້ໃຊ້ທີ່ສ້າງ)
- ຕົວຢ່າງ: `php artisan security:create-administrator --email=admin@example.ac.kr --name="관리자"`
- ເມື່ອລົ້ມເຫຼວ: ຖ້າເປັນ `system_administrator role is missing` ໃຫ້ແລ່ນ `setup:install` ຫຼື `db:seed` ກ່ອນ. ລະຫັດຜ່ານຕ້ອງມີຢ່າງໜ້ອຍ 12 ຕົວອັກສອນ.

### `security:sync-permissions`

- ການນຳໃຊ້: ເຮັດໃຫ້ລາຍການສິດໃນໂຄດ ແລະ ລາຍການສິດໃນ DB ກົງກັນ. ສິດໃໝ່ຈະຖືກສ້າງ ແລະ ສິດທີ່ຫາຍໄປຈາກລາຍການຈະຖືກລຶບ (ຖືກເອົາອອກຈາກທຸກບົດບາດ). ບົດບາດຂອງລະບົບຈະໄດ້ຮັບທຸກສິດສະເໝີ.
- ເວລາແລ່ນ: ຫຼັງການນຳໃຊ້ລະບົບ (`setup:install` ຈັດການໃຫ້ພ້ອມໃນຂັ້ນຕອນຂໍ້ມູນຈຳເປັນ).
- ຕົວເລືອກ: `--dry-run` (ສະແດງສະເພາະລາຍການສ້າງ/ລຶບ), `--force` (ຂ້າມການຢືນຢັນການລຶບ).
- ການກວດສອບ: ບັນທຶກ (ສິດທີ່ສ້າງ/ລຶບ)
- ການອ່ານຜົນອອກ: ແຖວ `create`, `delete`. ຖ້າມີການລຶບ ຈະມີຄຳຖາມຢືນຢັນ.
- ເມື່ອລົ້ມເຫຼວ: ຖ້າຕອບ "ບໍ່" ຕໍ່ຄຳຖາມຢືນຢັນ ຈະອອກດ້ວຍລະຫັດ 1 ໂດຍບໍ່ປ່ຽນແປງຫຍັງ.

### `security:reset-mfa`

- ການນຳໃຊ້: ຕັ້ງຄ່າໃໝ່ການຢືນຢັນສອງຂັ້ນຕອນຂອງຜູ້ໃຊ້ (ແອັບຢືນຢັນ, ລະຫັດອີເມວ, ລະຫັດກູ້ຄືນ, ອຸປະກອນທີ່ຈື່ໄວ້). ຜູ້ໃຊ້ຈະລົງທະບຽນໃໝ່ເມື່ອເຂົ້າສູ່ລະບົບຄັ້ງຕໍ່ໄປ. ໃຊ້ເມື່ອບໍ່ມີຜູ້ບໍລິຫານຄົນໃດເຂົ້າໜ້າບໍລິຫານໄດ້ (ຕົວຢ່າງ: ຜູ້ບໍລິຫານຄົນດຽວເຮັດໂທລະສັບເສຍ). ກໍລະນີອື່ນໃຫ້ໃຊ້ **ຜູ້ໃຊ້ > ຕັ້ງຄ່າໃໝ່ການຢືນຢັນສອງຂັ້ນຕອນ** ໃນໜ້າບໍລິຫານ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{user}` ອີເມວຜູ້ໃຊ້, `--reason=` (ຈຳເປັນ), `--actor=` (ຈຳເປັນ. ຜູ້ບໍລິຫານທີ່ຕັດສິນໃຈຕັ້ງຄ່າໃໝ່).
- ການກວດສອບ: ບັນທຶກ (ທັງບັນທຶກການກວດສອບທາງທຸລະກິດ ແລະ log ຄວາມປອດໄພ ພ້ອມເຫດຜົນ)
- ຕົວຢ່າງ: `php artisan security:reset-mfa admin@example.ac.kr --reason="휴대폰 분실, 본인 확인 완료(전화)" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- ການນຳໃຊ້: ປົດລັອກບັນຊີທີ່ຖືກລັອກຍ້ອນໃສ່ລະຫັດຜ່ານຜິດຕິດຕໍ່ກັນ ກ່ອນເວລາລັອກຈະໝົດ. ຄືກັນກັບ **ຜູ້ໃຊ້ > ປົດລັອກການເຂົ້າສູ່ລະບົບ** ໃນໜ້າບໍລິຫານ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{user}` ອີເມວຜູ້ໃຊ້, `--reason=` (ຈຳເປັນ).
- ການກວດສອບ: ບັນທຶກ (ບັນທຶກໃນ log ຄວາມປອດໄພດ້ວຍ)
- ການອ່ານຜົນອອກ: ຖ້າເປັນ `The account is not locked.` ໝາຍວ່າບໍ່ໄດ້ປ່ຽນແປງຫຍັງ.
- ໝາຍເຫດ: ເກນການລັອກ (ຈຳນວນຄັ້ງທີ່ລົ້ມເຫຼວ, ເວລາລັອກ) ກຳນົດທີ່ **ການຕັ້ງຄ່າ > ວິທີເຂົ້າສູ່ລະບົບ** ໃນໜ້າບໍລິຫານ.

## ບຸກຄົນ ແລະ ບັນທຶກນັກສຶກສາ

### `people:find-duplicates`

- ການນຳໃຊ້: ສະແດງລາຍຊື່ບຸກຄົນທີ່ເບິ່ງຄືວ່າເປັນຄົນດຽວກັນ. ເກນຄືເລກບັດປະຈຳຕົວ (ແຮດຊ໌ຄົ້ນຫາ) ກົງກັນ ຫຼື ຊື່ເປັນຕົວອັກສອນລາຕິນ ແລະ ວັນເດືອນປີເກີດກົງກັນ. ບໍ່ລວມບຸກຄົນທີ່ຖືກລວມແລ້ວ.
- ຕົວເລືອກ: `--limit=100` (ຈຳນວນກຸ່ມທີ່ສະແດງ).
- ການກວດສອບ: ບໍ່ບັນທຶກ (ອ່ານເທົ່ານັ້ນ)
- ລະຫັດອອກ: 2 ຖ້າມີຜູ້ສົງໄສວ່າຊ້ຳກັນ.
- ການດຳເນີນການຕໍ່: ກວດແຕ່ລະກຸ່ມທີ່ **ບຸກຄົນ** ໃນໜ້າບໍລິຫານ ແລະ ຖ້າເປັນຄົນດຽວກັນ ໃຫ້ແລ່ນ **ລວມບຸກຄົນທີ່ຊ້ຳກັນ** ຈາກໜ້າຂອງບຸກຄົນທີ່ຈະເກັບໄວ້. ການລວມຍ້ອນກັບບໍ່ໄດ້ ([ຄູ່ມືຜູ້ບໍລິຫານ ບົດທີ 14](../admin/14-merge-and-invitations.md)).

## ການຮັບເຂົ້າຮຽນ

### `admission:matriculate`

- ການນຳໃຊ້: ສ້າງບັນທຶກນັກສຶກສາ (ລະຫັດນັກສຶກສາໃໝ່) ໃຫ້ຜູ້ສະໝັກທີ່ຢືນຢັນການລົງທະບຽນແລ້ວຂອງຮອບຮັບສະໝັກ. ຄືກັນກັບ **ສ້າງບັນທຶກນັກສຶກສາ** ແບບກຸ່ມທີ່ **ການຮັບເຂົ້າຮຽນ > ໃບສະໝັກ** ໃນໜ້າບໍລິຫານ. ປະມວນຜົນຜູ້ສະໝັກແຕ່ລະຄົນແຍກກັນ ດັ່ງນັ້ນເຖິງວ່າຄົນໜຶ່ງຈະລົ້ມເຫຼວ ຄົນອື່ນກໍດຳເນີນຕໍ່.
- ອາກິວເມັນ/ຕົວເລືອກ: `{cycle}` ລະຫັດຮອບຮັບສະໝັກ, `--term=` (ຈຳເປັນ. ລະຫັດພາກຮຽນເຂົ້າຮຽນ ຕົວຢ່າງ: `2027-SP`. ວັນເຂົ້າຮຽນຄືມື້ທຳອິດຂອງພາກຮຽນ), `--actor=` (ຈຳເປັນ. ບັນຊີທີ່ມີສິດ `ສ້າງບັນທຶກນັກສຶກສາຂອງຜູ້ຖືກຮັບ`. ປະມວນຜົນສະເພາະຜູ້ສະໝັກທີ່ຢູ່ໃນຂອບເຂດສິດຂອງບັນຊີນັ້ນ), `--dry-run` (ສະແດງລາຍຊື່ເປົ້າໝາຍເທົ່ານັ້ນ).
- ການກວດສອບ: ບັນທຶກ (ຮອບ, ພາກຮຽນ, ຈຳນວນເປົ້າໝາຍ, ຈຳນວນທີ່ສ້າງ, ເລກປະຈຳຕົວຜູ້ສອບທີ່ລົ້ມເຫຼວ). ບັນທຶກການກວດສອບທາງທຸລະກິດ (`application.matriculated`) ຕໍ່ຜູ້ສະໝັກກໍຖືກບັນທຶກເຊັ່ນກັນ.
- ລະຫັດອອກ: 2 ຖ້າມີຜູ້ສະໝັກທີ່ລົ້ມເຫຼວ.
- ຕົວຢ່າງ: `php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- ເມື່ອລົ້ມເຫຼວ: `not ready` ໝາຍວ່າມີບັນທຶກນັກສຶກສາຢູ່ແລ້ວ ຫຼື ບໍ່ຢູ່ໃນສະຖານະຢືນຢັນການລົງທະບຽນ ສ່ວນ `program is not in effect` ໝາຍວ່າຫຼັກສູດບໍ່ມີຜົນໃນວັນເຂົ້າຮຽນ (ກວດໄລຍະນຳໃຊ້ທີ່ ຂໍ້ມູນອ້າງອີງ > ຫຼັກສູດ).

### `admission:expire-drafts`

- ການນຳໃຊ້: ປ່ຽນໃບສະໝັກທີ່ຍັງຮ່າງຢູ່ຂອງຮອບທີ່ປິດແລ້ວ ແລະ ໃບສະໝັກທີ່ຍັງຮ່າງຢູ່ທີ່ບໍ່ໄດ້ແກ້ໄຂຕະຫຼອດໄລຍະທີ່ຕັ້ງໄວ້ (**ການຕັ້ງຄ່າ > ການຮັບເຂົ້າຮຽນ > ໝົດອາຍຸໃບສະໝັກທີ່ຍັງຮ່າງຢູ່** ຄ່າເລີ່ມຕົ້ນ 90 ວັນ) ໃຫ້ເປັນ **ໝົດກຳນົດ**. ໃບສະໝັກທີ່ໝົດອາຍຸຈະບໍ່ຂັດຂວາງການສະໝັກໃໝ່ໃນຮອບດຽວກັນ.
- ເວລາແລ່ນ: ຕາມກຳນົດເວລາ (ທຸກວັນ 03:10, [ວຽກຕາມກຳນົດເວລາ](scheduled-jobs.md)).
- ຕົວເລືອກ: `--dry-run` (ຈຳນວນເປົ້າໝາຍເທົ່ານັ້ນ).
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນທີ່ໝົດອາຍຸ)

## ກຸ່ມຮຽນ

### `section:copy`

- ການນຳໃຊ້: ເລີ່ມການຈັດກຸ່ມຮຽນຂອງພາກຮຽນໃໝ່ຈາກກຸ່ມຮຽນຂອງພາກຮຽນກ່ອນ. ຄືກັນກັບ **ກຸ່ມຮຽນ > ສຳເນົາຈາກພາກຮຽນອື່ນ** ໃນໜ້າບໍລິຫານ. ສຳເນົາກຸ່ມຮຽນທີ່ບໍ່ຖືກຍົກເລີກໃນສະຖານະຮ່າງ ພ້ອມກັບອາຈານຜູ້ສອນ (ຖ້າຍັງເຮັດວຽກຢູ່), ເວລາສອນ ແລະ ຫ້ອງຮຽນ, ການຈັດສັນບ່ອນນັ່ງ (ເວລາປ່ຽນເລື່ອນຕາມຄວາມຕ່າງຂອງວັນເລີ່ມພາກຮຽນ) ແລະ ແຜນການສອນ (ຮ່າງທີ່ບໍ່ເປີດເຜີຍ). ເວີຊັນວິຊາຈະປ່ຽນເປັນເວີຊັນທີ່ມີຜົນໃນວັນເລີ່ມເຊສຊັນໃໝ່.
- ອາກິວເມັນ/ຕົວເລືອກ: `{from-term}`, `{to-term}` ລະຫັດພາກຮຽນ (ຕົວຢ່າງ: `2026-FA`), `--org-unit=*` (ສະເພາະກຸ່ມຮຽນຂອງລະຫັດໜ່ວຍງານນີ້), `--dry-run` (ສະແດງຜົນໂດຍບໍ່ບັນທຶກ), `--actor=` (ຈຳເປັນ. ສຳເນົາສະເພາະກຸ່ມຮຽນໃນຂອບເຂດສິດ `ຈັດກຸ່ມຮຽນ` ຂອງບັນຊີນັ້ນ).
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນທີ່ສຳເນົາ, ຂ້າມ ແລະ ຕ້ອງກວດ)
- ການອ່ານຜົນອອກ: `skipped` ຄືກຸ່ມຮຽນທີ່ມີກຸ່ມດຽວກັນຢູ່ແລ້ວໃນພາກຮຽນເປົ້າໝາຍ ຫຼື ບໍ່ມີເວີຊັນວິຊາທີ່ມີຜົນ ສ່ວນ `note` ຄືສຳເນົາແລ້ວແຕ່ມີສິ່ງທີ່ຂາດ (ຫ້ອງຮຽນຖືກໃຊ້ຢູ່ແລ້ວຈຶ່ງສຳເນົາໂດຍບໍ່ມີຫ້ອງຮຽນ, ອາຈານທີ່ລາອອກແລ້ວ ແລະ ອື່ນໆ). ເຊສຊັນຈັບຄູ່ດ້ວຍລະຫັດ ຖ້າບໍ່ມີ ຈະໃສ່ໃນເຊສຊັນເຕັມພາກຮຽນ.
- ຕົວຢ່າງ: `php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- ການນຳໃຊ້: ກວດກຸ່ມຮຽນຂອງພາກຮຽນກ່ອນເປີດເຜີຍຕາຕະລາງຮຽນ. ການຈັດຫ້ອງຮຽນ ຫຼື ອາຈານຊ້ຳກັນຖືກ DB ຂັດຂວາງຢູ່ແລ້ວ ແຕ່ຄຳສັ່ງນີ້ຊອກຫາບັນຫາທີ່ DB ອະນຸຍາດ ເຊັ່ນ: ຈຳນວນຮັບໃຫຍ່ກວ່າຄວາມຈຸຂອງຫ້ອງຮຽນ, ເວີຊັນວິຊາທີ່ບໍ່ມີຜົນໃນວັນເລີ່ມເຊສຊັນ, ອາຈານຜູ້ສອນທີ່ລາອອກແລ້ວ, ການຈັດສັນບ່ອນນັ່ງເກີນຈຳນວນຮັບ, ວັນສອນນອກເຊສຊັນ. ກວດການຊ້ຳກັນຂອງຫ້ອງຮຽນໃນຂໍ້ມູນທີ່ເຂົ້າມາໂດຍບໍ່ມີຂໍ້ຈຳກັດ ເຊັ່ນ ການກູ້ຄືນຈາກການສຳຮອງຂໍ້ມູນ ອີກດ້ວຍ.
- ອາກິວເມັນ: `{term}` ລະຫັດພາກຮຽນ.
- ການກວດສອບ: ບໍ່ບັນທຶກ (ອ່ານເທົ່ານັ້ນ)
- ລະຫັດອອກ: 2 ຖ້າມີບັນຫາ. ກຸ່ມຮຽນທີ່ຍັງບໍ່ມີອາຈານຜູ້ສອນ ຫຼື ຫ້ອງຮຽນ ຈະສະແດງເປັນຂໍ້ມູນອ້າງອີງເທົ່ານັ້ນ.

## ການລົງທະບຽນຮຽນ

### `registration:preflight`

- ການນຳໃຊ້: ກວດພາກຮຽນກ່ອນເປີດການລົງທະບຽນຮຽນ. ສະແດງໄລຍະລົງທະບຽນຮຽນ ແລະ ໄລຍະເພີ່ມ-ຖອນ, ຊຸດກົດລະບຽບ, ຈຳນວນກຸ່ມຮຽນທີ່ເປີດເຜີຍ, ກຸ່ມຮຽນທີ່ຈຳນວນຮັບເປັນ 0, ການຈັດສັນບ່ອນນັ່ງເກີນຈຳນວນຮັບ, ເວີຊັນວິຊາທີ່ບໍ່ມີຜົນໃນວັນເລີ່ມເຊສຊັນ, ຈຳນວນນັກສຶກສາປັດຈຸບັນທີ່ບໍ່ມີເພດານໜ່ວຍກິດ ແລະ ຈຳນວນນັກສຶກສາທີ່ຖືກຈຳກັດການລົງທະບຽນຮຽນ.
- ອາກິວເມັນ: `{term}` ລະຫັດພາກຮຽນ (ຕົວຢ່າງ: `2027-SP`).
- ການກວດສອບ: ບໍ່ບັນທຶກ (ອ່ານເທົ່ານັ້ນ)
- ລະຫັດອອກ: 2 ຖ້າມີບັນຫາ. ຖ້າບໍ່ມີຊຸດກົດລະບຽບ ຈະສະແດງເປັນຂໍ້ມູນອ້າງອີງ ບໍ່ແມ່ນບັນຫາ (ນຳໃຊ້ຄ່າເລີ່ມຕົ້ນຂອງກົດລະບຽບ).
- ຕົວຢ່າງ: `php artisan registration:preflight 2027-SP`

### `registration:simulate`

- ການນຳໃຊ້: ສະແດງຜົນຕໍ່ກົດລະບຽບວ່າຈະເກີດຫຍັງຂຶ້ນຖ້ານັກສຶກສາລົງທະບຽນກຸ່ມຮຽນຕອນນີ້ (ຫຼື ໃນເວລາທີ່ລະບຸ). ບໍ່ບັນທຶກ ແລະ ບໍ່ທິ້ງບັນທຶກການພະຍາຍາມ. ໃຊ້ຕອບຄຳຖາມ "ເປັນຫຍັງລົງທະບຽນບໍ່ໄດ້".
- ອາກິວເມັນ: `{student-number}` ລະຫັດນັກສຶກສາ, `{section}` `ລະຫັດວິຊາ-ກຸ່ມ` (ຕົວຢ່າງ: `CSE2010-01`).
- ຕົວເລືອກ: `--term=` (ລະຫັດພາກຮຽນ. ຄ່າເລີ່ມຕົ້ນຄືພາກຮຽນຫຼ້າສຸດທີ່ມີກຸ່ມນັ້ນ), `--at=` (ເວລາຕັດສິນ. ຕົວຢ່າງ: `"2027-02-10 10:00 Asia/Seoul"`).
- ການກວດສອບ: ບໍ່ບັນທຶກ (ອ່ານເທົ່ານັ້ນ)
- ການອ່ານຜົນອອກ: ຕໍ່ກົດລະບຽບ ຜ່ານ/ບໍ່ຜ່ານ, ຂັດຂວາງ/ເຕືອນ ແລະ ຂໍ້ຄວາມ. ກົດລະບຽບທີ່ມີຂໍ້ຍົກເວັ້ນ (override) ນຳໃຊ້ຈະສະແດງເປັນບໍ່ຜ່ານ ແຕ່ບໍ່ຂັດຂວາງ. ຈຳນວນຮັບສະແດງແຍກຕ່າງຫາກລຸ່ມຕາຕະລາງກົດລະບຽບ.
- ລະຫັດອອກ: 2 ຖ້າການລົງທະບຽນຈະຖືກປະຕິເສດ.

### `waitlist:promote`

- ການນຳໃຊ້: ລົງທະບຽນຜູ້ລໍຖ້າຂອງກຸ່ມຮຽນທີ່ມີບ່ອນວ່າງຕາມລຳດັບ. ເມື່ອເລື່ອນຂຶ້ນ ຈະກວດທຸກກົດລະບຽບຄືນໃໝ່ ແລະ ຜູ້ລໍຖ້າທີ່ບໍ່ຜ່ານກົດລະບຽບຈະຖືກເອົາອອກຈາກລາຍຊື່ລໍຖ້າ (ບັນທຶກເຫດຜົນ). ລາຍຊື່ລໍຖ້າຂອງກຸ່ມຮຽນທີ່ໄລຍະລົງທະບຽນຮຽນ ແລະ ໄລຍະເພີ່ມ-ຖອນປິດແລ້ວທັງສອງຈະໝົດອາຍຸ. ສົ່ງເມວຜົນໃຫ້ນັກສຶກສາ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{term?}` ລະຫັດພາກຮຽນ (ຄ່າເລີ່ມຕົ້ນ: ທຸກພາກຮຽນທີ່ມີຜູ້ລໍຖ້າ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນກຸ່ມຮຽນ, ເລື່ອນຂຶ້ນ, ເອົາອອກ ແລະ ໝົດອາຍຸ)
- ເວລາແລ່ນ: ເມື່ອມີການຍົກເລີກ/ຖອນ ແລະ ການປ່ອຍການຈັດສັນບ່ອນນັ່ງ ກຸ່ມຮຽນນັ້ນຈະຖືກປະມວນຜົນທັນທີດ້ວຍວຽກໃນຄິວ. ຄຳສັ່ງນີ້ເປັນຕາໜ່າງນິລະໄພທີ່ແລ່ນທຸກຊົ່ວໂມງຕາມກຳນົດເວລາເພື່ອຈັດການສິ່ງທີ່ຕົກຄ້າງ.
- ຕົວຢ່າງ: `php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- ການນຳໃຊ້: ໝາຍການຈັດສັນບ່ອນນັ່ງທີ່ເລີຍເວລາປ່ຽນແລ້ວ (ຕົວຢ່າງ: ບ່ອນນັ່ງສະຫງວນສຳລັບນັກສຶກສາສາຂາວິຊາເອກ) ວ່າປະມວນຜົນແລ້ວ ແລະ ໃສ່ວຽກເລື່ອນຂຶ້ນຈາກລາຍຊື່ລໍຖ້າຂອງກຸ່ມຮຽນນັ້ນເຂົ້າຄິວ. ບ່ອນນັ່ງສະຫງວນຈະກາຍເປັນບ່ອນນັ່ງທົ່ວໄປທັນທີໃນການຄຳນວນເມື່ອເລີຍເວລາປ່ຽນ ດັ່ງນັ້ນຄຳສັ່ງນີ້ມີໜ້າທີ່ສົ່ງຕໍ່ບ່ອນນັ່ງໃຫ້ຜູ້ລໍຖ້າເທົ່ານັ້ນ.
- ການກວດສອບ: ບໍ່ບັນທຶກ (ແລ່ນທຸກ 5 ນາທີ. ຜົນການເລື່ອນຂຶ້ນຢູ່ໃນບັນທຶກການລົງທະບຽນຮຽນ)
- ເວລາແລ່ນ: ຕາມກຳນົດເວລາ (ທຸກ 5 ນາທີ).

## ເກຣດ

### `term:close`

- ການນຳໃຊ້: ປິດພາກຮຽນ. ເກຣດທັງໝົດຂອງພາກຮຽນຕ້ອງຖືກຢືນຢັນແລ້ວ. ຄຳນວນບັນທຶກພາກຮຽນ (ໜ່ວຍກິດ, GPA ຂອງພາກຮຽນ ແລະ ສະສົມ) ຂອງນັກສຶກສາແຕ່ລະຄົນ ແລະ ຕັດສິນສະຖານະການຮຽນ (ປົກກະຕິ, ເຕືອນທາງວິຊາການ, ພິຈາລະນາໃຫ້ອອກ) ແລະ ການເປັນນັກສຶກສາດີເດັ່ນ (batch ໃນຄິວ) ຈາກນັ້ນຈັດອັນດັບນັກສຶກສາດີເດັ່ນຕໍ່ຫຼັກສູດ ປິດບັນທຶກພາກຮຽນເປັນບັນທຶກທາງການ ແລະ ປ່ຽນພາກຮຽນເປັນສະຖານະ **ປິດເກຣດ**. ຄືກັນກັບ **ເກຣດ > ບັນທຶກພາກຮຽນ > ປິດພາກຮຽນ** ໃນໜ້າບໍລິຫານ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{term}` ລະຫັດພາກຮຽນ, `--dry-run` (ກວດສະເພາະວ່າປິດໄດ້ຫຼືບໍ່), `--reason=` (ເຫດຜົນທີ່ຈະບັນທຶກ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນນັກສຶກສາ, ຈຳນວນກຸ່ມຮຽນທີ່ຍັງບໍ່ຢືນຢັນ). ເມື່ອປິດສຳເລັດ ບັນທຶກການກວດສອບ `term.closed` ຈະເກັບຈຳນວນຜູ້ຖືກເຕືອນທາງວິຊາການ, ພິຈາລະນາໃຫ້ອອກ ແລະ ນັກສຶກສາດີເດັ່ນ.
- ລະຫັດອອກ: 2 ຖ້າມີກຸ່ມຮຽນທີ່ເກຣດຍັງບໍ່ຖືກຢືນຢັນ (ສະແດງຈຳນວນທີ່ຍັງບໍ່ຢືນຢັນຕໍ່ກຸ່ມຮຽນ). ພາກຮຽນທີ່ບໍ່ຢູ່ໃນສະຖານະເປີດເຜີຍ (published) ເປັນ 1.
- ເວລາແລ່ນ: ຫຼັງການປ້ອນ ແລະ ຢືນຢັນເກຣດສຳເລັດ. ເບິ່ງຄວາມຄືບໜ້າຂອງ batch ໃນ Horizon. ຖ້າບໍ່ມີຕົວປະມວນຜົນຄິວ ສະຖານະພາກຮຽນຈະບໍ່ປ່ຽນ.
- ຕົວຢ່າງ: `php artisan term:close 2026-FA --dry-run`, `php artisan term:close 2026-FA --reason="2026-2 성적 마감" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- ການນຳໃຊ້: ຄຳນວນບັນທຶກພາກຮຽນ (ໜ່ວຍກິດ, GPA ຂອງພາກຮຽນ ແລະ ສະສົມ) ຄືນໃໝ່ຈາກເກຣດທີ່ຢືນຢັນແລ້ວ. ໃຊ້ເມື່ອປ່ຽນນະໂຍບາຍການປະມວນຜົນເກຣດ (ຈຳນວນຕຳແໜ່ງທົດສະນິຍົມຂອງ GPA, ການນັບການຮຽນຊ້ຳ) ແລ້ວນຳໃຊ້ກັບພາກຮຽນທີ່ຜ່ານມາ. ສະຖານະການຮຽນ ແລະ ນັກສຶກສາດີເດັ່ນຍັງຄົງຄ່າທີ່ກຳນົດຕອນປິດພາກຮຽນ. ການອະນຸມັດການແກ້ໄຂເກຣດຈະຄຳນວນນັກສຶກສາຄົນນັ້ນຄືນໃໝ່ອັດຕະໂນມັດ ຈຶ່ງບໍ່ຈຳເປັນຕ້ອງໃຊ້ຄຳສັ່ງນີ້.
- ຕົວເລືອກ: `--term=` (ນັກສຶກສາທີ່ມີເກຣດໃນພາກຮຽນນັ້ນ ເລີ່ມແຕ່ພາກຮຽນນັ້ນ), `--student-number=` (ນັກສຶກສາຄົນດຽວ), `--reason=` (ຈຳເປັນ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນນັກສຶກສາ, ເຫດຜົນ)
- ຕົວຢ່າງ: `php artisan grades:recalculate --term=2026-SP --reason="평점 소수 셋째 자리로 변경"`

### `grades:remind-missing`

- ການນຳໃຊ້: ສົ່ງເມວແຈ້ງເຕືອນໃຫ້ອາຈານຜູ້ສອນຂອງກຸ່ມຮຽນທີ່ຍັງບໍ່ສົ່ງເກຣດ (ຍັງບໍ່ປ້ອນ ຫຼື ບັນທຶກຊົ່ວຄາວ). ລວມກຸ່ມຮຽນຕໍ່ອາຈານແລ້ວສົ່ງຄົນລະສະບັບ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{term}` ລະຫັດພາກຮຽນ, `--dry-run` (ສະແດງເປົ້າໝາຍໂດຍບໍ່ສົ່ງ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນກຸ່ມຮຽນ, ອາຈານ ແລະ ທີ່ສົ່ງ)
- ເວລາແລ່ນ: ສອງສາມມື້ກ່ອນສິ້ນສຸດໄລຍະປ້ອນເກຣດ. ລົງທະບຽນໃນຕົວກຳນົດເວລາຖ້າຈຳເປັນ.

## ການປະເມີນການສອນ

### `evaluation:remind`

- ການນຳໃຊ້: ສົ່ງເມວແຈ້ງເຕືອນໃຫ້ນັກສຶກສາທີ່ຍັງມີວິຊາທີ່ບໍ່ໄດ້ປະເມີນໃນຂະນະທີ່ໄລຍະການປະເມີນການສອນເປີດຢູ່. ລວມວິຊາທີ່ເຫຼືອຕໍ່ນັກສຶກສາແລ້ວສົ່ງຄົນລະສະບັບ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{term}` ລະຫັດພາກຮຽນ, `--dry-run` (ສະເພາະຈຳນວນນັກສຶກສາເປົ້າໝາຍ ໂດຍບໍ່ສົ່ງ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນນັກສຶກສາເປົ້າໝາຍ, ຈຳນວນທີ່ສົ່ງ)
- ເວລາແລ່ນ: ໜຶ່ງຫຼືສອງຄັ້ງໃນລະຫວ່າງໄລຍະການປະເມີນ. ລົງທະບຽນໃນຕົວກຳນົດເວລາຖ້າຈຳເປັນ.

### `evaluation:publish-results`

- ການນຳໃຊ້: ເປີດເຜີຍຜົນການປະເມີນການສອນຂອງພາກຮຽນໃຫ້ອາຈານ. ຄືກັນກັບ **ການປະເມີນການສອນ > ການປະເມີນການສອນຂອງພາກຮຽນ > ເປີດເຜີຍຜົນ** ໃນໜ້າບໍລິຫານ. ຫຼັງເປີດເຜີຍແລ້ວ ກໍຍັງເຫັນຜົນສະເພາະກຸ່ມຮຽນທີ່ບັນລຸຈຳນວນຄຳຕອບຂັ້ນຕ່ຳ ແລະ ອັດຕາການຕອບ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{term}` ລະຫັດພາກຮຽນ, `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນຄຳຕອບ, ເປີດເຜີຍແລ້ວຫຼືບໍ່)
- ເວລາແລ່ນ: ຫຼັງໄລຍະການປະເມີນ ແລະ ການປະມວນຜົນເກຣດສິ້ນສຸດ. ພາກຮຽນທີ່ເປີດເຜີຍແລ້ວຈະບໍ່ຖືກປ່ຽນ.

## ໃບຢັ້ງຢືນ

### `certificate:verify`

- ການນຳໃຊ້: ກວດລະຫັດຢືນຢັນຂອງໃບຢັ້ງຢືນດ້ວຍເກນດຽວກັນກັບໜ້າກວດຄວາມແທ້ສາທາລະນະ. ສະແດງປະເພດ, ເລກທີອອກ, ວັນທີອອກ ແລະ ຊື່ເຈົ້າຂອງທີ່ຖືກປິດບັງບາງສ່ວນ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{code}` ລະຫັດຢືນຢັນ.
- ການກວດສອບ: ບໍ່ມີ (ອ່ານ)
- ລະຫັດອອກ: 0 ຖ້າຖືກຕ້ອງ, 2 ຖ້າເປັນລະຫັດທີ່ບໍ່ມີຢູ່, ຖືກຍົກເລີກ ຫຼື ໝົດອາຍຸ.

### `certificate:render`

- ການນຳໃຊ້: ສ້າງ PDF ຂອງໃບຢັ້ງຢືນທີ່ອອກແລ້ວຄືນໃໝ່ດ້ວຍຂໍ້ມູນ ແລະ ແບບຟອມປັດຈຸບັນ ແລະ ປ່ຽນໄຟລ໌ທີ່ເກັບໄວ້. ຄືກັນກັບ **ທະບຽນການອອກ > ສ້າງໃໝ່** ໃນໜ້າບໍລິຫານ. ເລກທີອອກ ແລະ ລະຫັດຢືນຢັນຄົງເດີມ ແຕ່ checksum ປ່ຽນ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{issue}` ເລກທີອອກ, `--reason=` (ຈຳເປັນ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ເລກທີອອກ, checksum ໃໝ່)
- ເວລາແລ່ນ: ເມື່ອຕ້ອງການສ້າງໃບຢັ້ງຢືນສະເພາະໃບຄືນໃໝ່ຫຼັງແກ້ໄຂແບບຟອມ ຫຼື ການສະກົດຊື່.

## ການສອບເສັງພາສາ/ການສອບເສັງລວມ

### `assessment:import-results`

- ການນຳໃຊ້: ປ້ອນຜົນຂອງຮອບການສອບເສັງຈາກ CSV. ກົດລະບຽບດຽວກັນກັບ **ຮອບການສອບເສັງ > ນຳເຂົ້າຜົນ** ໃນໜ້າບໍລິຫານ (ສະເພາະນັກສຶກສາທີ່ລົງທະບຽນສອບ, ຕັດສິນຜ່ານດ້ວຍຄະແນນ, ຖ້າປ້ອນຊ້ຳກ່ອນເປີດເຜີຍຈະແທນທີ່).
- ອາກິວເມັນ/ຕົວເລືອກ: `{type}` ລະຫັດປະເພດການສອບເສັງ / `{held_date}` ວັນສອບ `YYYY-MM-DD` / `{file}` CSV ແບບ UTF-8 ທີ່ມີແຖວຫົວ, `--actor=` (ຈຳເປັນ), `--dry-run` (ກວດແຖວໂດຍບໍ່ບັນທຶກ).
- ຮູບແບບຖັນ: [ຄູ່ມືຜູ້ບໍລິຫານ ບົດທີ 24](../admin/24-assessments.md).
- ການກວດສອບ: ບັນທຶກ (ຮອບ, ຊື່ໄຟລ໌, ຈຳນວນແຖວ, ຈຳນວນທີ່ປ້ອນ, ຂາດສອບ ແລະ ຜິດພາດ)
- ລະຫັດອອກ: 2 ຖ້າມີແຖວຜິດພາດ (ແຖວທີ່ເຫຼືອຖືກບັນທຶກ).
- ຕົວຢ່າງ: `php artisan assessment:import-results ENG_COMP 2026-05-15 storage/app/eng.csv --actor=registrar@example.ac.kr --dry-run`

### `assessment:publish-results`

- ການນຳໃຊ້: ເປີດເຜີຍຜົນຂອງຮອບໃຫ້ນັກສຶກສາ. ຄືກັນກັບ **ຮອບການສອບເສັງ > ເປີດເຜີຍຜົນ** ໃນໜ້າບໍລິຫານ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{type}` ລະຫັດປະເພດການສອບເສັງ / `{held_date}` ວັນສອບ, `--actor=` (ຈຳເປັນ).
- ການກວດສອບ: ບັນທຶກ (ຮອບ, ຈຳນວນຜົນ)
- ເວລາແລ່ນ: ຫຼັງການປ້ອນຜົນສຳເລັດ. ຮອບທີ່ເປີດເຜີຍແລ້ວຈະລົ້ມເຫຼວ.

## ການເຂົ້າຮຽນ

### `attendance:generate-sessions`

- ການນຳໃຊ້: ສ້າງຄາບຮຽນຈາກເວລາສອນ (ວັນ, ເວລາ, ໄລຍະ) ສຳລັບແຕ່ລະກຸ່ມຮຽນຂອງພາກຮຽນ. ຄືກັນກັບ **ສ້າງຄາບຮຽນ** ໃນພອດທໍອາຈານ ແລະ ໜ້າບໍລິຫານ. ຄາບຮຽນ ແລະ ການເຂົ້າຮຽນທີ່ມີຢູ່ແລ້ວຄົງເດີມ (ແລ່ນຊ້ຳໄດ້ຢ່າງປອດໄພ).
- ອາກິວເມັນ/ຕົວເລືອກ: `{term}` ລະຫັດພາກຮຽນ, `--section=` (ລະຫັດວິຊາ-ກຸ່ມ ຕົວຢ່າງ: `CSE2010-01` ພຽງອັນດຽວ), `--dry-run` (ສະເພາະຈຳນວນກຸ່ມຮຽນເປົ້າໝາຍ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ພາກຮຽນ, ຈຳນວນກຸ່ມຮຽນ, ຈຳນວນຄາບຮຽນທີ່ສ້າງ)
- ເວລາແລ່ນ: ກ່ອນເລີ່ມພາກຮຽນ ຫຼັງຢືນຢັນເວລາສອນແລ້ວ. ແລ່ນຊ້ຳເມື່ອເວລາສອນປ່ຽນ.

## ການຈົບການສຶກສາ

### `degree-audit:run`

- ການນຳໃຊ້: ບັນທຶກການກວດເງື່ອນໄຂການຈົບການສຶກສາຂອງນັກສຶກສາປັດຈຸບັນແຕ່ລະຄົນ. ຄືກັນກັບ **ການກວດເງື່ອນໄຂການຈົບການສຶກສາ > ແລ່ນການກວດ** ໃນໜ້າບໍລິຫານ. ການກວດຫຼ້າສຸດທີ່ບັນທຶກໄວ້ເປັນພື້ນຖານຂອງການດຳເນີນການຈົບການສຶກສາ.
- ຕົວເລືອກ: `--term=` (ລະຫັດພາກຮຽນທີ່ການກວດສັງກັດ), `--student-number=` (ຄົນດຽວ), `--min-year-level=` (ສະເພາະຊັ້ນປີນີ້ຂຶ້ນໄປ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນນັກສຶກສາ, ຈຳນວນທີ່ຄົບເງື່ອນໄຂ)
- ເວລາແລ່ນ: ກ່ອນການພິຈາລະນາຈົບການສຶກສາ (ທ້າຍພາກຮຽນ) ແລະ ຫຼັງແກ້ໄຂຊຸດເງື່ອນໄຂ ຫຼື ວິຊາທົດແທນ.

## ການເຊື່ອມຕໍ່ LMS

### `lms:sync`

- ການນຳໃຊ້: ສົ່ງກຸ່ມຮຽນທີ່ເປີດເຜີຍແລ້ວເຂົ້າແພລັດຟອມ (ສ້າງ ແລະ ເຊື່ອມຕໍ່ຫ້ອງຮຽນ, ອາຈານຜູ້ສອນ, ນັກສຶກສາທີ່ກຳລັງລົງທະບຽນຮຽນ). ດຳເນີນການຄືກັນກັບ **ການເຊື່ອມຕໍ່ຫ້ອງຮຽນ > ຊິງຄືນໃໝ່** ໃນໜ້າບໍລິຫານ ແຕ່ເປັນລະດັບພາກຮຽນ. ກຸ່ມຮຽນທີ່ເຊື່ອມຕໍ່ແລ້ວຈະຖືກຮັບປະກັນຄືນເທົ່ານັ້ນ (idempotent).
- ອາກິວເມັນ/ຕົວເລືອກ: `{platform}` ລະຫັດແພລັດຟອມ, `--term=` (ລະຫັດພາກຮຽນ ຄ່າເລີ່ມຕົ້ນຄືທຸກພາກຮຽນທີ່ຍັງບໍ່ສິ້ນສຸດ), `--section=` (ລະຫັດວິຊາ-ກຸ່ມ ອັນດຽວ), `--dry-run` (ບັນທຶກສິ່ງທີ່ຈະສົ່ງເປັນ "ຂ້າມ" ເທົ່ານັ້ນ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ແພລັດຟອມ, ຈຳນວນກຸ່ມຮຽນ, ຈຳນວນສະມາຊິກ, ຈຳນວນທີ່ລົ້ມເຫຼວ)
- ລະຫັດອອກ: 2 ຖ້າມີກຸ່ມຮຽນທີ່ລົ້ມເຫຼວ.

### `lms:reconcile`

- ການນຳໃຊ້: ປຽບທຽບລາຍຊື່ຫ້ອງຮຽນຂອງແພລັດຟອມກັບລາຍຊື່ຜູ້ລົງທະບຽນຮຽນຂອງລະບົບບໍລິຫານການສຶກສາ ແລ້ວເພີ່ມສະມາຊິກທີ່ຂາດ ແລະ ເອົາສະມາຊິກທີ່ເກີນອອກ. ຄວາມແຕກຕ່າງຖືກບັນທຶກໃນບັນທຶກການຊິງ (`reconcile`).
- ອາກິວເມັນ/ຕົວເລືອກ: `{platform?}` (ຖ້າບໍ່ມີ ທຸກແພລັດຟອມທີ່ໃຊ້ງານຢູ່), `--term=`, `--dry-run` (ບັນທຶກສະເພາະຄວາມແຕກຕ່າງ), `--actor=`.
- ການກວດສອບ: ບັນທຶກ (ຈຳນວນກຸ່ມຮຽນຕໍ່ແພລັດຟອມ, ຈຳນວນທີ່ເພີ່ມ, ເອົາອອກ ແລະ ລົ້ມເຫຼວ)
- ເວລາແລ່ນ: ຕາມກຳນົດເວລາທຸກວັນ 02:30. ແລ່ນດ້ວຍມືຫຼັງແພລັດຟອມຂັດຂ້ອງ.

## ການກວດກາ ແລະ ລ້າງຂໍ້ມູນໃນການດຳເນີນງານ

- ການກວດສອບ: ບໍ່ມີ (ອ່ານ)

- ຕົວເລືອກ: `--chunk=500`, `--dry-run` (ນັບສະເພາະຈຳນວນບັນທຶກທີ່ໃຊ້ກະແຈເກົ່າ), `--force`.
- ການກວດສອບ: ບັນທຶກ (ID batch, ຈຳນວນວຽກ / ຈຳນວນຂອງການເບິ່ງລ່ວງໜ້າ)
- ການກວດ: ເບິ່ງຄວາມຄືບໜ້າຂອງ batch ໃນ Horizon (`/horizon`). ຫຼັງສຳເລັດ ຖ້າຜົນ `--dry-run` ເປັນ 0 ໃຫ້ເອົາກະແຈເກົ່າອອກຈາກ `PII_PREVIOUS_KEYS`.

## ຫຼາຍພາສາ

### `i18n:missing`

- ການນຳໃຊ້: ສະແດງກະແຈທີ່ຂາດຕໍ່ພາສາ ແລະ ກະແຈທີ່ບໍ່ໃຊ້ແລ້ວ ທຽບກັບພາສາອ້າງອີງ (en).
- ອາກິວເມັນ/ຕົວເລືອກ: `{locale?}` (ພາສາດຽວ), `--strict` (ລະຫັດອອກ 2 ຖ້າມີທີ່ຂາດ. ໃຊ້ໃນ CI).
- ການກວດສອບ: ບໍ່ບັນທຶກ

### `i18n:export`

- ການນຳໃຊ້: ສ້າງໄຟລ໌ JSON ສຳລັບມອບໃຫ້ນັກແປ. ຮູບແບບ: `{"ກະແຈ": {"source": "ພາສາອັງກິດ", "translation": "ຄຳແປ"}}`.
- ອາກິວເມັນ/ຕົວເລືອກ: `{locale} {path}`, `--missing` (ສະເພາະກະແຈທີ່ຂາດ).
- ການກວດສອບ: ບໍ່ບັນທຶກ
- ຕົວຢ່າງ: `php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- ການນຳໃຊ້: ນຳ JSON ທີ່ນັກແປຕື່ມແລ້ວເຂົ້າ `lang/{locale}`. ນຳເຂົ້າສະເພາະກະແຈທີ່ມີໃນພາສາອ້າງອີງ ແລະ ບໍ່ສົນໃຈຄຳແປທີ່ວ່າງ.
- ອາກິວເມັນ/ຕົວເລືອກ: `{locale} {path}`, `--dry-run` (ສະແດງສະເພາະລາຍການກະແຈທີ່ຈະຂຽນ).
- ການກວດສອບ: ບັນທຶກ
- ຂໍ້ຄວນລະວັງ: ໄຟລ໌ຄຳແປຖືກຄຸ້ມຄອງໃນ repository. ຫຼັງນຳເຂົ້າແລ້ວໃຫ້ commit ການປ່ຽນແປງ.

## ການກວດ

### `naming:check`

- ການນຳໃຊ້: ກວດຊື່ຕາຕະລາງ/ຖັນຂອງ migration ຕາມ [ກົດການຕັ້ງຊື່](../../../development/naming.md).
- ຕົວເລືອກ: `--path=*` (ໄດເຣັກທໍຣີທີ່ຈະກວດ ຄ່າເລີ່ມຕົ້ນ `database/migrations`).
- ການກວດສອບ: ບໍ່ບັນທຶກ
- ລະຫັດອອກ: 2 ຖ້າມີບັນຫາ.

### `pdf:sample`

- ການນຳໃຊ້: ສ້າງຕາຕະລາງທີ່ປະສົມພາສາເກົາຫຼີ, ຈີນ, ລາວ ແລະ ອັງກິດເປັນ PDF ເພື່ອກວດຟອນ ແລະ ການເຊື່ອມຕໍ່ບໍລິການ PDF (Gotenberg).
- ອາກິວເມັນ: `{path=pdf-sample.pdf}` (ອ້າງອີງຈາກດິສກ໌ທ້ອງຖິ່ນ `storage/app/private`).
- ການກວດສອບ: ບໍ່ບັນທຶກ
- ເມື່ອລົ້ມເຫຼວ: ຖ້າເປັນຂໍ້ຜິດພາດການເຊື່ອມຕໍ່ ໃຫ້ກວດ `GOTENBERG_URL` ແລະ ສະຖານະ container ຂອງ Gotenberg.
