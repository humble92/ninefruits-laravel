# ການຄຸ້ມຄອງກະແຈ

- ກຸ່ມເປົ້າໝາຍ: ຜູ້ປະຕິບັດງານ IT

| ກະແຈ | ການນຳໃຊ້ | ຖ້າສູນເສຍ | ການປ່ຽນກະແຈ |
|---|---|---|---|
| `APP_KEY` | ເຊສຊັນ, cookie, ຄ່າລັບຂອງການຢືນຢັນສອງຂັ້ນຕອນ, ລາຍເຊັນ cookie ຈື່ອຸປະກອນ | ຜູ້ໃຊ້ທຸກຄົນຖືກອອກຈາກລະບົບ, ການຢືນຢັນສອງຂັ້ນຕອນ (ແອັບຢືນຢັນ) ທີ່ລົງທະບຽນໄວ້ໃຊ້ບໍ່ໄດ້ | ວາງກະແຈເກົ່າໄວ້ໃນ `APP_PREVIOUS_KEYS` ແລ້ວປ່ຽນ |
| `PII_ENCRYPTION_KEY` | ເຂົ້າລະຫັດຂໍ້ມູນສ່ວນບຸກຄົນ ເຊັ່ນ ເລກບັດປະຈຳຕົວ | **ບໍ່ສາມາດກູ້ຄືນຂໍ້ມູນສ່ວນບຸກຄົນທີ່ເຂົ້າລະຫັດໄວ້ໄດ້** | ຂັ້ນຕອນຂ້າງລຸ່ມ |
| `PII_HASH_KEY` | ແຮດຊ໌ສຳລັບການຄົ້ນຫາຂໍ້ມູນສ່ວນບຸກຄົນແບບກົງກັນທຸກຕົວອັກສອນ | ຄົ້ນຫາບໍ່ໄດ້ (ຂໍ້ມູນຍັງຢູ່) | ໂດຍຫຼັກການແລ້ວບໍ່ປ່ຽນ |

ຫຼັກການເກັບຮັກສາ

- ເກັບກະແຈທັງສາມໄວ້ຢ່າງໜ້ອຍສອງຊຸດ ແຍກຈາກການຕັ້ງຄ່າສະພາບແວດລ້ອມຂອງເຊີບເວີ ໃນບ່ອນເກັບຄວາມລັບ (Vault, ຕົວຄຸ້ມຄອງຄວາມລັບຂອງ cloud ແລະ ອື່ນໆ) ຫຼື ໃນບ່ອນເກັບແບບປິດຜະນຶກແບບ offline.
- ຢ່າເກັບໄວ້ບ່ອນດຽວກັນກັບໄຟລ໌ສຳຮອງ. ເຖິງວ່າການສຳຮອງ DB ຈະຮົ່ວໄຫຼ ກໍຕ້ອງອ່ານຂໍ້ມູນສ່ວນບຸກຄົນບໍ່ໄດ້ຖ້າບໍ່ມີກະແຈ.

## ຂັ້ນຕອນການປ່ຽນກະແຈຂໍ້ມູນສ່ວນບຸກຄົນ

1. ສ້າງກະແຈໃໝ່ດ້ວຍ `php artisan pii:generate-key` (ໃຊ້ສະເພາະ `PII_ENCRYPTION_KEY` ຈາກຜົນອອກ).
2. ວາງກະແຈປັດຈຸບັນໄວ້ໃນ `PII_PREVIOUS_KEYS` (ຫຼາຍອັນແຍກດ້ວຍເຄື່ອງໝາຍຈຸດ) ແລະ ວາງກະແຈໃໝ່ໄວ້ໃນ `PII_ENCRYPTION_KEY`.
3. ໃຫ້ລະບົບອ່ານການຕັ້ງຄ່າຄືນໃໝ່: `php artisan config:cache`, `php artisan horizon:terminate`.
4. ສຳລັບແຕ່ລະໂມເດລຂໍ້ມູນສ່ວນບຸກຄົນ ໃຫ້ກວດຈຳນວນເປົ້າໝາຍດ້ວຍ `php artisan pii:reencrypt {ໂມເດລ} --dry-run` ແລ້ວແລ່ນໂດຍບໍ່ມີ `--force`.
5. ຫຼັງຈາກຢືນຢັນໃນ Horizon ວ່າ batch ສຳເລັດແລ້ວ ແລະ ຜົນ `--dry-run` ເປັນ 0 ໃຫ້ລຶບກະແຈເກົ່າອອກຈາກ `PII_PREVIOUS_KEYS`.
6. ເກັບກະແຈເກົ່າໄວ້ແບບປິດຜະນຶກຕະຫຼອດໄລຍະເວລາເກັບຮັກສາການສຳຮອງຂໍ້ມູນ (ຈຳເປັນເມື່ອກູ້ຄືນການສຳຮອງຂໍ້ມູນເກົ່າ).
