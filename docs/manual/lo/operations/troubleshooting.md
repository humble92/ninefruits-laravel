# ການແກ້ໄຂບັນຫາ

- ກຸ່ມເປົ້າໝາຍ: ຜູ້ປະຕິບັດງານ IT

| ອາການ | ສິ່ງທີ່ຕ້ອງກວດ |
|---|---|
| ຫຼັງເຂົ້າສູ່ລະບົບຖືກພາໄປໜ້າຄວາມປອດໄພທັນທີ | ນະໂຍບາຍການຢືນຢັນສອງຂັ້ນຕອນເປັນ "ບັງຄັບ" ແລະ ໄລຍະຜ່ອນຜັນໝົດແລ້ວ. ແກ້ໄດ້ເມື່ອຜູ້ໃຊ້ລົງທະບຽນ. ນະໂຍບາຍຢູ່ທີ່ **ການຕັ້ງຄ່າ > ຄວາມປອດໄພ** |
| ໜ້າບໍລິຫານສະແດງ 403 | ຜູ້ໃຊ້ບໍ່ມີການມອບບົດບາດທີ່ຍັງມີຜົນ ເຊິ່ງມີສິດ `admin_panel.access`. ກວດທີ່ **ຜູ້ໃຊ້ ແລະ ສິດ > ຜູ້ໃຊ້ > ການມອບບົດບາດ** |
| ບໍ່ເຫັນເມນູ | ບົດບາດບໍ່ມີສິດຂອງໜ້ານັ້ນ (ຕົວຢ່າງ: `roles.view`) |
| ລະຫັດທາງອີເມວບໍ່ມາ | ການຕັ້ງຄ່າເມວ (`MAIL_*`), ບັນທຶກ `ສົ່ງລະຫັດທາງອີເມວ` ໃນເຫດການຄວາມປອດໄພ, ຂີດຈຳກັດການສົ່ງ (1 ຄັ້ງຕໍ່ນາທີ, 5 ຄັ້ງຕໍ່ຊົ່ວໂມງ) |
| ໜ້າຈໍສະແດງຂໍ້ມູນຂອງຄົນອື່ນ 0 ລາຍການ | ອາດເປັນເລື່ອງປົກກະຕິ (ຄວາມປອດໄພລະດັບແຖວ). ກວດວ່າຜູ້ປະຕິບັດຂອງເຊສຊັນ DB ຖືກຕັ້ງແລ້ວຫຼືບໍ່ ຈາກຖັນຜູ້ໃຊ້ໃນ **ບັນທຶກການປ່ຽນແປງຂໍ້ມູນ** |
| `permission denied for schema public` | ແອັບພລິເຄຊັນພະຍາຍາມແລ່ນ DDL ດ້ວຍ `app_runtime`. ແລ່ນ migration ດ້ວຍ `php artisan migrate` ເທົ່ານັ້ນ (ໃຊ້ `app_migrator` ອັດຕະໂນມັດ) |
| `Audit records are append-only` | ມີການພະຍາຍາມແກ້ໄຂ/ລຶບຕາຕະລາງບັນທຶກການກວດສອບ. ນີ້ຄືການຂັດຂວາງທີ່ຖືກຕ້ອງ |
| ສ້າງ PDF ບໍ່ສຳເລັດ | `php artisan pdf:sample`, ສະຖານະ Gotenberg, `GOTENBERG_URL` |
| ວຽກໃນຄິວຢຸດຄ້າງ | ກວດວຽກທີ່ລົ້ມເຫຼວທີ່ `/horizon`, `php artisan horizon:status` |

ການຕິດຕາມລະດັບຄຳຮ້ອງຂໍ: ດ້ວຍຄ່າຂອງ header ຕອບກັບ `X-Request-Id` ສາມາດຄົ້ນຫາ log, ບັນທຶກການກວດສອບທາງທຸລະກິດ, ບັນທຶກການປ່ຽນແປງຂໍ້ມູນ ແລະ ເຫດການຄວາມປອດໄພໄດ້ພ້ອມກັນ.
