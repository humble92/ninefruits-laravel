# Artisan командын лавлах

- Зориулалт: МТ-ийн ашиглалтын ажилтнууд
- Хамрах хүрээ: энэ репозиторид бүртгэгдсэн аппликейшны бүх команд. Шинэ команд нэмэхэд энд мөн нэмэх ёстой, эс бөгөөс CI амжилтгүй болно (`tests/Feature/Tooling/CommandDocumentationTest.php`).

## Нийтлэг дүрэм

Бүх команд `php artisan {command}` хэлбэрээр ажиллана. Хөгжүүлэлтийн орчинд `./vendor/bin/sail artisan {command}`.

| Зүйл | Дүрэм |
|---|---|
| Аудитын бичлэг | Өгөгдөл өөрчилдөг командууд (доор "Аудит: бүртгэнэ") ажиллах бүрдээ команд, аргумент, сонголт, үйлдлийн системийн хэрэглэгч, exit code болон үр дүнг үйлдлийн бүртгэлд (log `command`) бичнэ. Удирдлагын самбарын **Аудит > Үйлдлийн бүртгэл** хэсэгт шалгана |
| Ажиллуулалтын ID | Ажиллуулалт бүр хүсэлтийн ID-ийн оронд `cmd-`-ээр эхэлсэн ID авна. Үйлдлийн бүртгэл, тухайн ажиллуулалтын хийсэн өгөгдлийн өөрчлөлтүүд болон түүний илгээсэн дарааллын ажлууд бүгд ижил ID-тай тул "энэ өөрчлөлтийг аль команд хийсэн бэ" гэдэгт ID-аар хариулна. `--actor` нь ашиглалтын ажилтны оруулсан утга тул өгөгдлийн өөрчлөлтийн хэрэглэгчийн баганад оруулахгүй (бодит гүйцэтгэгч нь үйлдлийн системийн хэрэглэгч) |
| `--actor=<email>` | Аудиттай бүх командад нийтлэг. Хариуцсан админы бүртгэлийг тэмдэглэнэ. Үл мэдэгдэх и-мэйл бол ажиллуулалт зогсоно |
| `--dry-run` | Юуг ч өөрчлөхгүйгээр үр дүнг хэвлэнэ. Буцаахад хэцүү үйлдлүүдэд байдаг |
| `--force` | Баталгаажуулах асуултгүйгээр ажиллана (төлөвлөгдсөн ажил болон байршуулалтын скриптэд) |
| `--reason=` | Шалтгаан шаарддаг командуудад байдаг |
| Exit code | 0 амжилттай, 1 амжилтгүй эсвэл цуцлагдсан, 2 шалгах команд асуудал илрүүлсэн |
| DB контекст | Команд ажиллах үед DB сессийн гүйцэтгэгч `system:command:{command}` гэж тохируулагдаж, өгөгдлийн өөрчлөлтөд (trigger) харагдана |

## Суулгалт ба демо

### `setup:install`

- Зориулалт: шинэ суулгалт ба шинэчлэл. Миграц, үндсэн өгөгдөл, байгууллагын анхдагч утга, суулгалтын профайл болон анхны админыг дарааллаар нь ажиллуулна. Дахин ажиллуулахад аюулгүй (байгаа өгөгдөл болон админуудын өөрчилсөн утгууд хадгалагдана).
- Хэзээ: анхны суулгалт болон байршуулалт бүрд.
- Сонголтууд: `--institution-name=`, `--locale=` (анхдагч хэл), `--timezone=` (жишээ нь `Asia/Seoul`), `--profile=*` (суулгалтын профайлын түлхүүр), `--grade-scale=` (дүнгийн шкал `4.5` эсвэл `4.3`. Нэг удаа тохируулсны дараа өөрчлөх боломжгүй. Хоосон бол эхний профайлын шкал), `--admin-email=`, `--admin-name=`, `--force` (асуултгүйгээр ажиллана. Админы нууц үгийг стандарт оролтоос уншина).
- Аудит: бүртгэнэ
- Жишээ

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="Demo University" --admin-email=admin@example.ac.kr --admin-name="Administrator"
  ```

- Гаралтыг унших: алхам бүрд `DONE`/`FAIL`. `Administrator exists` нь системийн админы оноолт аль хэдийн байгаа тул үүсгэхийг алгассан гэсэн үг.
- Алдаа гарвал: түлхүүр дутуу гэсэн алдаа бол `key:generate` болон `pii:generate-key`-ийн үүсгэсэн утгуудыг орчны тохиргоонд оруулна. Миграцын алдаа ихэвчлэн DB-ийн роль бэлтгэгдээгүйг илтгэнэ (суулгалтын гарын авлагыг үзнэ үү).

### `setup:demo`

- Зориулалт: factory-гоор зохиомол их сургуулийн өгөгдөл үүсгэнэ. Үүрэг тус бүрийн тогтмол демо бүртгэлүүдийг (`registrar@demo.test` гэх мэт) хэвлэнэ.
- Хэзээ: хөгжүүлэлт, сургалт, танилцуулгын орчин. **Production-д (`APP_ENV=production`) `--force`-тэй ч ажиллахгүй.**
- Сонголтууд: `--size=tiny|small|medium|large` (ойролцоогоор 20/100/2,000/20,000 оюутан. `tiny` нь тест болон хурдан шалгалтад), `--seed=` (ижил утга ижил өгөгдөл үүсгэнэ), `--force`.
- `--student-accounts`: идэвхтэй оюутан бүрд бүртгэл (`student{student number}@demo.test`, демо нууц үг) үүсгэж, `storage/app/private/load-accounts.csv`-д бичнэ. Ачааллын тестэд ([Ачааллын тест](load-testing.md)).
- Аудит: бүртгэнэ
- Жишээ: `php artisan setup:demo --size=small --seed=42`
- Алдаа гарвал: үндсэн өгөгдөл байхгүй бол демо бүртгэлүүд үүрэггүй болж алгасагдана. Эхлээд `setup:install` ажиллуулна.

## Лавлах мэдээлэл ба улирал

### `reference:import`

- Зориулалт: лавлах мэдээллийг CSV-ээс оруулна. Удирдлагын самбар дахь **CSV оруулах**-тай ижил оруулах дүрэм ашиглана (байгаа мөрийг кодоор нь тааруулж шинэчилнэ, хоосон орчуулгын нүд байгаа утгыг хадгална, зөвхөн амжилтгүй мөрүүдийг тусад нь бүртгэнэ).
- Аргументууд: `{type}` нь `org_units`, `programs`, `buildings`, `rooms`, `lookup_values`, `students`, `instructors`, `courses`, `registration_holds`-ийн аль нэг / `{file}` толгой мөртэй UTF-8 CSV.
- Сонголтууд: `--actor=` (заавал. Оруулалтын бичлэг болон дууссан тухай мэдэгдэл энэ бүртгэл рүү очно), `--chunk=100` (дарааллын нэг ажил дахь мөрийн тоо), `--dry-run` (зөвхөн толгой шалгах ба мөр тоолох).
- Аудит: бүртгэнэ (төрөл, файлын нэр, мөрийн тоо, амжилтгүй мөрийн тоо)
- Баганын формат: [Админы гарын авлагын 9-р бүлэг](../admin/09-csv-import.md).
- Exit code: дараалал синхрон ажиллавал үр дүн шууд хэвлэгдэж, амжилтгүй мөр байвал exit code 2 болно. Асинхрон (Horizon) бол оруулалтыг зөвхөн хүлээн авч, exit code 0 болно. Үр дүн нь `--actor` бүртгэлийн удирдлагын самбарын мэдэгдэлд амжилтгүй мөрүүдийн CSV болж ирнэ.
- Жишээ: `php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- Зориулалт: тухайн цагт үргэлжилж буй улирал болон нээлттэй үйл ажиллагааны хугацаануудыг (төрөл, улирал, хамрах шалгуур, дуусах цаг) харуулна. Улирал болон үйл ажиллагааны хугацааны тохиргоог шалгах эсвэл "яагаад хичээл сонголт нээгдээгүй вэ" гэх мэт асуултад хариулахад ашиглана.
- Сонголтууд: `--at=` (анхдагч одоо. Жишээ нь `"2027-02-15 09:00"`. Цагийн бүсгүй бол серверийн цагийн бүсээр (UTC) тайлбарлана. Цагийн бүсийг `"2027-02-15 09:00 Asia/Seoul"` гэж өгч болно).
- Аудит: бүртгэхгүй
- Гаралтыг унших: огнооны шийдвэр байгууллагын цагийн бүсийг ашиглана. Төлөвлөсөн эсвэл архивласан төлөвтэй улирлын үйл ажиллагааны хугацаа хэзээ ч нээгдэхгүй.

## Аюулгүй байдал

### `security:create-administrator`

- Зориулалт: системийн админы үүрэгтэй бүртгэл үүсгэнэ. Ихэвчлэн `setup:install` дуудна.
- Сонголтууд: `--email=`, `--name=`, `--password-stdin` (нууц үгийг стандарт оролтоос авна. Интерактив бус ажиллуулалтад заавал).
- Аудит: бүртгэнэ (үүсгэсэн хэрэглэгчийн ID)
- Жишээ: `php artisan security:create-administrator --email=admin@example.ac.kr --name="Administrator"`
- Алдаа гарвал: `system_administrator role is missing` нь эхлээд `setup:install` эсвэл `db:seed` ажиллуулах ёстой гэсэн үг. Нууц үг дор хаяж 12 тэмдэгттэй байх ёстой.

### `security:sync-permissions`

- Зориулалт: DB дахь эрхийн жагсаалтыг код дахь эрхийн каталогтой нийцүүлнэ. Шинэ эрхүүдийг үүсгэж, каталогт байхгүй эрхүүдийг устгана (бүх үүргээс хасна). Системийн үүргүүд үргэлж бүх эрхийг авна.
- Хэзээ: байршуулалтын дараа (`setup:install` үүнийг үндсэн өгөгдлийн алхамд хийдэг).
- Сонголтууд: `--dry-run` (зөвхөн үүсгэх/устгах жагсаалтыг хэвлэнэ), `--force` (устгах баталгаажуулалтыг алгасна).
- Аудит: бүртгэнэ (үүсгэсэн/устгасан эрхүүд)
- Гаралтыг унших: `create` болон `delete` мөрүүд. Устгах зүйл байвал баталгаажуулах асуулт гарна.
- Алдаа гарвал: баталгаажуулалтад "үгүй" гэж хариулбал код 1-ээр гарч, юуг ч өөрчлөхгүй.

### `security:reset-mfa`

- Зориулалт: хэрэглэгчийн хоёр шатлалт баталгаажуулалтыг (баталгаажуулах апп, и-мэйлийн код, сэргээх код, санасан төхөөрөмж) шинэчилнэ. Хэрэглэгч дараагийн нэвтрэлтээр дахин бүртгүүлнэ. Удирдлагын самбарт нэвтэрч чадах админ байхгүй үед (жишээ нь цорын ганц админ утсаа гээсэн) ашиглана. Бусад тохиолдолд удирдлагын самбарын **Хэрэглэгчид > Хоёр шатлалт баталгаажуулалтыг шинэчлэх**-ийг ашиглана.
- Аргумент/сонголтууд: `{user}` хэрэглэгчийн и-мэйл, `--reason=` (заавал), `--actor=` (заавал. Шинэчлэх шийдвэр гаргасан админ).
- Аудит: бүртгэнэ (үйлдлийн бүртгэл болон аюулгүй байдлын бүртгэлийн аль алинд, шалтгаантай нь)
- Жишээ: `php artisan security:reset-mfa admin@example.ac.kr --reason="Phone lost, identity verified by phone call" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- Зориулалт: буруу нууц үгийг давтан оруулснаас түгжигдсэн бүртгэлийг түгжээний хугацаа дуусахаас өмнө тайлна. Удирдлагын самбарын **Хэрэглэгчид > Нэвтрэлтийн түгжээг тайлах**-тай ижил.
- Аргумент/сонголтууд: `{user}` хэрэглэгчийн и-мэйл, `--reason=` (заавал).
- Аудит: бүртгэнэ (аюулгүй байдлын бүртгэлд ч)
- Гаралтыг унших: `The account is not locked.` нь юу ч өөрчлөгдөөгүй гэсэн үг.
- Тайлбар: түгжээний босго (амжилтгүй оролдлого, түгжээний үргэлжлэх хугацаа)-г удирдлагын самбарын **Тохиргоо > Нэвтрэх аргууд** хэсэгт тохируулна.

## Хувь хүмүүс ба оюутны бүртгэл

### `people:find-duplicates`

- Зориулалт: нэг хүн байж болзошгүй хувь хүмүүсийг жагсаана. Шалгуур нь ижил регистрийн дугаар (хайлтын хэш), эсвэл ижил латин үсгийн нэр ба төрсөн огноо. Нэгтгэгдсэн хувь хүмүүсийг хасна.
- Сонголтууд: `--limit=100` (хэвлэх бүлгийн тоо).
- Аудит: бүртгэхгүй (зөвхөн унших)
- Exit code: давхардлын нэр дэвшигч байвал 2.
- Дараагийн алхам: бүлэг бүрийг удирдлагын самбарын **Хувь хүмүүс** хэсэгт хянаж, нэг хүн бол үлдээх хувь хүний хуудаснаас **Давхардлыг нэгтгэх**-ийг ажиллуулна. Нэгтгэлийг буцаах боломжгүй ([Админы гарын авлагын 14-р бүлэг](../admin/14-merge-and-invitations.md)).

## Элсэлт

### `admission:matriculate`

- Зориулалт: элсэлтийн үеийн элсэлтээ баталгаажуулсан өргөдөл гаргагчдад оюутны бүртгэл (шинэ оюутны код) үүсгэнэ. Удирдлагын самбарын **Элсэлт > Өргөдлүүд** дэх бөөнөөр хийх **Оюутны бүртгэл үүсгэх** үйлдэлтэй ижил. Өргөдөл гаргагч бүрийг тусад нь боловсруулдаг тул нэг алдаа бусдыг зогсоохгүй.
- Аргумент/сонголтууд: `{cycle}` элсэлтийн үеийн код, `--term=` (заавал. Элсэлтийн улирлын код, жишээ нь `2027-SP`. Элсэлтийн огноо нь улирлын эхний өдөр), `--actor=` (заавал. `Тэнцсэн өргөдөл гаргагчид оюутны бүртгэл үүсгэх` эрхтэй бүртгэл. Зөвхөн тэр бүртгэлийн эрхийн хамрах хүрээнд байгаа өргөдөл гаргагчдыг боловсруулна), `--dry-run` (зөвхөн хамрах жагсаалт).
- Аудит: бүртгэнэ (элсэлтийн үе, улирал, хамрах тоо, үүсгэсэн тоо, амжилтгүй өргөдлийн дугаарууд). Өргөдөл гаргагч бүрд үйлдлийн бичлэг (`application.matriculated`) мөн бичигдэнэ.
- Exit code: аль нэг өргөдөл гаргагч амжилтгүй бол 2.
- Жишээ: `php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- Алдаа гарвал: `not ready` нь оюутны бүртгэл аль хэдийн байгаа эсвэл өргөдөл гаргагч элсэлтээ баталгаажуулсан төлөвт биш гэсэн үг; `program is not in effect` нь элсэлтийн огноонд хөтөлбөр хүчин төгөлдөр биш гэсэн үг (Лавлах мэдээлэл > Хөтөлбөрүүд хэсэгт хүчинтэй хугацааг шалгана).

### `admission:expire-drafts`

- Зориулалт: хаагдсан элсэлтийн үеийн ноорог өргөдлүүд болон тохируулсан хугацаанд (**Тохиргоо > Элсэлт > Хөндөгдөөгүй ноорогийг хүчингүй болгох хугацаа (хоног)**, анхдагч 90 хоног) хөндөгдөөгүй ноорог өргөдлүүдийг **Хугацаа дууссан** гэж тэмдэглэнэ. Хугацаа дууссан өргөдөл нь ижил элсэлтийн үед шинэ өргөдөл гаргахад саад болохгүй.
- Хэзээ: төлөвлөгдсөн (өдөр бүр 03:10, [Төлөвлөгдсөн ажил](scheduled-jobs.md)).
- Сонголтууд: `--dry-run` (зөвхөн тоо).
- Аудит: бүртгэнэ (хугацаа дууссан тоо)

## Хичээлийн бүлэг

### `section:copy`

- Зориулалт: өмнөх улирлын бүлгүүдээс шинэ улирлын төлөвлөлтийг эхлүүлнэ. Удирдлагын самбарын **Бүлгүүд > Өөр улирлаас хуулах**-тай ижил. Цуцлагдаагүй бүлгүүдийг ноорог болгон хуулж, багш (ажилласаар байгаа бол), хичээллэх цаг ба танхим, суудлын хуваарилалт (чөлөөлөх цагийг улирлын эхлэх огнооны зөрүүгээр шилжүүлнэ) болон силлабусыг (хаалттай ноорог болгон) хамт хуулна. Хичээлийн хувилбарыг шинэ хичээллэх хугацааны эхэнд хүчин төгөлдөр байгаа хувилбараар солино.
- Аргумент/сонголтууд: `{from-term}`, `{to-term}` улирлын кодууд (жишээ нь `2026-FA`), `--org-unit=*` (зөвхөн энэ бүтцийн нэгжийн кодын бүлгүүд), `--dry-run` (зөвхөн үр дүн, юу ч хадгалахгүй), `--actor=` (заавал. Зөвхөн тэр бүртгэлийн `Бүлэг төлөвлөх` эрхийн хамрах хүрээнд байгаа бүлгүүдийг хуулна).
- Аудит: бүртгэнэ (хуулсан, алгассан, хянах шаардлагатай тоо)
- Гаралтыг унших: `skipped` нь зорилтот улиралд ижил бүлгийн код аль хэдийн байгаа эсвэл хүчин төгөлдөр хичээлийн хувилбар байхгүй гэсэн үг; `note` нь бүлгийг хуулсан ч ямар нэг зүйл орхигдсон гэсэн үг (танхим аль хэдийн эзлэгдсэн тул танхимгүй хуулсан, тэтгэвэрт гарсан багш гэх мэт). Хичээллэх хугацааг кодоор нь тааруулна; байхгүй бол бүлэг бүтэн улирлын хичээллэх хугацаанд орно.
- Жишээ: `php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- Зориулалт: хичээлийн хуваарийг нийтлэхээс өмнө улирлын бүлгүүдийг шалгана. Танхим болон багшийн давхар захиалгаас DB аль хэдийн сэргийлдэг; энэ команд DB зөвшөөрдөг асуудлуудыг олно: танхимын багтаамжаас их багтаамж, хичээллэх хугацааны эхлэх огноонд хүчин төгөлдөр биш хичээлийн хувилбар, тэтгэвэрт гарсан багш, багтаамжаас их суудлын хуваарилалт, хичээллэх хугацаанаас гадуурх хичээлийн цагийн огноо. Мөн нөөцөөс сэргээх зэргээр хязгаарлалтгүйгээр орж ирсэн өгөгдөл дэх танхимын давхцлыг шалгана.
- Аргумент: `{term}` улирлын код.
- Аудит: бүртгэхгүй (зөвхөн унших)
- Exit code: асуудал байвал 2. Багш эсвэл танхим хараахан оноогдоогүй бүлгүүдийг зөвхөн мэдээлэл болгон харуулна.

## Хичээл сонголт

### `registration:preflight`

- Зориулалт: хичээл сонголтыг нээхээс өмнө улирлыг шалгана. Хичээл сонголт болон нэмэх/хасах үйл ажиллагааны хугацаа, дүрмийн багц, нийтлэгдсэн бүлгийн тоо, багтаамж 0 бүлгүүд, багтаамжаас их суудлын хуваарилалт, хичээллэх хугацааны эхлэх огноонд хүчин төгөлдөр биш хичээлийн хувилбар, кредитийн хязгаарт хамрагдаагүй идэвхтэй оюутны тоо, хичээл сонголтын хоригтой оюутны тоог харуулна.
- Аргумент: `{term}` улирлын код (жишээ нь `2027-SP`).
- Аудит: бүртгэхгүй (зөвхөн унших)
- Exit code: асуудал байвал 2. Дүрмийн багц байхгүй бол асуудал биш, мэдээлэл болгон харуулна (дүрмийн анхдагч утга хэрэгжинэ).
- Жишээ: `php artisan registration:preflight 2027-SP`

### `registration:simulate`

- Зориулалт: оюутан одоо (эсвэл заасан цагт) бүлэгт бүртгүүлбэл юу болохыг дүрэм тус бүрээр харуулна. Юу ч хадгалахгүй, оролдлого бүртгэхгүй. "Яагаад бүртгүүлж чадахгүй байна вэ?" гэсэн асуултад ашиглана.
- Аргументууд: `{student-number}` оюутны код, `{section}` `хичээлийн индекс-бүлгийн код` (жишээ нь `CSE2010-01`).
- Сонголтууд: `--term=` (улирлын код. Анхдагч нь тухайн бүлэгтэй хамгийн сүүлийн улирал), `--at=` (үнэлэх цаг. Жишээ нь `"2027-02-10 10:00 Asia/Seoul"`).
- Аудит: бүртгэхгүй (зөвхөн унших)
- Гаралтыг унших: дүрэм тус бүрээр тэнцсэн/тэнцээгүй, хориглох/анхааруулах болон мессеж. Онцгой зөвшөөрлөөр хамрагдсан дүрэм тэнцээгүй гэж харагдах ч хориглохгүй. Багтаамжийг дүрмийн хүснэгтийн доор тусад нь харуулна.
- Exit code: бүртгэлээс татгалзах байсан бол 2.

### `waitlist:promote`

- Зориулалт: сул суудалтай бүлгүүдэд хүлээлгийн жагсаалтад байгаа оюутнуудыг дарааллаар нь бүртгэнэ. Дэвшүүлэх үед бүх дүрмийг дахин шалгах бөгөөд дүрэмд тэнцээгүй хүлээлгийн бичлэгүүдийг жагсаалтаас хасна (шалтгааныг бүртгэнэ). Хичээл сонголт болон нэмэх/хасах үйл ажиллагааны хугацаа хоёулаа хаагдсан бүлгүүдийн хүлээлгийн жагсаалтын хугацаа дуусна. Оюутнууд үр дүнг и-мэйлээр авна.
- Аргумент/сонголтууд: `{term?}` улирлын код (анхдагч: хүлээлгийн бичлэгтэй бүх улирал), `--actor=`.
- Аудит: бүртгэнэ (бүлэг, дэвшүүлсэн, хассан, хугацаа дууссан тоо)
- Хэзээ: хасах, цуцлах эсвэл суудлын хуваарилалтыг чөлөөлөх үед хамаарах бүлгийг дарааллын ажил шууд боловсруулдаг. Энэ команд нь орхигдсон зүйлийг гүйцээх цаг тутмын төлөвлөгдсөн хамгаалалт юм.
- Жишээ: `php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- Зориулалт: чөлөөлөх цаг нь өнгөрсөн суудлын хуваарилалтыг (жишээ нь мэргэжлийн оюутнуудад нөөцөлсөн суудал) боловсруулсан гэж тэмдэглэж, тэдгээр бүлгийн хүлээлгийн жагсаалтаас дэвшүүлэх ажлыг дараалалд оруулна. Нөөцөлсөн суудал нь чөлөөлөх цаг өнгөрмөгц тооцоонд ерөнхий суудал болдог тул энэ команд зөвхөн суудлыг хүлээлгийн жагсаалтад шилжүүлнэ.
- Аудит: бүртгэхгүй (5 минут тутам ажиллана. Дэвшүүлсэн үр дүн хичээлийн бүртгэлд байна)
- Хэзээ: төлөвлөгдсөн (5 минут тутам).

## Дүн

### `term:close`

- Зориулалт: улирлыг хаана. Улирлын бүх дүн баталгаажсан байх ёстой. Оюутан тус бүрд улирлын дүнгийн бүртгэлийг (кредит, улирлын болон нийт голч дүн) тооцоолж, сурлагын байдал (хэвийн, академик сануулга, хасах эсэхийг хянах) болон онц сурлагад тэнцэх эсэхийг (дарааллын багц) тодорхойлж, дараа нь хөтөлбөр тус бүрээр онц сурлагыг эрэмбэлж, улирлын дүнгийн бүртгэлийг албан ёсны бүртгэл болгон хааж, улирлыг **Дүн хаагдсан** төлөвт оруулна. Удирдлагын самбарын **Дүн > Улирлын дүнгийн бүртгэлүүд > Улирал хаах**-тай ижил.
- Аргумент/сонголтууд: `{term}` улирлын код, `--dry-run` (зөвхөн улирлыг хааж болох эсэхийг шалгана), `--reason=` (бичлэгт хадгалах шалтгаан), `--actor=`.
- Аудит: бүртгэнэ (оюутны тоо, баталгаажаагүй дүнтэй бүлгийн тоо). Хаалт дуусахад `term.closed` аудитын бичлэг академик сануулга, хасах эсэхийг хянах болон онц сурлагын тоог агуулна.
- Exit code: зарим бүлэгт баталгаажаагүй дүн байвал 2 (бүлэг тус бүрийн баталгаажаагүй тоог хэвлэнэ). Улирал нийтлэгдсэн төлөвт биш бол 1.
- Хэзээ: дүн оруулах болон баталгаажуулалт дууссаны дараа. Багцын явцыг Horizon-оос хянана. Дарааллын worker байхгүй бол улирлын төлөв өөрчлөгдөхгүй.
- Жишээ: `php artisan term:close 2026-FA --dry-run`, `php artisan term:close 2026-FA --reason="Fall 2026 grades closed" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- Зориулалт: баталгаажсан дүнгээс улирлын дүнгийн бүртгэлийг (кредит, улирлын болон нийт голч дүн) дахин тооцоолно. Өөрчлөгдсөн дүнгийн бодлогыг (голч дүнгийн аравтын орон, давтан судлах хичээлийн боловсруулалт) өнгөрсөн улирлуудад хэрэглэхэд ашиглана. Сурлагын байдал болон онц сурлага улирал хаах үед тогтоосон утгаа хадгална. Батлагдсан дүнгийн засвар тухайн оюутныг автоматаар дахин тооцоолдог тул үүнд энэ команд хэрэггүй.
- Сонголтууд: `--term=` (тухайн улиралд дүнтэй оюутнууд, тухайн улирлаас хойш), `--student-number=` (нэг оюутан), `--reason=` (заавал), `--actor=`.
- Аудит: бүртгэнэ (оюутны тоо, шалтгаан)
- Жишээ: `php artisan grades:recalculate --term=2026-SP --reason="GPA changed to three decimal places"`

### `grades:remind-missing`

- Зориулалт: дүнгээ хараахан илгээгээгүй (оруулаагүй эсвэл ноорог болгон хадгалсан) бүлгүүдийн багш нарт и-мэйл илгээнэ. Бүлгүүдийг багш тус бүрээр нэг мессежид бүлэглэнэ.
- Аргумент/сонголтууд: `{term}` улирлын код, `--dry-run` (илгээхгүйгээр хамрах хүрээг хэвлэнэ), `--actor=`.
- Аудит: бүртгэнэ (бүлэг, багш, илгээсэн мессеж)
- Хэзээ: дүн оруулах үйл ажиллагааны хугацаа хаагдахаас хэд хоногийн өмнө. Шаардлагатай бол төлөвлөгдсөн ажилд нэмнэ.

## Хичээлийн үнэлгээ

### `evaluation:remind`

- Зориулалт: хичээлийн үнэлгээний хугацаа нээлттэй байх үед үнэлгээ өгөөгүй хичээлтэй оюутнуудад и-мэйл илгээнэ. Үлдсэн хичээлүүдийг оюутан тус бүрээр нэг мессежид бүлэглэнэ.
- Аргумент/сонголтууд: `{term}` улирлын код, `--dry-run` (зөвхөн хамрах оюутны тоо, юу ч илгээхгүй), `--actor=`.
- Аудит: бүртгэнэ (хамрах оюутан, илгээсэн мессеж)
- Хэзээ: үнэлгээний хугацаанд нэг юмуу хоёр удаа. Шаардлагатай бол төлөвлөгдсөн ажилд нэмнэ.

### `evaluation:publish-results`

- Зориулалт: улирлын хичээлийн үнэлгээний үр дүнг багш нарт нийтэлнэ. Удирдлагын самбарын **Хичээлийн үнэлгээ > Улирлын үнэлгээнүүд > Үр дүн нийтлэх**-тэй ижил. Нийтэлсний дараа ч үр дүн зөвхөн хариултын хамгийн бага тоо болон хариултын хувьд хүрсэн бүлгүүдэд харагдана.
- Аргумент/сонголтууд: `{term}` улирлын код, `--actor=`.
- Аудит: бүртгэнэ (хариултын тоо, аль хэдийн нийтлэгдсэн эсэх)
- Хэзээ: үнэлгээний хугацаа болон дүнгийн боловсруулалт дууссаны дараа. Аль хэдийн нийтлэгдсэн улиралд өөрчлөлт оруулахгүй.

## Тодорхойлолт

### `certificate:verify`

- Зориулалт: тодорхойлолтын баталгаажуулах кодыг нийтийн баталгаажуулах хуудастай ижил шалгуураар шалгана. Төрөл, олгосон дугаар, олгосон огноо болон далдалсан эзэмшигчийг хэвлэнэ.
- Аргумент/сонголтууд: `{code}` баталгаажуулах код.
- Аудит: байхгүй (зөвхөн унших)

### `certificate:render`

- Зориулалт: олгосон тодорхойлолтын PDF-ийг одоогийн өгөгдөл болон загвараар дахин үүсгэж, архивласан файлыг солино. Удирдлагын самбарын **Олгосон тодорхойлолтууд > Дахин үүсгэх**-тэй ижил. Олгосон дугаар болон баталгаажуулах код хэвээр үлдэнэ; checksum өөрчлөгдөнө.
- Аргумент/сонголтууд: `{issue}` олгосон дугаар, `--reason=` (заавал), `--actor=`.
- Аудит: бүртгэнэ (олгосон дугаар, шинэ checksum)
- Хэзээ: загвар эсвэл нэрийн бичлэгийг зассаны дараа тодорхой тодорхойлолтыг дахин үүсгэхэд.

## Шалгалт

- Аргумент/сонголтууд: `{type}` шалгалтын төрлийн код / `{held_date}` шалгалтын огноо `YYYY-MM-DD` / `{file}` толгой мөртэй UTF-8 CSV, `--actor=` (заавал), `--dry-run` (зөвхөн мөрийн шалгалт, юу ч бүртгэхгүй).

- Аргумент/сонголтууд: `{type}` шалгалтын төрлийн код / `{held_date}` шалгалтын огноо, `--actor=` (заавал).

- Хэзээ: дүн оруулж дууссаны дараа. Аль хэдийн нийтлэгдсэн шалгалтын хуваарь бол амжилтгүй болно.

## Ирц

### `attendance:generate-sessions`

## Төгсөлт

### `degree-audit:run`

- Зориулалт: идэвхтэй оюутан бүрд төгсөлтийн шаардлагын шалгалтыг хадгална. Удирдлагын самбарын **Төгсөлтийн шалгалтууд > Шалгалт ажиллуулах**-тай ижил. Хамгийн сүүлд хадгалсан шалгалт нь төгсөлтийн боловсруулалтын үндэс болно.
- Сонголтууд: `--term=` (шалгалт хамаарах улирлын код), `--student-number=` (нэг оюутан), `--min-year-level=` (зөвхөн энэ курс ба түүнээс дээш), `--actor=`.
- Аудит: бүртгэнэ (оюутны тоо, шаардлага хангасан тоо)
- Хэзээ: төгсөлтийн хяналтын өмнө (улирлын төгсгөл), мөн шаардлагын багц эсвэл дүйцэх хичээлийг өөрчилсний дараа.

## LMS холболт

### `lms:sync`

- Зориулалт: нийтлэгдсэн бүлгүүдийг платформ руу илгээнэ (хичээл үүсгэх ба холбох, багш нар, бүртгүүлсэн оюутнууд). Удирдлагын самбарын **Хичээлийн холбоосууд > Дахин синхрончлох**-ын хийдэг зүйлийг бүтэн улиралд хийнэ. Аль хэдийн холбогдсон бүлгүүдийг зөвхөн дахин баталгаажуулна (idempotent).
- Аргумент/сонголтууд: `{platform}` платформын код, `--term=` (улирлын код, анхдагч нь дуусаагүй бүх улирал), `--section=` (нэг хичээлийн индекс-бүлгийн код), `--dry-run` (илгээх байсан зүйлийг зөвхөн "skipped" гэж бүртгэнэ), `--actor=`.
- Аудит: бүртгэнэ (платформ, бүлэг, гишүүд, алдаа)
- Exit code: аль нэг бүлэг амжилтгүй бол 2.

### `lms:reconcile`

- Зориулалт: платформын хичээлийн нэрсийн жагсаалтыг оюутны мэдээллийн систем дэх бүртгэлийн жагсаалттай харьцуулж, дутуу гишүүдийг нэмж, илүү гишүүдийг хасна. Зөрүүг синхрончлолын бүртгэлд (`reconcile`) хадгална.
- Аргумент/сонголтууд: `{platform?}` (орхивол бүх идэвхтэй платформ), `--term=`, `--dry-run` (зөвхөн зөрүүг бүртгэнэ), `--actor=`.
- Аудит: бүртгэнэ (платформ тус бүрийн бүлэг, нэмсэн/хассан/амжилтгүй тоо)
- Хэзээ: өдөр бүр 02:30-д төлөвлөгдсөн. Платформын тасалдлын дараа гараар ажиллуулна.

## Ашиглалтын шалгалт ба цэвэрлэгээ

### `system:health-check`

- Зориулалт: тохиргоо ба түлхүүр (APP_KEY, PII түлхүүрүүд, APP_DEBUG), DB-ийн холболт ба ролиуд (runtime, migrator, reporting), хувийн мэдээллийн хүснэгтүүдийн RLS, хүлээгдэж буй миграц, эрхийн каталогийн синхрончлол, Redis, дараалал (Horizon), Gotenberg, медиа хадгалалтад бичих болон төлөвлөгчийн heartbeat-ийг шалгана.
- Сонголтууд: `--json` (мониторингийн гаралт).
- Аудит: байхгүй (зөвхөн унших)
- Exit code: аль нэг шалгалт амжилтгүй бол 2.
- Хэзээ: байршуулсны дараа шууд, тасалдал сэжиглэгдэх үед, мониторингоос тогтмол.

### `audit:seal`

- Зориулалт: аудитын хүснэгтүүдийн шинэ мөрүүдийг хэш гинжинд холбоно ([Аудитын бүрэн бүтэн байдал](audit-and-maintenance.md)).
- Сонголтууд: `--table=` (record_changes, activity_log, security_events-ийн аль нэг; давтаж болно), `--actor=`.
- Аудит: бүртгэнэ (хүснэгт тус бүрийн битүүмжилсэн мөр)
- Хэзээ: өдөр бүр 03:30-д төлөвлөгдсөн.

### `audit:verify-chain`

- Зориулалт: аудитын мөрүүдийн агуулгын хэш болон гинжийг дахин тооцоолж, хуурамчаар өөрчилсөн, устгасан, дарааллыг өөрчилсөн байдлыг илрүүлнэ.
- Сонголтууд: `--table=`.
- Аудит: байхгүй (зөвхөн унших)
- Exit code: зөрүү байвал 2.
- Хэзээ: нөөцлөхийн өмнө, аюулгүй байдлын хяналтын үеэр, цэвэрлэсний дараа.

### `audit:prune`

- Зориулалт: хадгалах хугацаа нь дууссан **битүүмжлэгдсэн** аудитын мөрүүдийг устгана. Схемийн эзэмшигчийн холболтоор ажиллана.
- Сонголтууд: `--before=YYYY-MM-DD` (заавал), `--table=`, `--dry-run` (зөвхөн тоо), `--actor=`.
- Аудит: бүртгэнэ (хязгаар огноо, хүснэгт тус бүрийн устгасан мөр)
- Хэзээ: хадгалах бодлогын дагуу, нөөцөлсний дараа.

### `media:prune-orphans`

- Зориулалт: эзэмшигч нь байхаа больсон медиа мөрүүд болон мөргүй директоруудыг устгана (хувь хүний зураг, өргөдлийн баримт, тодорхойлолтын PDF, шалгалтын нотлох баримт).
- Сонголтууд: `--dry-run` (зөвхөн жагсаалт), `--actor=`.
- Аудит: бүртгэнэ (мөр, директор)
- Хэзээ: сар бүр эсвэл их хэмжээний устгалтын дараа.

## Хувийн мэдээллийн шифрлэлтийн түлхүүр

### `pii:generate-key`

- Зориулалт: `PII_ENCRYPTION_KEY` болон `PII_HASH_KEY`-д зориулсан шинэ түлхүүр хэвлэнэ. Юу ч хадгалахгүй.
- Аудит: бүртгэхгүй
- Анхааруулга: `PII_HASH_KEY`-г өөрчилбөл бүх хайлтын хэш хүчингүй болно. Түлхүүр солих журам [security-keys.md](security-keys.md)-д байна.

### `pii:reencrypt`

- Зориулалт: түлхүүр солисны дараа өмнөх түлхүүрээр шифрлэгдсэн хувийн мэдээллийг одоогийн түлхүүрээр дахин шифрлэнэ. Дарааллын багцаар ажиллана.
- Аргумент: загварын класс (одоогоор `App\\Models\\Person\\Person`).
- Сонголтууд: `--chunk=500`, `--dry-run` (зөвхөн өмнөх түлхүүр ашиглаж буй бичлэгийг тоолно), `--force`.
- Аудит: бүртгэнэ (багцын ID, ажлын тоо / урьдчилан харах тоо)
- Шалгах: багцын явцыг Horizon-оос (`/horizon`) хянана. Дуусаад `--dry-run` 0 гэж мэдээлбэл өмнөх түлхүүрийг `PII_PREVIOUS_KEYS`-ээс хасна.

## Хэлний дэмжлэг

### `i18n:missing`

- Зориулалт: хэл тус бүрээр үндсэн хэлтэй (en) харьцуулахад дутуу түлхүүрүүд болон ашиглагдахаа больсон түлхүүрүүдийг харуулна.
- Аргумент/сонголтууд: `{locale?}` (зөвхөн нэг хэл), `--strict` (түлхүүр дутуу бол exit code 2. CI-д ашиглана).
- Аудит: бүртгэхгүй

### `i18n:export`

- Зориулалт: орчуулагчдад өгөх JSON файл үүсгэнэ. Формат: `{"key": {"source": "English text", "translation": "translation"}}`.
- Аргумент/сонголтууд: `{locale} {path}`, `--missing` (зөвхөн дутуу түлхүүрүүд).
- Аудит: бүртгэхгүй
- Жишээ: `php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- Зориулалт: орчуулагчдын бөглөсөн JSON-г `lang/{locale}`-д хэрэглэнэ. Зөвхөн үндсэн хэлэнд байгаа түлхүүрүүдийг оруулна; хоосон орчуулгыг үл тооно.
- Аргумент/сонголтууд: `{locale} {path}`, `--dry-run` (бичигдэх түлхүүрүүдийн жагсаалтыг л хэвлэнэ).
- Аудит: бүртгэнэ
- Анхааруулга: орчуулгын файлуудыг репозиторид удирддаг. Оруулсны дараа өөрчлөлтийг commit хийнэ.

## Шалгалтууд

### `naming:check`

- Зориулалт: миграц дахь хүснэгт болон баганын нэрийг [нэршлийн дүрэм](../../../development/naming.md)-тэй тулгаж шалгана.
- Сонголтууд: `--path=*` (шалгах директорууд, анхдагч `database/migrations`).
- Аудит: бүртгэхгүй
- Exit code: асуудал байвал 2.

### `pdf:sample`

- Зориулалт: Хангыль, CJK, лао, тай, деванагари, кирилл болон латин бичгийг холилдуулсан хүснэгтийг PDF болгон үүсгэж, фонт болон PDF үйлчилгээтэй (Gotenberg) холболтыг шалгана.
- Аргумент: `{path=pdf-sample.pdf}` (локал диск `storage/app/private`-ээс харьцангуй).
- Аудит: бүртгэхгүй
- Алдаа гарвал: холболтын алдаа бол `GOTENBERG_URL` болон Gotenberg контейнерын төлөвийг шалгана.
