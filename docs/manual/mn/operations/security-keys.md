# Түлхүүрийн удирдлага

- Зориулалт: МТ-ийн ашиглалтын ажилтнууд

| Түлхүүр | Зориулалт | Алдвал | Солих |
|---|---|---|---|
| `APP_KEY` | Сесс, күүки, хоёр шатлалт баталгаажуулалтын нууц, санасан төхөөрөмжийн күүкийн гарын үсэг | Бүх хэрэглэгч системээс гарна; бүртгүүлсэн хоёр шатлалт баталгаажуулалт (баталгаажуулах апп) ажиллахаа больно | Өмнөх түлхүүрийг `APP_PREVIOUS_KEYS`-д хийгээд солино |
| `PII_ENCRYPTION_KEY` | Регистрийн дугаар зэрэг хувийн мэдээллийн шифрлэлт | **Шифрлэгдсэн хувийн мэдээллийг сэргээх боломжгүй** | Доорх журмаар |
| `PII_HASH_KEY` | Хувийн мэдээллийг яг таарцаар хайх хэш | Хайлт ажиллахаа больно (өгөгдөл хэвээр үлдэнэ) | Зарчмын хувьд солихгүй |

Хадгалах зарчим

- Гурван түлхүүрийг серверийн орчны тохиргооноос гадна нууц хадгалалтад (Vault, үүлэн нууц менежер гэх мэт) эсвэл битүүмжилсэн офлайн хадгалалтад дор хаяж хоёр хуулбараар хадгална.
- Нөөц файлуудтай хамт хэзээ ч хадгалахгүй. DB-ийн нөөц алдагдсан ч түлхүүргүйгээр хувийн мэдээллийг унших боломжгүй байх ёстой.

## Хувийн мэдээллийн түлхүүр солих журам

1. `php artisan pii:generate-key`-ээр шинэ түлхүүр үүсгэнэ (гаралтаас зөвхөн `PII_ENCRYPTION_KEY`-г ашиглана).
2. Одоогийн түлхүүрийг `PII_PREVIOUS_KEYS`-д (хэд хэдэн бол таслалаар тусгаарлана), шинэ түлхүүрийг `PII_ENCRYPTION_KEY`-д хийнэ.
3. Тохиргоог дахин ачаална: `php artisan config:cache`, `php artisan horizon:terminate`.
4. Хувийн мэдээллийн загвар тус бүрээр `php artisan pii:reencrypt {model} --dry-run`-аар хамаарах бичлэгийн тоог шалгаад `--force`-гүйгээр ажиллуулна.
5. Horizon багцыг дууссан гэж харуулж, `--dry-run` 0 гэж мэдээлсний дараа өмнөх түлхүүрийг `PII_PREVIOUS_KEYS`-ээс хасна.
6. Өмнөх түлхүүрийг нөөцийн хадгалах хугацааны турш битүүмжлэн хадгална (хуучин нөөцийг сэргээхэд хэрэгтэй).
