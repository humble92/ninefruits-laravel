# समस्या समाधान

- पाठक: IT सञ्चालक

| लक्षण | के जाँच गर्ने |
|---|---|
| साइन इन गर्नेबित्तिकै सुरक्षा पृष्ठमा पुनर्निर्देशित हुन्छ | दुई-चरण प्रमाणीकरण नीति "अनिवार्य" छ र छुट अवधि सकिएको छ। प्रयोगकर्ताले दर्ता गरेपछि समाधान हुन्छ। नीति **सेटिङ > सुरक्षा** मा छ |
| प्रशासन प्यानलमा 403 | प्रयोगकर्तासँग `admin_panel.access` अनुमति भएको मान्य भूमिका तोकाइ छैन। **प्रयोगकर्ता र पहुँच > प्रयोगकर्ताहरू > भूमिका तोकाइ** जाँच गर्नुहोस् |
| कुनै मेनु वस्तु देखिँदैन | भूमिकासँग त्यो स्क्रिनको अनुमति छैन (उदाहरणका लागि `roles.view`) |
| इमेल कोड आइपुग्दैन | मेल सेटिङ (`MAIL_*`), सुरक्षा घटनाहरूमध्ये `इमेल कोड पठाइयो` प्रविष्टिहरू, पठाउने सीमा (प्रति मिनेट एक पटक, प्रति घण्टा पाँच पटक) |
| स्क्रिनले अरूको डेटा 0 पङ्क्ति देखाउँछ | सामान्य हुन सक्छ (row level security)। **डेटा परिवर्तनहरू** को प्रयोगकर्ता स्तम्भ हेरेर DB सत्रको कार्यकर्ता सेट भएको पुष्टि गर्नुहोस् |
| `permission denied for schema public` | एप्लिकेसनले `app_runtime` को रूपमा DDL प्रयास गर्‍यो। माइग्रेसन केवल `php artisan migrate` (जसले स्वतः `app_migrator` प्रयोग गर्छ) ले मात्र चलाउनुहोस् |
| `Audit records are append-only` | अडिट तालिका अद्यावधिक वा मेटाउने प्रयास। यो रोक जानाजानी गरिएको हो |
| PDF निर्माण विफल हुन्छ | `php artisan pdf:sample`, Gotenberg को अवस्था, `GOTENBERG_URL` |
| क्यु कार्यहरू अड्किएका छन् | `/horizon` मा विफल कार्यहरू जाँच गर्नुहोस्, `php artisan horizon:status` |

प्रति-अनुरोध ट्रेसिङ: `X-Request-Id` प्रतिक्रिया हेडरको मानले लगहरू, गतिविधि लग, डेटा परिवर्तनहरू र सुरक्षा घटनाहरू सबै एकैसाथ खोज्न सकिन्छ।
