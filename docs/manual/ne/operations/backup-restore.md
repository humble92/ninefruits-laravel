# ब्याकअप र पुनर्स्थापना

- पाठक: IT सञ्चालक

## के ब्याकअप गर्ने

| लक्ष्य | विधि | आवृत्ति (सिफारिस) |
|---|---|---|
| PostgreSQL | `pg_dump -Fc` वा PITR (WAL संग्रह) | दैनिक पूर्ण + निरन्तर WAL |
| फाइल भण्डारण (`storage/app/private` वा S3) | स्न्यापसट वा संस्करण भएको बकेट | DB जस्तै |
| वातावरण कन्फिगरेसन र कुञ्जीहरू | गोप्य भण्डार | प्रत्येक परिवर्तनमा |

DB र फाइल भण्डारण एउटै समय-बिन्दुमा पुनर्स्थापना गर्न सकिने हुनुपर्छ (फोटो र प्रमाणपत्र PDF को मेटाडेटा DB मा रहन्छ)।

## DB ब्याकअपको उदाहरण

```bash
pg_dump -U app_migrator -d sis -Fc -f sis-$(date +%F).dump
```

`app_migrator` सबै स्किमाहरू (`public`, `audit`, `reporting`, `util`) को मालिक हो, त्यसैले यही खाताबाट ब्याकअप लिनुहोस्। भूमिकाहरू (`app_*`) क्लस्टर वस्तु हुन् र डम्पमा समावेश हुँदैनन्। पुनर्स्थापना सर्भरमा, [स्थापना](installation.md) को खण्ड 2 मा वर्णन गरेअनुसार पहिले भूमिकाहरू बनाउनुहोस्।

## पुनर्स्थापनाको उदाहरण

```bash
createdb -U postgres sis_restore
psql -U postgres -d sis_restore -f database/sql/roles/prepare_database.sql
pg_restore -U app_migrator -d sis_restore --no-owner --role=app_migrator sis-2026-10-22.dump
```

## पुनर्स्थापना अभ्यास

प्रत्येक त्रैमासिकमा छुट्टै सर्भरमा पुनर्स्थापना गरी निम्न कुराहरू प्रमाणित गर्नुहोस्: साइन इन, व्यक्तिगत विवरणको डिक्रिप्सन (कुञ्जीहरू मेल खान्छन्), अडिट अभिलेख हेर्ने, फाइलहरू (फोटो, PDF) खोल्ने।
