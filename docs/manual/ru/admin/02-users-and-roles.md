# 2. Пользователи и роли

## Основные понятия

| Термин | Значение |
|---|---|
| Разрешение | Право пользоваться одной функцией. Примеры: `Просматривать пользователей`, `Сбрасывать двухфакторную аутентификацию` |
| Роль | Набор разрешений. Примеры: сотрудник учебного отдела, методист кафедры |
| Назначение роли | Предоставление пользователю роли с областью действия и сроком |
| Область действия | Где действует роль: **Все**, **Подразделение** (институт, кафедра и т. п.) или **Программа** |
| Роль категории пользователя | Абитуриент, студент, выпускник, преподаватель, куратор. Предоставляется автоматически на основе учебных данных; назначить вручную нельзя |

При изменении обязанностей меняется только состав ролей или назначения, сама программа не меняется. Каждое изменение записывается в журнал аудита.

## Создание учётной записи пользователя

1. Перейдите в **Пользователи и доступ > Пользователи** и нажмите **Создать**.
2. Введите имя, адрес электронной почты и язык, затем сохраните.
3. Пользователь получит по электронной почте ссылку для установки пароля. Администраторы пароль никогда не видят.

Учётные записи не удаляются. Чтобы прекратить действие учётной записи, например при увольнении, откройте страницу **Изменить** пользователя и отключите **Активен**. Неактивная учётная запись не может войти в систему и теряет все разрешения. Уже открытые экраны выходят из системы при следующем запросе.

Ограничения при изменении учётных записей

- Нельзя деактивировать собственную учётную запись.
- Нельзя изменять учётную запись, у которой есть разрешения, которых нет у вас (администратор с более высокими полномочиями).
- Изменение адреса электронной почты сбрасывает его подтверждение, завершает все сеансы этого пользователя и записывает событие безопасности `Эл. почта изменена`.
- Когда пользователь меняет пароль, сеансы на других устройствах и автоматический вход («запомнить меня») завершаются, а также записывается событие безопасности `Пароль изменён`.

## Создание и изменение ролей

1. Перейдите в **Пользователи и доступ > Роли** и нажмите **Создать** или **Изменить** у нужной роли.
2. **Внутреннее имя** состоит из строчных латинских букв и символов подчёркивания (например, `exam_office`). После создания его лучше не менять.
3. Введите **Отображаемое название** на каждом языке. Английское название обязательно. Если очистить поле языка, название на этом языке удаляется.
4. В разделе **Разрешения** отметьте разрешения по функциям. При сохранении добавленные и удалённые разрешения записываются в журнал аудита.

| Вид роли | Изменение | Удаление |
|---|---|---|
| Системная роль (системный администратор) | Только название. Всегда имеет все разрешения | Невозможно |
| Роль категории пользователя | Отображаемое название и разрешения. Внутреннее имя — нет | Невозможно |
| Обычная роль | Всё | Только если у неё нет действующих назначений |

## Назначение ролей

1. Перейдите в **Пользователи и доступ > Пользователи**, откройте пользователя и прокрутите страницу до списка **Назначения ролей** внизу.
2. Нажмите **Назначить роль** и укажите роль, область действия, начало и окончание (необязательно), а также **Причина**.
   - Если областью действия является подразделение или программа, выберите его в поле **Объект области действия**. При выборе подразделения включаются все подчинённые ему подразделения.
   - Оставьте начало пустым, чтобы назначение действовало сразу; оставьте окончание пустым для бессрочного назначения.
3. Назначения никогда не изменяются. Чтобы изменить назначение, воспользуйтесь действием **Завершить назначение** у существующего назначения (причина обязательна) и создайте новое. История при этом сохраняется.

Нельзя завершать собственные назначения (разделение обязанностей). Обратитесь к другому администратору.

Правила, предотвращающие повышение полномочий

- Нельзя назначить роль самому себе.
- Нельзя назначить роль, содержащую разрешения, которых нет у вас.
- Область действия можно выбирать только в пределах области действия вашего собственного разрешения `Назначать роли и завершать назначения`. Например, администратор, имеющий его для Инженерного института, не может назначить область действия «Все» или область другого института.
- Команду `security:create-administrator`, которая создаёт первого администратора, запускает оператор сервера, поэтому эти правила на неё не распространяются.
