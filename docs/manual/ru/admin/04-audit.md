# 4. Аудит

Три экрана в меню **Аудит** доступны только для чтения; никто не может их изменять или удалять (требуются разрешения `Просматривать записи аудита` и `Просматривать события безопасности`).

| Экран | Что показывает | Примеры |
|---|---|---|
| Журнал действий | Кто что сделал и **почему**. Причина и подробности | Назначение роли (причина: замещение на время семестра), изменение разрешений (список добавленных и удалённых), изменение настроек (до и после), запуск команды |
| Изменения данных | Значения строк таблиц до и после изменения. Записываются и прямые изменения в обход приложения | `users` UPDATE, изменённый столбец `locale` |
| События безопасности | Входы, неудачные входы, двухфакторная аутентификация, события, связанные с разрешениями, изменения пароля и адреса электронной почты, очистка аудита (`audit:prune`) | Неудачный вход (имя для входа, IP) |

## Как их читать

- Столбец **Пользователь**: для действий на экране показывается имя пользователя или `user:номер`, для автоматических заданий — `system:job:...`, для команд — `system:command:...`.
- Пароли, секреты двухфакторной аутентификации и подобные значения скрываются как `[redacted]`.
- Записи с одинаковым **ID запроса** созданы одним запросом экрана. Поиск по одному ID запроса на всех экранах показывает полный след одного действия.

## Типичные запросы

| Что нужно узнать | Как |
|---|---|
| Когда изменились разрешения пользователя | В журнале действий: журнал `security`, события `role.assigned`, `role.assignment_revoked` |
| Учётная запись с большим числом неудачных входов | В событиях безопасности отфильтруйте по событию `Неудачный вход` и посмотрите столбец имени для входа |
| Кто изменил политику безопасности | Событие `settings.updated` в журнале действий |
| Как изменилась конкретная строка | В изменениях данных отфильтруйте по таблице и найдите по ID записи |
