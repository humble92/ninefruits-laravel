# 20. Запись на дисциплины

Меню: **Запись на дисциплины > Записи на дисциплины**, **Ограничения**, **Исключения из правил**, **Правила записи на дисциплины**, **Лимиты кредитов**, **Попытки записи**, а также вкладки **Список группы** и **Лист ожидания** на экране редактирования в разделе **Группы**

| Разрешение | Что позволяет |
|---|---|
| `Просматривать записи на дисциплины и списки групп` | Просмотр записей на дисциплины, списков групп и попыток записи |
| `Записывать студентов на дисциплины, отменять запись и оформлять выход за них (с указанием причины)` | Запись сотрудником, отмена записи и выход из дисциплины, удаление из листа ожидания и немедленный перевод из него. При назначении с областью действия «подразделение» — только группы, открываемые этим подразделением |
| `Устанавливать и снимать ограничения, предоставлять исключения из правил` | Ограничения, исключения из правил. При назначении с областью действия — только студенты в этой области |
| `Управлять наборами правил записи и лимитами кредитов` | Наборы правил по семестрам, лимиты кредитов |

Роли по умолчанию: у сотрудника учебного отдела (Registrar) есть все четыре разрешения, у сотрудника учебного управления (Academic Affairs) — просмотр, а также правила и лимиты кредитов, у методиста кафедры — просмотр и корректировка записей (назначается с областью действия кафедры).

## Отличия от прежней системы

- Правила, жёстко зашитые в прежней системе (YUSTIC) по цифрам студенческого номера или кодам кафедр, например лимиты кредитов или исключение дисциплин банка кредитов, стали **настройками семестра**. Прежние правила YUST воспроизводятся профилем установки `yust-legacy` (см. ниже).
- Если запрос отклонён, **все причины показываются сразу** (прежняя система останавливалась на первой). Каждая попытка и результат по каждому правилу сохраняются в разделе **Попытки записи**.
- Ошибка прежней системы в лимите кредитов для факультета сестринского дела со студенческими номерами с 2014 года (применялось 18 кредитов вместо положенных 21) не воспроизводится. Применяется 21 кредит.
- Оформления покупки учебников при записи нет.

## Подготовка семестра

1. **Периоды семестра** ([глава 10](10-terms.md)): корзина записи, запись на дисциплины (поэтапное открытие по курсам), добавление/отказ, выход из дисциплины. Периоды добавления/отказа и выхода из дисциплины задаются для каждого учебного периода.
2. **Правила записи на дисциплины > Подготовить правила для семестра**: выберите семестр и прежний семестр, из которого копировать. Оставьте пустым, чтобы начать со значений по умолчанию. Семестр без набора правил использует значения по умолчанию.
3. **Лимиты кредитов**: лимиты по видам семестров и группам студентов (см. ниже).
4. **Группы**: число мест, зарезервированные места (зарезервированные места и время их открытия), **Размер листа ожидания** ([глава 18](18-sections-and-timetables.md)). Чтобы принимать записи, группа должна быть **опубликована**.
5. **Ограничения**: введите список студентов с ограничениями, например за неоплату обучения (возможен импорт из CSV, [глава 9](09-csv-import.md)).
6. Проверка: `php artisan registration:preflight 2027-SP` ([команды эксплуатации](../operations/commands.md)). Команда сообщает о периодах, наборе правил, числе мест и количестве студентов без лимита кредитов.

## Правила

Все правила проверяются в указанном ниже порядке. **Период, открытость группы и места** применяются всегда и в список не входят.

| Правило | Что проверяет | Параметры |
|---|---|---|
| Период записи | Должен быть открыт период семестра, соответствующий критериям охвата студента. Для отмены записи нужен период записи или период добавления/отказа учебного периода дисциплины; для выхода из дисциплины — период выхода из дисциплины этого учебного периода | Нет |
| Ограничения | Отказ, если ограничение запрещает запись на дисциплины | Нет |
| Статус студента | Записываться могут только студенты с выбранными статусами (по умолчанию «обучается») | Статусы студентов, которым разрешена запись |
| Условия допуска в группу | Критерии допуска и исключения группы | Нет |
| Повторная запись на дисциплину | Дисциплина только один раз за семестр | Нет |
| Пересечение по времени | Отказ, если время пересекается с другой группой, на которую студент записан. Первая и вторая половины семестра с непересекающимися датами не конфликтуют | Допустимое пересечение (минут) |
| Лимит кредитов | Сумма записанных кредитов ≤ применимого лимита кредитов. Дисциплины с выключенным параметром «Учитывается в лимите кредитов» не учитываются | Нет (задаётся на экране «Лимиты кредитов») |
| Пререквизиты | Пререквизиты сданы (эквивалентные дисциплины засчитываются, минимальная оценка); на кореквизиты можно записаться в том же семестре | Нет (задаётся на экране дисциплины) |
| Повторное изучение | Можно ли снова изучать сданную дисциплину | Повторное изучение разрешено, максимум попыток, только при оценке ниже |

У каждого правила есть свои настройки.

- **Включено**: если выключено, правило не проверяется.
- **При невыполнении**: Запретить или Только предупредить. При предупреждении запись проходит, а студент только видит сообщение.
- **Исключения допускаются**: должно быть включено, чтобы действовали исключения из правил и поле «Не применять правила» при записи сотрудником. Для ограничений и повторной записи на дисциплину по умолчанию выключено.

Повторное изучение определяется автоматически, и запись помечается как **Повторное изучение**. Обработка оценок при повторном изучении — этап 6.

## Лимиты кредитов

Укажите вид семестра (пусто: все виды семестров), студентов (курс, год поступления, программа, подразделение, академический статус), максимум кредитов и приоритет. Академический статус устанавливается при закрытии оценок семестра ([глава 21](21-grades.md)). Например, чтобы ограничить студентов с академическим предупреждением 12 кредитами, выберите «Академическое предупреждение» в академическом статусе и задайте лимиту более высокий приоритет, чем общему (так настроены демонстрационные данные). Если студенту соответствует несколько лимитов, применяется только **лимит с наивысшим приоритетом**. Если не соответствует ни один, лимита нет (`registration:preflight` сообщает об этом).

Пример: прежние правила YUST (профиль `yust-legacy`)

| Вид семестра | Студенты | Максимум | Приоритет |
|---|---|---|---|
| 1-й и 2-й семестры | Поступившие в 2014 году или позже, факультет сестринского дела (код подразделения `NURS`) | 21 | 40 |
| 1-й и 2-й семестры | Поступившие в 2014 году или позже | 18 | 30 |
| 1-й и 2-й семестры | Поступившие в 2013 году или раньше, факультет сестринского дела | 20 | 20 |
| 1-й и 2-й семестры | Поступившие в 2013 году или раньше | 17 | 10 |
| Летний и зимний | Поступившие в 2014 году или позже, факультет сестринского дела / остальные | 6 / 5 | 40 / 30 |
| Летний и зимний | Поступившие в 2013 году или раньше | 6 | 10 |

Для дисциплин банка кредитов с кодами, начинающимися с `009` или `900`, выключите у дисциплины параметр «Учитывается в лимите кредитов». Профиль устанавливается командой `setup:install --profile=yust-legacy` (он включает профиль корейского университета).

## Места и лист ожидания

- Место закрепляется в момент записи за счёт блокировки строки группы. Даже когда много студентов записываются одновременно, число мест не превышается.
- **Зарезервированные места** (например, 30 мест для студентов специальности) до времени открытия используются только своими студентами. Оставшиеся зарезервированные места в момент открытия становятся свободными. Портал показывает их как «свободно, зарезервировано, всего».
- Если **Размер листа ожидания** больше 0, студенты могут **Встать в лист ожидания** заполненной группы. Для этого также нужно пройти все правила, кроме мест.
- Когда место освобождается из-за отмены записи, выхода из дисциплины или открытия зарезервированных мест, ожидающие студенты **автоматически переводятся** по очереди. При переводе все правила проверяются снова. Студент, который тем временем записался на другую дисциплину и теперь превышает лимит кредитов или имеет пересечение по времени, удаляется из листа ожидания с записью причины. Студент получает письмо.
- Когда все периоды записи и добавления/отказа закрыты, оставшиеся записи в листе ожидания истекают.
- Число мест нельзя уменьшить ниже числа уже записанных студентов.

Изменить порядок в листе ожидания нельзя. Чтобы поставить определённого студента первым, используйте **Записать студента** (если группа заполнена, увеличьте число мест).

## Экран студента

На портале в разделе **Запись на дисциплины** студент выбирает семестр, ищет по коду или названию дисциплины и записывается, добавляет в корзину или встаёт в лист ожидания. Экран показывает состояние периода записи (открыта, только корзина, время открытия), записанные кредиты относительно лимита кредитов и расписание.

- **Корзина**: в период корзины студенты собирают дисциплины, а после открытия записи нажимают **Записаться на все**. При добавлении в корзину правила проверяются заранее и сообщается о проблемах, но добавлению препятствуют только проверки периода, открытости группы и повторной записи на дисциплину. При записи правила проверяются снова.
- Кнопки отмены записи и выхода из дисциплины меняются в зависимости от периодов семестра. Дисциплина, из которой студент вышел, остаётся в истории как **Выход из дисциплины** (оценка W — этап 6).
- Каждое лицо может отправлять не более 30 запросов в минуту.

## Записи на дисциплины и корректировки сотрудниками

**Записи на дисциплины**: фильтр по семестру и статусу, поиск по студенческому номеру или ФИО. По умолчанию показываются действующие записи текущего (или следующего) семестра.

**Записать студента** (вверху раздела «Записи на дисциплины» или на вкладке **Список группы** группы): введите студенческий номер, группу, правила, которые не применять, и причину.

- Проверяются те же правила, что и для студентов. **Период записи на запись сотрудником не распространяется.**
- «Не применять правила» действует только для правил с включённым параметром **Исключения допускаются**. Открытость группы и места выбрать нельзя (вместо этого увеличьте число мест).
- Результат (записан, добавлен в лист ожидания, отказ с причинами) показывается в уведомлении. Он записывается в журнал действий вместе с причиной.

**Отмена записи и выход из дисциплины**: из строки в разделе «Записи на дисциплины» или на вкладке «Список группы», с указанием причины. Возможны независимо от периодов семестра. Когда место освобождается, следует перевод из листа ожидания.

## Ограничения и исключения из правил

**Ограничения** (прежний запрет записи `SRDENY`): студенческий номер, вид ограничения (Не записан на дисциплины в семестре, Финансовое, Академическое, Административное, Другое), действие (запрещает запись на дисциплины / просмотр оценок / выдачу справок), начало и окончание, причина. Запреты просмотра оценок и выдачи справок по умолчанию выключены. Помимо неоплаты обучения, они служат для административных случаев, когда оценки нужно на время скрыть, например при расследовании нарушения академической честности. При запрете просмотра оценок студент не видит экран оценок на портале и ведомость оценок ([глава 21](21-grades.md)). На экраны сотрудников и ввод оценок преподавателями это не влияет. При запрете выдачи справок сотрудники не могут выдавать справки ([глава 23](23-certificates.md)). Ограничения не удаляются; их **снимают** с указанием причины. Список по умолчанию показывает действующие ограничения.

**Исключения из правил** (прежнее разрешение записи `SRALLOW`): студент, семестр, правило, к чему применяется (пусто: весь семестр, либо определённая группа или дисциплина), срок действия, причина. При исключении запись проходит, даже если это правило не выполнено (при условии, что у правила включён параметр «Исключения допускаются»). Исключением можно открыть и правило периода записи (например, для выпускающегося студента, пропустившего период). Открытость группы и места исключением обойти нельзя. Когда исключение больше не нужно, **отзовите** его (**Отозвать**).

## Попытки записи

Каждая попытка записи, отмены записи, выхода из дисциплины, постановки в лист ожидания, перевода и добавления в корзину сохраняется с временем, результатом, невыполненными правилами и сообщениями, сотрудником или студентом, который её выполнил, и ID запроса. Для вопросов «почему я не смог записаться» ищите по студенческому номеру. Что произойдёт, если студент запишется сейчас, можно посмотреть заранее командой `php artisan registration:simulate {student number} {course code-section number}`.
