# Справочник команд Artisan

- Для кого: ИТ-специалисты по эксплуатации
- Охват: все команды приложения, зарегистрированные в этом репозитории. Добавленную команду необходимо описать и здесь, иначе CI завершится ошибкой (`tests/Feature/Tooling/CommandDocumentationTest.php`).

## Общие соглашения

Каждая команда запускается как `php artisan {command}`. В среде разработки — `./vendor/bin/sail artisan {command}`.

| Пункт | Правило |
|---|---|
| Запись аудита | Команды, изменяющие данные (ниже — «Аудит: записывается»), при каждом запуске заносят в журнал действий (журнал `command`) команду, аргументы, параметры, пользователя ОС, код завершения и результат. Просматривайте их в разделе **Аудит > Журнал действий** панели администрирования |
| ID запуска | Каждый запуск получает ID, начинающийся с `cmd-`, вместо ID запроса. Журнал действий, изменения данных, сделанные этим запуском, и поставленные им задания очереди несут один и тот же ID, поэтому на вопрос «какая команда внесла это изменение» отвечает этот ID. `--actor` — значение, которое указывает оператор, поэтому оно не заносится в столбец пользователя изменений данных (фактический исполнитель — пользователь ОС) |
| `--actor=<email>` | Общий для всех аудируемых команд. Записывает учётную запись ответственного администратора. Неизвестный адрес эл. почты прерывает запуск |
| `--dry-run` | Выводит результат, ничего не изменяя. Доступен для операций, которые трудно отменить |
| `--force` | Выполнение без запросов подтверждения (для расписаний и сценариев развёртывания) |
| `--reason=` | Доступен в командах, требующих указать причину |
| Коды завершения | 0 — успех, 1 — сбой или отмена, 2 — команда проверки обнаружила проблему |
| Контекст БД | Во время выполнения команды исполнитель сессии БД задаётся как `system:command:{command}` и отображается в изменениях данных (триггер) |

## Установка и демонстрационные данные

### `setup:install`

- Назначение: новые установки и обновления. По очереди выполняет миграции, обязательные данные, параметры учебного заведения по умолчанию, профиль установки и создание первого администратора. Повторный запуск безопасен (существующие данные и значения, изменённые администраторами, сохраняются).
- Когда: при первой установке и при каждом развёртывании.
- Параметры: `--institution-name=`, `--locale=` (язык по умолчанию), `--timezone=` (например, `Asia/Seoul`), `--profile=*` (ключ профиля установки), `--grade-scale=` (шкала оценок `4.5` или `4.3`. После установки изменить нельзя. Если не указана — шкала первого профиля), `--admin-email=`, `--admin-name=`, `--force` (выполнение без вопросов. Пароль администратора читается из стандартного ввода).
- Аудит: записывается
- Примеры

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="Demo University" --admin-email=admin@example.ac.kr --admin-name="Administrator"
  ```

- Как читать вывод: `DONE`/`FAIL` для каждого шага. `Administrator exists` означает, что назначение системного администратора уже существует, поэтому создание пропущено.
- При сбое: если ошибка сообщает об отсутствии ключа, занесите в конфигурацию окружения значения, сгенерированные `key:generate` и `pii:generate-key`. Сбой миграции обычно означает, что роли БД не подготовлены (см. руководство по установке).

### `setup:demo`

- Назначение: создаёт с помощью фабрик данные вымышленного университета. Выводит фиксированные демонстрационные учётные записи для каждой роли (`registrar@demo.test` и т. д.).
- Когда: среды разработки, обучения и демонстрации. **В эксплуатационной среде (`APP_ENV=production`) команда не выполняется даже с `--force`.**
- Параметры: `--size=tiny|small|medium|large` (около 20/100/2 000/20 000 студентов. `tiny` — для тестов и быстрых проверок), `--seed=` (одно и то же значение даёт одинаковые данные), `--force`.
- `--student-accounts`: создаёт учётную запись для каждого обучающегося студента (`student{student number}@demo.test`, демонстрационный пароль) и записывает их в `storage/app/private/load-accounts.csv`. Для нагрузочных тестов ([Нагрузочное тестирование](load-testing.md)).
- Аудит: записывается
- Пример: `php artisan setup:demo --size=small --seed=42`
- При сбое: если обязательных данных нет, демонстрационные учётные записи не получают ролей и пропускаются. Сначала выполните `setup:install`.

## Справочные данные и семестры

### `reference:import`

- Назначение: импортирует справочные данные из CSV. Использует те же правила импорта, что и **Импорт CSV** в панели администрирования (существующие строки сопоставляются по коду и обновляются, пустые ячейки переводов сохраняют прежнее значение, отдельно записываются только неудавшиеся строки).
- Аргументы: `{type}` — одно из `org_units`, `programs`, `buildings`, `rooms`, `lookup_values`, `students`, `instructors`, `courses`, `registration_holds` / `{file}` — CSV в UTF-8 со строкой заголовков.
- Параметры: `--actor=` (обязателен. Запись об импорте и уведомление о завершении направляются этой учётной записи), `--chunk=100` (строк на одно задание очереди), `--dry-run` (только проверка заголовков и подсчёт строк).
- Аудит: записывается (тип, имя файла, число строк, число неудавшихся строк)
- Формат столбцов: [глава 9 руководства администратора](../admin/09-csv-import.md).
- Коды завершения: если очередь работает синхронно, результат выводится сразу, а при наличии неудавшихся строк код завершения — 2. Если асинхронно (Horizon), импорт только принимается и код завершения — 0. Результат приходит в виде CSV с неудавшимися строками в уведомлениях панели администрирования учётной записи `--actor`.
- Пример: `php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- Назначение: показывает текущий семестр на заданный момент и открытые периоды семестра (вид, семестр, критерии охвата, время окончания). Используйте её для проверки настройки семестров и периодов или для ответа на вопросы вроде «почему запись на дисциплины не открыта».
- Параметры: `--at=` (по умолчанию — текущий момент. Например, `"2027-02-15 09:00"`. Без часового пояса интерпретируется в часовом поясе сервера (UTC). Пояс можно указать, например, так: `"2027-02-15 09:00 Asia/Seoul"`).
- Аудит: не записывается
- Как читать вывод: решения по датам принимаются в часовом поясе учебного заведения. Периоды семестров в статусе планирования или архива никогда не открываются.

## Безопасность

### `security:create-administrator`

- Назначение: создаёт учётную запись с ролью системного администратора. Обычно вызывается из `setup:install`.
- Параметры: `--email=`, `--name=`, `--password-stdin` (пароль из стандартного ввода. Обязателен при неинтерактивном запуске).
- Аудит: записывается (ID созданного пользователя)
- Пример: `php artisan security:create-administrator --email=admin@example.ac.kr --name="Administrator"`
- При сбое: `system_administrator role is missing` означает, что сначала нужно выполнить `setup:install` или `db:seed`. Пароль должен содержать не менее 12 символов.

### `security:sync-permissions`

- Назначение: приводит список разрешений в БД в соответствие с каталогом разрешений в коде. Новые разрешения создаются; разрешения, отсутствующие в каталоге, удаляются (и снимаются со всех ролей). Системные роли всегда получают все разрешения.
- Когда: после развёртывания (`setup:install` выполняет это в рамках шага обязательных данных).
- Параметры: `--dry-run` (выводит только список создаваемых и удаляемых), `--force` (пропускает подтверждение удаления).
- Аудит: записывается (созданные и удалённые разрешения)
- Как читать вывод: строки `create` и `delete`. При наличии удалений появляется запрос подтверждения.
- При сбое: ответ «нет» на запрос подтверждения завершает команду с кодом 1 без изменений.

### `security:reset-mfa`

- Назначение: сбрасывает двухфакторную аутентификацию пользователя (приложение-аутентификатор, коды по эл. почте, коды восстановления, запомненные устройства). Пользователь подключает её заново при следующем входе. Используйте команду, когда ни один администратор не может войти в панель администрирования (например, единственный администратор потерял телефон). В остальных случаях используйте **Пользователи > Сбросить двухфакторную аутентификацию** в панели администрирования.
- Аргументы/параметры: `{user}` — адрес эл. почты пользователя, `--reason=` (обязателен), `--actor=` (обязателен. Администратор, принявший решение о сбросе).
- Аудит: записывается (в журнал действий и в журнал безопасности, с причиной)
- Пример: `php artisan security:reset-mfa admin@example.ac.kr --reason="Phone lost, identity verified by phone call" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- Назначение: снимает блокировку с учётной записи, заблокированной из-за повторного ввода неверного пароля, до окончания срока блокировки. То же, что **Пользователи > Разблокировать вход** в панели администрирования.
- Аргументы/параметры: `{user}` — адрес эл. почты пользователя, `--reason=` (обязателен).
- Аудит: записывается (также в журнал безопасности)
- Как читать вывод: `The account is not locked.` означает, что ничего не изменено.
- Примечание: пороги блокировки (число неудачных попыток, длительность блокировки) задаются в разделе **Настройки > Способы входа** панели администрирования.

## Лица и личные дела студентов

### `people:find-duplicates`

- Назначение: выводит лица, которые, по-видимому, являются одним и тем же человеком. Критерии — совпадающий номер национального удостоверения личности (поисковый хеш) либо совпадающие имя в латинской транскрипции и дата рождения. Объединённые лица исключаются.
- Параметры: `--limit=100` (число выводимых групп).
- Аудит: не записывается (только чтение)
- Коды завершения: 2, если есть кандидаты в дубликаты.
- Дальнейшие действия: просмотрите каждую группу в разделе **Лица** панели администрирования и, если это один и тот же человек, выполните **Объединить дубликат** на странице лица, которое нужно сохранить. Объединение нельзя отменить ([глава 14 руководства администратора](../admin/14-merge-and-invitations.md)).

## Приём

### `admission:matriculate`

- Назначение: создаёт личные дела студентов (новые студенческие номера) для абитуриентов приёмной кампании с подтверждённым зачислением. То же, что массовое действие **Создать личное дело** в разделе **Приём > Заявления** панели администрирования. Каждый абитуриент обрабатывается отдельно, поэтому сбой по одному не останавливает остальных.
- Аргументы/параметры: `{cycle}` — код приёмной кампании, `--term=` (обязателен. Код семестра зачисления, например `2027-SP`. Датой зачисления считается первый день семестра), `--actor=` (обязателен. Учётная запись с разрешением `Создавать личные дела для принятых абитуриентов`. Обрабатываются только абитуриенты в пределах области действия разрешений этой учётной записи), `--dry-run` (только список охватываемых).
- Аудит: записывается (кампания, семестр, число охватываемых, число созданных, номера неудавшихся заявлений). Для каждого абитуриента также записывается действие (`application.matriculated`).
- Коды завершения: 2, если по какому-либо абитуриенту произошёл сбой.
- Пример: `php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- При сбое: `not ready` означает, что личное дело уже существует или абитуриент не находится в статусе подтверждённого зачисления; `program is not in effect` означает, что программа не действует на дату зачисления (проверьте срок действия в разделе Справочные данные > Программы).

### `admission:expire-drafts`

- Назначение: помечает как **Истёк срок** черновики заявлений закрытых кампаний и черновики, не изменявшиеся в течение заданного срока (**Настройки > Приём > Аннулировать неизменяемые черновики через (дней)**, по умолчанию 90 дней). Заявления с истёкшим сроком не мешают подать новое заявление в той же кампании.
- Когда: по расписанию (ежедневно в 03:10, [Задания по расписанию](scheduled-jobs.md)).
- Параметры: `--dry-run` (только подсчёт).
- Аудит: записывается (число заявлений с истёкшим сроком)

## Учебные группы

### `section:copy`

- Назначение: начинает планирование нового семестра на основе групп предыдущего семестра. То же, что **Группы > Копировать из другого семестра** в панели администрирования. Копирует неотменённые группы как черновики вместе с преподавателями (если они ещё работают), временем занятий и аудиториями, распределением мест (время освобождения сдвигается на разницу дат начала семестров) и рабочей программой (как закрытый черновик). Версия дисциплины заменяется версией, действующей на начало нового учебного периода.
- Аргументы/параметры: `{from-term}`, `{to-term}` — коды семестров (например, `2026-FA`), `--org-unit=*` (только группы подразделения с этим кодом), `--dry-run` (только результаты, ничего не сохраняется), `--actor=` (обязателен. Копируются только группы в пределах области действия разрешения `Планировать группы (преподаватели, время, аудитории)` этой учётной записи).
- Аудит: записывается (число скопированных, пропущенных и требующих проверки)
- Как читать вывод: `skipped` означает, что в целевом семестре уже есть группа с тем же кодом или нет действующей версии дисциплины; `note` означает, что группа скопирована, но что-то было опущено (скопирована без аудитории, потому что аудитория уже занята, преподаватель уволился и т. п.). Учебные периоды сопоставляются по коду; если подходящего нет, группа попадает в учебный период на весь семестр.
- Пример: `php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- Назначение: проверяет группы семестра перед публикацией расписания. Двойное бронирование аудиторий и преподавателей уже исключено на уровне БД; команда находит проблемы, которые БД допускает: вместимость группы больше вместимости аудитории, версия дисциплины, не действующая на дату начала учебного периода, уволившийся преподаватель, распределение мест сверх вместимости, даты занятий вне учебного периода. Она также проверяет конфликты аудиторий в данных, поступивших без ограничений, например при восстановлении из резервной копии.
- Аргументы: `{term}` — код семестра.
- Аудит: не записывается (только чтение)
- Коды завершения: 2, если есть проблемы. Группы, у которых ещё нет преподавателя или аудитории, показываются только для сведения.

## Запись на дисциплины

### `registration:preflight`

- Назначение: проверяет семестр перед открытием записи на дисциплины. Показывает периоды записи и добавления/отказа, набор правил, число опубликованных групп, группы с вместимостью 0, распределения мест сверх вместимости, версии дисциплин, не действующие на дату начала учебного периода, число обучающихся студентов, на которых не распространяется лимит кредитов, и число студентов с ограничением на запись.
- Аргументы: `{term}` — код семестра (например, `2027-SP`).
- Аудит: не записывается (только чтение)
- Коды завершения: 2, если есть проблемы. Отсутствие набора правил показывается для сведения, а не как проблема (применяются правила по умолчанию).
- Пример: `php artisan registration:preflight 2027-SP`

### `registration:simulate`

- Назначение: показывает по каждому правилу, что произошло бы, если бы студент записался в группу сейчас (или в заданный момент). Ничего не сохраняется, попытка не записывается. Используйте для вопросов «почему я не могу записаться?».
- Аргументы: `{student-number}` — студенческий номер, `{section}` — `код дисциплины-код группы` (например, `CSE2010-01`).
- Параметры: `--term=` (код семестра. По умолчанию — последний семестр, в котором есть эта группа), `--at=` (момент оценки. Например, `"2027-02-10 10:00 Asia/Seoul"`).
- Аудит: не записывается (только чтение)
- Как читать вывод: по каждому правилу — пройдено/не пройдено, блокировка/предупреждение и сообщение. Правило, на которое распространяется исключение, показывается как не пройденное, но не блокирует. Вместимость показывается отдельно под таблицей правил.
- Коды завершения: 2, если запись была бы отклонена.

### `waitlist:promote`

- Назначение: по порядку записывает студентов из листа ожидания в группы, где есть свободные места. При продвижении все правила проверяются заново; записи листа ожидания, не прошедшие правило, удаляются из листа (с записью причины). Листы ожидания групп, у которых закрыты и период записи, и период добавления/отказа, аннулируются. Студенты получают результат по эл. почте.
- Аргументы/параметры: `{term?}` — код семестра (по умолчанию — все семестры с записями в листе ожидания), `--actor=`.
- Аудит: записывается (число групп, продвинутых, удалённых, аннулированных)
- Когда: при отмене записи, выходе из дисциплины или освобождении распределённого места соответствующая группа сразу обрабатывается заданием очереди. Эта команда — ежечасная страховочная задача по расписанию, которая обрабатывает всё пропущенное.
- Пример: `php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- Назначение: помечает как обработанные распределения мест, время освобождения которых прошло (например, места, зарезервированные для студентов специальности), и ставит в очередь задание продвижения листа ожидания для этих групп. Зарезервированные места становятся общими в расчёте сразу по наступлении времени освобождения, поэтому команда лишь передаёт места листу ожидания.
- Аудит: не записывается (запускается каждые 5 минут. Результаты продвижения — в записях о записи на дисциплины)
- Когда: по расписанию (каждые 5 минут).

## Оценки

### `term:close`

- Назначение: закрывает семестр. Все оценки семестра должны быть утверждены. Для каждого студента рассчитывает итоги семестра (кредиты, средний балл за семестр и накопленный), определяет академический статус (хорошая успеваемость, академическое предупреждение, рассмотрение отчисления) и право на отличие (пакет очереди), затем ранжирует отличие по программам, закрывает итоги семестра как официальные записи и переводит семестр в статус **Оценки закрыты**. То же, что **Оценки > Итоги семестров > Закрыть семестр** в панели администрирования.
- Аргументы/параметры: `{term}` — код семестра, `--dry-run` (только проверяет, можно ли закрыть семестр), `--reason=` (причина, сохраняемая в записи), `--actor=`.
- Аудит: записывается (число студентов, число групп с неутверждёнными оценками). По завершении закрытия запись аудита `term.closed` содержит число академических предупреждений, рассмотрений отчисления и отличий.
- Коды завершения: 2, если в некоторых группах есть неутверждённые оценки (выводится их число по каждой группе). 1, если семестр не в статусе опубликованного.
- Когда: после завершения выставления и утверждения оценок. Ход выполнения пакета отслеживайте в Horizon. Без обработчика очереди статус семестра не меняется.
- Примеры: `php artisan term:close 2026-FA --dry-run`, `php artisan term:close 2026-FA --reason="Fall 2026 grades closed" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- Назначение: пересчитывает итоги семестров (кредиты, средний балл за семестр и накопленный) по утверждённым оценкам. Используйте для применения изменённой политики оценивания (число знаков после запятой в среднем балле, порядок учёта повторного изучения) к прошлым семестрам. Академический статус и отличие сохраняют значения, определённые при закрытии семестра. Одобренное исправление оценки автоматически пересчитывает данные этого студента, поэтому для него команда не нужна.
- Параметры: `--term=` (студенты с оценками в этом семестре, начиная с этого семестра), `--student-number=` (один студент), `--reason=` (обязателен), `--actor=`.
- Аудит: записывается (число студентов, причина)
- Пример: `php artisan grades:recalculate --term=2026-SP --reason="GPA changed to three decimal places"`

### `grades:remind-missing`

- Назначение: отправляет по эл. почте напоминание преподавателям групп, оценки которых ещё не сданы (не введены или сохранены как черновик). Группы объединяются по преподавателю — по одному письму на каждого.
- Аргументы/параметры: `{term}` — код семестра, `--dry-run` (выводит адресатов без отправки), `--actor=`.
- Аудит: записывается (число групп, преподавателей, отправленных писем)
- Когда: за несколько дней до закрытия периода выставления оценок. При необходимости добавьте в расписание.

## Анкетирование по дисциплинам

### `evaluation:remind`

- Назначение: отправляет по эл. почте напоминание студентам, у которых остались неоценённые дисциплины, пока период анкетирования открыт. Оставшиеся дисциплины объединяются в одно письмо на каждого студента.
- Аргументы/параметры: `{term}` — код семестра, `--dry-run` (только число охватываемых студентов, ничего не отправляется), `--actor=`.
- Аудит: записывается (число охватываемых студентов, отправленных писем)
- Когда: один-два раза за период анкетирования. При необходимости добавьте в расписание.

### `evaluation:publish-results`

- Назначение: публикует для преподавателей результаты анкетирования по дисциплинам за семестр. То же, что **Анкетирование по дисциплинам > Анкетирование по семестрам > Опубликовать результаты** в панели администрирования. Даже после публикации результаты видны только по группам, набравшим минимальное число ответов и долю ответивших.
- Аргументы/параметры: `{term}` — код семестра, `--actor=`.
- Аудит: записывается (число ответов, был ли семестр уже опубликован)
- Когда: после завершения периода анкетирования и обработки оценок. Уже опубликованный семестр не изменяется.

## Справки

### `certificate:verify`

- Назначение: проверяет код проверки справки по тем же критериям, что и общедоступная страница проверки. Выводит вид, регистрационный номер, дату выдачи и замаскированного владельца.
- Аргументы/параметры: `{code}` — код проверки.
- Аудит: нет (только чтение)
- Коды завершения: 0, если справка действительна; 2 — неизвестный код, отозванная справка или истёкший срок действия.

### `certificate:render`

- Назначение: заново формирует PDF выданной справки по текущим данным и шаблону, заменяя архивный файл. То же, что **Выданные справки > Сформировать заново** в панели администрирования. Регистрационный номер и код проверки не меняются; меняется контрольная сумма.
- Аргументы/параметры: `{issue}` — регистрационный номер, `--reason=` (обязателен), `--actor=`.
- Аудит: записывается (регистрационный номер, новая контрольная сумма)
- Когда: чтобы заново сформировать конкретную справку после исправления шаблона или написания имени.

## Экзамены

### `assessment:import-results`

- Назначение: вносит результаты экзаменационной сессии из CSV. Те же правила, что и у **Экзаменационные сессии > Импорт результатов (CSV)** в панели администрирования (только зарегистрированные студенты, зачёт/незачёт определяется по баллу, повторный ввод до публикации заменяет результаты).
- Аргументы/параметры: `{type}` — код вида экзамена / `{held_date}` — дата экзамена `YYYY-MM-DD` / `{file}` — CSV в UTF-8 со строкой заголовков, `--actor=` (обязателен), `--dry-run` (только проверка строк, ничего не записывается).
- Формат столбцов: [глава 24 руководства администратора](../admin/24-assessments.md).
- Аудит: записывается (сессия, имя файла, число строк, число внесённых/неявок/ошибок)
- Коды завершения: 2, если есть строки с ошибками (остальные строки записываются).
- Пример: `php artisan assessment:import-results ENG_COMP 2026-05-15 storage/app/eng.csv --actor=registrar@example.ac.kr --dry-run`

### `assessment:publish-results`

- Назначение: публикует результаты сессии для студентов. То же, что **Экзаменационные сессии > Опубликовать результаты** в панели администрирования.
- Аргументы/параметры: `{type}` — код вида экзамена / `{held_date}` — дата экзамена, `--actor=` (обязателен).
- Аудит: записывается (сессия, число результатов)
- Когда: после завершения ввода результатов. Для уже опубликованной сессии команда завершается сбоем.

## Посещаемость

### `attendance:generate-sessions`

- Назначение: создаёт занятия для всех групп семестра по их расписанию (день недели, время, пара). То же, что **Создать занятия** в портале преподавателя и панели администрирования. Существующие занятия и отметки посещаемости сохраняются (повторный запуск безопасен).
- Аргументы/параметры: `{term}` — код семестра, `--section=` (код дисциплины-код группы, например `CSE2010-01`, только одна), `--dry-run` (только число охватываемых групп), `--actor=`.
- Аудит: записывается (семестр, группы, созданные занятия)
- Когда: до начала семестра, после утверждения расписания занятий. Запускайте повторно при изменении расписания.

## Выпуск

### `degree-audit:run`

- Назначение: сохраняет проверку требований к выпуску для каждого обучающегося студента. То же, что **Проверки требований к выпуску > Выполнить проверки** в панели администрирования. Последняя сохранённая проверка служит основанием для оформления выпуска.
- Параметры: `--term=` (код семестра, к которому относится проверка), `--student-number=` (один студент), `--min-year-level=` (только этот курс и старше), `--actor=`.
- Аудит: записывается (число студентов, число выполнивших требования)
- Когда: перед рассмотрением выпуска (в конце семестра), а также после изменения наборов требований или эквивалентных дисциплин.

## Интеграция с LMS

### `lms:sync`

- Назначение: передаёт опубликованные группы на платформу (создание и связывание курсов, преподаватели, записанные студенты). Делает для всего семестра то же, что **Связи с курсами > Синхронизировать снова** в панели администрирования. Для уже связанных групп состояние лишь подтверждается повторно (идемпотентно).
- Аргументы/параметры: `{platform}` — код платформы, `--term=` (код семестра, по умолчанию — все незавершённые семестры), `--section=` (один код дисциплины-код группы), `--dry-run` (только записывает то, что было бы отправлено, как «skipped»), `--actor=`.
- Аудит: записывается (платформа, группы, участники, сбои)
- Коды завершения: 2, если по какой-либо группе произошёл сбой.

### `lms:reconcile`

- Назначение: сравнивает списки участников курсов на платформе со списками записавшихся в системе управления учебным процессом, добавляет недостающих участников и удаляет лишних. Расхождения сохраняются в журнале синхронизации (`reconcile`).
- Аргументы/параметры: `{platform?}` (если не указан — все активные платформы), `--term=`, `--dry-run` (только записывает расхождения), `--actor=`.
- Аудит: записывается (группы по платформам, число добавленных/удалённых/сбоев)
- Когда: по расписанию ежедневно в 02:30. Запускайте вручную после сбоя платформы.

## Эксплуатационные проверки и очистка

### `system:health-check`

- Назначение: проверяет конфигурацию и ключи (APP_KEY, ключи PII, APP_DEBUG), подключение к БД и роли (runtime, migrator, reporting), RLS на таблицах персональных данных, невыполненные миграции, синхронизацию каталога разрешений, Redis, очередь (Horizon), Gotenberg, запись в хранилище медиафайлов и сигнал активности планировщика.
- Параметры: `--json` (вывод для мониторинга).
- Аудит: нет (только чтение)
- Коды завершения: 2, если какая-либо проверка не пройдена.
- Когда: сразу после развёртывания, при подозрении на сбой, периодически из системы мониторинга.

### `audit:seal`

- Назначение: связывает новые строки таблиц аудита в хеш-цепочку ([Целостность аудита](audit-and-maintenance.md)).
- Параметры: `--table=` (одно из record_changes, activity_log, security_events; можно указывать несколько раз), `--actor=`.
- Аудит: записывается (число запечатанных строк по таблицам)
- Когда: по расписанию ежедневно в 03:30.

### `audit:verify-chain`

- Назначение: заново вычисляет хеши содержимого и цепочку строк аудита, чтобы обнаружить подделку, удаление и перестановку.
- Параметры: `--table=`.
- Аудит: нет (только чтение)
- Коды завершения: 2 при обнаружении несоответствия.
- Когда: перед резервным копированием, при проверках безопасности, после очистки.

### `audit:prune`

- Назначение: удаляет **запечатанные** строки аудита с истёкшим сроком хранения. Выполняется через подключение владельца схемы.
- Параметры: `--before=YYYY-MM-DD` (обязателен), `--table=`, `--dry-run` (только подсчёт), `--actor=`.
- Аудит: записывается (дата отсечения, число удалённых строк по таблицам)
- Когда: в соответствии с политикой хранения, после резервного копирования.

### `media:prune-orphans`

- Назначение: удаляет строки медиафайлов, владелец которых больше не существует, и каталоги без соответствующей строки (фотографии лиц, документы к заявлениям, PDF-файлы справок, подтверждающие документы экзаменов).
- Параметры: `--dry-run` (только список), `--actor=`.
- Аудит: записывается (строки, каталоги)
- Когда: ежемесячно или после массового удаления.

## Ключи шифрования персональных данных

### `pii:generate-key`

- Назначение: выводит новые ключи для `PII_ENCRYPTION_KEY` и `PII_HASH_KEY`. Ничего не сохраняет.
- Аудит: не записывается
- Внимание: изменение `PII_HASH_KEY` делает недействительными все поисковые хеши. Порядок ротации ключей описан в [security-keys.md](security-keys.md).

### `pii:reencrypt`

- Назначение: после ротации ключа заново шифрует текущим ключом персональные данные, зашифрованные прежним ключом. Выполняется как пакет очереди.
- Аргументы: класс модели (сейчас `App\\Models\\Person\\Person`).
- Параметры: `--chunk=500`, `--dry-run` (только подсчитывает записи, использующие прежний ключ), `--force`.
- Аудит: записывается (ID пакета, число заданий / число при предварительном просмотре)
- Проверка: отслеживайте ход выполнения пакета в Horizon (`/horizon`). Когда он завершится и `--dry-run` сообщит 0, удалите прежний ключ из `PII_PREVIOUS_KEYS`.

## Локализация

### `i18n:missing`

- Назначение: показывает по каждому языку ключи, отсутствующие по сравнению с базовым языком (en), и ключи, которые больше не используются.
- Аргументы/параметры: `{locale?}` (только один язык), `--strict` (код завершения 2 при отсутствии ключей. Используется в CI).
- Аудит: не записывается

### `i18n:export`

- Назначение: создаёт JSON-файл для передачи переводчикам. Формат: `{"key": {"source": "English text", "translation": "translation"}}`.
- Аргументы/параметры: `{locale} {path}`, `--missing` (только отсутствующие ключи).
- Аудит: не записывается
- Пример: `php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- Назначение: применяет заполненный переводчиками JSON к `lang/{locale}`. Импортируются только ключи, существующие в базовом языке; пустые переводы игнорируются.
- Аргументы/параметры: `{locale} {path}`, `--dry-run` (выводит только список ключей, которые были бы записаны).
- Аудит: записывается
- Внимание: файлы переводов ведутся в репозитории. После импорта зафиксируйте изменения (commit).

## Проверки

### `naming:check`

- Назначение: проверяет имена таблиц и столбцов в миграциях на соответствие [соглашениям об именовании](../../../development/naming.md).
- Параметры: `--path=*` (проверяемые каталоги, по умолчанию `database/migrations`).
- Аудит: не записывается
- Коды завершения: 2, если есть проблемы.

### `pdf:sample`

- Назначение: формирует PDF с таблицей, в которой смешаны хангыль, иероглифы CJK, лаосское и тайское письмо, деванагари, кириллица и латиница, чтобы проверить шрифты и подключение к службе PDF (Gotenberg).
- Аргументы: `{path=pdf-sample.pdf}` (относительно локального диска `storage/app/private`).
- Аудит: не записывается
- При сбое: при ошибке подключения проверьте `GOTENBERG_URL` и состояние контейнера Gotenberg.
