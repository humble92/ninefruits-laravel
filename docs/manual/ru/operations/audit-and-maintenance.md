# Целостность аудита и плановое обслуживание

## Хеш-цепочка аудита

Таблицы аудита (`audit.record_changes` для изменений данных, `audit.activity_log` для деловых действий, `audit.security_events` для событий безопасности) допускают только добавление строк (это обеспечивают триггеры). Поверх этого действует механизм, который **выявляет** подделку.

- При вставке каждая строка получает SHA-256 своего содержимого (`row_hash`).
- `audit:seal` (по расписанию ежедневно в 03:30) связывает новые строки в цепочку в порядке ID: `chain_hash = SHA-256(previous chain_hash || row_hash)`.
- `audit:verify-chain` заново вычисляет хеш содержимого и цепочку для каждой строки. Строка с изменённым содержимым отображается как «row mismatch», отсутствующая или переставленная строка — как «chain mismatch», а команда возвращает код завершения 2.

Что нужно учитывать

- Строку, изменённую до запечатывания (в течение того же дня), цепочка обнаружить не может. Поэтому запечатывание выполняется ежедневно, а проверка — перед резервным копированием и при проверках безопасности.
- Когда очистка (`audit:prune`) удаляет самые старые строки, связь первой оставшейся строки не проверяется (удалённый диапазон сохраняется в записи аудита команды очистки).
- Установить `app.audit_maintenance = on` может только администратор БД (владелец схемы). У роли приложения нет привилегий UPDATE и DELETE.

## Сроки хранения и очистка

1. Определите сроки хранения (например, изменения данных — 3 года, деловые действия — 5 лет, события безопасности — 1 год).
2. Перед очисткой сделайте резервную копию ([Резервное копирование и восстановление](backup-restore.md)) и убедитесь с помощью `audit:verify-chain`, что цепочка не нарушена.
3. Проверьте количество строк командой `audit:prune --before=YYYY-MM-DD --table=record_changes --dry-run`, затем выполните её без `--dry-run`. Незапечатанные строки никогда не удаляются, поэтому сначала выполните `audit:seal`.
4. После очистки снова выполните `audit:verify-chain`.

Сама очистка тоже записывается: каждый запуск заносит в журнал действий (журнал `command`) дату отсечения, параметры, исполнителя и пользователя ОС, а также по каждой таблице **число удалённых строк, диапазон удалённых ID и chain_hash на границе**; фактическое удаление дополнительно записывается как событие безопасности `audit.pruned` (**Аудит > События безопасности**). Эта строка записи сама включается в цепочку при следующем запечатывании. Именно из-за этой границы `audit:verify-chain` не проверяет связь первой оставшейся строки; сравнив граничный хеш с записью об очистке, можно убедиться, что удалённый диапазон соответствует зарегистрированной очистке.

## Очистка файлов

`media:prune-orphans --dry-run` выводит строки медиафайлов, владелец которых больше не существует, и каталоги без соответствующей строки; без `--dry-run` команда удаляет их. Она охватывает фотографии лиц, документы к заявлениям, PDF-файлы справок и подтверждающие документы экзаменов. Запускайте её ежемесячно или после массового удаления.

## Проверка состояния

`system:health-check` проверяет конфигурацию и ключи, роли БД и RLS, миграции, каталог разрешений, Redis и очередь (Horizon), Gotenberg, хранилище и сигнал активности планировщика (записывается в кеш каждую минуту) и возвращает код завершения 2, если что-то не в порядке. Параметр `--json` позволяет подключить её к системе мониторинга.
