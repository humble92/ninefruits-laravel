# Управление ключами

- Для кого: ИТ-специалисты по эксплуатации

| Ключ | Назначение | При потере | Ротация |
|---|---|---|---|
| `APP_KEY` | Сессии, cookie, секреты двухфакторной аутентификации, подпись cookie запомненных устройств | Все пользователи выходят из системы; подключённая двухфакторная аутентификация (приложения-аутентификаторы) перестаёт работать | Поместите прежний ключ в `APP_PREVIOUS_KEYS`, затем замените ключ |
| `PII_ENCRYPTION_KEY` | Шифрование персональных данных, например номеров национальных удостоверений личности | **Зашифрованные персональные данные восстановить невозможно** | Порядок описан ниже |
| `PII_HASH_KEY` | Хеши для поиска персональных данных по точному совпадению | Поиск перестаёт работать (данные сохраняются) | Как правило, не меняется |

Принципы хранения

- Храните не менее двух копий трёх ключей вне конфигурации окружения сервера — в хранилище секретов (Vault, облачный менеджер секретов и т. п.) или в опечатанном автономном хранилище.
- Никогда не храните их вместе с файлами резервных копий. Даже при утечке резервной копии БД персональные данные без ключей должны оставаться нечитаемыми.

## Порядок ротации ключа персональных данных

1. Сгенерируйте новый ключ командой `php artisan pii:generate-key` (из вывода используйте только `PII_ENCRYPTION_KEY`).
2. Поместите текущий ключ в `PII_PREVIOUS_KEYS` (несколько ключей — через запятую), а новый — в `PII_ENCRYPTION_KEY`.
3. Перезагрузите конфигурацию: `php artisan config:cache`, `php artisan horizon:terminate`.
4. Для каждой модели персональных данных проверьте число затрагиваемых записей командой `php artisan pii:reencrypt {model} --dry-run`, затем выполните её без `--force`.
5. Когда Horizon покажет, что пакет завершён, а `--dry-run` сообщит 0, удалите прежний ключ из `PII_PREVIOUS_KEYS`.
6. Храните прежний ключ в опечатанном виде в течение срока хранения резервных копий (он нужен для восстановления старых копий).
