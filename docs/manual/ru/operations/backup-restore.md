# Резервное копирование и восстановление

- Для кого: ИТ-специалисты по эксплуатации

## Что копировать

| Объект | Способ | Периодичность (рекомендуемая) |
|---|---|---|
| PostgreSQL | `pg_dump -Fc` или PITR (архивирование WAL) | Ежедневная полная копия + непрерывный WAL |
| Файловое хранилище (`storage/app/private` или S3) | Снимок или бакет с версионированием | Как для БД |
| Конфигурация окружения и ключи | Хранилище секретов | При каждом изменении |

БД и файловое хранилище должны восстанавливаться на один и тот же момент времени (метаданные фотографий и PDF-файлов справок хранятся в БД).

## Пример резервного копирования БД

```bash
pg_dump -U app_migrator -d sis -Fc -f sis-$(date +%F).dump
```

`app_migrator` владеет всеми схемами (`public`, `audit`, `reporting`, `util`), поэтому резервную копию делайте под этой учётной записью. Роли (`app_*`) — объекты кластера и в дамп не входят. На сервере восстановления сначала создайте роли, как описано в разделе 2 документа [Установка](installation.md).

## Пример восстановления

```bash
createdb -U postgres sis_restore
psql -U postgres -d sis_restore -f database/sql/roles/prepare_database.sql
pg_restore -U app_migrator -d sis_restore --no-owner --role=app_migrator sis-2026-10-22.dump
```

## Учебные восстановления

Ежеквартально восстанавливайте копию на отдельный сервер и проверяйте следующее: вход в систему, расшифровку персональных данных (совпадение ключей), просмотр записей аудита, открытие файлов (фотографии, PDF).
