# Устранение неполадок

- Для кого: ИТ-специалисты по эксплуатации

| Признак | Что проверить |
|---|---|
| Сразу после входа происходит переход на страницу безопасности | Политика двухфакторной аутентификации — «обязательно», и льготный период истёк. Проблема решается, когда пользователь подключит двухфакторную аутентификацию. Политика находится в разделе **Настройки > Безопасность** |
| 403 в панели администрирования | У пользователя нет действующего назначения роли с разрешением `admin_panel.access`. Проверьте **Пользователи и доступ > Пользователи > Назначения ролей** |
| Отсутствует пункт меню | У роли нет разрешения на этот экран (например, `roles.view`) |
| Не приходят коды по эл. почте | Настройки почты (`MAIL_*`), записи `Код по эл. почте отправлен` среди событий безопасности, ограничения отправки (раз в минуту, пять раз в час) |
| Экран показывает 0 строк чужих данных | Это может быть нормой (построчная защита). Убедитесь, что исполнитель сессии БД задан, посмотрев столбец пользователя в разделе **Изменения данных** |
| `permission denied for schema public` | Приложение попыталось выполнить DDL под `app_runtime`. Выполняйте миграции только через `php artisan migrate` (она автоматически использует `app_migrator`) |
| `Audit records are append-only` | Попытка изменить или удалить таблицу аудита. Эта блокировка предусмотрена |
| Не формируется PDF | `php artisan pdf:sample`, состояние Gotenberg, `GOTENBERG_URL` |
| Задания очереди зависли | Проверьте неудавшиеся задания в `/horizon`, `php artisan horizon:status` |

Трассировка отдельного запроса: по значению заголовка ответа `X-Request-Id` можно одновременно искать в логах, журнале действий, изменениях данных и событиях безопасности.
