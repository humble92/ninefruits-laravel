# Контрольный список развёртывания и настройки безопасности PHP

## Версия PHP

- Используйте **PHP ≥ 8.5.12** (или 8.4.27, 8.3.36). Выпуск безопасности от 2026-10-21 устранил две уязвимости удалённого выполнения кода без аутентификации (CVE-2026-109618 — повреждение состояния при нехватке памяти, CVE-2026-109619 — утечка состояния между запросами), и php.net заявил, что «полного способа смягчения нет; единственный безопасный вариант — обновление». Ограничение `"php": "^8.5.12"` в `composer.json` не позволяет установить систему на более старую версию PHP.
- Среда разработки: выполните `./vendor/bin/sail build --no-cache && ./vendor/bin/sail up -d`, затем проверьте версию командой `./vendor/bin/sail php -v`.
- При сборке образов контейнеров или серверов не фиксируйте пакет PHP; берите последний патч-выпуск. Версию PHP также показывает `system:health-check`.

## php.ini для эксплуатации (пул php-fpm или конфигурация сервера, а не `.user.ini` или `ini_set()`)

| Параметр | Значение | Причина |
|---|---|---|
| `session.upload_progress.enabled` | `0` | Закрывает пути атак CVE-2026-109619 и CVE-2026-115560 (бюллетени php.net от 21 и 23 октября 2026 г.). Система не использует отслеживание хода загрузки |
| `fatal_error_backtraces` | `0` (PHP 8.5) | Закрывает путь через трассировку фатальных ошибок из того же бюллетеня |
| `memory_limit` | `256M` или больше, зафиксировано через `php_admin_value` | Чтобы код приложения не мог его изменить |
| `post_max_size` / `upload_max_filesize` | `32M` / `20M` | Верхний предел для загрузки документов приёма, подтверждающих документов экзаменов и фотографий (с запасом сверх проверок приложения 5 МБ и 2 МБ) |
| `expose_php` | `Off` | Не раскрывать версию |
| `display_errors` | `Off`, `log_errors=On` | Эксплуатация |
| `session.cookie_secure`, `session.cookie_httponly`, `session.cookie_samesite` | `1`, `1`, `Lax` | Вместе с настройками сессий Laravel (`SESSION_SECURE_COOKIE=true`) |
| `opcache.enable`, `opcache.validate_timestamps` | `1`, `0` (перезапуск при развёртывании) | Производительность |

## Окружение приложения (.env)

- `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL` — реальный адрес.
- Передавайте `APP_KEY`, `PII_ENCRYPTION_KEY` и `PII_HASH_KEY` из хранилища секретов и сделайте их резервные копии ([Управление ключами](security-keys.md)). При потере ключей персональные данные невозможно расшифровать.
- БД: `DB_USERNAME=app_runtime`, `DB_MIGRATOR_USERNAME=app_migrator` (пароль, используемый только для миграций), `app_reporting` — только для BI-инструментов.
- `QUEUE_CONNECTION=redis`, `CACHE_STORE=redis`, `SESSION_DRIVER=redis`. Зарегистрируйте Horizon (`php artisan horizon`) и планировщик (`* * * * * php artisan schedule:run`) как службы.
- `GOTENBERG_URL`: адрес во внутренней сети. Gotenberg никогда не открывается наружу.
- Почта (`MAIL_*`): используется для приглашений, двухфакторных кодов по эл. почте, уведомлений о записи на дисциплины и об оценках.

## Порядок развёртывания

1. Сделайте резервную копию ([Резервное копирование и восстановление](backup-restore.md)).
2. Разверните код, выполните `composer install --no-dev --optimize-autoloader`, `npm ci && npm run build`.
3. `php artisan migrate --force` (автоматически переключается на подключение мигратора), `php artisan security:sync-permissions`, `php artisan setup:install --force` (обновляет обязательные данные, сохраняя правки администраторов).
4. `php artisan optimize`, перезапуск Horizon (`horizon:terminate`), перезапуск php-fpm (применяет новый php.ini).
5. Проверьте состояние командой `php artisan system:health-check`. Проверьте цепочку аудита командой `audit:verify-chain`.

## Плановые проверки

| Периодичность | Задача |
|---|---|
| Ежедневно (автоматически) | `audit:seal`, `lms:reconcile`, освобождение зарезервированных мест записи, продвижение листа ожидания, истечение черновиков заявлений |
| Еженедельно | `system:health-check`, проверка обновлений безопасности PHP и ОС, проверка неудавшихся заданий в Horizon |
| Ежемесячно | `media:prune-orphans --dry-run`, учебное восстановление из резервной копии, `audit:verify-chain` |
| Каждый семестр | Пересмотр назначений ролей (уволившиеся и переведённые сотрудники), очистка записей аудита с истёкшим сроком хранения (`audit:prune`) |
