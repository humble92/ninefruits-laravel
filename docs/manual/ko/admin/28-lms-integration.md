# 28. LMS 연동

메뉴: **LMS 연동 > LMS 플랫폼**, **강좌 연결**, **동기화 기록**(`LMS 플랫폼, 연결, 동기화 관리` 권한, 기본: 시스템 관리자·학적 담당 외 교무 담당). 교원은 **담당 강좌**와 강좌 상세의 LMS 링크, 성적 입력의 **LMS 점수 불러오기**를 쓴다. 불러오기는 성적 입력과 같은 조건이다(담당 교원은 성적 입력 기간 안에서, 직원은 `성적 관리` 범위 안에서).

개발자용 상세는 [LMS 연동 가이드](../../../lms-integration-guide.md).

## 무엇이 어디로 가나

| 학사 → LMS | 시점 |
|---|---|
| 개설강좌(강좌 생성) + 담당 교원 | 강좌 **공개** 시, 그리고 `lms:sync` |
| 수강 확정 → 등록 | 수강신청·대기자 승격·직원 수강 처리 즉시 |
| 수강 취소·철회 → 등록 해제 | 즉시 |
| 전체 대조 | 매일 02:30 (`lms:reconcile`) |

| LMS → 학사 | 시점 |
|---|---|
| 최종 점수(초안) | 교원이 성적 입력에서 **LMS 점수 불러오기**를 누를 때. 저장·제출은 교원이 한다 |

확정 성적은 LMS로 보내지 않는다. 강의 자료·과제·퀴즈는 LMS 안에 있다.

## 플랫폼

**LMS 플랫폼**: 코드, 이름, 드라이버, 기본 URL, 인증 정보(키/값, 암호화 저장, 수정 시 비워 두면 유지), 사용 여부, 수강 명단 동기화, 최종 점수 가져오기.

- 드라이버 **없음(기록만)**: 아무것도 호출하지 않고 보낼 내용을 기록한다. 연동 전 흐름을 점검하거나 시연할 때 쓴다. 데모 데이터의 `DEMO` 플랫폼이 이것이다.
- `Moodle`, `Open edX`: 커넥터가 아직 없다(미구현 표시). 선택하면 동기화가 실패로 기록된다.
- **사용**을 켜면 그때부터 강좌 공개·수강 변동이 즉시 전달되고 야간 대조 대상이 된다.

## 강좌 연결과 동기화 기록

- **강좌 연결**: 어느 개설강좌가 어느 플랫폼 강좌(ID, URL)에 연결됐는지, 상태(대기/연결됨/실패), 마지막 동기화와 오류. **다시 동기화**로 강좌·교원·수강생을 다시 밀어넣는다.
- **동기화 기록**: 단계별(강좌, 구성원 추가·제거, 점수 가져오기, 대조) 결과와 메시지. 실패 원인을 여기서 본다.
- 명령: `lms:sync {플랫폼} --term={학기}`(전체 밀어넣기, `--dry-run`), `lms:reconcile`(대조).

## 포털

- 학생·교원의 강좌 상세와 교원의 담당 강좌 목록에 플랫폼 강좌 링크가 보인다(연결된 강좌만).
- 성적 입력: 플랫폼에 **최종 점수 가져오기**가 켜져 있고 강좌가 연결돼 있으면 **LMS 점수 불러오기** 버튼이 나온다. 점수 칸만 채우며 저장하지 않는다.

## 자주 묻는 질문

- **학생이 LMS에 없다.** 학생에게 계정(사용자)이 있어야 동기화된다. 계정이 없으면 초대 후([14장](14-merge-and-invitations.md)) 다음 대조에서 추가된다.
- **동기화가 실패로 남는다.** 기록의 메시지를 본다. 인증 정보 만료가 흔하다. 플랫폼 수정에서 값을 바꾸고 **다시 동기화**.
- **플랫폼을 바꿨다.** 새 플랫폼을 만들고 옛 플랫폼의 사용을 끈다. 연결은 플랫폼별로 따로 생긴다.
