# Artisan コマンドリファレンス

- 対象読者: IT 運用担当者
- 範囲: このリポジトリに登録されているすべてのアプリケーションコマンド。コマンドを追加した場合はここにも追記する必要があり、追記しないと CI が失敗します(`tests/Feature/Tooling/CommandDocumentationTest.php`)。

## 共通ルール

すべてのコマンドは `php artisan {command}` で実行します。開発環境では `./vendor/bin/sail artisan {command}` です。

| 項目 | ルール |
|---|---|
| 監査記録 | データを変更するコマンド(以下「監査: 記録あり」)は、実行のたびにコマンド、引数、オプション、OS ユーザー、終了コード、結果を業務ログ(ログ `command`)に書き込みます。管理画面の **監査 > 業務ログ** で確認できます |
| 実行 ID | 各実行にはリクエスト ID の代わりに `cmd-` で始まる ID が付与されます。業務ログ、その実行によるデータ変更、その実行が投入したキュージョブはすべて同じ ID を持つため、「どのコマンドがこの変更を行ったか」は ID でわかります。`--actor` は運用担当者が指定する値であるため、データ変更履歴のユーザー列には入りません(実際の実行者は OS ユーザーです) |
| `--actor=<email>` | 監査対象のすべてのコマンドに共通です。責任者となる管理者アカウントを記録します。存在しないメールアドレスを指定すると実行は中止されます |
| `--dry-run` | 何も変更せずに結果を表示します。元に戻しにくい操作で使用できます |
| `--force` | 確認プロンプトなしで実行します(スケジュールやデプロイスクリプト用) |
| `--reason=` | 理由を必要とするコマンドで使用できます |
| 終了コード | 0 成功、1 失敗または取消、2 チェック系コマンドが問題を検出 |
| DB コンテキスト | コマンドの実行中、DB セッションの実行者は `system:command:{command}` に設定され、データ変更履歴(トリガー)に表示されます |

## インストールとデモ

### `setup:install`

- 目的: 新規インストールと更新。マイグレーション、必須データ、機関の既定値、インストールプロファイル、初期管理者を順に実行します。再実行しても安全です(既存データと管理者が変更した値は保持されます)。
- 実行時期: 初回インストール時と、デプロイのたび。
- オプション: `--institution-name=`、`--locale=`(既定の言語)、`--timezone=`(例: `Asia/Seoul`)、`--profile=*`(インストールプロファイルのキー)、`--grade-scale=`(成績評価基準 `4.5` または `4.3`。一度設定すると変更できません。空欄の場合は最初のプロファイルの基準)、`--admin-email=`、`--admin-name=`、`--force`(質問なしで実行。管理者パスワードは標準入力から読み取ります)。
- 監査: 記録あり
- 例

  ```bash
  php artisan setup:install
  echo "$ADMIN_PASSWORD" | php artisan setup:install --force --locale=ko --timezone=Asia/Seoul \
      --institution-name="Demo University" --admin-email=admin@example.ac.kr --admin-name="Administrator"
  ```

- 出力の読み方: ステップごとに `DONE`/`FAIL`。`Administrator exists` はシステム管理者の割り当てがすでに存在するため、作成をスキップしたことを意味します。
- 失敗時: キーがないというエラーの場合は、`key:generate` と `pii:generate-key` で生成した値を環境設定に設定します。マイグレーションの失敗は、多くの場合 DB ロールが準備されていないことが原因です(インストールマニュアルを参照)。

### `setup:demo`

- 目的: ファクトリーを使って架空の大学のデータを作成します。ロールごとの固定デモアカウント(`registrar@demo.test` など)を表示します。
- 実行時期: 開発、研修、デモ環境。**本番環境(`APP_ENV=production`)では `--force` を付けても実行されません。**
- オプション: `--size=tiny|small|medium|large`(学生数 約 20/100/2,000/20,000。`tiny` はテストや簡単な確認用)、`--seed=`(同じ値なら同じデータを生成)、`--force`。
- `--student-accounts`: 在籍中のすべての学生にアカウント(`student{学籍番号}@demo.test`、デモ用パスワード)を作成し、`storage/app/private/load-accounts.csv` に書き出します。負荷テスト用です([負荷テスト](load-testing.md))。
- 監査: 記録あり
- 例: `php artisan setup:demo --size=small --seed=42`
- 失敗時: 必須データがない場合、デモアカウントにロールが付与されずスキップされます。先に `setup:install` を実行してください。

## 基準データと学期

### `reference:import`

- 目的: CSV から基準データを取り込みます。管理画面の **CSV 取り込み** と同じ取り込みルールを使用します(既存の行はコードで照合して更新し、翻訳の空欄セルは既存の値を保持し、失敗した行のみ別途記録します)。
- 引数: `{type}` は `org_units`、`programs`、`buildings`、`rooms`、`lookup_values`、`students`、`instructors`、`courses`、`registration_holds` のいずれか / `{file}` はヘッダー行付きの UTF-8 CSV。
- オプション: `--actor=`(必須。取り込み記録と完了通知はこのアカウントに送られます)、`--chunk=100`(キュージョブあたりの行数)、`--dry-run`(ヘッダーの確認と行数のみ)。
- 監査: 記録あり(種類、ファイル名、行数、失敗行数)
- 列の形式: [管理者マニュアル 第 9 章](../admin/09-csv-import.md)。
- 終了コード: キューが同期実行の場合は結果がすぐに表示され、失敗行があると終了コードは 2 です。非同期(Horizon)の場合は取り込みが受け付けられるだけで、終了コードは 0 です。結果は `--actor` アカウントの管理画面通知に失敗行の CSV として届きます。
- 例: `php artisan reference:import org_units storage/app/org-units.csv --actor=admin@example.ac.kr --dry-run`

### `term:inspect`

- 目的: 指定した時点で授業中の学期と、開いている業務期間(種類、学期、対象条件、終了日時)を表示します。学期や業務期間の設定を確認したり、「なぜ履修登録が開いていないのか」といった問い合わせに答えたりするのに使います。
- オプション: `--at=`(既定は現在。例: `"2027-02-15 09:00"`。タイムゾーンを指定しない場合はサーバーのタイムゾーン(UTC)として解釈されます。`"2027-02-15 09:00 Asia/Seoul"` のようにタイムゾーンを指定できます)。
- 監査: 記録なし
- 出力の読み方: 日付の判定には機関のタイムゾーンを使用します。計画中またはアーカイブ済みの状態の学期の業務期間は開きません。

## セキュリティ

### `security:create-administrator`

- 目的: システム管理者ロールを持つアカウントを作成します。通常は `setup:install` から呼び出されます。
- オプション: `--email=`、`--name=`、`--password-stdin`(標準入力からパスワードを読み取ります。非対話型の実行では必須)。
- 監査: 記録あり(作成されたユーザーの ID)
- 例: `php artisan security:create-administrator --email=admin@example.ac.kr --name="Administrator"`
- 失敗時: `system_administrator role is missing` は、先に `setup:install` または `db:seed` を実行する必要があることを意味します。パスワードは 12 文字以上である必要があります。

### `security:sync-permissions`

- 目的: DB の権限一覧をコード内の権限カタログに合わせます。新しい権限は作成し、カタログにない権限は削除します(すべてのロールからも外されます)。システムロールは常にすべての権限を受け取ります。
- 実行時期: デプロイ後(`setup:install` は必須データのステップの一部としてこれを実行します)。
- オプション: `--dry-run`(作成/削除の一覧のみ表示)、`--force`(削除の確認を省略)。
- 監査: 記録あり(作成/削除された権限)
- 出力の読み方: `create` と `delete` の行。削除がある場合は確認プロンプトが表示されます。
- 失敗時: 確認に「no」と答えると、終了コード 1 で終了し、何も変更されません。

### `security:reset-mfa`

- 目的: ユーザーの二要素認証(認証アプリ、メールのコード、リカバリーコード、記憶されたデバイス)をリセットします。ユーザーは次回のログイン時に再登録します。管理画面にログインできる管理者がいない場合(例: 唯一の管理者がスマートフォンを紛失した場合)に使用します。それ以外の場合は、管理画面の **ユーザー > 二要素認証をリセット** を使用してください。
- 引数/オプション: `{user}` ユーザーのメールアドレス、`--reason=`(必須)、`--actor=`(必須。リセットを決定した管理者)。
- 監査: 記録あり(業務ログとセキュリティログの両方に、理由とともに記録)
- 例: `php artisan security:reset-mfa admin@example.ac.kr --reason="Phone lost, identity verified by phone call" --actor=it-lead@example.ac.kr`

### `security:unlock-user`

- 目的: パスワードの繰り返し誤入力でロックされたアカウントを、ロック期間の終了前に解除します。管理画面の **ユーザー > ログインロックを解除** と同じです。
- 引数/オプション: `{user}` ユーザーのメールアドレス、`--reason=`(必須)。
- 監査: 記録あり(セキュリティログにも記録)
- 出力の読み方: `The account is not locked.` は何も変更されなかったことを意味します。
- 注意: ロックのしきい値(失敗回数、ロック時間)は管理画面の **設定 > ログイン方法** で設定します。

## 人物と学籍

### `people:find-duplicates`

- 目的: 同一人物と思われる人物を一覧表示します。基準は、国民識別番号が同一(検索用ハッシュ)、またはローマ字氏名と生年月日が同一であることです。統合済みの人物は除外されます。
- オプション: `--limit=100`(表示するグループ数)。
- 監査: 記録なし(読み取り専用)
- 終了コード: 重複候補がある場合は 2。
- 後続作業: 管理画面の **人物** で各グループを確認し、同一人物であれば、残す人物のページから **重複を統合** を実行します。統合は取り消せません([管理者マニュアル 第 14 章](../admin/14-merge-and-invitations.md))。

## 入試

### `admission:matriculate`

- 目的: 入試回の入学確定済み志願者に学籍(新しい学籍番号)を作成します。管理画面の **入試 > 出願** の一括操作 **学籍を作成** と同じです。志願者ごとに個別に処理するため、1 件が失敗しても他の処理は止まりません。
- 引数/オプション: `{cycle}` 入試回のコード、`--term=`(必須。入学学期のコード、例: `2027-SP`。入学日は学期の初日です)、`--actor=`(必須。`合格者の学籍作成` 権限を持つアカウント。そのアカウントの権限範囲内の志願者のみ処理されます)、`--dry-run`(対象一覧のみ)。
- 監査: 記録あり(入試回、学期、対象数、作成数、失敗した出願番号)。志願者ごとに業務記録(`application.matriculated`)も書き込まれます。
- 終了コード: 失敗した志願者がいる場合は 2。
- 例: `php artisan admission:matriculate DEMO-2027-REG --term=2027-SP --actor=admissions@example.ac.kr --dry-run`
- 失敗時: `not ready` は学籍がすでに存在するか、志願者が入学確定の状態ではないことを意味します。`program is not in effect` は入学日にプログラムが有効でないことを意味します(基準データ > プログラム で有効期間を確認してください)。

### `admission:expire-drafts`

- 目的: 締め切られた入試回の下書きの出願と、設定された期間(**設定 > 入試 > 未更新の下書きの失効(日)**、既定 90 日)更新されていない下書きの出願を **失効** にします。失効した出願は、同じ入試回での新たな出願を妨げません。
- 実行時期: スケジュール実行(毎日 03:10、[スケジュールジョブ](scheduled-jobs.md))。
- オプション: `--dry-run`(件数のみ)。
- 監査: 記録あり(失効件数)

## 開講科目

### `section:copy`

- 目的: 前の学期の開講科目をもとに新しい学期の編成を始めます。管理画面の **開講科目 > 別の学期からコピー** と同じです。休講になっていない開講科目を下書きとしてコピーし、教員(在職中の場合)、授業時間と教室、確保枠(開放日時は学期開始日の差だけずらします)、シラバス(非公開の下書きとして)も一緒にコピーします。科目バージョンは、新しい授業期間の開始時点で有効なバージョンに置き換えられます。
- 引数/オプション: `{from-term}`、`{to-term}` 学期コード(例: `2026-FA`)、`--org-unit=*`(この組織単位コードの開講科目のみ)、`--dry-run`(結果のみ、保存しない)、`--actor=`(必須。そのアカウントの `開講科目の編成` 権限の範囲内の開講科目のみコピーされます)。
- 監査: 記録あり(コピー、スキップ、要確認の件数)
- 出力の読み方: `skipped` は対象学期に同じ開講科目コードがすでにあるか、有効な科目バージョンがないことを意味します。`note` は開講科目はコピーされたものの一部が除外されたことを意味します(教室がすでに使用中のため教室なしでコピー、退職した教員など)。授業期間はコードで対応付けられ、該当するものがない場合は学期全体の授業期間に入ります。
- 例: `php artisan section:copy 2026-FA 2027-FA --actor=academic@example.ac.kr --dry-run`

### `schedule:check-conflicts`

- 目的: 時間割を公開する前に学期の開講科目をチェックします。教室と教員の二重予約は DB ですでに防止されているため、このコマンドは DB が許容してしまう問題を検出します: 教室の収容人数を超える定員、授業期間の開始日に有効でない科目バージョン、退職した教員、定員を超える確保枠、授業期間外の授業日。バックアップからの復元など、制約なしで入ってきたデータの教室の競合もチェックします。
- 引数: `{term}` 学期コード。
- 監査: 記録なし(読み取り専用)
- 終了コード: 問題がある場合は 2。まだ教員や教室が割り当てられていない開講科目は参考情報としてのみ表示されます。

## 履修登録

### `registration:preflight`

- 目的: 履修登録を開始する前に学期をチェックします。履修登録と履修追加・削除の業務期間、ルールセット、公開済み開講科目の数、定員 0 の開講科目、定員を超える確保枠、授業期間の開始日に有効でない科目バージョン、履修単位上限の対象外となっている在籍学生の数、履修登録の制限措置を受けている学生の数を表示します。
- 引数: `{term}` 学期コード(例: `2027-SP`)。
- 監査: 記録なし(読み取り専用)
- 終了コード: 問題がある場合は 2。ルールセットがない場合は問題ではなく参考情報として表示されます(ルールの既定値が適用されます)。
- 例: `php artisan registration:preflight 2027-SP`

### `registration:simulate`

- 目的: 学生が現時点(または指定した時点)でその開講科目を履修登録した場合にどうなるかを、ルールごとに表示します。何も保存されず、試行も記録されません。「なぜ履修登録できないのか」という問い合わせに使います。
- 引数: `{student-number}` 学籍番号、`{section}` `科目コード-開講科目コード`(例: `CSE2010-01`)。
- オプション: `--term=`(学期コード。既定はその開講科目がある最新の学期)、`--at=`(評価する時点。例: `"2027-02-10 10:00 Asia/Seoul"`)。
- 監査: 記録なし(読み取り専用)
- 出力の読み方: ルールごとに合否、ブロック/警告、メッセージ。ルール例外が適用されたルールは不合格と表示されますが、ブロックはしません。定員はルール表の下に別途表示されます。
- 終了コード: 履修登録が拒否される場合は 2。

### `waitlist:promote`

- 目的: 空席のある開講科目について、キャンセル待ちの学生を順番に履修登録します。繰り上げ時にすべてのルールを再チェックし、ルールを満たさないキャンセル待ちはキャンセル待ちから外されます(理由を記録)。履修登録と履修追加・削除の業務期間がどちらも終了した開講科目のキャンセル待ちは期限切れになります。学生には結果がメールで届きます。
- 引数/オプション: `{term?}` 学期コード(既定: キャンセル待ちのあるすべての学期)、`--actor=`。
- 監査: 記録あり(開講科目、繰り上げ、除外、期限切れの件数)
- 実行時期: 削除、履修中止、確保枠の開放があると、該当する開講科目はキュージョブで直ちに処理されます。このコマンドは、取りこぼしを処理するために毎時スケジュール実行される安全網です。
- 例: `php artisan waitlist:promote 2027-SP --actor=registrar@example.ac.kr`

### `registration:release-reserved-seats`

- 目的: 開放日時を過ぎた確保枠(例: 専攻生向けの確保枠)を処理済みにし、その開講科目のキャンセル待ち繰り上げジョブをキューに入れます。確保枠は開放日時を過ぎた時点で計算上すでに一般枠になるため、このコマンドは席をキャンセル待ちに引き渡すだけです。
- 監査: 記録なし(5 分ごとに実行されます。繰り上げの結果は履修登録の記録にあります)
- 実行時期: スケジュール実行(5 分ごと)。

## 成績

### `term:close`

- 目的: 学期の成績締めを行います。学期のすべての成績が確定している必要があります。学生ごとに学期記録(単位、学期 GPA、累積 GPA)を計算し、学業状況(良好、学業警告、除籍審査)と成績優秀者の資格を判定し(キューバッチ)、その後プログラムごとに成績優秀者の順位を付け、学期記録を公式記録として確定し、学期を **成績締め済み** にします。管理画面の **成績 > 学期記録 > 成績締め** と同じです。
- 引数/オプション: `{term}` 学期コード、`--dry-run`(成績締めが可能かどうかのチェックのみ)、`--reason=`(記録に残す理由)、`--actor=`。
- 監査: 記録あり(学生数、未確定の成績がある開講科目の数)。成績締めが完了すると、`term.closed` の監査記録に学業警告、除籍審査、成績優秀者の件数が保存されます。
- 終了コード: 未確定の成績がある開講科目がある場合は 2(開講科目ごとの未確定件数が表示されます)。学期が公開状態でない場合は 1。
- 実行時期: 成績入力と確定がすべて完了した後。バッチの進行状況は Horizon で確認します。キューワーカーがないと学期の状態は変わりません。
- 例: `php artisan term:close 2026-FA --dry-run`、`php artisan term:close 2026-FA --reason="Fall 2026 grades closed" --actor=registrar@example.ac.kr`

### `grades:recalculate`

- 目的: 確定済みの成績から学期記録(単位、学期 GPA、累積 GPA)を再計算します。変更した成績ポリシー(GPA の小数点以下の桁数、再履修の扱い)を過去の学期に適用するときに使います。学業状況と成績優秀者は成績締め時に決定した値を保持します。承認された成績訂正はその学生を自動的に再計算するため、このコマンドは不要です。
- オプション: `--term=`(その学期に成績がある学生を、その学期以降について)、`--student-number=`(学生 1 名)、`--reason=`(必須)、`--actor=`。
- 監査: 記録あり(学生数、理由)
- 例: `php artisan grades:recalculate --term=2026-SP --reason="GPA changed to three decimal places"`

### `grades:remind-missing`

- 目的: 成績がまだ提出されていない(未入力または下書き保存の)開講科目の教員にメールを送ります。開講科目は教員ごとにまとめられ、1 通のメッセージになります。
- 引数/オプション: `{term}` 学期コード、`--dry-run`(送信せずに対象を表示)、`--actor=`。
- 監査: 記録あり(開講科目、教員、送信メッセージ数)
- 実行時期: 成績入力の業務期間が終了する数日前。必要に応じてスケジュールに追加します。

## 授業評価

### `evaluation:remind`

- 目的: 授業評価の業務期間中に、まだ評価していない科目がある学生にメールを送ります。残っている科目は学生ごとにまとめられ、1 通のメッセージになります。
- 引数/オプション: `{term}` 学期コード、`--dry-run`(対象学生数のみ、送信しない)、`--actor=`。
- 監査: 記録あり(対象学生、送信メッセージ数)
- 実行時期: 評価の業務期間中に 1〜2 回。必要に応じてスケジュールに追加します。

### `evaluation:publish-results`

- 目的: 学期の授業評価結果を教員に公開します。管理画面の **授業評価 > 学期の授業評価 > 結果を公開** と同じです。公開後も、最小回答数と回答率に達した開講科目の結果のみ表示されます。
- 引数/オプション: `{term}` 学期コード、`--actor=`。
- 監査: 記録あり(回答数、すでに公開済みかどうか)
- 実行時期: 評価の業務期間と成績処理が完了した後。すでに公開済みの学期は変更されません。

## 証明書

### `certificate:verify`

- 目的: 公開検証ページと同じ基準で証明書の検証コードをチェックします。種別、発行番号、発行日、マスク処理された所持者を表示します。
- 引数/オプション: `{code}` 検証コード。
- 監査: なし(読み取り専用)
- 終了コード: 有効な場合は 0、不明なコード、失効した証明書、有効期限切れの場合は 2。

### `certificate:render`

- 目的: 発行済み証明書の PDF を現在のデータとテンプレートで再作成し、保管されているファイルを置き換えます。管理画面の **発行済み証明書 > 再作成** と同じです。発行番号と検証コードは変わらず、チェックサムが変わります。
- 引数/オプション: `{issue}` 発行番号、`--reason=`(必須)、`--actor=`。
- 監査: 記録あり(発行番号、新しいチェックサム)
- 実行時期: テンプレートや氏名の表記を修正した後に、特定の証明書を再生成するとき。

## 試験

### `assessment:import-results`

- 目的: 試験実施回の結果を CSV から入力します。管理画面の **試験実施回 > 結果を取り込み(CSV)** と同じルールです(申込済みの学生のみ、素点から合否を判定、公開前に再入力すると結果を置き換え)。
- 引数/オプション: `{type}` 試験種別コード / `{held_date}` 試験日 `YYYY-MM-DD` / `{file}` ヘッダー行付きの UTF-8 CSV、`--actor=`(必須)、`--dry-run`(行の検証のみ、記録しない)。
- 列の形式: [管理者マニュアル 第 24 章](../admin/24-assessments.md)。
- 監査: 記録あり(試験実施回、ファイル名、行数、入力/欠席/エラーの件数)
- 終了コード: エラー行がある場合は 2(その他の行は記録されます)。
- 例: `php artisan assessment:import-results ENG_COMP 2026-05-15 storage/app/eng.csv --actor=registrar@example.ac.kr --dry-run`

### `assessment:publish-results`

- 目的: 試験実施回の結果を学生に公開します。管理画面の **試験実施回 > 結果を公開** と同じです。
- 引数/オプション: `{type}` 試験種別コード / `{held_date}` 試験日、`--actor=`(必須)。
- 監査: 記録あり(試験実施回、結果の件数)
- 実行時期: 結果の入力が完了した後。すでに公開済みの試験実施回では失敗します。

## 出欠

### `attendance:generate-sessions`

- 目的: 学期のすべての開講科目について、授業時間(曜日、時刻、時限)から授業回を作成します。教員ポータルと管理画面の **授業回を生成** と同じです。既存の授業回とその出欠は保持されます(再実行しても安全です)。
- 引数/オプション: `{term}` 学期コード、`--section=`(科目コード-開講科目コード、例: `CSE2010-01`、1 件のみ)、`--dry-run`(対象の開講科目数のみ)、`--actor=`。
- 監査: 記録あり(学期、開講科目、作成された授業回)
- 実行時期: 学期開始前、授業時間が確定した後。授業時間が変わったら再実行します。

## 卒業

### `degree-audit:run`

- 目的: 在籍中のすべての学生について卒業要件の判定を保存します。管理画面の **卒業判定 > 判定を実行** と同じです。保存された最新の判定が卒業処理の基準になります。
- オプション: `--term=`(判定が属する学期コード)、`--student-number=`(学生 1 名)、`--min-year-level=`(この学年以上のみ)、`--actor=`。
- 監査: 記録あり(学生数、要件を満たした人数)
- 実行時期: 卒業審査の前(学期末)、および要件セットや代替科目を変更した後。

## LMS 連携

### `lms:sync`

- 目的: 公開済みの開講科目をプラットフォームに送信します(コースの作成と連携、教員、履修学生)。管理画面の **コース連携 > 再同期** が行う処理を学期全体に対して行います。すでに連携済みの開講科目は状態の再確認のみ行います(冪等)。
- 引数/オプション: `{platform}` プラットフォームコード、`--term=`(学期コード、既定は終了していないすべての学期)、`--section=`(科目コード-開講科目コード 1 件)、`--dry-run`(送信される内容を「skipped」として記録するのみ)、`--actor=`。
- 監査: 記録あり(プラットフォーム、開講科目、メンバー、失敗)
- 終了コード: 失敗した開講科目がある場合は 2。

### `lms:reconcile`

- 目的: プラットフォームのコース名簿と学生情報システムの履修者一覧を比較し、不足しているメンバーを追加し、余分なメンバーを削除します。差分は同期ログ(`reconcile`)に保存されます。
- 引数/オプション: `{platform?}`(省略時は有効なすべてのプラットフォーム)、`--term=`、`--dry-run`(差分の記録のみ)、`--actor=`。
- 監査: 記録あり(プラットフォームごとの開講科目、追加/削除/失敗の件数)
- 実行時期: 毎日 02:30 にスケジュール実行。プラットフォームの障害後は手動で実行します。

## 運用チェックとクリーンアップ

### `system:health-check`

- 目的: 設定とキー(APP_KEY、PII キー、APP_DEBUG)、DB 接続とロール(runtime、migrator、reporting)、個人情報テーブルの RLS、未適用のマイグレーション、権限カタログの同期、Redis、キュー(Horizon)、Gotenberg、メディアストレージへの書き込み、スケジューラーのハートビートをチェックします。
- オプション: `--json`(監視用の出力)。
- 監査: なし(読み取り専用)
- 終了コード: チェックが 1 つでも失敗した場合は 2。
- 実行時期: デプロイ直後、障害が疑われるとき、監視から定期的に。

### `audit:seal`

- 目的: 監査テーブルの新しい行をハッシュチェーンに連結します([監査の完全性](audit-and-maintenance.md))。
- オプション: `--table=`(record_changes、activity_log、security_events のいずれか。複数指定可)、`--actor=`。
- 監査: 記録あり(テーブルごとの封印行数)
- 実行時期: 毎日 03:30 にスケジュール実行。

### `audit:verify-chain`

- 目的: 監査行の内容ハッシュとチェーンを再計算し、改ざん、削除、順序の入れ替えを検出します。
- オプション: `--table=`。
- 監査: なし(読み取り専用)
- 終了コード: 不一致がある場合は 2。
- 実行時期: バックアップ前、セキュリティレビュー時、削除(prune)後。

### `audit:prune`

- 目的: 保存期間を過ぎた**封印済み**の監査行を削除します。スキーマ所有者の接続で実行されます。
- オプション: `--before=YYYY-MM-DD`(必須)、`--table=`、`--dry-run`(件数のみ)、`--actor=`。
- 監査: 記録あり(基準日、テーブルごとの削除行数)
- 実行時期: 保存ポリシーに従って、バックアップの後。

### `media:prune-orphans`

- 目的: 所有者が存在しなくなったメディアの行と、行のないディレクトリを削除します(人物の写真、出願書類、証明書の PDF、試験の証拠資料)。
- オプション: `--dry-run`(一覧のみ)、`--actor=`。
- 監査: 記録あり(行、ディレクトリ)
- 実行時期: 毎月、または一括削除の後。

## 個人情報の暗号鍵

### `pii:generate-key`

- 目的: `PII_ENCRYPTION_KEY` と `PII_HASH_KEY` の新しいキーを表示します。何も保存しません。
- 監査: 記録なし
- 注意: `PII_HASH_KEY` を変更すると、すべての検索用ハッシュが無効になります。キーのローテーション手順は [security-keys.md](security-keys.md) にあります。

### `pii:reencrypt`

- 目的: キーのローテーション後、以前のキーで暗号化された個人情報を現在のキーで再暗号化します。キューバッチとして実行されます。
- 引数: モデルクラス(現在は `App\\Models\\Person\\Person`)。
- オプション: `--chunk=500`、`--dry-run`(以前のキーを使用しているレコードの件数のみ)、`--force`。
- 監査: 記録あり(バッチ ID、ジョブ数 / プレビュー件数)
- 確認: バッチの進行状況は Horizon(`/horizon`)で確認します。完了して `--dry-run` が 0 を報告したら、`PII_PREVIOUS_KEYS` から以前のキーを削除します。

## ローカライズ

### `i18n:missing`

- 目的: 言語ごとに、基準言語(en)と比べて不足しているキーと、使われなくなったキーを表示します。
- 引数/オプション: `{locale?}`(1 言語のみ)、`--strict`(キーが不足している場合に終了コード 2。CI で使用)。
- 監査: 記録なし

### `i18n:export`

- 目的: 翻訳者に渡す JSON ファイルを作成します。形式: `{"key": {"source": "English text", "translation": "translation"}}`。
- 引数/オプション: `{locale} {path}`、`--missing`(不足しているキーのみ)。
- 監査: 記録なし
- 例: `php artisan i18n:export ko storage/app/ko.json --missing`

### `i18n:import`

- 目的: 翻訳者が記入した JSON を `lang/{locale}` に適用します。基準言語に存在するキーのみ取り込まれ、空の翻訳は無視されます。
- 引数/オプション: `{locale} {path}`、`--dry-run`(書き込まれるキーの一覧のみ表示)。
- 監査: 記録あり
- 注意: 翻訳ファイルはリポジトリで管理されています。取り込み後は変更をコミットしてください。

## チェック

### `naming:check`

- 目的: マイグレーション内のテーブル名と列名を[命名規則](../../../development/naming.md)に照らしてチェックします。
- オプション: `--path=*`(チェックするディレクトリ、既定は `database/migrations`)。
- 監査: 記録なし
- 終了コード: 問題がある場合は 2。

### `pdf:sample`

- 目的: ハングル、CJK、ラオ文字、タイ文字、デーヴァナーガリー、キリル文字、ラテン文字を混在させた表を PDF に出力し、フォントと PDF サービス(Gotenberg)への接続を確認します。
- 引数: `{path=pdf-sample.pdf}`(ローカルディスク `storage/app/private` からの相対パス)。
- 監査: 記録なし
- 失敗時: 接続エラーの場合は、`GOTENBERG_URL` と Gotenberg コンテナの状態を確認してください。
