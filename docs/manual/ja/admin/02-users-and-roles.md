# 2. ユーザーとロール

## 概念

| 用語 | 意味 |
|---|---|
| 権限 | 1 つの機能を使用する資格。例: `ユーザーの閲覧`、`二要素認証のリセット` |
| ロール | 権限をまとめたもの。例: 学籍担当、学科助手 |
| ロール割り当て | ユーザーに範囲と期間を指定してロールを与えること |
| 範囲 | ロールが適用される対象: **全体**、**組織単位**(学部、学科など)または **プログラム** |
| 身分ロール | 志願者、学生、卒業生、教員、指導教員。教務データから自動的に付与され、手動では割り当てできません |

担当業務が変わったときは、ロールの構成または割り当てだけを変更し、プログラム自体は変更しません。すべての変更は監査ログに記録されます。

## ユーザーアカウントの作成

1. **ユーザーとアクセス > ユーザー** に移動し、**作成** を押します。
2. 氏名、メールアドレス、言語を入力して保存します。
3. ユーザーにはパスワード設定用のリンクがメールで届きます。管理者がパスワードを見ることはありません。

アカウントは削除しません。退職などでアカウントを停止するには、ユーザーの **編集** ページを開き、**有効** をオフにします。無効なアカウントはログインできず、すべての権限を失います。すでにログインしていた画面は、次のリクエスト時にログアウトされます。

アカウント編集時の安全策

- 自分自身のアカウントは無効にできません。
- 自分が持っていない権限を持つアカウント(より上位の権限を持つ管理者)は編集できません。
- メールアドレスを変更すると、メールアドレスの確認状態がリセットされ、そのユーザーのすべてのログインセッションが終了し、セキュリティイベント `メールアドレスの変更` が記録されます。
- ユーザーがパスワードを変更すると、他のデバイスのセッションと自動ログイン(remember me)が終了し、セキュリティイベント `パスワードの変更` が記録されます。

## ロールの作成と編集

1. **ユーザーとアクセス > ロール** に移動し、**作成** を押すか、ロールの **編集** を押します。
2. **内部名** には英小文字とアンダースコアを使います(例: `exam_office`)。作成後は変更しないことをお勧めします。
3. 言語ごとに **表示名** を入力します。英語名は必須です。言語の欄を空にすると、その言語の名前は削除されます。
4. **権限** で、機能ごとに権限にチェックを入れます。保存すると、追加・削除された権限が監査ログに記録されます。

| ロールの種類 | 編集 | 削除 |
|---|---|---|
| システムロール(システム管理者) | 名前のみ。常にすべての権限を持ちます | 不可 |
| 身分ロール | 表示名と権限。内部名は不可 | 不可 |
| 一般ロール | すべて | 有効な割り当てがない場合のみ |

## ロールの割り当て

1. **ユーザーとアクセス > ユーザー** に移動してユーザーを開き、下の **ロール割り当て** 一覧までスクロールします。
2. **ロールを割り当て** を押し、ロール、範囲、開始・終了(任意)、**理由** を入力します。
   - 範囲が組織単位またはプログラムの場合は、**範囲の対象** で選択します。組織単位を選ぶと、その下位のすべての組織単位が含まれます。
   - 開始を空にするとすぐに適用され、終了を空にすると期限のない割り当てになります。
3. 割り当ては編集しません。変更するには、既存の割り当てで **割り当てを終了** を使い(理由は必須)、新しい割り当てを作成します。履歴はそのまま残ります。

自分自身の割り当ては終了できません(職務の分離)。他の管理者に依頼してください。

権限昇格を防ぐルール

- 自分自身にロールを割り当てることはできません。
- 自分が持っていない権限を含むロールは割り当てできません。
- 範囲は、自分の `ロールの割り当て・終了` 権限の範囲内でのみ選択できます。例えば、工学部の範囲でこの権限を持つ管理者は、全体の範囲や他の学部の範囲を割り当てることはできません。
- 最初の管理者を作成する `security:create-administrator` コマンドはサーバー運用者が実行するため、これらのルールは適用されません。
