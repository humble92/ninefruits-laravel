# 23. 証明書

メニュー: **証明書 > 発行済み証明書**、**証明書種別**、**設定 > 証明書設定**。証明書は学籍画面(**学生・教職員 > 学籍 > 表示**)の **証明書を発行** ボタンで発行します。学生はポータルの **証明書** で自分の証明書の PDF をダウンロードします。証明書は誰でも `/verify/{code}` ページで検証できます。

| 権限 | できること |
|---|---|
| `証明書の発行・再作成・失効` | 発行、再作成、失効、発行済み証明書の閲覧(学籍閲覧の範囲内) |
| `証明書種別・テンプレート・設定の管理` | 種別と言語ごとのテンプレート、発行番号の形式、発行者名義 |

ロールの既定: 証明書担当は発行を、学籍担当は両方を、教務担当は種別とテンプレートの管理を持ちます。

## 旧システムとの違い

- **発行台帳。** 旧システム(YUSTIC)は画面から直接印刷しており(`aca3/cti_*`)、台帳(`SRCERT`)は番号の採番のためだけに存在したため、誰が発行したのか、失効したのかが分かりませんでした。新システムは発行ごとに発行番号、検証コード、職員、用途、部数、PDF ファイル、チェックサムを記録し、失効した証明書もその行が残ります。
- **検証。** 旧システムにはありませんでした。すべての証明書に検証コードと QR コードが付き、公開ページで発行の事実、種別、発行日、マスクされた所持者(姓と名それぞれの最初と最後の文字、学籍番号の先頭 4 桁)が表示されます。
- **テンプレート。** 旧システムは種別と言語ごとに別々の PDF スクリプトを持っていました。新システムでは、種別ごとに言語別のテンプレート(表題、本文、フッター、発行者名義)を画面で編集します。
- **制限。** 旧システムは履修登録拒否の一覧にかかわらず証明書を発行していました。新システムは証明書発行の制限がある学生には発行しません([第 20 章](20-registration.md))。
- 手数料は記録しません(旧システムは金額を記録するだけでした)。
- 学生によるオンライン申請はありません(移行計画 17.5)。証明書は職員が発行します。

## 種別とテンプレート

**証明書種別**: コード(発行番号に使用)、名称(3 言語)、対象(すべての学籍 / 学生 / 卒業生)、成績を含む、写真を含む、有効、順序。韓国の大学プロファイルでは 3 つの種別があらかじめ登録されます。

| コード | 種別 | 対象 | 備考 |
|---|---|---|---|
| `ENR` | 在学証明書 | 学生(卒業前) | |
| `GRD` | 卒業証明書 | 卒業生 | 卒業日、学位記番号 |
| `TRN` | 成績証明書 | すべての学籍 | 学期ごとの確定成績の表、累積 GPA、修得単位 |

**テンプレート**(種別編集画面の下部): 言語ごとに 1 つ。表題、本文(段落は空行で区切ります)、フッター、発行者名義。本文には波かっこで囲んだプレースホルダーを使います。

| プレースホルダー | 値 |
|---|---|
| `{institution}` | 機関名(その言語のもの) |
| `{student_name}`、`{student_number}` | 氏名(その言語の表記。なければラテン文字表記)、学籍番号 |
| `{program}`、`{org_unit}` | プログラム、組織単位 |
| `{admission_date}`、`{graduation_date}`、`{degree_number}` | 入学日、卒業日、学位記番号 |
| `{status}`、`{year_level}` | 学籍状態、学年 |
| `{birth_date}`、`{gender}`、`{nationality}` | 生年月日、性別、国籍 |
| `{issue_date}`、`{serial_number}`、`{purpose}`、`{copies}` | 発行日、発行番号、用途、部数 |

日付はその言語の形式で出力されます。値がない場合(例: 卒業日)は空欄として出力されます。本文の上には、個人情報の表(氏名、学籍番号、生年月日、性別、国籍、プログラム、入学日、さらに卒業生には卒業日、それ以外には学籍状態と学年)が自動的に追加されます。

## 設定

**設定 > 証明書設定**

- **発行番号の形式**: 既定は `{TYPE}-{YYYY}-{SEQ:6}` → `ENR-2026-000001`。`{SEQ:n}` は必須です。連番は、異なる接頭部分ごとに別々に数えられます。`{TYPE}-{SEQ:6}` は年をまたいで種別ごとに、`{YYYY}{SEQ:5}` は種別をまたいで年ごとに数えます。同時に発行しても番号が重なることはありません(カウンターはデータベースで原子的に増やされます)。
- **検証の有効期間(日)**: 0 は無期限です。期間を過ぎると、検証ページは「期限切れ」と答えます。発行自体は台帳に残ります。
- **言語別の発行者名義**: 印影の上に印刷される名義(「Ninefruits 大学 学長」)。テンプレートの発行者名義が優先されます。

## 発行

学籍画面の **証明書を発行**: 種別、言語、用途、部数(1〜20)。保存すると新しいタブで PDF が開きます。

次の場合は発行が拒否されます。

- 種別の対象が合わない(卒業生への在学証明書、在学生への卒業証明書)
- 種別が無効になっている
- その言語のテンプレートがない
- 学生に **証明書発行の制限** が有効になっている(制限措置、[第 20 章](20-registration.md))。先に解除してください
- 学籍が閲覧範囲外である

発行は業務ログに記録されます(`certificate.issued`: 学籍番号、種別、言語、発行番号、部数、用途)。

## 発行済み証明書

**証明書 > 発行済み証明書**: 発行日、発行番号、種別と言語、学籍番号、氏名、用途、部数、状態、職員。種別と状態で絞り込めます。閲覧範囲は学籍と同じです。

- **PDF**: 保存されたファイルを開きます。再作成はしないため、発行時のままです。
- **検証ページ**: 公開ページを開きます。
- **再作成**: テンプレートを修正した後などに、現在のデータから新しい PDF を作成し、ファイルを置き換えます。発行番号と検証コードはそのままで、チェックサムは変わります。監査イベントは `certificate.rerendered`。コマンド `certificate:render` と同じです。
- **失効させる**: 理由が必要です。行とファイルは残り、状態は失効になり、検証ページは「失効」と答えます。監査イベントは `certificate.revoked`。失効した証明書は元に戻さず、新しく発行します。

台帳の行は画面で編集・削除できません。

## 検証

- 証明書の下部には、検証 URL(`/verify/{code}`)と QR コードが印刷されます。コードはランダムな 20 文字の文字列です。
- このページはログインせずに開け、1 分あたり 30 リクエストに制限されています。証明書が発行されたかどうか、種別、発行番号、発行日、マスクされた氏名と学籍番号が表示されます。失効、期限切れ、存在しないコードには、それぞれ異なる答えが返ります。
- 提出された PDF ファイルそのものを確認するには、台帳のチェックサム(SHA-256)とファイルのハッシュを比較します。コマンド `certificate:verify {code}` でも確認できます。

## 学生ポータル

**証明書**: 学生本人の学籍で発行された証明書と PDF。失効した証明書も状態付きで一覧に表示されますが、学生は失効した証明書の PDF をダウンロードできません(発行した職員は記録確認のために開けます)。他の学生のファイルは開けません(アプリケーションとデータベースで保証)。

## よくある質問

- **氏名の綴りが間違っている。** 人物の(その言語の)氏名表記を修正し、**再作成** します。証明書がすでに提出されている場合は、失効させて新しく発行します。
- **テンプレートを変更したが、発行済みの証明書はどうなるか。** 変わりません。必要に応じて **再作成** します。
- **発行番号が飛んでいる。** 発行中にエラーが発生すると(例: PDF サービスの停止)、番号は消費されますが台帳の行が残らないことがあります。番号は一意であることが保証されますが、連続することは保証されません。
