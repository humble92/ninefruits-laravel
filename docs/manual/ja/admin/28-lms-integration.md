# 28. LMS 連携

メニュー: **LMS 連携 > LMS プラットフォーム**、**コース連携**、**同期ログ**(`LMS プラットフォーム・連携・同期の管理` 権限。既定: システム管理者と学籍担当のほか、教務担当)。教員は **担当授業** と開講科目の詳細にある LMS へのリンクと、成績入力画面の **LMS から得点を読み込む** を使います。読み込みは成績入力と同じ条件に従います(教員は成績入力期間内、職員は `成績` の管理範囲内)。

開発者向けの詳細は [LMS 連携ガイド](../../../lms-integration-guide.md) にあります。

## 何をどこへ送るか

| SIS → LMS | タイミング |
|---|---|
| 開講科目(コースの作成)+ 担当教員 | 開講科目を **公開** したとき、および `lms:sync` の実行時 |
| 確定した履修 → 受講登録 | 履修登録、キャンセル待ちの繰り上げ、職員による履修登録の時点で即時 |
| 削除・履修中止 → 受講登録の解除 | 即時 |
| 全体の照合 | 毎日 02:30(`lms:reconcile`) |

| LMS → SIS | タイミング |
|---|---|
| 最終得点(下書き) | 教員が成績入力画面で **LMS から得点を読み込む** をクリックしたとき。保存と提出は教員が行います |

確定した成績は LMS に送りません。授業資料、課題、小テストは LMS で扱います。

## プラットフォーム

**LMS プラットフォーム**: コード、名称、ドライバー、ベース URL、認証情報(キーと値。暗号化して保存され、編集時に空欄のままにすると保存済みの値が保持されます)、有効、履修者名簿を同期、最終得点を取得。

- ドライバー **なし(記録のみ)**: 何も呼び出さず、送信される内容を記録します。連携前に流れを確認したり、デモンストレーションしたりするときに使います。デモデータの `DEMO` プラットフォームはこれを使っています。
- `Moodle`、`Open edX`: コネクターはまだありません(未実装と表示されます)。選択した場合、同期は失敗として記録されます。
- **有効** をオンにすると、それ以降、開講科目の公開と履修の変更が即時に送られるようになり、そのプラットフォームが毎晩の照合の対象になります。

## コース連携と同期ログ

- **コース連携**: どの開講科目がどのプラットフォームのコース(ID、URL)に連携されているか、状態(保留中/連携済み/失敗)、最終同期、エラー。**再同期** で開講科目、担当教員、履修者名簿を改めて送ります。
- **同期ログ**: 手順(コース、メンバー追加、メンバー削除、得点取得、照合)ごとの結果とメッセージ。失敗の原因はここで確認します。
- コマンド: `lms:sync {platform} --term={term}`(全体の送信、`--dry-run`)、`lms:reconcile`(照合)。

## ポータル

- プラットフォームのコースへのリンクは、学生と教員の科目詳細、および教員の **担当授業** の一覧(連携済みの開講科目のみ)に表示されます。
- 成績入力: プラットフォームで **最終得点を取得** がオンになっていて、開講科目が連携済みであれば、**LMS から得点を読み込む** ボタンが表示されます。素点の列を埋めるだけで、保存はしません。

## よくある質問

- **LMS に学生がいない。** 同期されるには、学生にアカウント(ユーザー)が必要です。アカウントがない場合は招待してください([第 14 章](14-merge-and-invitations.md))。次の照合で追加されます。
- **同期が失敗したままになる。** 同期ログのメッセージを確認してください。認証情報の期限切れがよくある原因です。プラットフォームの編集画面で値を変更し、**再同期** します。
- **プラットフォームを切り替えた。** 新しいプラットフォームを作成し、古いプラットフォームの有効をオフにします。連携はプラットフォームごとに別々に作成されます。
