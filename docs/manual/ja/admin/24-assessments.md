# 24. 試験

メニュー: **試験 > 試験実施回**、**試験結果**、**試験種別**。学生はポータルの **試験** で申込を行い、結果を確認します。

| 権限 | できること |
|---|---|
| `学生の申込登録、結果の入力・公開、外部試験の結果の記録` | 学生の申込登録・取消・欠席処理、結果の入力、CSV 取り込み、結果の公開、外部試験の結果の記録・削除、結果台帳の閲覧(学籍閲覧の範囲内) |
| `試験種別・領域・実施回の管理` | 種別、領域、実施回の作成と編集 |

ロールの既定: 学籍担当と教務担当が両方を持ちます。

## 旧システムとの違い

- **種別ごとの固定列がない。** 旧システム(YUSTIC)は、`CET` に文法・作文・聴解・読解の 4 列を固定で持ち、総合試験(`SSCORE_ADD`)では科目ごとに P/N の 1 文字、コンピューター試験(`COMEXAM`)ではさらに別のテーブルを使っていました。新システムでは **試験種別** に領域と評価方法を定義し、すべての試験を同じ実施回・申込・結果の構造で扱います。
- **合否判定。** 旧システムでは 4 領域の合計が合格ラインに達すれば合格で、領域ごとの最低点はありませんでした。新システムは種別(または実施回)の合格点と **領域ごとの最低基準点** で判定します。合否型の種別は職員が判定します。
- **申込期間と定員。** 旧システムにはありませんでした。実施回には申込の開始・締切日時と定員があります。
- **結果の公開。** 旧システムでは入力した時点で学生に結果が見え、しかも最新の実施回だけでした。新システムでは実施回の **結果を公開** の後に学生が結果を確認でき、すべての実施回の結果が保存されます。
- **外部試験の結果。** 旧システムには TOEFL や TOPIK などの外部試験を記録する場所がありませんでした(卒業判定表の HSK 欄は中身のないラベルでした)。外部試験の結果は証拠書類のファイルとともに記録します。
- **卒業要件との連携。** 旧システムでは担当者が卒業判定表を読んで判断していました。要件の種類 **試験合格** によって、これが教育課程に組み込まれます([第 17 章](17-courses-and-curriculum.md))。

## 試験種別と試験領域

**試験種別**: コード、名称(3 言語)、区分(語学、総合、論文、外部試験)、評価方法、満点、合格点、外部試験の結果、有効。

| 評価方法 | 入力 | 判定 |
|---|---|---|
| 点数 | 領域ごとの点数(領域がなければ合計) | 合計 ≥ 合格点 かつ すべての領域 ≥ その最低基準点。合格点がなければ職員が選択 |
| 合否 | 合格かどうか | 職員が選択 |

**試験領域**(種別編集画面の下部): コード(CSV の列名)、名称、満点、最低基準点(任意)。領域がある場合、合計は各領域の点数の和になります。

韓国の大学プロファイルで登録される種別:

| コード | 種別 | 判定 | 備考 |
|---|---|---|---|
| `ENG_COMP` | 英語総合試験 | 点数、60 点で合格 | 聴解、読解、作文、文法、各 25 点 |
| `COMP_EXAM` | コンピューター総合試験 | 合否 | |
| `THESIS` | 卒業論文 | 合否 | |
| `TOPIK` | 韓国語能力試験 | 合否、外部 | 級と証明書番号を記録 |

## 実施回

**試験実施回**: 種別、実施日(種別ごとに一意)、会場、定員、申込開始と申込締切、合格点(空欄: 種別の値)。**申込者** の一覧は実施回編集画面の下部にあります。

- **学生を申込登録**(学籍番号を入力): 職員は申込期間にかかわらず、試験日まで学生を申込登録できます。定員は適用されます。実施日を過ぎた実施回には誰も申込登録できません。結果は申込済みの学生にのみ入力でき、未申込の学生の CSV の行はエラーとして報告され、スキップされます。
- 学生は申込期間中にポータルで申込と取消を行います。申込できるのは在学・休学中の学生だけです。
- **結果を入力**: 領域ごとの点数(または合計)、必要に応じて合格かどうか、備考。公開前は、再度入力すると上書きされます(監査イベント `assessment.result_recorded`)。**公開後はロックされます**(後述の訂正申請を参照)。
- **欠席**: 申込したが受験しなかった場合。結果を入力すると、申込は申込済みに戻ります。
- **申込を取消**: 結果がある申込は取り消せません。
- **結果を公開**: 以後、学生はこの実施回の結果を確認できます。公開後は結果を直接編集・削除できず、**訂正申請** によって変更します(2026-10-23 の決定)。コマンド `assessment:publish-results` と同じです。
- 実施回の **合格点**(種別の値を上書き): 試験が難しかったため会議で合格ラインを下げる場合などに使います。**公開前** に限り変更でき、変更した時点で、その実施回にすでに入力されているすべての結果が、保存された点数から **再判定** されます(合計は新しい基準で、領域の最低基準点は種別の設定どおり)。理由を付けると、監査イベント `assessment.pass_score_changed` に、変更前後の基準と判定が変わった学生の学籍番号が記録されます。**公開後** はロックされます(訂正申請のみ)。領域ごとの最低基準点は実施回では変更できません(種別の設定)。
- **結果を取り込み(CSV)**: 形式は以下のとおりです。未申込の学生の行はエラーとしてスキップされます。コマンド `assessment:import-results` と同じです。

CSV の形式(ヘッダー行あり、UTF-8):

| 列 | 内容 |
|---|---|
| `student_number` | 学籍番号(必須) |
| 領域コード(`LISTENING` など) | 領域の点数。大文字と小文字は区別しません |
| `total` | 領域のない種別の合計 |
| `passed` | `Y`/`N`。合否型の種別、または合格点のない種別では必須 |
| `absent` | `Y` で欠席として処理 |
| `note` | 備考 |

エラーの行はスキップされ、結果の通知(画面)または出力(コマンド)に行番号付きで報告されます。

## 結果訂正

公開済みの実施回の結果を変更する手続きです。成績訂正と同じように動作します。

1. 実施回の申込者一覧から **訂正を申請**: 新しい点数(または合格かどうか)と理由。1 つの結果につき承認待ちの申請は 1 件までです。監査イベント `assessment.correction_requested`。
2. **試験 > 結果訂正** で、`試験種別・領域・実施回の管理` 権限の保有者が **承認**(メモは任意)または **却下**(メモが必要)をクリックします。**自分の申請は誰も判断できません。**
3. 承認されると、結果はすぐに新しい値に変わり、学生にも表示されます。監査イベント `assessment.correction_approved`、`assessment.result_corrected`。申請者は判断が下るまで申請を取り消せます。

一覧には既定で承認待ちの申請が表示され、現在の値と訂正後の値が並べて表示されます。

## 結果台帳

**試験結果**: すべての結果(実施回と外部試験)。種別、出所、合格で絞り込めます。閲覧範囲は学籍と同じです。

- **外部試験の結果を記録**: 学籍番号、種別(外部試験の結果を受け付ける種別のみ)、受験日(未来の日付は不可)、合計、級・レベル、合格かどうか、証明書番号、証拠書類のファイル(PDF、JPG、PNG、5 MB)、備考。監査イベント `assessment.external_recorded`。
- **証拠書類**: ファイルを開きます。学生は自分のものを開けます。
- **削除**: 理由が必要で、監査イベントは `assessment.result_removed`。誤って入力した外部試験の結果や、公開前の結果を削除して記録し直すためのものです。公開済みの実施回の結果は削除できません(訂正申請)。

## 卒業要件

**卒業要件** の編集画面で、要件の種類 **試験合格** を選び、試験種別を指定します。学生は、その種別の合格結果(実施回または外部試験)が 1 件以上あれば要件を満たします。ポータルの **試験** ページの上部には、学生の教育課程で求められる種別と、合格しているかどうかが表示されます。卒業判定(Phase 11)はこの要件を読み取ります。

## 学生ポータル

**試験**: 教育課程の要件と合格状況、申込受付中の実施回(申込、取消)、自分の申込、自分の結果(公開済みの実施回と外部試験の結果、領域ごとの点数、証拠書類)。

## よくある質問

- **申込期間外に学生を申込登録する必要がある。** 職員が実施回の **申込者 > 学生を申込登録** で申込登録します。
- **この実施回だけ合格点を変えたい。** 結果の公開前に実施回の合格点を入力します。すでに入力された結果は、保存済みの点数ですぐにすべて再判定されます(領域ごとの最低点は種別の値のままです)。公開後は変更できないため、訂正申請で対応します。
- **点数を誤って入力した。** 公開前であれば、もう一度 **結果を入力** して上書きします。公開後は **訂正申請** を出し、別の職員に承認してもらいます。
- **欠席者の統計。** 申込者の一覧を状態で絞り込みます。
