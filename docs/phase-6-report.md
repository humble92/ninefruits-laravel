## 1. 요약

다음을 구현했다.

- 성적 입력(교원 포털 그리드, 점수→등급, 임시 저장, 제출), 담당자의 확정과 반려
- 확정 성적의 정정 요청과 승인(직무 분리, DB 트리거 보호)
- 평점 계산(정수 연산, 자릿수·반올림·재수강 정책)과 학기 기록
- 학기 마감 배치(`Bus::batch`, 학사경고·제적 검토·성적우수)
- 학생 성적 조회와 인쇄용 성적표, 성적 처리 정책 설정

Phase 5 이후 결정한 사항도 반영했다.

- 수강신청 제한의 성적 조회 차단: 기본 꺼짐, 부정행위 조사 등에도 사용. 이번에 적용했다.
- 릴리스 때 처리할 PHP 보안 조치: 계획서 Phase 13에 기록했다.

검증 결과는 다음과 같다.

- 테스트 TESTS개(단언 ASSERTIONS개) 통과. Phase 5 대비 DELTA개 추가. Larastan 레벨 6 오류 0, Pint 위반 0, 명명 검사 위반 0, 번역 누락 0, `composer audit` 통과

## 5. 발견해 고친 문제

- **평점 자릿수 저장**: 학기 기록의 평점 열을 `numeric(5,3)`으로 만들었더니, 2자리로 계산한 값이 3자리(0.000)로 저장되었다. 계산한 자릿수 그대로 저장하도록 자릿수 제한 없는 `numeric`으로 바꿨다(`GradeWorkflowTest`).
- **중복 정정 요청과 트랜잭션**: 진행 중인 요청이 있는 성적에 다시 요청하면 unique 위반 뒤 트랜잭션이 중단되어 같은 요청 안의 이후 쿼리가 실패했다. 먼저 확인하고, INSERT는 세이브포인트 안에서 실행하게 했다.
- **성적 처리 현황 집계**: `withCount` 별칭 형식이 잘못되어 화면이 500 오류를 냈다(관리 화면 테스트에서 발견).
- **데모의 무작위성**: 정정 요청 데모가 특정 성적(B0)과 첫 번째 교원에 의존해 실행마다 만들어지지 않을 수 있었다. 계정이 있는 교원과 아무 확정 성적으로 넓혔다.
