## 1. 요약

다음을 구현했다.

- 성적 입력(교원 포털 그리드, 점수→등급, 임시 저장, 제출), 담당자의 확정과 반려
- 확정 성적의 정정 요청과 승인(직무 분리, DB 트리거 보호)
- 평점 계산(정수 연산, 자릿수·반올림·재수강 정책)과 학기 기록
- 학기 마감 배치(`Bus::batch`, 학사경고·제적 검토·성적우수)
- 학생 성적 조회와 인쇄용 성적표, 성적 처리 정책 설정

Phase 5 이후 결정한 사항도 반영했다.

- 수강신청 제한의 성적 조회 차단: 기본 꺼짐, 부정행위 조사 등에도 사용. 이번에 적용했다.
- 릴리스 때 처리할 PHP 보안 조치: 계획서 Phase 13에 기록했다.
- 절대평가와 상대평가.
  - 절대평가는 점수를 입력하고 4.3·4.5 두 척도의 성적을 함께 저장한다.
  - 상대평가는 성적만 입력한다.
  - 시스템 설정은 절대평가 기준 척도 하나다.
- 2단계 인증 마감일을 기관 시간대로 표시한다.

검증 결과는 다음과 같다.

- 테스트 406개(단언 약 1,780개) 통과. Phase 5 대비 51개 추가. 전체 실행 약 6분. Larastan 레벨 6 오류 0, Pint 위반 0, 명명 검사 위반 0, 번역 누락 0, `composer audit` 통과
- 빈 DB에서 `setup:install --force --profile=korean-university`와 `setup:demo --size=small --seed=42`가 성공했다(데모 약 18초).
  - 지난 학기: 확정 성적 305건, 학기 기록 61건(학사경고 5명, 성적우수 4명)
  - 이번 학기: 강좌 셋 중 하나가 절대평가. 점수로 제출 완료한 절대평가 강좌 1개(두 척도 성적 저장), 임시 저장한 상대평가 강좌 1개, 재수강 33건, 대기 중인 정정 요청 1건

## 5. 발견해 고친 문제

- **평점 자릿수 저장**: 학기 기록의 평점 열을 `numeric(5,3)`으로 만들었더니, 2자리로 계산한 값이 3자리(0.000)로 저장되었다. 계산한 자릿수 그대로 저장하도록 자릿수 제한 없는 `numeric`으로 바꿨다(`GradeWorkflowTest`).
- **중복 정정 요청과 트랜잭션**: 진행 중인 요청이 있는 성적에 다시 요청하면 unique 위반 뒤 트랜잭션이 중단되어 같은 요청 안의 이후 쿼리가 실패했다. 먼저 확인하고, INSERT는 세이브포인트 안에서 실행하게 했다.
- **성적 처리 현황 집계**: `withCount` 별칭 형식이 잘못되어 화면이 500 오류를 냈다(관리 화면 테스트에서 발견).
- **데모의 무작위성**: 정정 요청 데모가 특정 성적(B0)과 첫 번째 교원에 의존해 실행마다 만들어지지 않을 수 있었다. 계정이 있는 교원과 아무 확정 성적으로 넓혔다.
- **테스트 시간 (82분)**: 데모 정정 요청 시더의 중첩 `whereHas`(강좌 → 교원 → 인물 → 사용자)가 RLS 아래에서 쿼리 하나에 수십 초~수 분 걸렸다. 데모 전체를 시딩하는 성적 관리 테스트마다 실행되어 전체 테스트가 82분이 되었다. 단계별 조회로 바꿔 6분으로 돌아왔다. 중단한 테스트의 쿼리가 DB에 남아 다음 실행을 막는 일도 겹쳤다. 개발 중 테스트를 중단하면 `pg_stat_activity`를 확인한다.
- **Phase 5 테스트 간헐 실패**: 직원 수강신청 테스트가 정렬 없는 `first()`로 수강을 골라, 드물게 정원이 찬 대기자 시연 강좌가 뽑혔다. 정원이 남은 강좌를 id 순으로 고른다.
- **2단계 인증 마감일 시간대**: 포털 안내가 UTC 날짜로 표시되어, 서울 기준 오전 9시 이전 마감이면 하루 전 날짜로 보였다. 기관 시간대로 표시한다.

## 8. 보완 (2026-10-23)

4.3/4.5 두 척도 설계를 검토한 결과, 기준 척도 설정이 성적을 망칠 수 있는 설정이었고 비교 척도 값은 쓰이지 않았다. 다음으로 고쳤다([0011](decisions/0011-grades-and-term-records.md) 수정 절).

| 항목 | 내용 |
|---|---|
| 척도 | 설치 때 확정(`setup:install --grade-scale`), 이후 변경·삭제 불가. 기준 척도 설정과 비교 척도 칸 삭제 |
| 평가 방식 | 기본 절대평가. 상대평가는 교원이 요청하고 개설 담당자가 승인(승인 시 임시 저장 성적 삭제, 메일). 성적 제출 후 변경 불가 |
| 등급 비율 상한 | 설정(A 30%, B 40%, 허용 1%p, 10명 이상 검사). 교원은 넘기면 제출 불가(검사 버튼). 직원은 사유를 적고 예외 제출: 강좌 표시, 감사, 검토 권한자 메일, 현황 필터 |
| 테스트 | `RelativeEvaluationTest`(비율 검사·면제, 교원 차단, 직원 예외 제출과 알림·감사, 변경 요청 승인과 임시 저장 삭제, 화면, 척도 고정) |
