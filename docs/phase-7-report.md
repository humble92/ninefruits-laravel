## 1. 요약

강의평가 양식과 문항, 학기별 설정, 세션별 평가 기간, 학생 익명 응답, 최소 응답 기준을 둔 결과 공개, 미완료 시 성적 조회 제한(설정)을 구현했다. 레거시는 응답에 학번을 저장해 익명이 아니었다. 신규 시스템은 완료 기록과 응답을 분리하고, 응답에는 학생·순번·시각을 남기지 않는다.

- 테스트 419개(단언 1,883개) 통과. Phase 6 대비 13개 추가. 전체 실행 6분 30초 → 3분 54초(아래 5절). Larastan 레벨 6 오류 0, Pint 위반 0, 명명 검사 위반 0, 번역 누락 0, `composer audit` 통과
- 빈 DB에서 `setup:install --force --profile=korean-university`, `setup:demo --size=small --seed=42` 성공(데모 약 21초).
  - 표준 양식 1개(16문항)
  - 지난 학기: 응답 211건(의견 44건), 결과 공개
  - 이번 학기: 시연용 평가 기간이 열려 있음
- CI(GitHub Actions): 7절

## 5. 발견해 고친 문제

- **데이터 감사와 익명성**: 기존 규칙(모든 업무 테이블 감사)을 그대로 적용하면 감사 기록의 수행자 ID로 학생과 응답이 이어진다. 응답·답변·완료 테이블은 감사하지 않고, 테스트로 감사 기록이 생기지 않는 것을 확인한다.
- **응답 순서**: 일련번호 ID를 쓰면 완료 순서와 응답 순서를 맞출 수 있다. 응답은 무작위 UUID, 답변은 복합 키로 두었다.

- **테스트 시간**: Phase 6 CI의 테스트 작업이 17분 56초로 Phase 5(7분 37초)의 두 배를 넘었다. 테스트별 시간을 재 보니 두 파일이 전체의 55%였다(`RegistrationAdminTest` 120초/8개, `GradingAdminTest` 89초/5개). 둘 다 테스트마다 데모 전체(학생 100명)를 시딩했다. 테스트 전용 데모 크기 `tiny`(학생 20명, `setup:demo --size=tiny`로도 쓸 수 있음)로 바꿔 두 파일이 209초에서 58초가 되었고, 단언은 그대로 통과한다. 로컬 전체 실행은 6분 30초에서 3분 54초가 되었다.
- **재수강 상한 테스트 보강(Phase 6 확인 요청)**: 같은 점수에서 재수강만 상한으로 낮아지는지, 비교 척도 성적도 낮아지는지, 평점(학기 기록)이 점수가 아니라 상한 평점을 쓰는지, 재수강 성적을 새 점수로 정정해도 상한이 다시 적용되는지를 한 테스트로 확인한다(`GradeWorkflowTest`).

## 6. 실행 방법

`./vendor/bin/sail artisan setup:demo --size=small` 후 (비밀번호 `demo-password`):

| 계정 | 볼 것 |
|---|---|
| `instructor@demo.test` | 포털 담당 강좌: 지난 학기를 고르면 강의평가 결과(공개됨, 응답이 충분한 강좌) |
| `academic-affairs@demo.test` | 강의평가: 학기 강의평가(지난 학기 공개, 이번 학기 진행 중), 양식(표준 양식, 응답이 있어 잠김), 강좌별 응답, 설정 |
| 이번 학기 수강 학생 | 포털 강의평가(시연용 평가 기간이 열려 있음). 성적 조회 제한은 확정 성적이 있는 학기에서 보이므로, 데모에서는 테스트(`EvaluationTest`)로 확인한다 |
