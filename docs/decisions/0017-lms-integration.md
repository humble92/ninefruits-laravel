# 0017. LMS 연동 기반

- 상태: 채택 (2026-10-23, Phase 12)
- 관련: [이식 계획 12절](../porting-plan.md), [LMS 연동 가이드](../lms-integration-guide.md), [0011 성적](0011-grades-and-term-records.md), [관리자 매뉴얼 28장](../manual/admin/28-lms-integration.md)

## 배경

레거시에는 LMS가 없었고 강의실 기능(게시판, 자료)이 학사 시스템 안에 있었다. 신규 시스템은 강의실 기능을 LMS에 맡기고(10.9절) 학사 시스템은 원본 데이터(사용자, 개설강좌, 수강 명단, 확정 성적)만 내보낸다. 이번 단계는 특정 LMS를 붙이지 않고 **붙일 수 있는 자리**를 만든다.

## 결정

### 커넥터 인터페이스와 null 구현

- `LmsConnector`(강좌 보장, 사용자 보장, 등록, 해제, 구성원 목록, 최종 점수)를 두고 드라이버별 구현을 `ConnectorRegistry`에 등록한다. 플랫폼 행이 드라이버와 인증 정보를 가지므로 같은 커넥터로 여러 플랫폼(캠퍼스별 Moodle 등)을 운영할 수 있다.
- `NullConnector`는 결정적 ID만 돌려준다. 이벤트 → 잡 → 로그 → 대조의 전 과정을 실제 플랫폼 없이 테스트·시연한다. 구현 없는 드라이버는 조용히 성공하지 않고 실패로 기록된다.

### 이벤트 기반 즉시 반영 + 야간 대조

- 도메인 이벤트 `SectionPublished`, `EnrollmentConfirmed`, `EnrollmentDropped`(신규), `GradesFinalized`(기존)를 `QueueLmsSync`가 구독해 활성 플랫폼마다 큐 작업을 만든다. 작업은 `afterCommit`으로 트랜잭션 뒤에만 나간다.
- 확정 성적은 보내지 않는다(학사 시스템이 원본, LMS는 원점수 보유). 이벤트는 구독해 두어 연동 범위가 한눈에 보이게 했다.
- 이벤트는 놓칠 수 있으므로(큐 장애, 플랫폼 장애) `ReconcilePlatform`이 매일 공개 강좌의 명단을 플랫폼과 비교해 맞춘다. 두 경로가 같은 `SyncSection::member/removeMember`를 쓴다.

### 점수는 초안으로만

- `PullGrades`는 플랫폼 최종 점수를 수강별로 매핑해 돌려줄 뿐 저장하지 않는다. 성적 입력 화면의 **LMS 점수 불러오기**가 점수 칸을 채우고, 저장·제출·확정은 기존 성적 흐름(0011)을 그대로 거친다. 상대평가 강좌(등급만 입력)에서는 점수 칸이 없어 쓰이지 않는다.

### 기록과 보안

- 모든 단계는 `lms_sync_logs`에 대기 → 성공/실패/건너뜀으로 남는다(`SyncLogger`). 외부 호출 실패는 예외로 전파되어 큐가 재시도한다.
- 인증 정보는 `encrypted:array` 캐스트로 암호화 저장하고 모델 `hidden`, 데이터 감사의 비밀 칼럼으로 둔다. 화면은 값을 되돌려 보여 주지 않는다.
- RLS: 강좌 연결은 로그인 사용자 모두 읽음(포털 링크), 사용자 연결은 본인, 기록과 모든 쓰기는 `lms.manage`. 잡은 시스템 컨텍스트.

## 하지 않은 것

- 실제 커넥터(Moodle, Open edX), LTI 1.3, 통합 로그인(IdP 구축), OneRoster 내보내기.
- 점수 자동 저장, LMS 측 삭제(강좌 취소 시 플랫폼 강좌는 남긴다).
- 플랫폼별 역할 매핑 UI(`options` jsonb에 둔다).
