# 0014. 어학/종합시험: 종류별 영역과 판정, 회차, 외부 성적

- 상태: 채택 (2026-10-23, Phase 9)
- 관련: [이식 계획 10.8절, Phase 9](../porting-plan.md), [0006 기준정보](0006-reference-data-model.md), [관리자 매뉴얼 24장](../manual/admin/24-assessments.md)

## 레거시 분석 요약

- 세 가지 구조가 따로 있었다. `CET`(어학: 문법·쓰기·듣기·읽기 고정 칼럼, 회차 `CET_HISTORY`, 합격 플래그, 증서 번호), `SSCORE_ADD`(영어종합·전산종합·졸업논문: 학생×구분당 P/N 한 글자, 회차 없음), `COMEXAM`(전산 자격: 필기·실기 점수, 항상 'P').
- 합격은 네 영역 합계 ≥ 커트라인뿐이었고 영역별 최저점이 없었다. 커트라인이 없는 종류는 합격 플래그가 비었다.
- 회차 뷰(`V_LCET`)가 종류별 최신 회차만 보여 과거 기록이 화면에서 사라졌다. 회차를 지우면 응시 행이 고아가 됐다. 접수 기간·정원·결과 공개 개념이 없었다.
- 외부 시험(TOEFL, TOPIK, HSK) 기록은 없었다. 졸업 사정표는 값을 찍어 줄 뿐 판정하지 않았다.

## 결정

### 종류가 구조를 정의한다

- `assessment_types`: 코드, 이름, 구분(언어/종합/논문/외부), 판정 방식(`score`/`pass_fail`), 만점, 합격 점수, 외부 성적 허용.
- `assessment_components`: 종류별 영역(코드, 이름, 만점, 최저점). 영역이 없는 점수 종류는 총점 하나로 판정한다.
- 세 레거시 구조를 모두 이 하나로 표현한다. CET → 점수 종류 + 영역 4개, SSCORE_ADD → 합격/불합격 종류 3개, COMEXAM → 점수 종류(필기·실기 영역) 또는 합격/불합격.

### 판정 규칙은 앱이 적용하고 결과에 저장한다

- 점수 종류: 총점(영역 합) ≥ 합격 점수(회차 값이 우선) 이고 모든 영역 ≥ 최저점. 합격 점수가 없으면 담당자가 판정한다.
- 합격/불합격 종류: 담당자가 판정한다.
- 결과 행에 `is_passed`를 저장한다. 기준이 나중에 바뀌어도 과거 판정은 그대로다(다시 입력해야 바뀜). 졸업 요건 판정은 저장된 값을 읽는다.

### 회차, 접수, 결과

- `assessment_sessions`: 종류 × 시험일 unique, 장소, 접수 기간, 정원, 합격 점수 override, 결과 공개 시각. 외래 키 `restrict`로 응시가 있는 회차는 지울 수 없다(레거시 고아 방지).
- `assessment_registrations`: 회차 × 학적 unique, 상태(접수/취소/결시), 접수 주체(학생이면 null). 취소 행을 남기고 재접수 시 되살린다.
- `assessment_results`: 학적, 종류, 회차(null = 외부), 접수(회차 결과는 1:1), 출처, 응시일, 총점, 등급, 합격, 증서 번호, 비고, 입력자. 영역 점수는 `assessment_component_scores`. 외부 성적의 증빙은 미디어 컬렉션 `evidence`.
- 학생 접수는 앱이 기간·정원·중복·학적 상태를 확인한 뒤 **시스템 컨텍스트**로 쓴다(0012 강의평가와 같은 방식). 학생에게 쓰기 RLS 정책을 열지 않기 위해서다.
- 학생은 회차 결과를 **결과 공개** 뒤에만 읽는다(RLS). 외부 성적은 바로 읽는다.
- 직원 접수는 시험일까지다. 시험일이 지난 회차에 접수 없이 응시한 학생은 결과 입력(CSV 가져오기)이 응시 기록을 함께 만든다(`forResult`). 응시하지 않은 학생을 뒤늦게 접수시키는 일은 막는다.

### 공개 뒤에는 잠그고 정정 요청으로 바꾼다 (2026-10-23 추가)

- 결과 공개 뒤 `RecordAssessmentResult::forRegistration`과 `remove`는 거부한다(`published_locked`). 학생이 이미 본 값이 조용히 바뀌지 않게 하기 위해서다.
- `assessment_result_corrections`: 결과, 이전 값·정정 값(jsonb), 사유, 상태(대기/승인/반려/취소), 요청자, 결정자·의견. 결과당 대기 중 요청은 하나(부분 유니크).
- 요청은 `assessments.record`, 결정은 `assessments.manage`이며 **요청자 본인은 결정할 수 없다**(0011 성적 정정과 같은 규칙). 승인은 같은 트랜잭션에서 값을 반영한다(`applyingCorrection`, 감사 `assessment.result_corrected`).
- 회차의 합격 점수 변경은 데이터 감사 트리거가 기록한다. 이미 판정된 결과는 다시 판정하지 않는다(저장된 `is_passed` 유지).

### 졸업 요건 연계

- `curriculum_requirements.kind = 'assessment_pass'` + `assessment_type_id`. CHECK 제약을 종류별로 다시 정의했다.
- `AssessmentPassCheck::hasPassed(record, type)`: 합격 결과가 하나라도 있으면 충족. 출처(교내/외부)를 가리지 않는다. Phase 11 졸업 사정이 이 서비스를 호출한다.

### CSV 가져오기

- 회차별로 `student_number`, 영역 코드 열, `total`, `passed`, `absent`, `note`. 접수하지 않은 학생은 접수 처리한다(레거시 bulk 입력과 같은 편의). 오류 행은 건너뛰고 보고한다. 화면과 명령이 같은 서비스를 쓴다.

## 하지 않은 것

- 응시료, 좌석 배정, 고사장 분반(레거시에도 없음).
- 학생이 외부 성적을 직접 제출하고 직원이 승인하는 흐름. 직원이 증빙을 보고 등록한다. 필요하면 "검토 중" 상태를 더한다.
- 결과 공개 알림 메일.
- 외부 시험의 등급 ↔ 합격 기준 표(예: TOPIK 4급 이상 합격). 등급은 문자열로 기록하고 합격은 담당자가 고른다.
- 레거시 이관: CET 회차 → 회차, 응시 행 → 접수+결과, SSCORE_ADD → 합격/불합격 결과(응시일은 알 수 없어 졸업 또는 입력일로 대체).
