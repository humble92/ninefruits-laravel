# 0013. 증명서: 서식, 발급 대장, 진위 확인

- 상태: 채택 (2026-10-23, Phase 8)
- 관련: [이식 계획 Phase 8, 17.5](../porting-plan.md), [0004 PDF](0004-pdf-rendering.md), [0010 수강신청(제한)](0010-registration.md), [관리자 매뉴얼 23장](../manual/admin/23-certificates.md)

## 레거시 분석 요약

- 종류는 코드 10/11/12(성적, 재학, 졸업)에 언어 K/C/E를 붙인 조합이었고, 종류·언어마다 PDFlib 스크립트가 따로 있었다(`aca3/cti_*`, `all_score*`, `all_biye*`).
- 대장 `SRCERT`는 발급번호(YYMM + 순번)를 만들기 위한 것이었다. 잠금 없이 `MAX+1`로 번호를 매겨 동시 발급 시 겹칠 수 있었고, 담당자·취소·파일이 없었다.
- 진위 확인 수단이 없었다. 수강거부 명단과 무관하게 발급했다. 수수료는 금액만 적었다.
- 발급은 증명서 담당 역할(ACACERT)만 했고 학생 신청 기능은 없었다.

## 결정

### 종류와 서식은 데이터다

- `certificate_types`: 코드, 이름(jsonb), 대상(any/enrolled/graduated), 성적 포함, 사진 포함, 사용 여부.
- `certificate_templates`: 종류 × 언어로 제목, 본문, 하단 문구, 발급자. 본문은 `{placeholder}` 치환. 치환 항목 목록은 `CertificateRenderer::PLACEHOLDERS` 한 곳에 둔다.
- 레이아웃(머리글, 인적 사항 표, 성적 표, 서명, 확인 URL과 QR)은 Blade 뷰 `pdf.certificate` 하나다. 기관이 바꾸는 것은 문구이고, 레이아웃은 코드다.
- 프로파일 시더가 재학·졸업·성적증명서와 3개 언어 서식을 넣는다. 관리자 수정은 유지한다(없을 때만 생성).

### 발급 대장은 지우지 않는다

- `certificate_issues`: 학적, 종류, 언어, 발급번호(unique), 확인 코드(unique, 20자 무작위), 용도, 매수, 상태(issued/revoked), 발급 시각·담당자, PDF 체크섬(SHA-256), 취소 시각·담당자·사유. 상태와 취소 시각은 CHECK로 묶는다.
- 화면에서 수정·삭제 불가(정책). 취소는 행과 파일을 남기고 상태만 바꾼다. 감사 트리거 적용.
- PDF는 발급 시점에 만들어 미디어 컬렉션에 보관한다(PDF 서비스 장애 때도 발급된 문서를 보여 주기 위함, 체크섬으로 파일 검증). **다시 만들기**는 명시적 행위이며 감사에 남는다.
- 발급 수수료는 두지 않는다. 필요하면 대장에 금액 칼럼을 더한다.

### 발급번호는 DB가 원자적으로 센다

- 형식 설정 `{TYPE}-{YYYY}-{SEQ:6}`. 접두어(`{SEQ}` 앞까지 치환한 문자열)마다 `certificate_number_sequences`에 한 행을 두고 `INSERT … ON CONFLICT DO UPDATE SET last_value = last_value + 1 RETURNING` 으로 받는다. 동시 발급에도 겹치지 않는다. 발급 트랜잭션이 실패하면 번호는 건너뛴다(연속성보다 유일성).

### 진위 확인은 공개, 명의자는 가린다

- `/verify/{code}`: 로그인 없음, 분당 30회 제한, `noindex`. 발급 여부와 종류, 발급번호, 발급일, 가려진 성명(첫·마지막 글자)과 학번(앞 4자리)만 보여 준다. 취소, 기간 만료(설정 `verification_valid_days`, 기본 0=항상), 없는 코드를 구분한다.
- 조회는 시스템 컨텍스트에서 한다(비로그인 사용자는 RLS로 아무것도 못 읽기 때문). 코드는 유일 인덱스로 찾는다.
- PDF 본문에 확인 URL과 QR(SVG, `bacon/bacon-qr-code`)을 인쇄한다.

### 발급 조건

- 직원만 발급한다(권한 `certificates.issue` + 학적 조회 범위). 학생 온라인 신청은 계획서 17.5대로 하지 않는다.
- 종류의 대상(재학/졸업)에 맞아야 한다. 증명서 제한(`registration_holds.blocks_certificates`)이 적용 중이면 거부한다(2026-10-22 결정: 기본 꺼짐, 부정행위 조사 등 행정 처리용).

### 접근

- RLS: 대장은 보이는 학적(`student_records` 정책)의 것만, 쓰기는 `certificates.issue`. 학생은 자기 학적의 것만 읽는다. 종류·서식은 모두 읽고 `certificates.manage`로 쓴다.
- 다운로드 라우트는 정책 `view`(발급 권한자 또는 명의자)로 막고 비공개 디스크에서 스트리밍한다.

## 하지 않은 것

- 학생 온라인 신청·결제, 수수료 기록
- 사진 포함 증명서의 사진 품질 검증(인물 사진을 그대로 넣는다)
- 전자서명(PAdES)·타임스탬프: 필요하면 PDF 생성 뒤 서명 단계를 더한다
- 레거시 대장 이관: 번호 체계가 달라 그대로 못 넣는다. 이관한다면 옛 번호를 `serial_number`로, 확인 코드는 새로 만든다
